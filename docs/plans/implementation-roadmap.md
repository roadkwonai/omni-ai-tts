## 1. 진행 방식

기능 하나를 화면·API·DB·공급자 연결까지 한 번에 완성한다. 기능이 앱에서 실제로 동작하고, 검증과 사용자 테스트를 통과해야 다음 기능으로 간다.

- **기존 계획과 다른 점:** [요구사항 6절](tts-service-requirements.md)과 [UI 우선 구현 계획](tts-ui-first-implementation.md)은 "화면 7개를 가상 데이터로 먼저 옮기고, 그 뒤에 데이터와 공급자를 붙인다"는 층별 순서였다. 이 로드맵이 그 순서를 대신한다. "UI/UX 먼저"라는 확정 사항은 HTML 시안(UI-01~10)으로 이미 채웠다. HTML은 앞으로도 각 기능의 화면 명세로 쓴다.
- **이유:** 층별 순서로 하면 공급자 연결 위험(유료 호출 중복, 오디오 4.5MB 한도, 계정 권한)을 맨 끝에야 알게 된다. 사용자가 실제로 써 볼 수 있는 기능도 끝까지 없다.
- **TASK 하나 = dev-cycle F 라운드 하나.** 라운드는 한 번에 하나만 열리므로(`pnpm dev-cycle status`) 순서가 도구로도 지켜진다.

## 2. 로그인 전 운영: 로컬 관리자 모드

T1~T13은 로그인 없이 로컬 관리자 한 명으로 동작한다. 로그인은 T14에서 붙인다. 그동안의 보호는 아래와 같다.

| 항목 | 방식 |
|---|---|
| 소유자 | 서버가 정한 로컬 관리자 id 하나. 보호 프로시저(`protectedProcedure`)는 context의 `ownerId`만 쓰고, 클라이언트 입력으로 소유자를 받지 않는다 |
| 배포 차단 | `NODE_ENV=production`이면 `ownerId`가 없어 보호 프로시저가 모두 `UNAUTHORIZED`다. T14 전에는 배포하지 않고, 배포 환경에 공급자 키를 넣지 않는다 |
| 네트워크 | 개발 서버는 `127.0.0.1`에만 연다. 같은 네트워크의 다른 기기가 공급자 키를 쓰지 못하게 한다 |
| 다른 사이트 | oRPC CSRF 방어(`SimpleCsrfProtection` 플러그인)로 브라우저에 열린 다른 사이트가 로컬 API를 부르지 못하게 한다. 다른 도메인 이름을 127.0.0.1로 풀리게 하는 DNS 리바인딩은 Host 검사로 막는다(루프백 Host에만 소유자를 준다) |
| 로그인 도입(T14) | 바꿀 곳은 `apps/web/src/context.ts`의 소유자 결정과 로그인 화면이다. 데이터 테이블은 처음(T4 목록 캐시, [ADR 0003](../adr/0003-postgres-cache.md))부터 소유자 컬럼을 두고, 2계정 격리 테스트도 T4부터 한다 |

- 앞 TASK가 7단계까지 끝나기 전에는 다음 TASK의 스펙·계획·코드를 만들지 않는다. 앞 TASK를 하다 다음 TASK에 필요한 사실을 알게 되면 이 문서 5절의 "설계 때 정할 것"에만 적는다.
- 사용자가 순서나 범위를 바꾸자고 하면 이 문서를 먼저 고치고 진행한다.
- TASK가 너무 커서 한 라운드로 끝내기 어려우면 설계 단계에서 Tnn-a, Tnn-b로 나누고, 나눈 TASK마다 같은 게이트를 거친다.

**TASK 완료 정의:** 스펙의 수용 기준마다 증거가 있다. 자동 테스트·타입·린트·빌드가 통과한다. 공급자 기능은 실제 공급자로 확인했다(유료 호출은 사용자 승인 뒤). 계정 제한으로 확인하지 못했으면 그렇게 적고, 그 공급자 기능은 미완료로 둔다. `docs/domain/project.md`와 `GLOSSARY.md`가 현재 모습과 맞다. 사용자 테스트와 피드백 반영이 끝났다.

- Typecast를 성우 조회의 첫 공급자로 한 이유: 목록에 페이지 나눔이 없어서 성우 공통 계약과 화면을 가장 단순하게 세울 수 있다. ElevenLabs·Fish Audio는 그 틀에 페이지 나눔을 더한다.
- 첫 DB 표는 T4의 목록 캐시다([ADR 0003](../adr/0003-postgres-cache.md) Postgres 3단 캐시). DB·격리 테스트의 틀을 여기서 세운다.
- 내 문장 듣기(T5)는 첫 사용자 문장 합성 흐름이다. 생성 기록(요청 id 선점, 동시 1건)과 오디오 전달, 같은 조합의 결과 재사용을 여기서 만들고, 작업실 생성(T9)이 그대로 쓴다. Typecast·ElevenLabs는 유료이며 Fish Audio 무료 모델은 확인 없이 쓸 수 있다.
- T5 코드 지침 후속(T9): 캐스팅의 긴 목록·URL 상태 공유는 생성 기능과 분리해 실제 지연과 필요를 먼저 확인한다(T5-04). 기존 tap-highlight 정리는 VC-12다.
- T5 실제 과금 관측 후속(T9, T5-05): ElevenLabs v4/13CP1회 예상13과 구독잔액감소1 차이는 표본으로 일반화하지 않고 할인·반영시점·계산기준을 확인한다.
- 채널·분류(T6)를 보관함(T7)보다 먼저 한다. CRUD와 삭제 확인의 틀을 작은 범위에서 세운다. 보관함은 그 틀과 T3·T4의 성우 식별(공급자 + 성우 id)을 함께 쓴다. 프리셋(T8)은 T5의 듣기 설정과 T6의 채널을 쓴다.
- 클론(T13)은 가장 크고 공급자마다 계정 조건이 달라서 기능 쪽 마지막에 둔다.

**TASK마다 만드는 공통 부분**

앞 TASK가 만든 것을 다음 TASK가 그대로 쓴다. 공통 부분은 그 TASK에서 실제로 쓰는 만큼만 만들고, 뒤 TASK가 쓸 때 넓힌다. 쓰지 않는 확장점은 미리 만들지 않는다(ponytail).

| TASK | 공통 부분 |
|---|---|
| T1 | 앱 틀(내비게이션, 테마, 디자인 토큰), 페이지 머리와 빈 상태, 없는 주소 화면, 보호 프로시저와 소유자 결정 한 곳, CSRF 방어, 테스트 러너(vitest), 전체 Biome 기준선 |

T2에는 렌더 중에 던지는 코드가 없어 확인할 수 없었다(2026-09-30 T2 재검토). 목록 조회 오류를 오류 경계로 받게 하고, 흉내 낸 응답으로 확인한다. Next 16.3에서 prop은 `retry`다.

T2 QA에서 Typecast 구독 조회가 한 번 약 9초 걸렸다(확인 제한 10초, 다른 회차는 1초대). 성우 목록 조회의 시간 제한을 정할 때 참고한다. ElevenLabs 카드가 공급자가 준 지난 초기화 날짜를 그대로 보여 준다(CS-08). 지난 시각을 어떻게 보일지 정한다.

- **사용자 테스트 피드백(2026-10-04):** 테마 버튼이 사이드바 아래의 이름 없는 아이콘 메뉴라 찾기 어려웠다. 세 칸 버튼을 거쳐 사용자 선택대로 아이콘 하나를 누를 때마다 시스템 설정 → 라이트 → 다크로 바뀌게 하고, 바닥 줄 오른쪽 끝에 두었다(툴팁에 지금 값과 다음 값). 세 공급자 통합, 공급자별 필터 전부, 채널·분류·보관함·프리셋 정리, 내 문장 듣기 요청은 로드맵 재편(T4·T5·T8)으로 옮겼다. 그 설계를 위해 세 공급자 공식 문서를 다시 확인한 결과는 `tasks/evidence/T03/research/`에 있다(T4·T5 설계에서 `docs/research/*-api-options.md`에 합친다).

### T4 성우 캐스팅 세 공급자 통합
- **설계 단계에서 먼저(2026-10-04 사용자 요청):** 성우 캐스팅·내 문장 듣기·채널·분류·성우 보관함·프리셋 전체의 화면 구조를 기획하고 시안으로 정한다. 정보 구조, 공급자 탭, 공급자별 필터 줄, 성우 패널, 그리고 듣기·담기·분류·프리셋이 들어갈 자리를 정한다. T5~T8은 이 구조에 기능을 붙인다. 출발점은 이전 HTML 시안 브리프 `docs/briefs/tts-voice-casting.md`·`tts-voice-provider-filters.md`와 T3 화면이다.
- **포함:** ElevenLabs 계정 성우와 공개 Voice Library, Fish Audio 공개 성우와 내 성우를 성우 캐스팅에 더한다. 공급자 탭(전체·Typecast·ElevenLabs·Fish Audio). 공급자를 고르면 필터 줄이 그 공급자 것으로 바뀌고, 공급자가 목록 API로 주는 조건·정렬·응답 필드를 모두 쓴다. 서버 쪽 검색·필터와 페이지 나눔(라이브러리는 1만 명 이상). 기본 샘플 듣기(한 번에 하나). 공급자별 이용 제한 표시(예: ElevenLabs 무료 플랜은 라이브러리 성우를 API로 쓸 수 없다). 공개 성우를 판정할 필드를 research 문서에 적는다(T5·T10 권한 판정에 쓴다).
- **공급자가 주는 필터(2026-10-04 공식 문서 재확인):**
  - Typecast `GET /v3/voices`: 모델·성별·연령·콘텐츠. 검색·언어·정렬·페이지 나눔은 없어 브라우저에서 처리한다(T3).
  - ElevenLabs 라이브러리 `GET /v1/shared-voices`: 검색·카테고리·성별·연령·억양·언어·지역·콘텐츠·설명어·추천·정렬(최신·사용량·인기 급상승·클론 수), 100명씩. 계정 성우 `GET /v2/voices`: 검색·유형·카테고리·성별·연령·언어·억양·콘텐츠·정렬(이름·만든 날)과 방향.
  - Fish Audio `GET /model`: 제목 검색·태그·언어·보증 성우·작성자·정렬(점수·사용량·최신)·내 성우, 100명씩.
- **제외:** 내 문장 듣기(T5), 담기(T7). ElevenLabs 라이브러리 성우를 계정에 추가하는 호출(공급자 상태 변경, 필요 여부는 T5에서 정한다).
- **사용자 테스트:** 공급자 탭 전환, 공급자마다 필터 전부, 라이브러리 3페이지 이상 탐색, 샘플 청취.
- **설계 때 정할 것:** T4-a(ElevenLabs)·T4-b(Fish Audio)로 나눌지. '전체' 탭에서 페이지 나눔이 다른 공급자를 어떻게 보일지(공급자별 묶음 등). 값 목록을 문서가 주지 않는 필터(ElevenLabs 성별·연령·언어, Fish Audio 태그)의 선택지를 어디서 얻을지. 한국어 거르기 값(`language=ko`는 추정, 첫 무료 조회로 확인). ElevenLabs 기본 성우는 영어뿐이고 2026-03 이후 계정에는 없으며 2026-12-31에 끝난다(0명을 정상으로 다룬다). Fish Audio 목록은 유형·상태 필터가 없어 `svc`·미학습·삭제 성우를 응답에서 거른다. 계정 성우·내 성우 목록을 로컬 관리자 모드에서 그대로 보일지(tts-provider: 공용 서버 키에서는 남의 클론이 섞인다).
- **목록 서버 캐시(2026-10-04 사용자 결정 "Postgres 3단 캐시", [ADR 0003](../adr/0003-postgres-cache.md)):**
  - Postgres 표 하나에 둔다. 키는 공급자·목록 종류·정렬한 필터·페이지·계약 판이고, 값은 zod로 검사한 응답 JSON과 받은 시각·만료 시각이다.
  - 기본 유지 24시간과 '목록 새로 고침' 버튼을 둔다. 같은 키의 동시 요청은 공급자 호출 하나로 합친다(개발 모드 StrictMode의 2회도 1회가 된다).
  - 공급자가 실패하면 지난 목록을 받은 시각과 함께 보인다. 429 `Retry-After`까지는 부르지 않는다. 오류는 저장하지 않는다. 만료 행은 쓰기 때 지운다.
  - Typecast 목록도 같은 방식으로 바꾼다. 공개 목록은 공용 키, 계정·내 성우 목록은 소유자를 키에 넣는다.
  - 설계 때 정할 것: 공급자별 유지 시간을 달리할지, 새로 고침 버튼의 범위(지금 보는 목록인지 그 공급자 전체인지). 공급자 문서는 목록 조회의 과금을 명시하지 않는다(2026-10-04 재확인).
- **첫 DB 표이므로:** 소유자 컬럼에 `user` 외래 키를 걸지와 로컬 관리자 `user` 행을 만드는 방법을 정한다(옛 T6 메모).

### T5 내 문장으로 샘플 듣기
- **스펙·계획:** [T5 스펙](tasks/T05-my-sentence-listening.md), [T5 계획](tasks/T05-my-sentence-listening-plan.md).
- **포함:** `/casting`의 문장 바·행 버튼·패널 설정과 결과 목록. 문장은 코드포인트 기준 200자까지 입력하고 IME 조합 중에는 자르지 않는다. 예상 사용량은 Typecast·ElevenLabs 글자 수, Fish Audio UTF-8 바이트 기준이다.
- **무료·유료:** Typecast와 ElevenLabs는 사용자 문장 무료 API 미리듣기가 없어 확인 후 생성한다. Fish Audio `s2.1-pro-free`는 무료 배지와 확인 없는 정상 생성을 제공하고, 2026-11-30 무료 기간이 끝났으면 서버가 공급자를 부르지 않는다. Fish Audio `model` 헤더는 항상 명시한다.
- **기록과 재생:** 생성 전에 소유자별 요청 ID와 동시 생성 한 건을 선점한다. 같은 요청 ID는 기존 상태·결과를 돌려주며 다시 부르지 않는다. 같은 조합은 저장 결과를 찾아 공급자 호출 없이 재생한다. 완료 결과는 Postgres에 마지막 재생 후 30일 보관하고 사용자가 지울 수 있다. 목록은 최신 20개이며 재생 때 서버 조회로 보관을 연장한다.
- **실패:** 공급자 응답 상태를 받지 못한 실패는 처리 여부 미확인으로 남기고 자동 재시도하지 않는다. 일반 재시도는 먼저 저장 결과를 찾고, 없으면 확인 절차를 거친다. 명시적 새로 만들기는 저장본 찾기를 건너뛴다. DB 또는 429 대기 조회가 실패하면 생성하지 않는다. ElevenLabs 모델 요금 조회의 일반 오류는 배율 1로 계산하지만 429·새 대기 시각은 생성을 멈춘다.
- **부분 확인(CS-09, 2026-10-06):** Fish 무료1회성공/양쪽차감0,유료요청1회는API0·웹free10000에서잔액거절됐다. 유료성공차감대상은API충전뒤추가승인실측이필요하고,그결과로크레딧안내대상을정한다(`tasks/todo.md` CS-09).
- **미확정 사용자 테스트(VC-18):** ElevenLabs '무료 플랜 불가' 배지와 공통 안내를 사용자 플랜에 따라 보일지 크레딧 확인과 함께 정한다(`tasks/todo.md` VC-18).
- **권한:** Better Auth 가입은 열려 있어도 세션은 공급자 권한에 쓰지 않는다. development·test의 루프백 Host에서 서버가 `context.ownerId` 한 명을 정한다. 이 현재 단일 소유 예외에서만 성우 조회 없이 공급자 거절에 맡긴다. 허용 소유자가 둘 이상이 되거나 T14 세션 권한을 도입하면 클론 성우 소유권 조회를 적용한다.
- **구현 상태:** 완료(2026-10-06, 사용자 확인). 승인 실측 5회(성공 4, Fish 유료 잔액 거절 1). Fish 유료 성공 때 차감 잔액은 CS-09로 남긴다.

### T14 로그인(소유자 전용)
- **포함:** 로컬 관리자 모드를 로그인으로 바꾼다. context의 소유자 결정을 세션 + 허용 목록으로 교체하고, 로컬 관리자 데이터를 본인 계정으로 옮기는 방법을 정한다. 아래는 사용자가 2026-09-29에 이미 정한 결정이다.
  - 본인 판정은 서버 환경변수 `OWNER_EMAILS`의 이메일 허용 목록이다. 목록이 비면 모두 거부하고, 앞뒤 공백과 대소문자는 무시한다.
  - 공개 가입은 서버에서 막고(`disableSignUp`), 가입 화면을 두지 않는다. 로그인하지 않으면 `/login`으로 보내고, 소유자가 아니면 "접근 권한 없음"과 로그아웃을 보인다.
  - 계정은 로컬 DB에서만 동작하는 스크립트로 만든다. 원격 DB 주소와 production을 거부한다. 비밀번호를 명령 인자, 환경변수, 출력, 로그에 남기지 않는다. 같은 이메일이 있으면 바꾸지 않는다.
- **사용자 테스트:** 본인 로그인, 가입 거부, 허용 목록 밖 계정 거부, 로그아웃 뒤 보호 화면 차단.
- **T4에서 넘어온 것(2026-10-04 계획 리뷰):** 성우 캐스팅의 '내 계정'은 소유자가 한 명이라는 근거로 서버 키 계정의 계정 성우(클론 포함)를 그대로 보인다(`tts-provider` 예외). 허용 목록(`OWNER_EMAILS`)에 두 명 이상이 들어가면 이 근거가 사라진다. 그때는 '내 계정' 출처를 숨기거나 소유 매핑(T13)으로 거른다. 목록 캐시의 계정 행은 이미 소유자별로 나뉘어 있다.
- **T4에서 넘어온 것(T4 보안 리뷰):** 목록 캐시는 검색어·커서마다 행이 생기고 상한이 없다(만료 뒤 7일 보관). 소유자가 둘 이상이 되면 소유자별 호출 빈도 제한이나 공급자·종류별 행 수 상한을 둔다.
