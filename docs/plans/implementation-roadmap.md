## 1. 진행 방식

기능 하나를 화면·API·DB·공급자 연결까지 한 번에 완성한다. 기능이 앱에서 실제로 동작하고, 검증과 사용자 테스트를 통과해야 다음 기능으로 간다.

- **기존 계획과 다른 점:** [요구사항 6절](tts-service-requirements.md)과 [UI 우선 구현 계획](tts-ui-first-implementation.md)은 "화면 7개를 가상 데이터로 먼저 옮기고, 그 뒤에 데이터와 공급자를 붙인다"는 층별 순서였다. 이 로드맵이 그 순서를 대신한다. "UI/UX 먼저"라는 확정 사항은 HTML 시안(UI-01~10)으로 이미 채웠다. HTML은 앞으로도 각 기능의 화면 명세로 쓴다.
- **이유:** 층별 순서로 하면 공급자 연결 위험(유료 호출 중복, 오디오 4.5MB 한도, 계정 권한)을 맨 끝에야 알게 된다. 사용자가 실제로 써 볼 수 있는 기능도 끝까지 없다.
- **TASK 하나 = dev-cycle F 라운드 하나.** 라운드는 한 번에 하나만 열리므로(`pnpm dev-cycle status`) 순서가 도구로도 지켜진다.

## 2. 소유자와 로그인

T1~T13은 로그인 없이 로컬 관리자 한 명(development·test의 루프백 Host 요청에 `local-admin`)으로 동작했다. T14부터는 로그인으로 바뀌었다([T14 스펙](tasks/T14-owner-login.md), [ADR 0012](../adr/0012-session-owner-single-allowlist.md)).

| 항목 | 방식 |
|---|---|
| 소유자 | 세션 이메일이 서버 환경 변수 `OWNER_EMAILS`의 이메일 정확히 하나와 같을 때만 `context.ownerId = user.id`. 보호 프로시저(`protectedProcedure`)는 `ownerId`만 쓰고 클라이언트 입력으로 소유자를 받지 않는다 |
| 가입·계정 | 공개 가입은 서버에서 막는다. 계정은 로컬 DB에서만 `pnpm owner:create`로 만들고, 그때 `local-admin` 데이터를 옮긴다 |
| 페이지 | proxy가 세션 쿠키 없는 요청을 `/login?next=…`로 보내고, `(app)/layout`이 서버에서 소유자를 다시 판정한다 |
| 네트워크 | 개발 서버는 `127.0.0.1`에만 연다. 개발 주소는 `BETTER_AUTH_URL`과 같은 출처 하나다(로그인 출처 검사) |
| 다른 사이트 | oRPC CSRF 방어(`SimpleCsrfProtection`)와 Better Auth 출처 검사 |
| 단일 소유 예외 | 소유자가 한 명이라 공급자 voice id 소유권·'내 계정' 출처·자동 태그 횟수 같은 다중 소유 검사는 미룬 채 유지한다. 두 번째 소유자가 필요해지면 별도 TASK로 연다 |

### T5 내 문장으로 샘플 듣기
- **스펙·계획:** [T5 스펙](tasks/T05-my-sentence-listening.md), [T5 계획](tasks/T05-my-sentence-listening-plan.md).

- **무료·유료:** Typecast와 ElevenLabs는 사용자 문장 무료 API 미리듣기가 없어 확인 후 생성한다. Fish Audio `s2.1-pro-free`는 무료 배지와 확인 없는 정상 생성을 제공하고, 2026-11-30 무료 기간이 끝났으면 서버가 공급자를 부르지 않는다. Fish Audio `model` 헤더는 항상 명시한다.
- **기록과 재생:** 생성 전에 소유자별 요청 ID와 동시 생성 한 건을 선점한다. 같은 요청 ID는 기존 상태·결과를 돌려주며 다시 부르지 않는다. 같은 조합은 저장 결과를 찾아 공급자 호출 없이 재생한다. 완료 결과는 Postgres에 마지막 재생 후 30일 보관하고 사용자가 지울 수 있다. 목록은 최신 20개이며 재생 때 서버 조회로 보관을 연장한다.
- **실패:** 공급자 응답 상태를 받지 못한 실패는 처리 여부 미확인으로 남기고 자동 재시도하지 않는다. 일반 재시도는 먼저 저장 결과를 찾고, 없으면 확인 절차를 거친다. 명시적 새로 만들기는 저장본 찾기를 건너뛴다. DB 또는 429 대기 조회가 실패하면 생성하지 않는다. ElevenLabs 모델 요금 조회의 일반 오류는 배율 1로 계산하지만 429·새 대기 시각은 생성을 멈춘다.
- **부분 확인(CS-09, 2026-10-06):** Fish 무료1회성공/양쪽차감0,유료요청1회는API0·웹free10000에서잔액거절됐다. 유료성공차감대상은API충전뒤추가승인실측이필요하고,그결과로크레딧안내대상을정한다(`tasks/todo.md` CS-09).

### T9 Typecast 음성 생성·재생·다운로드

- **T8에서 넘어온 것:** 작업실 '프리셋 불러오기'는 프리셋의 성우(담은 성우)와 설정을 함께 적용한다. 성우가 비었거나 '현재 이용 불가'면 성우를 다시 고르게 한다(자동 대체 없음). 채널을 고르면 그 채널의 기본 프리셋을 적용한다. 생성 기록은 프리셋을 가리키지 않고 설정 스냅샷을 저장한다. `presetList`는 서버가 정렬하지 않으므로 화면이 `byName`으로 정렬한다. Fish Audio 무료 기간(2026-11-30) 뒤 무료 모델 프리셋의 요약·적용 표시를 정한다. `/presets`의 채널별 보기는 이 TASK에서 다시 본다.
- **T7에서 넘어온 것:** 작업실 성우 고르기는 `savedVoiceList`(담은 성우)를 먼저 보이고, 성공한 생성으로 `saved_voice`에 최근 사용·사용 횟수를 더한다. `unavailable`(현재 이용 불가) 성우는 고르지 못하게 하고 다른 성우로 자동 대체하지 않는다. 목록 출력은 `checkedAt`·`savedAt`을 내보내지 않으므로 정렬에 필요하면 그때 더한다.
- **사용자 테스트:** 짧은 대본으로 실제 생성 1회(승인 뒤), 재생·다운로드, 빈 대본·상한 초과 차단, 두 번 눌러도 요청 1회.

- **리디자인 critique에서 넘어온 것(2026-10-03, [리디자인 브리프](../briefs/redesign.md) 4절 7·8·10):** 문단 줄에는 번호·성우·대사·재생만 두고 속도·쉼·감정·지시는 기본값과 다를 때만 표식으로 보인다. 무료 재생(▷)과 유료 생성은 기호부터 다르게 하고 돈이 드는 동작에는 앱 전체에서 같은 표식을 쓴다. 세 단·상단 버튼·하단 막대가 동시에 다투지 않게 초점을 하나로 정한다.

### T9.5 드라마 작업실 (Fish Audio Drama 3)

- **T9에서 넘어온 것:** 저장 대본을 작업실 카드에 넣거나 바꾼다. 임시 작업(`tts-pilot:studio:v1:*`)과 저장 대본을 구분한다.
- **T6에서 넘어온 것:** 저장 대본의 선택 채널은 `channel` 외래 키(하나만), 분류는 연결 표(여러 개)다.
- **T10에서 넘어온 것(스펙 14·17절):** 최근 대본(만들기를 누른 대본 자동 보관, 최근 목록, 열 때 확인, 지우기)은 2026-11-11 사용자 결정으로 T10-b에서 빼고 여기서 대본 보관함과 함께 처음 만든다(이름, 채널, 분류, 검색). 임시 작업과 저장 대본을 구분하고, 문단 제작 계획을 서버에 둘 때는 임시 작업 키(`tts-pilot:studio:v2:work`)와 계약을 재사용한다.
- **T9.5에서 넘어온 것(스펙 13절):** 드라마 대본(화자·줄)도 대본 보관함에 저장할지 그때 정한다. 임시 작업(`tts-pilot:drama:v1`)과 저장 대본을 구분한다.

### T13 내 보이스(클론)
- **포함:** 녹음·파일 입력, 본인 음성 동의 기록, 공급자별 파일 조건 검사, 소유 매핑, 상태(처리 중·검증 필요·사용 가능·실패·미확인), 작업실·분류·프리셋 연결, 삭제 대기와 신규 합성 차단, 원본 임시 정리.
- **설계 때 정할 것:** 공급자별로 T13-a·b·c로 나눌지, 원본 전송 방식(ADR), 공급자별 계정 지원 여부.
- **설계 결정(2026-11-18 사용자, [T13 스펙](tasks/T13-my-voice.md) 2절):** 이번에는 Fish Audio·Gemini만 만든다. Typecast(무료 플랜, 클론 슬롯 0)와 ElevenLabs(지금 키에 즉석 클론 권한 없음)는 T13-b로 나눈다. Airy는 클론 API가 없다(T7.5 메모 해결). 원본은 브라우저에서 24kHz 모노 WAV로 바꿔 서버 메모리로만 보낸다([ADR 0011](../adr/0011-clone-source-in-memory.md)). 만든 클론은 성우 보관함에 자동으로 담고, 지우면 보관함에서도 뺀다. 앱 밖 클론은 가져오지 않는다.
- **T7.5에서 넘어온 것:** Airy 클론 API 유무를 다시 확인한다.
- **T8에서 넘어온 것:** 내 보이스를 지우면 그 보이스를 쓰는 프리셋은 성우가 비고 '성우를 다시 골라 주세요'가 된다(REQ-13 9번, T8의 `on delete set null`과 같다).
- **T9.5에서 넘어온 것(스펙 13절):** 클론 보이스를 드라마 화자 성우로 고를 수 있게 한다. 담은 성우 탭에 나오며, 서버 성우 검사(`usableVoices`)는 담은 Fish Audio 성우만 허용하므로 클론을 담는 규칙(위 T7 항목)을 바꾸면 함께 본다.
- **T7.6에서 넘어올 것:** Gemini 음성 복제(`POST /v1beta/voices`, `type: replicated`)는 참조 녹음 10~30초와 동의 문장 녹음(한국어 있음)을 함께 받는다. 프로젝트당 200명, 마지막 사용 뒤 1년 보관이고, `GET /v1beta/voices`가 프로젝트의 맞춤 성우를 공개 성우보다 먼저 돌려준다(리서치 11절). 프로젝트 맞춤 성우를 목록에 섞을 때는 지금 공용 캐시(`type=prebuilt`만 받는다)와 나눈다. 소유자별 행으로 `type=prompted,replicated`를 따로 받는다.
- **T7에서 넘어온 것:** 내 보이스도 성우와 같은 담기·분류 흐름(REQ-13 "일반 성우와 같은 즐겨찾기·카테고리·타입·채널")을 쓴다. `saved_voice`에 담고 `savedVoiceLinks`로 연결한다. 담기 입력 검사(`savedVoiceInputSchema`)가 Typecast는 출처 `public`만 받으므로 클론(`custom`)을 담으려면 그 규칙과 상세 조회의 `voice_type` 판정을 함께 바꾼다.
- **사용자 테스트:** 공급자별 본인 음성 등록 → 한국어 합성 → 삭제(각각 승인 뒤).

### T14 로그인(소유자 전용)
- **포함:** 로컬 관리자 모드를 로그인으로 바꾼다. context의 소유자 결정을 세션 + 허용 목록으로 교체하고, 로컬 관리자 데이터를 본인 계정으로 옮기는 방법을 정한다. 아래는 사용자가 2026-09-29에 이미 정한 결정이다.
  - 본인 판정은 서버 환경변수 `OWNER_EMAILS`의 이메일 허용 목록이다. 목록이 비면 모두 거부하고, 앞뒤 공백과 대소문자는 무시한다.
  - 공개 가입은 서버에서 막고(`disableSignUp`), 가입 화면을 두지 않는다. 로그인하지 않으면 `/login`으로 보내고, 소유자가 아니면 "접근 권한 없음"과 로그아웃을 보인다.
  - 계정은 로컬 DB에서만 동작하는 스크립트로 만든다. 원격 DB 주소와 production을 거부한다. 비밀번호를 명령 인자, 환경변수, 출력, 로그에 남기지 않는다. 같은 이메일이 있으면 바꾸지 않는다.
- **사용자 테스트:** 본인 로그인, 가입 거부, 허용 목록 밖 계정 거부, 로그아웃 뒤 보호 화면 차단.
- **설계 결정(2026-11-18 사용자, [스펙](tasks/T14-owner-login.md) 2절·[ADR 0012](../adr/0012-session-owner-single-allowlist.md)):** 로컬 관리자 모드를 없애고 개발에서도 로그인한다. 소유자는 한 명만(목록에 이메일이 둘 이상이면 모두 거부). `local-admin` 데이터는 계정 만들기 스크립트가 같은 실행에서 옮긴다. `owner_id` 외래 키는 걸지 않는다. 세션은 기본 7일. 이메일·로그아웃은 메뉴 아래 줄. 비밀번호 바꾸기·되찾기는 넣지 않는다. 로그인 뒤 열려던 화면으로.
- **소유자가 한 명이라 그대로 미루는 것:** 아래 'T4·T7·T7.6·T8·T9·T9.5·T10에서 넘어온 것'의 다중 소유 보강(공급자 voice id 소유권, '내 계정' 출처, 담기 upsert 덮어쓰기, 프리셋 기본값 교착 잠금, 목록 캐시 상한)과 T14 메모의 자동 태그 횟수 제한. 두 번째 소유자가 필요해지면 별도 TASK로 연다(배포 관련 항목은 T15에서 다시 본다).
- **T6에서 넘어온 것:** `channel`·`classification`·`trial_generation`·`saved_voice`(T7)의 `owner_id = 'local-admin'` 행을 실제 사용자 id로 옮기고, 그때 `user` 외래 키를 걸지 정한다([ADR 0004](../adr/0004-channel-classification-storage.md)).
- **T8에서 넘어온 것:** `voice_preset.owner_id`도 실제 사용자 id로 옮긴다(`channel_default_preset`에는 소유자 컬럼이 없다). 같은 채널의 기본 프리셋을 동시에 맞바꾸면 교착(40P01)이 나서 한쪽 요청이 500이 된다(데이터는 그대로). 다중 사용자가 되면 `setDefault`(`routers/preset.ts`의 `shortcut:` 주석) 첫 줄에 `pg_advisory_xact_lock(hashtext(ownerId))`를 둬 소유자별로 줄 세운다. 프리셋의 저장된 성우로 생성할 때(T9)는 저장된 공급자 voice id를 믿지 말고 서버에서 다시 검사한다(보안 리뷰). 방법은 위 T7.6 항목과 같다.
- **T9에서 넘어온 것:** `trial_generation`의 작업실 행(`kind = 'studio'`)도 소유자 이전 대상이다. 작업실의 성우 검사(`usableVoice`)는 '이 소유자가 담은 성우'라는 앱 수준 일관성 검사일 뿐 공급자 소유 검증이 아니다. 담은 성우의 voice id도 원래 클라이언트가 보낸 값(`savedVoiceSave`)이라, Typecast `uc_` 커스텀 성우처럼 공급자가 소유한 보이스인지는 확인하지 않는다. 소유자가 여럿이 되면 저장 때나 합성 전에 Typecast `getVoiceV3`의 `voice_type=original`이거나 앱 클론 매핑에 있는 성우만 허용한다.
- **T9.5에서 넘어온 것(스펙 13절):** `trial_generation`의 드라마 행(`kind = 'drama'`)도 소유자 이전 대상이다. 드라마 화자 성우 검사(`usableVoices`)도 T9와 같은 한계(담은 성우의 voice id는 클라이언트 값)를 가진다. 소유자가 여럿이 되면 위 T9 항목의 방법으로 함께 막는다.
- **T7.5에서 넘어온 것:** Airy `GET /v1/voices`가 계정 커스텀 성우를 섞는지 확인하고, 섞는다면 공용 캐시(ownerId null)와 public 출처 표시를 계정 행으로 나눈다.
- **T10에서 넘어온 것(스펙 14절, 보안 리뷰 한계):** 작업실 행(`kind = 'studio'`)은 다섯 공급자 모두 소유자 이전 대상이다. 작업실 성우 검사는 앱 수준 일관성 검사다(T9 메모와 같다). 단일 소유자 예외가 끝날 때(허용 소유자가 둘 이상이 되거나 세션 권한을 도입할 때) 작업실 다섯 공급자와 드라마의 공급자 voice id 소유권도 함께 검사한다(앱 클론 매핑 또는 공급자 공개 성우 조회).
- **T7.6에서 넘어온 것(보안 리뷰 S1):** Gemini 시험 생성·생성의 `voiceId`는 지금 공급자 거절에 맡긴다(단일 소유 예외). 소유자가 둘 이상이 되면 `getVoice`(prebuilt 목록)나 앱 소유 매핑으로 제한해, 프로젝트가 디자인·복제한 Gemini 성우를 id만 아는 사용자가 쓰지 못하게 한다.
- **T4에서 넘어온 것(2026-10-04 계획 리뷰):** 성우 캐스팅의 '내 계정'은 소유자가 한 명이라는 근거로 서버 키 계정의 계정 성우(클론 포함)를 그대로 보인다(`tts-provider` 예외). 허용 목록(`OWNER_EMAILS`)에 두 명 이상이 들어가면 이 근거가 사라진다. 그때는 '내 계정' 출처를 숨기거나 소유 매핑(T13)으로 거른다. 목록 캐시의 계정 행은 이미 소유자별로 나뉘어 있다.
- **T7에서 넘어온 것(보류한 리뷰 지적, 소유자가 한 명이라 미뤘다. 소유자가 둘 이상이 되면 다시 본다):**
  - 담기 upsert가 이미 담긴 행의 `voice`·`source`를 클라이언트가 보낸 값으로 덮어쓰고 `checked_at`은 유지한다. 서버가 `voiceSchema`·샘플 호스트로 검사하지만 값 자체는 공급자에게서 받은 것이 아니다.
  - 클라이언트가 보낸 Typecast·Fish Audio voiceId로 서버 키 상세 조회를 하므로(`savedVoiceCheck`), 여러 소유자 환경에서는 남의 클론 메타데이터가 저장될 수 있다. `tts-provider`의 '클론 보이스와 공급자 리소스 소유권' 기준(앱 소유 매핑 또는 공개 성우 판정)으로 다시 본다.
  - ElevenLabs 샘플 호스트 `storage.googleapis.com`은 어떤 버킷이든 통과한다(T4부터). 호스트 검사가 버킷까지는 보지 않는다.
- **T4에서 넘어온 것(T4 보안 리뷰):** 목록 캐시는 검색어·커서마다 행이 생기고 상한이 없다(만료 뒤 7일 보관). 소유자가 둘 이상이 되면 소유자별 호출 빈도 제한이나 공급자·종류별 행 수 상한을 둔다.
