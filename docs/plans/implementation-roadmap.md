## 1. 진행 방식

기능 하나를 화면·API·DB·공급자 연결까지 한 번에 완성한다. 기능이 앱에서 실제로 동작하고, 검증과 사용자 테스트를 통과해야 다음 기능으로 간다.

- **기존 계획과 다른 점:** [요구사항 6절](tts-service-requirements.md)과 [UI 우선 구현 계획](tts-ui-first-implementation.md)은 "화면 7개를 가상 데이터로 먼저 옮기고, 그 뒤에 데이터와 공급자를 붙인다"는 층별 순서였다. 이 로드맵이 그 순서를 대신한다. "UI/UX 먼저"라는 확정 사항은 HTML 시안(UI-01~10)으로 이미 채웠다. HTML은 앞으로도 각 기능의 화면 명세로 쓴다.
- **이유:** 층별 순서로 하면 공급자 연결 위험(유료 호출 중복, 오디오 4.5MB 한도, 계정 권한)을 맨 끝에야 알게 된다. 사용자가 실제로 써 볼 수 있는 기능도 끝까지 없다.
- **TASK 하나 = dev-cycle F 라운드 하나.** 라운드는 한 번에 하나만 열리므로(`pnpm dev-cycle status`) 순서가 도구로도 지켜진다.

## 2. 로그인 전 운영: 로컬 관리자 모드

T1~T13은 로그인 없이 로컬 관리자 한 명으로 동작한다. 로그인은 T14에서 붙인다. 그동안의 보호는 아래와 같다.

| 항목 | 방식 |
|---|---|
| 소유자 | 서버가 정한 로컬 관리자 id 하나. 보호 프로시저(`protectedProcedure`)는 context의 `ownerId`만 쓰고, 클라이언트 입력으로 소유자를 받지 않는다 |
| 배포 차단 | `NODE_ENV=production`이면 `ownerId`가 없어 보호 프로시저가 모두 `UNAUTHORIZED`다. T14 전에는 배포하지 않고, 배포 환경에 공급자 키를 넣지 않는다 |
| 네트워크 | 개발 서버는 `127.0.0.1`에만 연다. 같은 네트워크의 다른 기기가 공급자 키를 쓰지 못하게 한다 |
| 다른 사이트 | oRPC CSRF 방어(`SimpleCsrfProtection` 플러그인)로 브라우저에 열린 다른 사이트가 로컬 API를 부르지 못하게 한다. 다른 도메인 이름을 127.0.0.1로 풀리게 하는 DNS 리바인딩은 Host 검사로 막는다(루프백 Host에만 소유자를 준다) |
| 로그인 도입(T14) | 바꿀 곳은 `apps/web/src/context.ts`의 소유자 결정과 로그인 화면이다. 데이터 테이블은 처음(T6)부터 소유자 컬럼을 두고, 2계정 격리 테스트도 T6부터 한다 |

- 앞 TASK가 7단계까지 끝나기 전에는 다음 TASK의 스펙·계획·코드를 만들지 않는다. 앞 TASK를 하다 다음 TASK에 필요한 사실을 알게 되면 이 문서 5절의 "설계 때 정할 것"에만 적는다.
- 사용자가 순서나 범위를 바꾸자고 하면 이 문서를 먼저 고치고 진행한다.
- TASK가 너무 커서 한 라운드로 끝내기 어려우면 설계 단계에서 Tnn-a, Tnn-b로 나누고, 나눈 TASK마다 같은 게이트를 거친다.

**TASK 완료 정의:** 스펙의 수용 기준마다 증거가 있다. 자동 테스트·타입·린트·빌드가 통과한다. 공급자 기능은 실제 공급자로 확인했다(유료 호출은 사용자 승인 뒤). 계정 제한으로 확인하지 못했으면 그렇게 적고, 그 공급자 기능은 미완료로 둔다. `docs/domain/project.md`와 `GLOSSARY.md`가 현재 모습과 맞다. 사용자 테스트와 피드백 반영이 끝났다.

## 5. TASK별 범위

아래는 순서를 정하기 위한 범위다. 상세 설계는 그 TASK 차례가 왔을 때 게이트 1단계에서 한다.

### T1 앱 기반과 공통 틀 (로컬 관리자 모드)
- **포함:** 2절 로컬 관리자 모드(소유자 결정, 배포 차단, `127.0.0.1`, CSRF). 템플릿 화면 정리(ASCII 홈, `/dashboard`, 로그인·가입 화면, `privateData`). 앱 틀(메뉴 9개, 아직 없는 화면은 '준비 중')과 빈 작업실. `DESIGN.md` 라이트·다크 토큰, Pretendard, `lang="ko"`. vitest. 전체 Biome 정리(Q-01). `AGENTS.md`·`tts-provider` 스킬에 로컬 관리자 모드 규칙 반영.
- **제외:** 로그인(T14), DB 테이블(T6), 공급자(T2).
- **사용자 테스트:** 로그인 없이 작업실 틀 진입, 메뉴와 '준비 중', 테마 유지, 1440·1024·390 화면.
- 상세: [T1 스펙](tasks/T01-app-foundation.md).

### T2 공급자 연결 상태
- **포함:** 세 공급자의 서버 클라이언트(키가 없으면 만들지 않고 "연결 안 됨"). 공급자마다 과금 없는 확인 호출 하나. 공급자 오류 매핑. '연결 상태' 화면: 연결됨, 키 없음, 키 오류, 한도 부족, 요청 제한, 공급자 장애, 확인 실패를 구분해 보이고 다시 확인할 수 있다. 확인 호출이 잔여 사용량을 무료로 주면 함께 보인다.
- **사용자 테스트:** 세 키를 넣고 모두 "연결됨". 키 하나를 지우거나 틀리게 바꿔 표시가 달라지는지 본다.
- **설계 때 정할 것:** 공급자별 확인 호출(과금 없는 것을 공식 문서로 확인), 확인 결과를 얼마나 캐시할지, 키를 바꾼 뒤 서버를 다시 켜야 하는지.
- **T1 리뷰에서 넘어온 것:** '연결 상태'는 휴대폰 너비의 더보기 안에 있으므로, 링크로 열 때 경로가 바뀌면 더보기를 닫는다(`app-nav.tsx`의 `moreOpen`). 첫 보호 프로시저가 생기면 루프백이 아닌 Host로 부를 때(브라우저 호출과 SSR 경로 모두) `UNAUTHORIZED`인지 런타임에서 확인한다.

### T3 Typecast 성우 찾기와 샘플 듣기
- **포함:** 성우 공통 계약과 Typecast 목록·단건 조회. '성우 캐스팅' 화면(검색, 모델·성별·연령·용도 필터, 샘플 없음 표시). 한 번에 하나만 재생한다. 무료 호출만 쓴다.
- **제외:** 시험 생성(유료, T8), 보관함 담기(T7).
- **사용자 테스트:** 검색·필터, 샘플 청취, 다른 샘플을 누르면 앞 재생이 멈추는지.
- **설계 때 정할 것:** 목록을 서버에서 얼마나 캐시할지, HTML 성우 캐스팅 화면에서 이번에 옮길 영역. 검색 입력이 첫 입력 칸이므로 `--input`(border-strong) 경계 대비를 3:1 이상으로 맞춘다(T1 계획 디자인 리뷰: 흰 바탕 위 1.6:1).

### T4 ElevenLabs 성우 찾기와 샘플 듣기
- **포함:** 계정 성우와 공개 Voice Library(페이지 탐색), 검색·필터, 샘플. 공개 성우를 판정할 필드를 공식 문서로 확인해 research 문서에 적는다(T9 생성 권한 판정에 쓴다).
- **사용자 테스트:** 공개 라이브러리 3페이지 이상 탐색, 샘플 청취.

### T5 Fish Audio 성우 찾기와 샘플 듣기
- **포함:** 공개 성우와 내 성우 목록(페이지 탐색), 검색·필터, 샘플.
- **사용자 테스트:** 두 목록 탐색과 샘플 청취.

### T6 채널·분류 관리
- **포함:** 채널·카테고리·타입 테이블(소유자 컬럼), CRUD 프로시저, '채널·분류' 화면(만들기, 이름 바꾸기, 지우기), 테스트 DB와 2계정 격리 테스트.
- **사용자 테스트:** 채널 2개와 카테고리·타입을 만들고 이름을 바꾸고 지운다. 새로 고침 뒤에도 남는다.
- **설계 때 정할 것:** 소유자 컬럼에 `user` 외래 키를 걸지와 로컬 관리자 `user` 행을 만드는 방법, 기본 제공 항목이 필요한지, 순서 바꾸기가 필요한지. 템플릿 스킬(`bts-api`의 `context.session.user.id`, `references/ownership-test.md`의 `session` context)은 세션 기준이다. 이 프로젝트는 `context.ownerId`로 바꿔 읽는다(`AGENTS.md` TTS 규칙). 템플릿 파일은 고치지 않는다(템플릿 갱신 때 덮인다).

### T7 성우 보관함
- **포함:** 성우 담기(즐겨찾기와 자주 사용은 따로), 채널·카테고리·타입 여러 개 연결, 성우 캐스팅 화면에서 담기, '성우 보관함' 화면의 검색·필터, 분류를 지우면 연결만 풀림, 공급자 목록에서 사라진 성우는 "현재 이용 불가".
- **제외:** 최근 사용과 사용 횟수(생성 기록이 생기는 T8).
- **사용자 테스트:** 세 공급자 성우를 담고 분류를 붙여 필터로 다시 찾는다. 분류를 지워도 성우는 남는다.

### T8 Typecast 음성 생성·재생·다운로드
- **포함:** 작업실 대본 입력(초안 유지), 빈 값·2,000자 상한 검사. Typecast 모델별 설정(옵션 매핑표 기준). 생성 기록 테이블(요청 id 선점, 사용자별 동시 1건). 공급자 오류 매핑과 "처리 여부 미확인". 예상 사용량(글자 수). 결과 재생·다운로드(다운로드가 생성을 다시 부르지 않음), 이전 결과 표시, 파일 이름. 성공한 생성으로 보관함의 최근 사용·사용 횟수를 채운다.
- **사용자 테스트:** 짧은 대본으로 실제 생성 1회(승인 뒤), 재생·다운로드, 빈 대본·상한 초과 차단, 두 번 눌러도 요청 1회.
- **설계 때 정할 것:** 대본 입력을 HTML 작업실처럼 문단 카드 1장으로 시작할지 단일 편집기로 할지, 오디오 전달 방식(4.5MB 한도), 성우 캐스팅의 시험 생성을 여기서 함께 열지, 브라우저 QA에 쓸 모의 모드가 필요한지, 일일 사용 한도.

### T9 ElevenLabs·Fish Audio 음성 생성
- **포함:** 두 공급자의 모델별 설정과 생성을 T8의 생성 틀에 붙인다. ElevenLabs는 SDK 자동 재시도를 끈다. Fish Audio는 `model` 헤더로 합성 모델을 고르고, prosody·temperature·형식·인라인 감정 태그를 쓰며, 사용량은 UTF-8 바이트다. 공급자를 바꾸면 맞지 않는 옵션을 초기화한다.
- **사용자 테스트:** 공급자마다 실제 생성 1회(승인 뒤).
- **설계 때 정할 것:** T9-a(ElevenLabs), T9-b(Fish Audio)로 나눌지.

### T10 한국어 숫자 발음 교정
- **포함:** 규칙 기반 교정 엔진과 [요구사항 5절](tts-service-requirements.md) 수용표 전체의 자동 테스트. 원문과 발음용 대본 분리, 항목별 적용·유지·직접 수정·되돌리기, 원문을 고치면 재검수, 미검수 경고, 교정 후 길이 재계산, 발음용 대본 복사.
- **사용자 테스트:** 수용표 예시가 든 대본을 검수하고, 원하면 생성해 듣는다.
- **설계 때 정할 것:** Typecast AutoTag 채택 여부(P0-12 평가).

### T11 대본 보관함
- **포함:** 저장·수정·복제·삭제·검색, 작업실 삽입·교체, 저장 안 된 편집 경고, 동시 편집 충돌(버전 조건 갱신). 저장 상한(Q-02)은 설계 때 정한다.
- **사용자 테스트:** 대본을 저장하고 불러와 편집해도 원본이 바뀌지 않는지, 미저장 경고.

### T12 프리셋과 채널 기본값
- **포함:** 공급자별 유효 설정 저장·수정·복제·삭제, 채널 기본 프리셋, 적용 전 바뀌는 값 비교, 성우·모델을 쓸 수 없게 되면 다시 고르게 함.
- **사용자 테스트:** 프리셋 저장 → 새 작업에 적용 → 같은 설정으로 생성.

### T13 내 보이스(클론)
- **포함:** 녹음·파일 입력, 본인 음성 동의 기록, 공급자별 파일 조건 검사, 소유 매핑, 상태(처리 중·검증 필요·사용 가능·실패·미확인), 작업실·분류·프리셋 연결, 삭제 대기와 신규 합성 차단, 원본 임시 정리.
- **설계 때 정할 것:** 공급자별로 T13-a·b·c로 나눌지, 원본 전송 방식(ADR), 공급자별 계정 지원 여부.
- **사용자 테스트:** 공급자별 본인 음성 등록 → 한국어 합성 → 삭제(각각 승인 뒤).

### T14 로그인(소유자 전용)
- **포함:** 로컬 관리자 모드를 로그인으로 바꾼다. context의 소유자 결정을 세션 + 허용 목록으로 교체하고, 로컬 관리자 데이터를 본인 계정으로 옮기는 방법을 정한다. 아래는 사용자가 2026-09-29에 이미 정한 결정이다.
  - 본인 판정은 서버 환경변수 `OWNER_EMAILS`의 이메일 허용 목록이다. 목록이 비면 모두 거부하고, 앞뒤 공백과 대소문자는 무시한다.
  - 공개 가입은 서버에서 막고(`disableSignUp`), 가입 화면을 두지 않는다. 로그인하지 않으면 `/login`으로 보내고, 소유자가 아니면 "접근 권한 없음"과 로그아웃을 보인다.
  - 계정은 로컬 DB에서만 동작하는 스크립트로 만든다. 원격 DB 주소와 production을 거부한다. 비밀번호를 명령 인자, 환경변수, 출력, 로그에 남기지 않는다. 같은 이메일이 있으면 바꾸지 않는다.
- **사용자 테스트:** 본인 로그인, 가입 거부, 허용 목록 밖 계정 거부, 로그아웃 뒤 보호 화면 차단.

### T15 P0 통합 검수와 첫 배포
- **포함:** REQ-01~13 전체 시나리오, 접근성 전체 점검(P0-07), 독립 리뷰. GitHub origin과 Vercel 연결, 운영 소유자 계정과 환경변수, 릴리스와 production 배포(`bts-deploy`).
- **사용자 테스트:** 배포 주소에서 P0 전체 흐름.
