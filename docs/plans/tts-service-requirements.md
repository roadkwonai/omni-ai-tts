# TTS Pilot 요구사항 정의 및 개발 요청 계획

- 작성일: 2026-09-26 (Asia/Seoul)
- 상태: **개인용 범위 확정 · HTML 설계 단계 — 실제 서비스 기능 구현 전**. 사용자 확정 사항과 제안·가정을 구분한다.
- 목적: 한국어 콘텐츠 제작자가 Typecast·ElevenLabs·Fish Audio 성우를 비교하고, 용도별로 저장해 대본 교정부터 음성 다운로드까지 반복 작업을 줄인다.
- 이번 산출물: 요구사항, UI/UX 브리프, 개발 순서, 수용 기준, 후속 TODO. HTML UI 프로토타입과 앱 구현 계획을 포함한다. 실제 API·DB·배포 변경은 포함하지 않는다.
- 연결 문서: [UI/UX 브리프](../briefs/tts-studio.md), [참고 조사](../research/tts-references.md), [실행 및 후속 TODO](../../tasks/todo.md).

## 1. 확정 사항과 계획 가정

### 사용자 요청으로 확정된 사항

1. UI/UX 기획과 화면 개발을 먼저 진행한다. 기존 `DESIGN.md`를 참고하고 Pretendard를 사용한다.
2. Typecast **공식 API**, ElevenLabs **공식 API**, Fish Audio **공식 API**를 모두 지원한다. Fish Audio는 2026-09-28 요청으로 P0 세 번째 공급자가 되었다([API 조사](../research/fish-audio-api-options.md)).
3. 성우 목소리를 먼저 듣고, 개인 즐겨찾기를 카테고리·타입·채널·프리셋 기준으로 관리한다.
4. 자주 쓰는 대본을 등록하고 재사용한다.
5. 숫자를 한글로 변환해 대본 발음을 교정한다.
6. 위 기능이 모두 작동하는 간단한 TTS 서비스를 먼저 완성한다. 고도화 기능은 TODO에 등록하고 이후 별도로 상세 기획한다.
7. gowith153, Typecast, Vrew 및 지정 영상의 1:56:02~1:59:45 구간을 참고한다.
8. **내 목소리로 클론 보이스를 만드는 기능을 초기 필수 범위(P0)에 포함한다.** 2026-09-26 후속 요청으로 기존 P3-04에서 승격했다. 녹음/파일 등록부터 개인 성우로 대본을 읽는 흐름까지 다룬다.

| 제품명 | TTS Pilot은 저장소 기준 작업명 | 최종 서비스명은 별도 결정 |

개인용·HTML 우선 설계는 사용자 확인을 받았고 `PRODUCT.md`에 기록했다. 오디오 보관 등 남은 결정은 관련 구현 단계에서 확정한다. 현재 구현을 설명하는 `docs/domain/project.md`에 미래 기능을 구현된 것처럼 기록하지 않는다. 공개 가입·초대·결제 UI를 초기 구현에 추가하지 않는다. 소유권 검증에 쓰는 두 계정은 격리 테스트 fixture이며 다중 사용자 제품 구축을 뜻하지 않는다.

## 2. 접근 방식 비교와 권고

| 방식 | 장점 | 제약 | 선택 |
|---|---|---|---|
| 단일 입력 폼 중심 | 가장 빠른 단순 생성 | 성우 탐색·분류·재사용 작업이 분산 | 시제품에는 가능하나 핵심 요구 충족이 약함 |
| 개인 음성 작업실 중심 | 성우·대본·프리셋을 같은 작업에 연결. 필요한 기능부터 확장 가능 | 저장 모델과 선택 상태를 먼저 정의해야 함 | **권고: 이 문서의 기본안** |
| 전체 영상·음성 스튜디오 동시 개발 | 장기 비전을 한 번에 표현 | 자막·타임라인·전문 클론 학습·과금까지 초기 범위가 커짐 | 간편 내 목소리 클론은 P0, 나머지는 후속 단계로 분리 |

## 3. 핵심 이용 흐름

1. 로그인 → 음성 작업실 진입 → 공급자 연결 상태 확인.
2. 채널 또는 프리셋 선택 → 성우 검색·필터 → 기본 샘플 청취 → 즐겨찾기/분류 저장.
3. 대본 입력 또는 저장 대본 불러오기 → 원문 저장.
4. 숫자 교정 제안 확인 → 항목별 적용·유지·직접 수정 → 최종 발음용 대본 확정.
5. 공급자별 설정 확인 → 전달 글자 수·예상 사용량 확인 → 음성 생성.
6. 생성 결과 재생·탐색 → 다운로드 → 성우·설정을 프리셋으로 저장해 다음 작업에 재사용.

내 목소리를 사용할 때: 성우 보관함의 **내 보이스 → 클론 보이스 만들기 → 공급자 선택 → 직접 녹음/파일 업로드 → 원본 청취·본인 음성 확인 → 생성 → 필요 시 공급자 검증 → 사용 가능 확인 → 시험 대본 청취 → 작업실에서 사용**으로 이어진다. 등록한 보이스는 일반 성우와 같은 즐겨찾기·카테고리·타입·채널·프리셋 흐름을 사용한다.

```mermaid
flowchart LR
  A[성우 탐색·샘플 듣기] --> B[즐겨찾기·채널·프리셋 선택]
  B --> C[대본 작성·불러오기]
  C --> D[숫자 교정 검수]
  D --> E[최종 대본·설정 확인]
  E --> F[Typecast·ElevenLabs·Fish Audio 중 하나로 생성]
  F --> G[재생·다운로드]
  G --> H[대본·프리셋 재사용]
  H --> B
```

## 4. 초기 필수 기능과 수용 기준 (P0)

P0는 UI 시연뿐 아니라 세 공급자 API의 실제 생성까지 끝나야 기능 완료다. UI 개발 단계의 가상 데이터 통과를 서비스 완료로 간주하지 않는다.

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| REQ-01 | 소유자 인증·개인 공간 | 기존 인증으로 소유자 한 명만 접근하며 공개 가입을 닫는다. 로그인 전 개인 데이터 접근 불가. 즐겨찾기·분류·채널·대본·프리셋·생성 기록·클론 보이스·원본 녹음 모두 세션 소유자 기준. 다른 사용자 ID나 리소스 ID로 조회·변경·삭제·합성 불가 |
| REQ-02 | 세 공급자 성우 탐색 | Typecast API 제공 목록, ElevenLabs 계정 목록·공개 라이브러리, Fish Audio 공개 성우 목록·내 워크스페이스 성우를 끝까지 탐색. 공급자/목록 범위/공급자 분류/개인 타입 검색·필터 및 페이지 탐색. 목록 노출과 합성 가능 여부를 구분하고 이용 제한 이유 표시. 지원하지 않는 필드는 '정보 없음' 처리. 한 공급자 장애가 다른 목록을 막지 않음 |
| REQ-03 | 성우 미리듣기 | 기본 샘플 재생/정지, 동시에 한 개만 재생. 샘플 URL이 없으면 '샘플 없음'. 실패 시 재시도 안내. 내 대본 시험 생성은 별도 유료 생성 동작으로 명확히 구분하며 자동 호출 금지 |
| REQ-04 | 즐겨찾기·자주 사용·개인 분류 | 공급자별 즐겨찾기와 자주 사용 등록/해제를 독립 제공, 개인 메모, 여러 카테고리·타입·채널 연결. 새로고침·재로그인 후 유지. 공급자+성우 ID로 중복 방지. 프리셋 포함 여부로도 즐겨찾기 필터 가능 |
| REQ-05 | 분류·채널 관리 | 카테고리/타입/채널 생성·이름 변경·삭제. 삭제는 연결만 해제하고 성우·대본은 보존. 사용 중 연결 수를 보여 주고 삭제 확인. 동일 그룹 중복 이름 방지 |
| REQ-06 | 저장 대본 | 제목·본문·분류·선택 채널로 등록/수정/삭제/검색/복제. 작업실에서 교체 또는 삽입 선택. 저장 안 된 편집이 있으면 경고. 저장 대본을 불러온 뒤 편집해도 원본은 명시적 저장 전 변경되지 않음 |
| REQ-07 | 발음 교정 | 원문 보존, 숫자 패턴별 한글 제안, 변경 부분 비교, 항목별 승인/무시/직접 수정, 되돌리기. 미검수 항목이 있으면 알림; 사용자가 원문 유지로 확인할 수 있음. 실제 생성문을 별도 확인 가능 |
| REQ-08 | 공급자별 프리셋 | 이름·공급자·성우·모델·지원 설정·교정 모드(P1-07로 미룸, 2026-11-18)·선택 채널 저장/수정/복제/삭제. 채널의 기본 프리셋 지정. 선택 시 적용 값 미리보기. 프리셋 삭제는 기존 작업 스냅샷을 변경하지 않음 |
| REQ-09 | 음성 생성 | 세 공급자 각각 실제 한국어 생성 성공. 공백 대본/상한 초과/성우 미선택 차단. 교정 후 텍스트로 글자 수 재계산. 중복 클릭은 생성 요청 1회. API 옵션 서버 재검증. [공급자 옵션·제작 도구 계약](tts-provider-options-and-tools.md)과 [Fish Audio 옵션](../research/fish-audio-api-options.md)에 따라 모델별 감정/표현·음성 조절·발음/문맥·출력·고급 옵션을 누락 없이 UI 또는 서버 처리에 매핑 |
| REQ-10 | 재생·다운로드 | 성공한 오디오 재생/정지/탐색/볼륨, 실제 형식에 맞는 확장자로 다운로드. MP3를 공통 기본값으로 하고 WAV 등은 계정·모델 지원 시 노출. 재다운로드는 생성 API 재호출 없음 |
| REQ-11 | 상태·사용량·오류 | 준비/요청 중/완료/실패/처리 여부 미확인 구분. 401·권한·잔액·입력·429·타임아웃별 안내. 가짜 진행률 금지. 예상치와 실제 제공사 사용량 구분, 근거 없는 금액이나 '무료 무제한' 문구 금지 |
| REQ-12 | UI 기반 | Pretendard, 한국어 UI, 핵심 흐름의 반응형·키보드 조작·포커스·빈 상태·오류 상태. 기존 shadcn 프리미티브와 디자인 토큰 재사용 |
| REQ-13 | 내 클론 보이스 생성·관리 | 직접 녹음 또는 음성 파일로 내 보이스 생성. 공급자별 파일 조건·권한·슬롯 한도 검증, 본인 음성 확인, 처리/검증/사용 가능/실패 상태 제공. 사용 가능한 보이스만 TTS 선택 가능. 이름·메모·분류·즐겨찾기·프리셋 연결 및 삭제. 계정 지원 시 세 공급자 각각 생성→한국어 합성→삭제 검증; 접근 제한이 있으면 해당 공급자 미검증으로 보고하고 전체 완료로 처리하지 않음 |

### 내 클론 보이스 상세 (REQ-13)

1. `내 보이스`에 등록 목록과 만들기 버튼을 둔다. 보이스 이름·공급자·상태·생성일·연결된 프리셋을 표시한다. 보이스는 공급자별 개체이며 다른 공급자로 자동 복사하거나 호환된다고 가정하지 않는다.
2. 마이크 권한은 사용자가 녹음 버튼을 누를 때 요청한다. 정지·다시 녹음·원본 미리듣기·파일 대체를 지원하고 종료/이탈 시 마이크 트랙을 정리한다.
3. 공급자별 실제 길이·용량·코덱·파일 개수를 안내하고 서버에서 다시 검사한다. 브라우저 녹음 형식을 공급자가 받지 못하면 지원 형식으로 변환하거나 명확히 재등록을 안내한다. '10초면 항상 완성' 같은 공통 보장은 하지 않는다.
4. 업로드 전 본인 음성이며 클론 생성에 동의한다는 확인과 전송할 공급자를 표시한다. 필요한 공급자 소유권 검증은 우회하지 않는다. 초기 범위는 본인 음성이고 타인의 목소리 등록은 포함하지 않는다.
5. 상태는 앱 기준 `입력 중 → 업로드 중 → 생성 처리 중 → 검증 필요/사용 가능/실패/처리 여부 미확인`으로 정규화한다. 실제 API가 반환하지 않는 진행률이나 완료 시간을 만들지 않는다. 검증이 외부 공급자 화면에서만 가능하면 이동 안내 후 상태 재확인 흐름을 제공한다.
6. 생성 완료 후 샘플 URL이 없으면 원본 녹음과 합성 미리듣기를 구분한다. 명시적인 시험 대본 생성으로 품질을 확인하며 예상 사용량을 알린다. 샘플이 없어도 사용 가능한 클론을 숨기지 않는다.
7. 공용 공급자 키를 쓰더라도 개인 클론은 앱 소유권 매핑으로 격리한다. 전체 공급자 카탈로그를 통해 다른 사용자의 클론이 노출되거나 임의 voice ID로 합성되지 않게 한다. 앱 밖에서 만든 클론은 자동 소유자 배정하지 않는다.
8. 원본은 기본적으로 앱에 영구 보관하지 않는 방향으로 설계한다. 브라우저 원본·서버 임시 파일의 성공/실패/취소/시간 초과별 정리 기한을 구현 전 정하고, 제공사 측 보관과 별도로 안내한다. 클론 ID·소유자·상태·동의 기록 등 필요한 메타데이터만 영속화한다.
9. 삭제 전 연결 프리셋과 재생성 불가 영향을 보여 준다. 삭제 요청 시 신규 합성을 차단하고 제공사 삭제 완료를 확인한 뒤 앱에서 삭제 완료로 표시한다. 실패/응답 유실은 삭제 대기 상태를 유지하고 재확인·재시도한다. 프리셋은 보이스 선택 필요 상태로, 기존 생성 기록은 스냅샷으로 보존한다. 이미 내려받은 파일 삭제까지 보장하지 않는다.
10. 생성 중 중복 클릭·타임아웃은 기존 생성 요청과 보이스 목록을 먼저 확인하고 무조건 재등록하지 않는다. 공급자별 플랜 제한·슬롯 부족·마이크 거부·무음/잘못된 파일·검증 필요·삭제 실패를 수용 시나리오에 포함한다.

### 전체 성우 탐색과 반복 사용 상세 (REQ-02~04)

1. **전체의 범위:** 예시 성우나 추천 목록으로 제한하지 않는다. Typecast는 공식 API가 제공하는 전체 목록, ElevenLabs는 계정 성우와 공개 Voice Library 탐색을, Fish Audio는 공개 성우 목록과 내 워크스페이스(`self`) 성우 탐색을 모두 제공한다. 제공사 웹 서비스에만 있는 성우나 접근 권한이 없는 비공개 성우까지 제공한다고 약속하지 않는다. 개인 클론에는 REQ-13의 소유권 규칙을 적용한다.
2. **두 축의 탐색:** 공급자 `전체 / Typecast / ElevenLabs / Fish Audio`와 보기 `전체 성우 / 즐겨찾기 / 자주 사용 / 최근 사용`를 독립적으로 조합한다. ElevenLabs의 계정 목록·공개 라이브러리는 범위를 표시한다. 작업실의 짧은 선택 목록에서 `전체 성우 보기`로 이동하고 대본 초안을 유지한 채 선택하여 돌아온다.
3. **타입별 조회:** 공급자 원본 유형(기본/공유/클론 등), 제공되는 언어·성별·연령·억양·용도와 개인 카테고리·타입·채널·프리셋을 구분하여 필터링한다. 지원되는 필드와 원본 값을 보존하고 공통 의미가 확인된 값만 매핑한다. 이름만 보고 언어·성별·성격을 추정하지 않는다. 다중 축 AND/동일 축 OR를 적용하되 공급자가 지원하지 않는 필터는 완전한 대상 목록에서 처리하거나 지원하지 않음을 알린다. 현재 로드된 일부 데이터만 검색하고 전체 결과라고 표시하지 않는다.
4. **목록 누락 방지:** 공급자 방식에 맞게 전체 응답 또는 페이지/커서를 처리한다. 페이지 이동·더 보기, 로딩/끝/부분 실패/재시도를 제공한다. 필터 변경 시 페이지 상태와 이전 요청을 무효화하며 `(provider, voiceId)`로 중복을 막는다. 공개 목록과 계정 목록에서 같은 성우를 만나도 개인 분류는 한 개체에 연결한다. 전체 개수를 알 수 없으면 로드된 개수만 표시한다.
5. **미리듣기:** 목록의 모든 항목에 샘플 상태를 표시한다. URL이 있는 성우만 기본 샘플을 재생하며 동시에 한 개만 재생한다. 샘플 없음·URL 만료·청취 실패를 구분한다. 샘플 없는 성우는 숨기지 않고 사용 가능할 때 별도 시험 생성으로 확인한다. 목록 진입/선택/필터링만으로 유료 합성을 호출하지 않는다.
6. **즐겨찾기와 자주 사용:** 공급자마다 `즐겨찾기 추가/해제`와 `자주 사용 등록/해제`를 제공하고 서로 독립적으로 저장한다. 자주 사용은 수동 고정 목록이다. 별도로 성공한 생성 기록에 기반한 최근 사용/사용 횟수 정렬을 제공하며 샘플 청취·선택·실패·중복 콜백·재다운로드는 사용 횟수에 넣지 않는다. 이력이 없는 성우도 수동 등록할 수 있다.
7. **앱 저장과 공급자 저장:** 앱 즐겨찾기/자주 사용 등록은 개인 데이터만 저장하며 공급자 계정에 성우를 자동 추가하지 않는다. 공개 성우의 합성 가능 여부·계정 저장 여부·이용 조건은 별도 상태다. 공급자 계정 추가가 필요하면 별도 행동으로 안내하고 자동 추가/삭제하지 않는다. 계정 슬롯·권한 제한은 복구 가능한 오류로 처리한다.
8. **영속성과 이용 중단:** 두 목록과 개인 분류는 재로그인 후 복원한다. 공급자 목록에서 사라지거나 사용 제한된 성우도 개인 기록을 보존하고 `현재 이용 불가`를 표시한다. 다른 성우로 자동 대체하지 않는다.

**수용 시나리오:** 3페이지 이상의 목록 마지막 성우도 검색·선택 가능, 필터 변경 중 늦은 응답이 목록을 덮어쓰지 않음, 공급자 간 동명 성우의 독립 저장, 계정/공개 중복 성우의 동일 개인 상태, 공급자별 즐겨찾기와 자주 사용 조합, 등록·해제 후 재로그인 복원, 샘플 없음·만료·한 개 재생, 성공/실패/재전송별 사용 횟수, 한 공급자 장애 중 다른 공급자 이용을 검증한다. 실제 API 범위는 모의 목록 검증과 구분해 보고한다.

### 카탈로그 API 확인 근거 (2026-09-26)

- [Typecast llms.txt](https://typecast.ai/docs/llms.txt)를 먼저 확인한 뒤 [성우 목록 명세](https://typecast.ai/docs/api-reference/voices/list-voices.md)를 대조했다. `/v3/voices`는 기본·완료된 커스텀 성우와 `model/gender/age/use_cases/voice_type` 필터를 제공한다. 현재 명세에 페이지 인자는 없으며 `preview_url`은 없을 수 있다.
- [ElevenLabs 계정 목록](https://elevenlabs.io/docs/api-reference/voices/search)은 `next_page_token/has_more`, [공개 라이브러리](https://elevenlabs.io/docs/api-reference/voices/voice-library/get-shared.md)는 `page/has_more`로 탐색한다. 변동 가능한 총 개수를 종료 조건으로 삼지 않는다.
- [공개 라이브러리 안내](https://elevenlabs.io/docs/eleven-creative/voices/voice-library)는 계정 저장 없이 사용하는 흐름도 설명한다. 따라서 [공급자 계정 추가 API](https://elevenlabs.io/docs/api-reference/voices/voice-library/share)를 항상 선행하지 않는다. 현재 안내의 무료 플랜 API 제한 등은 구현 시점에 계정·성우별로 다시 확인한다.
- (2026-09-28) [Fish Audio 성우 목록](https://docs.fish.audio/api-reference/endpoint/model/list-models.md) `GET /model`은 `page_size`(1–100)·`page_number`와 `has_more`로 탐색하고 `self`·`language`·`tag`·`title` 필터를 제공한다. 성우 레코드는 API에서 `model`로 불리며 `samples[].audio`가 기본 샘플 URL이다. 무료 목록 조회 1회로 응답 구조만 확인했다.
- 공식 문서 검토이며 실제 계정 API 응답이나 음성 청취를 검증한 것은 아니다.

## 5. 한국어 숫자·발음 교정 상세

### 처리 원칙

1. 원문과 발음용 대본을 별도 보존한다. 원문을 다시 입력하거나 수정하면 이전 위치 기반 교정 결과를 무효화하고 재검수한다.
2. 긴 패턴부터 인식한다: 전화번호·날짜·시간 → 단위·화폐·비율 → 일반 숫자. 겹치는 범위를 중복 변환하지 않는다.
3. 각 제안에 원문 범위·원문·제안·규칙 종류·검수 상태를 기록한다. 신뢰도를 계산하지 않았다면 가짜 퍼센트를 표시하지 않는다.
4. 애매한 수량·제품명·버전·범위는 자동 확정하지 않는다. 원문 유지와 읽기 방식 선택을 제공한다.
5. 기본은 규칙 기반 후보 생성으로 제안한다. Typecast AutoTag는 공식 후보로 정확도·실행 환경·의존성을 별도 평가한다. LLM 교정을 P0 필수 의존성으로 두지 않는다.
6. API 자체 normalization이 앱 교정을 다시 바꿀 수 있으므로 최종 입력문과 실제 청취를 각 공급자에서 검증한다. 모든 발음의 완전 자동 정확성을 약속하지 않는다.

## 7. API 통합 계약과 실패 처리

- 공통 어댑터는 성우 목록, 지원 기능, 기본 샘플, 생성, 오류 정규화를 담당한다. 공급자별 요청 필드는 각 어댑터 안에서 만든다.
- Typecast: `GET /v3/voices`, `POST /v1/text-to-speech`, `X-API-KEY`.
- ElevenLabs: 계정 목록 `GET /v2/voices`, 공개 라이브러리 `GET /v1/shared-voices`, `POST /v1/text-to-speech/{voice_id}`, `xi-api-key`.
- Fish Audio: 성우 목록 `GET /model`, 생성 `POST /v1/tts`(모델은 body가 아닌 `model` 요청 헤더), `Authorization: Bearer`. 과금은 UTF-8 바이트 기준이다.
- 같은 이름의 성우를 같은 개체로 병합하지 않는다. 카탈로그에서 사라진 즐겨찾기는 기록을 유지하며 '현재 이용 불가'로 표시한다.
- 공급자/모델 전환 시 호환되지 않는 옵션을 초기화하고 알린다. 원문·분류는 유지한다. 다른 공급자로 자동 대체 생성하지 않는다.
- API 키는 클라이언트 번들·브라우저 저장소·응답·로그에 포함하지 않는다. 개인용 서버 키 방식이면 신규 공개 가입 계정이 공용 키를 쓸 수 없도록 소유자 접근 제한을 둔다.
- 생성 전 서버에서 요청문 상한·성우 접근성·모델 옵션을 검증한다. 사용자별 생성 속도·동시 요청을 제한한다.
- 중복 클릭/네트워크 재전송은 앱 요청 ID와 서버 상태로 억제한다. 제공사 멱등성·무과금 재시도를 보장한다고 쓰지 않는다.
- 타임아웃은 `처리 여부 미확인`으로 표시하고 자동 재생성하지 않는다. 429도 오류 종류와 Retry-After 등 공급자 지침에 맞춰 횟수를 제한한다. 잔액/인증/검증 오류는 사용자 조치 전 반복하지 않는다.
- 완료 오디오는 재생·다운로드에 재사용한다. 임시 오디오 만료·메모리 해제·페이지 이탈을 안내한다. 오래된 결과와 변경된 대본은 '이전 설정으로 생성한 결과'로 구분한다.
- 글자 수는 실제 전송문 기준이다. 예상 사용량·금액은 산식/기준일이 있을 때만 제시하고 제공사 최종 청구와 구분한다. 제공사별 크레딧·과금 단위(글자 수, UTF-8 바이트)를 같은 숫자로 합산하지 않는다.
- 초기 MP3 출력은 세 공급자에서 실제 검증한다. WAV·고음질·감정·발음 사전 등은 모델과 계정 권한을 확인한 것만 노출한다.
- 상세 출처와 문서 충돌은 [참고 조사](../research/tts-references.md)의 API 표를 따른다. 가격·모델·한도는 구현 시점에 재확인한다.

## 8. 검증과 초기 완료 정의

1. 성우를 듣고 카테고리·타입·채널을 지정해 즐겨찾기한 뒤 재로그인해도 유지된다.
2. 저장 대본을 불러와 숫자를 교정하고 원문을 보존한 채 세 공급자로 각각 생성·재생·다운로드한다.
3. 프리셋을 저장하고 다음 작업에서 같은 설정을 복원한다. 공급자 전환 시 잘못된 옵션을 보내지 않는다.
4. 상한 초과·성우 삭제·샘플 누락·API 키 오류·잔액 부족·429·응답 유실을 재현해 상태와 복구 동작을 확인한다.
5. 자동화 검사는 교정 규칙·생성 계약·CRUD·2계정 격리 중심으로 작성한다. 실제 발음 품질은 한국어 청취로 별도 확인한다.
6. `prokit-dev-cycle` F 라운드에서 해당 계층 검사, 독립 `prokit-reviewer` 리뷰, 타입·린트·빌드, Next 런타임, 데스크톱/모바일 브라우저 검증 증거를 기록한다.
7. API 키나 계정 조건 때문에 실제 생성 검증이 안 되면 'UI/모의 연동 완료, 실 API 검증 미완료'로 보고한다.
8. 직접 녹음과 파일 업로드로 본인 클론을 등록하고, 사용 가능 상태에서 숫자를 교정한 대본을 합성·다운로드한다. 분류/프리셋 재사용·재로그인 복원·삭제 후 신규 합성 차단·타인 클론 접근 거부를 검증한다. 원본 녹음과 클론 합성 결과를 각각 청취해 구분한다.
