## 3. 확인 호출

세 호출 모두 키가 있어야 성공하고 상태를 바꾸지 않는다. 공식 문서에 "무료" 문구는 없다. 계정 조회라 과금되지 않는다고 보지만, 그래서 자동 주기 확인을 두지 않고 QA 호출 수에 상한을 둔다(9절).

| 공급자 | 호출 | 방식 | 잔여 사용량 |
|---|---|---|---|
| Typecast | `GET /v1/users/me/subscription` | SDK `@neosapience/typecast-js`의 `getMySubscription()`. 호스트 `https://api.typecast.ai`를 명시한다 | 플랜 `plan`, 남은 크레딧 = `credits.plan_credits − credits.used_credits`. 초기화 시각 없음 |
| ElevenLabs | `GET /v1/user/subscription` | SDK `@elevenlabs/elevenlabs-js`의 `user.subscription.get()`. 요청 옵션 `maxRetries: 0`, `abortSignal` | 남은 글자 = `character_limit − character_count`, 초기화 `next_character_count_reset_unix` |
| Fish Audio | `GET /wallet/self/api-credit`, 성공하면 이어서 `GET /wallet/self/package` | `fetch`, `Authorization: Bearer`, `signal` | API 충전 잔액 `credit`(문자열로 온다. 아래 규칙으로 숫자로 바꾸고, 단위는 문서에 없어서 붙이지 않는다). 웹 플랜 크레딧 `type`·`balance`·`total`(2026-10-04 후속 수정) |

- **시간 제한:** 공급자마다 10초이고, 세 모듈이 같은 방식으로 끊는다. `AbortController`와 `setTimeout(10_000)`을 쓰고, 끝나면 타이머를 지운다.
  - Fish Audio는 그 신호를 `fetch`의 `signal`로 넘긴다.
  - ElevenLabs는 요청 옵션 `abortSignal`로 넘긴다. SDK의 `timeoutInSeconds`는 쓰지 않는다.
  - Typecast SDK에는 취소 옵션이 없어서 같은 타이머와 경주시킨다. 끊은 요청은 뒤에서 계속 돌지만 상태를 바꾸지 않는 조회라 괜찮다. 이 한계는 코드에 `ponytail:` 주석으로 남긴다.
  - `AbortSignal.timeout()`은 쓰지 않는다. vitest 가짜 타이머로 진행되지 않기 때문이다(재검토 때 vitest 5.0.2로 확인).
  - ElevenLabs의 `abortSignal` 옵션은 설치한 판의 타입 선언으로 확인한다. 없으면 Typecast처럼 경주시킨다.
- **재시도:** 없다. 확인은 사용자가 누를 때만 다시 한다.
- **응답 검증:** 필요한 필드가 없거나 숫자가 아니면 확인 실패다. Typecast·Fish Audio 응답은 zod로 검사한다(Typecast SDK는 응답을 검사하지 않는다). ElevenLabs는 SDK 2.70.0이 응답 전체를 자체 스키마로 검사해 `ParseError`를 던지므로 그것을 확인 실패로 바꾼다. 검증 실패 로그에는 실패한 필드 경로만 남기고 값은 남기지 않는다. SDK는 쓰지 않는 필드까지 검사하므로, 실측에서 연결된 계정이 확인 실패로 보이면 그 경로로 원인을 찾는다.
- **Fish Audio 크레딧:** `credit`은 `^\d+(\.\d+)?$`에 맞을 때만 숫자로 바꾸고, 맞지 않으면 확인 실패다. `z.coerce.number()`는 빈 문자열을 0으로 바꾸므로 쓰지 않는다.
  - 크레딧이 0이어도 한도 부족으로 판정하지 않는다. 무료 크레딧(`has_free_credit`)과 패키지 잔액(`/wallet/self/package`)이 따로 있어서, 이 값만으로는 생성할 수 있는지 알 수 없다.
  - 웹 플랜(2026-10-04 후속 수정): 사용자가 fish.audio 웹의 '남은 크레딧'과 우리 화면의 API 잔액 0을 헷갈려 함께 보이기로 했다. `api-credit`이 성공한 뒤에만 `package`를 부른다. 웹 플랜 조회가 실패하면(HTTP 오류, 응답 모양 다름) 웹 플랜 칸만 빠지고 연결 상태는 그대로다. 로그에는 상태 코드나 필드 경로만 남긴다. 두 호출이 10초 제한을 함께 써서 넘기면 확인 실패다. `type`은 1~40자일 때만 받는다.
  - Fish Audio의 한도 부족은 402일 때뿐이다.
- **`Retry-After`:** 1~999999초의 정수(`^[1-9]\d{0,5}$`)일 때만 결과에 담는다. 0, 너무 큰 값, HTTP 날짜 형식이거나 헤더를 읽을 수 없으면 `null`이다. Typecast SDK 오류는 헤더를 주지 않을 수 있다.
- **키 전달:** SDK 생성자에 키와 공식 호스트를 명시한다. 키가 비면 클라이언트를 만들지 않는다. 두 SDK 모두 인자가 없으면 `process.env`로 대체하기 때문이다. Typecast SDK는 키 없이도 요청을 보낸다.
- **키 교체:** 공급자 클라이언트는 요청마다 `ENV`에서 키를 읽어 만든다.
  - varlock은 개발 중 `.env`가 바뀌면 값을 다시 읽는 구조다(`@varlock/nextjs-integration` 1.2.2 소스의 `enableExtraFileWatchers`). 그러면 키를 바꾼 뒤 '다시 확인하기'만 누르면 된다.
  - 구현 때 실제로 확인한다. 반영되지 않으면 10절 사용자 테스트와 키 없음 안내를 "개발 서버를 다시 켜세요"로 바꾼다.

## 4. 상태 판정

| 상태 | 코드 값 | 판정 | 화면 안내(요지) |
|---|---|---|---|
| 연결됨 | `connected` | 확인 호출 200, 응답 검증 통과, 한도 부족이 아님 | 잔여 사용량과 확인 시각 |
| 키 없음 | `no_key` | 키가 비어 있다. 공급자를 부르지 않는다 | `apps/web/.env`에 넣을 변수 이름(`TYPECAST_API_KEY` 등) |
| 키 오류 | `provider_auth` | 401·403(아래 권한 부족 제외) | 키가 틀렸거나 만료됐어요. 공급자 대시보드에서 키 확인 |
| 권한 부족 | `no_permission` | 401·403이면서 본문 `detail.code` 또는 `detail.status`가 `missing_permissions`·`insufficient_permissions` | 키는 맞지만 사용량 조회 권한이 없어요(ElevenLabs 키 권한 설정) |
| 한도 부족 | `quota` | 402. 또는 200인데 잔여가 0 이하(Typecast, ElevenLabs. ElevenLabs는 `max_credit_limit_extension`이 0일 때만). Fish Audio는 402만 | 남은 사용량이 없어요. 사용량을 보여 준다 |
| 요청 제한 | `rate_limit` | 429. `Retry-After`가 정수 초면 함께 준다 | 잠시 뒤 다시 확인 |
| 공급자 장애 | `provider_error` | 5xx | {공급자} 서버에 문제가 생겼어요. 잠시 뒤 다시 확인 |
| 확인 실패 | `check_failed` | 시간 초과, 연결 끊김, 응답 검증 실패, 그 밖의 상태 코드, 예상 밖 예외 | 연결 상태를 확인하지 못했어요. 잠시 뒤 다시 확인 |

- 권한 부족 판정 값은 비공식 출처다. 공식 오류 표는 403 `insufficient_permissions`이고 비공식 자료는 401 `missing_permissions`다. 둘 다 받고, 어느 것도 아니면 키 오류로 떨어진다. 실제 범위 제한 키로 확인하지 못했음을 `[confirm]` 보고에 적는다.
- 상태 코드 → 사유 판정(`providers/errors.ts`)은 `tts-provider` 스킬의 오류 매핑 표(`provider_auth`, `quota`, `rate_limit`, `provider_input`, `provider_error`)를 그대로 따르고 `no_permission`을 더한다.
  - 확인 호출에서 `provider_input`(400·422)이 나오면 확인 실패로 보인다.
  - 조회의 시간 초과는 `unknown_outcome`이 아니라 확인 실패다. 상태를 바꾸지 않는 호출이라 처리 여부를 따질 필요가 없다.
  - T3부터 목록·생성 호출이 같은 판정을 쓴다.
- 공급자 문제는 예외로 던지지 않고 상태 값으로 돌려준다. 프로시저가 던지는 것은 소유자 없음(`UNAUTHORIZED`)과 잘못된 입력(`BAD_REQUEST`)뿐이다.
- 화면에서 조회 자체가 실패하면 그 카드에 확인 실패와 같은 표현과 '다시 확인하기'를 보인다. 자체 서버 500, 네트워크 끊김, CSRF 403이 여기에 든다. `UNAUTHORIZED`는 카드가 아니라 페이지 안내로 보인다(5절 8번).

## 5. 범위

DB 스키마와 소유 데이터는 바꾸지 않는다. 대조표의 DB 행(5, 7~10행)은 N/A다. 2계정 격리 테스트 행(13행)은 AC3(소유자 없음이면 `UNAUTHORIZED`이고 공급자 호출 0)으로 대신한다.

### 포함
1. **공급자 계약** `packages/api/src/providers/contract.ts`(신규): 공급자 id(`typecast`, `elevenlabs`, `fish_audio`), 상태 8종, 연결 상태 결과의 zod 스키마. 결과에는 공급자, 상태, 잔여 사용량, 공급자 오류 코드, `Retry-After` 초, 확인 시각이 들어간다. SDK와 서버 모듈을 import하지 않아 화면이 타입을 가져가도 공급자 코드가 딸려 가지 않는다.
2. **오류 사유 판정** `providers/errors.ts`(신규): HTTP 상태와 공급자 오류 코드로 사유를 고른다(4절).
3. **공급자 모듈** `providers/typecast.ts`, `elevenlabs.ts`, `fish-audio.ts`(신규): 키로 클라이언트를 만들고, 확인 호출 하나를 해 4절 상태로 바꾼다. SDK 오류 객체와 응답 헤더는 로그에 쓰지 않는다.
4. **서버 연결** `apps/web/src/context.ts`, `packages/api/src/context.ts`: 소유자가 있는 요청에만 `ENV`의 키로 공급자 클라이언트를 만들어 context에 넣는다(`providers: ownerId ? createProviders(ENV) : null`). 키가 없는 공급자는 `null`이다. 소유자가 없는 요청에는 클라이언트를 만들지 않는다. 루프백 요청이면 `publicProcedure`의 context에도 `providers`가 들어 있으므로, `publicProcedure`에서는 `context.providers`를 쓰지 않는다. `services.ts`는 바꾸지 않는다.
5. **프로시저** `providerStatus`: `protectedProcedure`, 입력 `{ provider }`(공급자 id enum), 출력은 계약의 연결 상태 결과. 키가 없으면 공급자를 부르지 않고 `no_key`다.
6. **화면** `/connections`: 브리프대로 만든다(페이지 머리, 요약 띠, 카드 3장).
   - `page.tsx`는 Server Component다. 제목 메타데이터만 두고 공급자·db 모듈을 부르지 않는다.
   - 클라이언트 컴포넌트 하나가 세 조회를 `useQueries`로 든다. 조회 설정은 `staleTime` 5분, `retry: false`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`, `meta: { toast: false }`다.
   - 카드 컴포넌트는 결과를 표시만 한다. 요약 띠도 같은 결과로 화면 컴포넌트가 그린다(브리프 5절 표). 조회를 더 하지 않는다.
   - '다시 확인하기'는 그 공급자 조회만 `refetch`한다. 확인 중에는 버튼을 누를 수 없으므로 같은 공급자로 두 번째 호출이 나가지 않는다.
7. **메뉴:** '연결 상태'를 `/connections` 링크로 열어 열린 화면 묶음(음성 작업실 아래)에 둔다. '준비 중' 7개는 접힌 묶음 "다음에 열릴 화면"에 넣는다(앱 틀 브리프 3절). 휴대폰 위 막대는 음성 작업실·연결 상태·더보기 3칸이다. 휴대폰 더보기는 다음처럼 동작한다(AF-01).
   - 경로가 바뀌거나, Esc를 누르거나, 바깥을 누르면 닫힌다.
   - Esc로 닫히면 포커스는 더보기 버튼으로 돌아간다.
   - 열린 동안 Tab과 Shift+Tab은 더보기 버튼과 펼친 내용 안에서만 돈다.
   - 더보기 안에 링크가 생기면(뒤 TASK) 링크 이동 뒤 포커스 복귀와 더보기 버튼의 현재 위치 표시를 그때 더한다(5절 "만들지 않는 것").
8. **조회 오류 공통:**
   - 전역 조회 오류 알림을 한국어로 바꾼다("데이터를 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요."). `meta.toast`가 `false`인 조회는 알림을 띄우지 않는다. 알림의 영문 'retry' 버튼은 뺀다.
   - `QueryClient`는 서버에서는 요청마다 새로 만들고 브라우저에서는 하나를 쓴다(`isServer`). 이렇게 해야 SSR 요청끼리 캐시가 섞이지 않는다.
   - 소유자가 없어 거절되면 카드 대신 페이지에 안내를 한 번 보인다: "개발 서버(`pnpm dev`)를 127.0.0.1 또는 localhost 주소로 열어 주세요." 루프백이 아닌 주소나 production 실행이 여기에 든다.
9. **로그 정책(AF-11):** rpc `onError`는 의도한 4xx(`ORPCError`이고 상태 500 미만)를 남기지 않고, 그 밖의 오류만 남긴다. 확인 호출에서 예상 밖 예외가 나면 공급자 이름과 오류 이름만 한 줄 남긴다.
10. **작업실 빈 상태:** 동작 없는 빈 상태 카드를 제작 흐름 지도(채널 → 성우 → 대본 → 검수 → 생성, 단계마다 '준비 중')로 바꾸고, 아래에 "공급자 연결은 [연결 상태]에서 확인할 수 있어요."([연결 상태]는 `/connections` 링크)를 둔다. 개발 순서를 말하는 문장은 두지 않는다(앱 틀 브리프 4절, 리디자인 5절 3번).
11. **페이지 제목:** 루트 레이아웃에 `title.template`("%s · TTS Pilot")을 두고 `/studio`는 "음성 작업실"(메뉴·페이지 제목과 같다), `/connections`는 "연결 상태", 없는 주소는 "페이지를 찾을 수 없어요"로 한다. T1 계획 디자인 리뷰가 두 번째 페이지가 생기는 T2로 미룬 항목이다(WCAG 2.4.2).
12. **토큰과 프리미티브:** `packages/ui/src/styles/globals.css`의 토큰 값을 새 세계로 바꾸고(시맨틱 이름 구조는 그대로) success·warning을 라이트·다크로 더한다(2절 상태 색). 기본 전환을 150ms `cubic-bezier(0.3,0,0,1)`로 둔다. 상태 표시는 shadcn `badge`, 진행 표시는 `spinner`를 shadcn 절차로 `packages/ui`에 더해 쓴다. `Button`의 `outline`은 청록 테두리·글자, `lg`는 44px·반경 8px로, `Card`는 반경 16px로 맞춘다.
13. **문서:**
    - `GLOSSARY.md`: 연결 상태·잔여 사용량.
    - `docs/domain/project.md`: 기능·화면·API 표.
    - `tts-provider` 스킬:
      - 오류 매핑 표에 `no_permission`을 더한다.
      - "상태 확인은 던지지 않고 값으로 돌려주고, 조회 시간 초과는 `check_failed`" 한 줄을 넣는다.
      - "공급자 클라이언트는 소유자가 있는 요청마다 context에서 만든다(키 교체 반영)"를 넣는다.
      - SDK 동작 표에 이번에 확인한 사실을 더한다: ElevenLabs 생성자는 키가 끝내 없으면 예외, Typecast SDK는 시간 제한·재시도·응답 검증 없음, 두 SDK의 확인 호출 메서드.
    - 로드맵 4절 T2 상태.
14. **앱 틀 리디자인(T1 화면, 앱 틀 브리프 2~5절):** 글자 로고(1200px 이상), 사이드바 256px, 활성 메뉴 표현, 고른 값을 보이는 테마 버튼, 띠와 경계선 없는 페이지 머리, 없는 주소 화면을 앱 틀 안에서 보이기(앱 틀을 `(app)/layout.tsx`에서 루트 레이아웃으로 옮긴다. 루트 `not-found`는 루트 레이아웃 안에서 그려진다. 모든 경로를 받는 라우트는 `typedRoutes` 검사를 없애므로 쓰지 않는다).

## 6. 구조

```text
브라우저 /connections
  page.tsx (Server Component, metadata.title)
  └ 연결 상태 화면(클라이언트): useQueries × 3  staleTime 5분, retry·창 포커스 재조회 없음, meta.toast false
```

## 7. 수용 기준

| # | 기준 | 확인 방법 |
|---|---|---|
| AC1 | 세 공급자의 200 응답이 연결됨과 잔여 사용량(3절 계산)으로 바뀐다. Typecast·ElevenLabs의 잔여 0 이하는 한도 부족이고, Fish Audio는 잔액 0이어도 연결됨이다 | 자동 테스트 |

## 8. 자동 테스트

실제 네트워크는 쓰지 않는다. `vi.stubGlobal("fetch", …)`로 HTTP 응답만 흉내 내어 SDK의 실제 오류 처리까지 지나게 한다. 두 SDK 모두 호출 시점의 전역 `fetch`를 쓴다.

- `providers/errors.test.ts`: 401·403·402·429·400·422·500·503과 권한 부족 코드 두 가지 → 사유.
- `providers/typecast.test.ts`, `elevenlabs.test.ts`, `fish-audio.test.ts`: 공급자마다 다음을 확인한다.
  - 200 정상이면 연결됨과 잔여 사용량이다.
  - 200에 잔여 0이면 Typecast는 한도 부족, ElevenLabs는 한도 확장이 없을 때만 한도 부족, Fish Audio는 연결됨이다.
  - 401, 403, 402, 429, 503은 해당 상태다. ElevenLabs는 403에 권한 부족 두 형태를 포함하고, 429는 `Retry-After`가 정수 초일 때, 날짜일 때, 없을 때를 모두 본다.
  - 다음은 확인 실패다:
    - 시간 초과: 가짜 타이머로 10초를 넘긴다. `setTimeout` 기반이라 진행된다.
    - `fetch` 예외: 연결 끊김.
    - 필드 누락, 숫자 아님.
    - Fish Audio `credit`이 `""`나 `"abc"`일 때.
  - 요청 URL의 호스트·경로와 인증 헤더에 키가 쓰였고, `fetch` 호출이 1회다. Fish Audio는 잔액 → 웹 플랜 순서로 2회이고, 잔액 조회가 실패(401·429·검증 실패)하면 1회다.
  - Fish Audio 웹 플랜(2026-10-04 후속 수정):
    - 웹 플랜 조회가 500·429이거나 응답 모양이 다르거나 플랜 이름이 41자 또는 빈칸이면, 연결됨이고 웹 플랜만 빠진다. 로그에는 상태 코드나 필드 경로만 남는다.
    - 잔액은 왔는데 웹 플랜이 10초를 넘기면 확인 실패이고 로그는 남지 않는다.
- `routers/provider-status.test.ts`(`createRouterClient`):
  - 소유자 없음이면 `UNAUTHORIZED`이고 `fetch`는 0회다.
  - 키 없음이면 `no_key`이고 `fetch`는 0회다.
  - 없는 공급자 id는 `BAD_REQUEST`다.
  - 결과 JSON에 키 문자열이 없다.

## 9. 테스트 시나리오 (브라우저 QA)

실제 키로 부르는 것은 3절의 조회 호출뿐이다. 생성·시험 생성·클론·삭제는 없다.

- **실제 호출 상한:** QA와 재QA를 합쳐 조회 45회, 공급자별 15회 이하다(2026-09-30 사용자 승인). 2026-10-04부터 Fish Audio 확인 1번은 조회 2회(잔액, 웹 플랜)로 센다. QA 앞뒤로 공급자 대시보드의 사용량이 늘지 않았는지 사용자에게 봐 달라고 한다.

## 10. 사용자 테스트 절차 (구현 뒤 드린다)

1. 개발 서버가 떠 있는 상태에서 `http://localhost:3001/connections`를 연다(메뉴 '연결 상태'). 강력 새로 고침(Cmd+Shift+R).
2. 세 카드가 "연결됨"이고 남은 크레딧·글자 수·잔액이 각 공급자 대시보드 값과 맞는지 본다. 대시보드의 사용량이 확인 전후로 늘지 않았는지도 본다.
3. 키 하나를 바꿔 본다.
   - `apps/web/.env`에서 그 키 값 앞에 `x`를 붙여 저장하고 그 카드의 '다시 확인하기'를 누른다 → "키 오류".
   - 값을 지우고 다시 확인한다 → "키 없음"과 넣을 변수 이름.
   - 원래대로 되돌리고 다시 확인한다 → "연결됨".
   - 3절의 키 교체가 자동으로 반영되지 않으면 이 단계 앞에 "개발 서버를 다시 켠다"를 넣어 드린다.
4. 메뉴의 "다음에 열릴 화면"을 펼치고 접어 본다. 작업실의 제작 흐름 지도를 보고 아래 '연결 상태' 링크로도 와 본다. 없는 주소(예: `/connections/x`)를 열어 메뉴가 그대로 있는지 본다.
5. 창을 휴대폰 너비로 줄인다. 위 막대가 음성 작업실·연결 상태·더보기 3칸인지 본다. 더보기를 연 채 '연결 상태'를 누르면 이동하면서 닫힌다. 더보기를 다시 열고 Esc, 바깥 누르기로도 닫히는지 본다.
6. 테마 버튼으로 시스템 설정·라이트·다크를 바꿔 본다. 버튼 아이콘이 고른 값을 보이는지, 두 테마에서 화면이 승인 시안의 느낌과 맞는지 본다.

통과 기준: 위 단계가 기대대로이고, 화면에 고칠 것이 없거나 피드백을 반영해 다시 확인했다.

## 11. 위험과 확인할 것

- **무료 여부:** 세 조회 호출 모두 공식 문서에 무료 문구가 없다. 계정 조회라 과금되지 않는다고 보지만, QA 호출에 상한을 두고(9절) QA와 사용자 테스트 전후로 공급자 대시보드의 사용량을 본다.
- **ElevenLabs 권한 부족:** 판정 값이 비공식 출처다. 범위 제한 키가 없으면 실측하지 못한다. 못 하면 `[confirm]`에 적는다.
- **Typecast 크레딧 단위:** 문서에 단위가 없다. 화면에는 "크레딧"으로만 적고 글자 수로 바꾸지 않는다.
- **Fish Audio 잔액 0:** 무료 크레딧과 패키지 잔액이 따로 있어 한도 부족으로 판정하지 않는다(3절). 생성 때의 402로 알게 되는 것은 T8에서 다룬다.
- **varlock 재읽기:** Turbopack 작업자에서도 같은 값을 보는지는 소스만으로 확정하지 못했다. 3절대로 구현 때 확인한다.
- **Typecast 시간 제한:** 경주로 끊은 요청은 뒤에서 계속 돈다. 조회라 괜찮다. 목록·생성 호출(T3·T8)은 SDK 대신 무엇으로 끊을지 그때 다시 정한다.
- **없는 주소 탭 제목:** `not-found.tsx`의 `metadata`는 번들 문서에 `global-not-found`만 적혀 있다. Next 소스(`resolve-metadata.js`)는 오류 규약 모듈의 `metadata`를 모으므로 쓸 수 있다고 보고, 구현 때 curl로 확인한다. 안 되면 멈추고 사용자와 정한다(계획 Task 9 Step 7).
- **앱 틀이 루트 레이아웃에 있음:** 앞으로 앱 틀 밖에 둘 화면(T14 로그인 등)이 생기면 그 TASK에서 루트 레이아웃을 라우트 그룹마다 나눈다.
- **hero 게이트의 실제 조회:** 시안 상태(Typecast 연결됨, ElevenLabs 키 오류, Fish Audio 키 없음)는 키 덮어쓰기 서버로 재현해 캡처마다 실제 조회 2회(Typecast, ElevenLabs)가 나간다. 9절 상한(45회, 공급자별 15회)에 함께 센다.
- **SDK 설치:** 두 SDK는 설치한 뒤 타입 선언으로 메서드·옵션(`abortSignal`, `maxRetries`)을 확인한다. ElevenLabs SDK의 선택 의존성(`ws`) 때문에 Next 빌드 경고가 나는지 보고, 나면 `serverExternalPackages`를 검토한다.
