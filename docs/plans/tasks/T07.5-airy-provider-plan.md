# T7.5 Airy 공급자 추가 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Airy(airy.so)를 네 번째 공급자로 더해 연결 상태·성우 캐스팅·내 문장 듣기·성우 보관함에서 다른 세 공급자와 같은 방식으로 쓴다.

**Architecture:**
- `packages/api`: 공급자 모듈 `providers/airy.ts` 하나(REST `fetch`, Fish Audio와 같은 틀)가 연결 확인·목록(공식 목록 + 공개 카탈로그 샘플)·시험 생성·한 명 조회를 맡는다. 오류 판정은 기존 `reasonFromHttp`·`runCheck`·`runList`·`runTrial`이 그대로 맡는다(새 매핑 없음). 카탈로그 제한 시간은 `errors.ts`의 `withTimeout`을 내보내 쓴다. 계약은 `providerIdSchema`에 `airy`를 더하고 목록 입력 `{ provider: "airy" }`, 시험 생성 설정 `airySettingsSchema`를 더한다. 새 프로시저는 없다.
- `packages/db`: `saved_voice`·`trial_generation`의 공급자 검사 제약에 `airy`를 더하는 마이그레이션 하나(넓히기만).
- 화면: 연결 상태 카드 넷(768px 이상 2열), 캐스팅 Airy 탭과 '전체' 마지막 묶음, 내 문장 듣기 설정(모델·언어·말투), 보관함 공급자 필터. 한 번 받아 브라우저에서 거르는 목록(Typecast·Airy)의 공통 몸통은 새 파일 `one-list.tsx`의 `OneList`로 뽑아 두 탭이 함께 쓴다(Typecast 콘텐츠 묶음은 Typecast 파일에 남는다).

**Tech Stack:** Next.js 16.3 App Router, React 19.3(React Compiler), oRPC 1.15.4, TanStack Query 5.103, zod 4, drizzle-orm·drizzle-kit 1.0.0-rc.4, Postgres(로컬 5433), vitest, shadcn `base-lyra`, Tailwind CSS 4, Biome 2, varlock(환경 변수 스키마), turbo 2.

**Spec:** [T7.5 스펙](T07.5-airy-provider.md)(사용자 확인 2026-10-07 "확인, 계획으로", 구속력 있는 정본. 2026-10-07 코디네이터가 2·4절에 U1·U3·U4를 반영했다). 공급자 계약 [airy-api-options](../../research/airy-api-options.md). 화면 브리프 [성우 캐스팅 13절](../../briefs/casting.md), [연결 상태 카드 절](../../briefs/provider-status.md). ## 계획에서 정한 것 (스펙이 정하지 않은 것)

1. **목록 몸통 공통화(ponytail 1):** `one-list.tsx`에 `OneList`(쿼리·포커스 넘김·`useListRecovery`·`useListRefresh`·조건 줄·상태 줄·지난 목록 안내·목록 칸의 문제/뼈대/0명/조건 0명 분기)와 두 목록 쿼리 옵션, `AiryVoiceList`를 둔다. 목록 모양(Typecast 콘텐츠 묶음·한 목록, Airy 한 목록)은 부르는 쪽이 `children`으로 그린다.
2. **검색은 새 순수 함수 `filterByNameOrId`(voice-filter.ts).** Typecast 검색(`filterVoices`, 이름만)은 그대로 두고 Airy만 성우 id 부분 일치를 더한다(브리프 13절 "이름이나 성우 id로 찾기").
3. **카탈로그는 자기 제한 8초(`AIRY_CATALOG_TIMEOUT_MS`, `withTimeout`)로 끊는다.** 목록 제한(10초, `runList`) 안에서 카탈로그가 걸려도 목록은 샘플 없이 돌아온다. 카탈로그 실패 목록도 24시간 공용 캐시에 들어가며 '목록 새로 고침'이 회복한다(U1 안내 줄).
4. **한 명 조회(`getVoice`)는 목록 함수가 만든 성우(카탈로그 샘플 포함)에서 id로 찾는다.** 목록 약속(Promise)을 클라이언트 하나에 한 번만 만든다. 클라이언트는 요청마다 만들어지므로(`apps/web/src/context.ts`) "한 번의 확인에서 목록 한 번"이 된다. 실패한 약속도 그 요청 안에서는 다시 쓴다. `preferred`(ElevenLabs 샘플 언어)는 무시한다.
5. **행 샘플(`previewUrl`)은 첫 샘플이다.** 한국어가 있으면 한국어, 없으면 영어다(브리프 13절에 적는다, D15).
6. **시험 생성 본문은 `request.settings`에서 바로 만든다**(`usedSettings`를 거치지 않는다). Airy 설정은 모두 열거값이라 정리할 것이 없고, `FIELDS.airy`가 `language`·`style`을 모두 받으므로 조합 키(`comboKey`)와 본문 값이 같다.
7. **오류 판정 코드는 바꾸지 않는다.** `reasonFromHttp`가 이미 401·403→`provider_auth`, 402→`quota`, 429→`rate_limit`, 400→`provider_input`, 5xx→`provider_error`를 준다. Airy 모듈은 본문 `error.code`만 읽는 `airyCodes`를 넘긴다.
8. **`CONTRACT_VERSION`은 올리지 않는다.** 기존 캐시 행의 모양은 그대로이고 열거값이 넓어지기만 한다.
9. **화면 문구:** Airy 행 메타 줄은 "여성 · 한국어·영어"(연령 값이 없어 언어, 한국어 먼저, 중복 제거). 패널은 Typecast처럼 출처('공개 라이브러리')를 보이지 않는다. 설정 요약은 "airy-tts-v1 · 영어 · 말투 밝게". 확인 창은 '예상 사용량 · 약 N크레딧 (Airy 요금 기준: 한국어 1글자 1.5크레딧)'이다(dt '예상 사용량'과 기존 `usageText` "약 N크레딧" 뒤에 근거, U4).
10. **연결 상태 요약 띠는 지금 문구 틀("4개 중 N개 연결됨")을 쓴다.** 띠는 카드 수로 글자를 만든다(`views.length`). 스펙 4절도 "4개 중 N개 연결됨"(기존 문구 틀)이다. 브리프 5절 표의 "3개"만 고친다(Task 7).
11. **남은 크레딧 숫자는 `creditNumber`(connection-view.ts, 소수 한 자리 버림, 0 아래는 0) 하나**로 카드와 확인 창이 쓴다(E4·D4).
12. **카탈로그가 실패한 때의 이용 가능 확인:** 성우는 '이용 가능'으로 남지만 저장한 정보의 샘플이 비워진다(다음 확인에서 돌아온다). `ponytail:` 주석과 테스트로 못 박고 백로그 T7.5-02에 둔다.
13. **Airy 입력 거절 문구(D7):** `unsupported_characters` → "Airy가 읽지 못하는 글자가 있어요. 문장이나 언어 설정을 확인해 주세요", `invalid_value` → "Airy가 이 설정을 받지 않았어요. 언어와 말투를 확인해 주세요"(구현 뒤 리뷰로 바꿈: 기본값이면 '처음 값으로'가 잠겨 있다), 그 밖의 Airy 코드 → "Airy가 이 문장을 받지 않았어요. 문장이나 언어 설정을 확인해 주세요". 공급자 코드는 보이지 않는다. 새 문구라 사용자 테스트 `[confirm]`에서 확인한다.

## Global Constraints

- 커밋은 태스크마다 하지 않는다. 라운드 끝(`bts-dev-cycle` 5절)에 코디네이터가 한 번 한다. 각 태스크의 마지막 단계는 "변경 파일 목록 보고"다.
- `apps/web/.env`·`packages/db/.env`를 읽거나 출력하지 않는다. 키를 출력하지 않는다. 테스트 DB 주소는 `source .superpowers/sdd/T07.5-airy-provider-plan/tools/testdb.env`로만 넘기고 출력하지 않는다(코디네이터가 T06 `tools/testdb.env`를 이 경로로 복사해 둔다). 증거에는 "로컬 5433 `tts-pilot-app_test`"만 적는다.
- 공급자를 실제로 부르지 않는다(`api.airy.so` 포함). 자동 테스트는 `fetchMock`(`providers/test-utils.ts`)·가짜 `Providers`로만 한다. 구현 서브에이전트는 개발 서버(`127.0.0.1:3001`)로 어떤 요청도 보내지 않고, 서버를 끄거나 켜지 않는다. 유료 호출(`POST /v1/audio/speech`)은 사용자 테스트 3번에서 사용자가 승인할 때 메인 세션만 한다.
- 테스트 키 문자열은 `sk-`로 시작하지 않는다(`scripts/dev-cycle.mjs`의 비밀 패턴 `\bsk-[A-Za-z0-9_-]{20,}`, E14).

## 읽은 스킬과 계획에 반영한 것

- `tts-provider`: 공급자 호출은 모듈 하나에, 공통 계약은 `contract.ts`(화면 번들 안전). 오류는 `ProviderHttpError`로 바꿔 담고 `runCheck`·`runList`·`runTrial` 틀을 쓴다. 목록은 항목 단위 검사(`parseVoiceItems`), 모두 빠지면 `provider_error`, 샘플 호스트가 아니면 null. 유료 호출은 재시도 없음·60초·자동 테스트에서 부르지 않음. 429 `Retry-After`는 기존 대기 표가 맡는다. 문서 갱신은 Task 7.
- `bts-api`: 새 프로시저 없음. 모든 경로가 기존 `protectedProcedure`이고 소유자는 `context.ownerId`. 입력 검사는 zod(목록 입력 갈래, 설정 열거값, 성우 id 정규식, 이름·언어 상한). 격리 테스트에 Airy 한 경우(Task 3).
- `bts-db`: 검사 제약만 넓힌다. `pnpm --filter @tts-pilot-app/db db:generate`로 만들고 SQL을 읽어 `DROP TABLE`·`DROP COLUMN`·타입 축소가 없는지 본다(검사 제약은 drizzle이 DROP CONSTRAINT → ADD CONSTRAINT로 바꾼다. 기존 행은 모두 새 검사를 지난다). 로컬·테스트 DB 적용 뒤 다시 generate해 "변경 없음"을 본다. 데이터 표 설명은 `docs/domain/project.md`(Task 7).
- `bts-web`: 목록은 `useQuery(orpc.voiceList.queryOptions(...))`, 무효화는 `.key()`(접두), 캐시 쓰기는 `queryOptions().queryKey`(lessons 2026-10-07). 이번에는 캐시 쓰기가 없다. 같은 쿼리 옵션을 부모(데이터로 거르기)와 `OneList`(회복·새로 고침)가 함께 구독한다(같은 키, 요청 하나). Server Component(`casting/page.tsx`)는 공급자를 부르지 않는다(문구만 바꾼다).
- `bts-ui`: 브리프 13절과 카드 절이 기준이다. 새 시각 요소 없음. UI 태스크(4~6) 편집 직전에 `.agents/skills/impeccable/reference/craft-floor.md`를 읽는다. 리뷰(critique·audit)는 메인 세션이 한다.

	// 공식 목록과 카탈로그를 함께 부르고 id로 샘플을 붙인다. 클라이언트는 요청마다 만들어지므로(apps/web/src/context.ts)
	// 한 요청에서 목록은 한 번만 부른다(이용 가능 확인, 스펙 2절). 실패한 약속도 그 요청 안에서는 다시 쓴다
	let listing: Promise<Voice[]> | undefined;
	const allVoices = () => {
		listing ??= runList("airy", async (signal) => {
			const [body, samples] = await Promise.all([
				fetchJson(`${AIRY_HOST}/v1/voices`, auth, signal, airyCodes),
				catalog(),
			]);
			return parseVoiceItems(
				"airy",
				voicesSchema.parse(body).voices,
				rawVoiceSchema,
				(raw) => airyVoice(raw, samples.get(raw.id)),
			);
		});
		return listing;
	};

	return {
		// 매개변수는 이 공급자의 요청만 받는다(메서드 이변성, ProviderClient 주석)
		synthesize: (request: Extract<TrialRequest, { provider: "airy" }>) =>
			runTrial("airy", async (signal) => {
				const { model, language, style } = request.settings;
				const response = await fetchOk(
					`${AIRY_HOST}/v1/audio/speech`,
					{
						method: "POST",
						headers: { ...auth, "Content-Type": "application/json" },
						// 계약 필드 여섯만 서버가 만든다. trailing_silence·다른 형식은 보내지 않는다(스펙 2절)
						body: JSON.stringify({
							model,
							input: sentText(request),
							voice: request.voiceId,
							language,
							style,
							response_format: "mp3",
						}),
						signal,
					},
					airyCodes,
				);
				return new Uint8Array(await response.arrayBuffer());
			}),
		checkStatus: () =>
			runCheck("airy", async (signal) => {
				const { total_balance, tier } = balanceSchema.parse(
					await fetchJson(
						`${AIRY_HOST}/v1/credits/balance`,
						auth,
						signal,
						airyCodes,
					),
				);
				return {
					// 0 이하이면 한도 부족(Typecast와 같다, 스펙 2절)
					status: total_balance <= 0 ? "quota" : "connected",
					quota: {
						remaining: total_balance,
						total: null,
						plan: tier ?? null,
						resetAt: null,
						overageAllowed: false,
					},
				};
			}),
		listVoices: (_input: ListInputOf<"airy">) =>
			allVoices().then((voices) => ({
				voices,
				next: null,
				total: voices.length,
				totalExact: true,
				windowLimited: false,
			})),
		// 한 명 조회 호출이 없어 목록에서 찾는다(research 2절). 없으면 '현재 이용 불가'
		// ponytail: 카탈로그만 실패한 확인에서는 저장한 정보의 샘플이 비워진다(다음 확인에서 돌아온다, 백로그 T7.5-02). 자주 보이면 라우터가 이전 샘플을 남긴다
		getVoice: (_source: VoiceSource, voiceId: string) =>
			allVoices().then(
				(voices) => voices.find((voice) => voice.voiceId === voiceId) ?? null,
			),
	};
}

export function filterByNameOrId(
	voices: readonly Voice[],
	query: string,
	genders: readonly string[],
): Voice[] {
	const needle = normalize(query);
	return voices.filter(
		(voice) =>
			(needle === "" ||
				normalize(voice.name).includes(needle) ||
				voice.voiceId.toLowerCase().includes(needle)) &&
			anyOf(genders, [voice.gender]),
	);

function useOneListBundle(
	provider: "typecast" | "airy",
	search: string,
): Bundle {
	const query = useQuery(
		provider === "typecast" ? typecastListOptions : airyListOptions,
	);
	const all = query.data?.voices ?? [];
	const found =
		provider === "typecast"
			? filterVoices(all, search, EMPTY_FILTERS)
			: filterByNameOrId(all, search, []);
	return {
		provider,
		query,
		first: query.data,
		busy: query.isFetching,
		...bundleOf(found, {
			total: query.data ? found.length : null,
			totalExact: true,
			of: search === "" ? undefined : all.length,
		}),
		reload: () =>
			query
				.refetch({ cancelRefetch: false })
				.then((result) => (result.isError ? undefined : result.data)),
	};
}
