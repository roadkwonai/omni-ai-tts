## 1. 목표

`/studio`(음성 작업실)를 문단 작업실로 바꾼다. 15분 넘는 대본을 붙여 넣으면 빈 줄을 기준으로 문단 카드가 된다. 문단마다 다섯 공급자의 담은 성우·설정으로 음성을 만들고, 받을 때는 세 가지로 받는다.

- 문단 사이 쉼을 넣은 WAV 한 파일
- 문단별 파일을 담은 zip
- 문단 단위 SRT 자막

한 성우가 읽는 긴 나레이션과 문단마다 성우가 바뀌는 대본을 같은 화면에서 만든다. 대화극은 계속 드라마 작업실이 맡는다.

돈에 관해 지킬 것은 다음과 같다.
- '전체 만들기'는 확인 창 한 번으로 시작한다. 새로 만들 문단이 모두 무료면 확인 창 없이 시작한다. 단, 처리 여부 미확인 문단이 있으면 무료여도 확인 창을 띄운다(2026-10-23 계획 리뷰, 드라마와 같은 규칙).
- 같은 문단·성우·설정은 다시 만들지 않고 저장된 결과를 쓴다.
- 실패하면 거기서 멈추고 자동으로 다시 요청하지 않는다.
- 두 번 눌러도 문단마다 공급자 요청은 1회다.

## 3. 문단 모델

- **작업:** 화면의 대본 하나다. 기본 성우(성우 + 설정), 기본 쉼, 채널, 문단 목록으로 이뤄진다. GLOSSARY '문단 제작 계획'이다.
- **문단:** id, 대본 글, 문단 뒤 쉼(비면 기본 쉼), 성우와 설정으로 이뤄진다. 성우와 설정이 비면 기본 성우를 따른다. T10-b에서 역할이 더해진다.
- **실제 성우와 설정:** 문단 것을 먼저 쓰고, 없으면 (T10-b) 역할 것, 그다음 기본 성우를 쓴다. 기본을 따르는 문단에서 설정 하나를 바꾸면, 그 문단은 기본 성우의 성우와 설정을 복사해 자기 것을 갖는다. '기본 따르기'를 누르면 다시 기본으로 돌아간다.
- **문단 요청:** `{ provider, voiceId, text, settings }` 모양의 음성 생성 요청이다. 이 요청이 조합 키를 정한다(`kind = 'studio'`). 쉼은 요청에 들지 않으므로, 쉼을 바꿔도 다시 만들지 않는다.
- **문단 쉼:** 0~5초, 0.1초 단위다. 기본 쉼의 처음 값은 0.5초다(드라마 작업실은 0.3초). 마지막 문단 뒤에는 쉼을 넣지 않는다.
- **빈 문단:** 공백만 있는 문단은 만들기와 받기에서 빠진다. 작업 요약에 "빈 문단 N개 제외"로 보인다.
- **상한:**
  - 문단 수는 1~200개다. 대본을 비우면 빈 카드 1장이 남는다.
  - 문단 글은 2,000자까지이고, Airy는 1,600자까지다(공급자 상한, 2026-10-23 공식 문서 "1–1600자" 확인. T7.5 기록 1,280자에서 바뀜).
  - 상한을 넘어도 입력은 막지 않는다. 그 문단만 만들기를 막는다.
  - 붙여 넣은 글이 200개를 넘게 나뉘면 앞 200개만 넣고 나머지를 알린다. 문단 2,000자 × 200개는 화면 상한일 뿐이고, 받기의 실제 한도는 13절에서 잰다.
- **문단 상태:**
  - 빈 문단
  - 안 만듦: 지금 요청의 저장된 결과가 없다. 막는 이유가 있으면 함께 보인다.
  - 만드는 중
  - 만듦: 저장된 결과가 있다. 이번에 만든 것과 예전 것을 같게 보인다.
  - 처리 여부 미확인
  - 실패: 이번 화면에서 난 실패와 그 이유를 보인다.

  상태는 서버의 저장된 결과(`studioFindMany`)와 이번 화면의 진행으로 정한다. 문단을 고쳐 요청이 바뀌면 '안 만듦'으로 돌아간다.

## 4. 데이터와 API

### 4.1 T10-a: 마이그레이션 없음

생성 기록 표 `trial_generation`은 이미 다섯 공급자(`trial_generation_provider`)와 `kind = 'studio'`를 받는다.

**프로시저** (모두 `protectedProcedure`, 소유자는 `context.ownerId`만)

| 프로시저 | 바뀌는 것 |
|---|---|
| `studioCreate` | 요청을 다섯 공급자의 discriminated union으로 넓힌다. 설정 계약은 T5 시험 생성의 공급자별 설정 계약이고, 대본 상한은 공급자별이다(Airy 1,600자, 나머지 2,000자. Airy 상한은 코드에 없어 새 상수로 둔다). 네 공급자의 `synthesize`가 대기 시간 옵션을 받게 해 모두 180초로 부른다(지금은 Typecast만 옵션을 받고 나머지는 60초). 오디오 32MiB 상한은 지금처럼 합성 뒤 라우터에서 검사한다. 늦은 결과 저장은 지금처럼 Typecast만 받는다(`onLate`). 성우 검사는 그 소유자가 담은 같은 공급자 성우이면서 이용 불가가 아닌 것으로 한다. 순서(재생 확인 → 성우 검사 → 대기 시각 → 추정 → 선점 → 합성 → 저장)는 그대로다 |
| `studioFind` | 넓힌 요청을 받는다 |
| `studioFindMany` (새) | 요청 배열(1~200개)을 받아, 같은 순서로 `{ id, createdAt, status('done'·'unknown'), usage, bytes } | null`을 돌려준다. 오디오는 주지 않고 공급자를 부르지 않는다. 미확인도 돌려주므로 화면이 15초마다 다시 확인할 수 있다. 지금 `trial.ts`의 `findMany`는 `kind = 'trial'`과 완료만 찾고 `status`·`bytes`를 주지 않는다. kind·미확인·bytes를 받게 넓힐지 작업실용을 따로 둘지는 계획에서 정한다 |
| `studioAudio` | 그대로다. 조각의 형식은 그 기록의 오디오 형식(`audio/mpeg`·`audio/wav`)이다 |
| `studioList`·`studioDelete` | 새 화면이 쓰지 않으면 지운다. 소비자는 계획에서 확인한다. 지우면 작업실 결과는 30일 만료에만 맡긴다(2절) |

- **조합 키:** Typecast 요청의 모양(필드와 설정 계약)을 바꾸지 않는다. 그래야 T9로 만든 작업실 결과가 같은 문단·성우·설정에서 그대로 찾아진다.
- **공급자별:**
  - ElevenLabs: SDK 자동 재시도는 끈 상태를 유지한다.
  - Fish Audio: `model` 헤더로 모델을 고른다. `s2.1-pro-free`는 무료이고 확인 창이 없다(2026-11-30까지).
  - Airy: 대본 언어에 따라 요율이 다르다(한국어 1.5배).
  - Gemini: 결과가 WAV이고, 사용량은 `usd_micro` 추정이다.
  - 예상 사용량은 지금의 `estimate()`를 쓴다.
- **사용 이력:** 문단 하나가 성공하면(늦은 성공 포함) 그 성우의 `use_count`가 1 오르고 `last_used_at`이 바뀐다(T9 규칙).
- **이번에 함께 고칠 백로그:**
  - T9-02·T95-03: 실패 기록 블록과 `[trial]` 로그 접두어를 공급자를 붙이기 전에 한 곳으로 묶고, 접두어는 인자로 받는다.

## 5. 화면과 흐름

### 5.1 T10-a

배치(레일·열·막대 위치)는 브리프가 정한다. 여기서는 무엇이 있고 어떻게 움직이는지만 정한다.

- **머리:**
  - 제목 '음성 작업실'과 설명이 있다. 설명 문구는 브리프가 정한다.
  - 채널 고르기: 기본 프리셋이 있으면 T8 '불러오기' 창이 뜨고, 그 프리셋을 기본 성우에 적용한다. 이제 공급자 제한이 없다.
  - '프리셋' 메뉴: 다섯 공급자 프리셋 목록이다. 불러오면 기본 성우가 바뀐다. '지금 기본 성우로 새 프리셋 저장'과 덮어쓰기가 있다.
- **작업 설정:**
  - 기본 성우: 성우 고르기 창에서 고르고, 그 공급자 설정을 둔다.
  - 기본 쉼.
- **성우 고르기 창:** 담은 성우와 프리셋을 다섯 공급자 탭으로 보인다. 드라마 작업실 창을 재사용한다.
  - 적용 대상은 '기본 성우'이거나 '문단 N'이다. 창 머리에 대상을 보인다.
  - 프리셋을 고르면 성우와 설정이 함께 바뀐다.
  - 이용 불가 성우는 고를 수 없다.
  - 기본 샘플을 들을 수 있고, 창이 닫히면 샘플이 멈춘다.
- **대본 붙여 넣기 창:** 긴 대본을 한 번에 넣는 곳이다. 드라마 붙여넣기 창의 틀을 쓴다.
  - 넣을 방식은 '전체 바꾸기'와 '끝에 더하기' 둘이다.
  - 나뉠 문단 수를 미리 보인다. 상한 때문에 더 나뉘는 수도 포함한다.
  - 바꾸면 되돌리기 알림을 띄운다.
  - 처음 방문해 카드가 빈 카드 1장이면 이 창으로 가는 길을 눈에 띄게 둔다.
- **카드 본문에 붙여 넣기:** 빈 줄이 들어간 글을 카드 대본 칸에 붙여 넣으면 바로 나눈다. 커서 앞 글과 첫 덩어리는 지금 카드에 남고, 나머지 덩어리는 새 카드가 된다. 마지막 덩어리에는 커서 뒤 글이 붙는다. "문단 N개로 나눴어요 · 되돌리기" 알림을 띄운다. 새 카드는 지금 카드의 성우와 설정 상태(기본 따름 또는 자기 것)를 물려받는다.
- **문단 카드:**
  - 번호를 보인다.
  - 성우를 보인다. 기본을 따르면 '기본' 표시가 붙는다.
  - 기본이나 성우의 처음 값과 다른 설정은 짧은 표식으로 보인다. 모델, 감정·말투, 속도 등이다.
  - 상태와 막는 이유를 보인다.
  - ▶:
    - 만든 문단이면 무료 듣기다.
    - 안 만든 문단이면 '이 문단 만들기'다. 모양과 이름을 듣기와 다르게 하고, 유료면 `Coins`를 붙인다(T95-20 교훈).
  - '설정': 성우 바꾸기와 그 공급자 설정 칸(모델·세부 설정·감정·말투·속도, 지금의 공급자별 설정 칸 재사용)이다. '기본 따르기'가 있다.
  - 문단 뒤 쉼: 마지막 문단에는 없다.
  - 본문: 그 자리에서 편집하고 높이가 자란다. 글자 수와 상한을 보인다.
  - ⋯ 메뉴: 위로, 아래로, 아래에 문단 추가, 여기서 나누기(커서 위치), 다음 문단과 합치기, 지우기. 지우기는 되돌리기 알림을 띄운다.
- **작업 요약:** 늘 보인다.
  - 문단 수(빈 문단 N개 제외)와 글자 수.
  - 만든 문단 N/M.
  - 예상 길이: 1초 5자 가정을 쓰고 '추정'으로 표시한다.
  - 새로 만들 문단의 공급자별 예상 사용량: Typecast·ElevenLabs·Airy는 크레딧, Fish Audio는 바이트 또는 무료, Gemini는 달러 추정.
- **'전체 만들기'** (화면의 주 버튼):
  1. 누르면 `studioFindMany`로 저장된 결과를 다시 확인한다.
  2. 확인 창을 띄운다. 창에는 다음이 나온다.
     - 새로 만들 문단 수
     - 공급자별 예상 사용량과 남은 크레딧(조회되는 공급자만)
     - 저장된 결과를 쓰는 문단 수(사용량 0)
     - 미확인 문단이 있으면 중복 과금 경고(T9 `unknownRetry`)
  3. 새로 만들 문단이 모두 무료면 창 없이 시작한다. 미확인 문단이 있으면 무료여도 창을 띄운다(같은 요청 id로 보내면 서버가 늘 미확인을 돌려주기 때문).
  4. 확인하면 문단 순서대로 하나씩 `studioCreate`를 보낸다. 요청 id는 문단 요청마다 하나이고, 이 화면이 떠 있는 동안 다시 쓴다(두 번 눌러도 1회).
- **진행 중:**
  - 막대에 "28개 중 3번째 · 문단 12 · 18초"와 '멈추기'를 보인다(큐 순번과 문단 번호를 나눈다, 2026-10-23 디자인 리뷰 D9).
  - 지금 만드는 카드에 표시를 하되, 그 카드로 스크롤을 옮기지는 않는다(편집 중일 수 있다). 대신 막대 진행 줄 끝에 '문단 12 보기' 링크를 둔다.
  - 진행 중에도 편집할 수 있다. 문단은 보낼 때의 요청으로 만들어진다. 보낸 뒤 고친 문단은 결과가 와도 '안 만듦'이다.
  - '멈추기'를 누르면 지금 문단이 끝난 뒤 멈춘다. 보낸 요청은 끊지 않는다.
- **멈춤과 이어서:**
  - 실패, 미확인, 다른 생성 진행 중, 공급자 대기 시각 가운데 하나가 나면 멈춘다.
  - 그 카드에 이유를 보이고, 막대에 "문단 12에서 멈췄어요 · {이유}"와 그 문단으로 가는 링크를 보인다.
  - 주 버튼은 '이어서 만들기'가 된다. 다시 확인 창을 거치고, 만든 문단은 건너뛴다.
- **미확인:** 15초마다 `studioFindMany`로 다시 확인한다. 만든 지 6분이 지나면 멈춘다(T9 규칙). 늦게 완료되면 카드가 '만듦'으로 바뀐다.
- **문단 듣기:** 카드 ▶는 그 문단의 결과를 받아 막대 플레이어에 올리고 재생한다. 소리는 한 번에 하나다.
- **'받기' 메뉴** (막대): 항목은 '한 파일로 받기 (WAV)', '문단마다 받기 (zip)', '자막 받기 (SRT)', '이어 듣기'다.
  - 받는 동안 진행을 보인다(문단 N/M 받는 중).
  - 이미 받은 조각은 다시 받지 않는다.
  - 한 파일과 SRT는 같은 잇기 계산에서 나온다. 문단마다 앞뒤 무음을 자르고(드라마 `joinSounds`와 같다) 문단 뒤 쉼을 넣는다.
  - SRT:
    - 문단마다 큐 하나이고, 시작과 끝은 이은 파일 기준이다.
    - 글은 문단 글에서 대괄호 태그(`[whispers]`)와 꺾쇠 태그(`<sigh>`)를 뺀 것이다.
    - UTF-8로 저장하고, 시각 형식은 `HH:MM:SS,mmm`이다.
  - '이어 듣기'는 이은 WAV를 막대 플레이어에 올린다. 문단 이동과 강조는 T10-b에서 한다.
- **파일 이름:**
  - 한 파일·zip·SRT: `{첫 문단 앞 20자}_{YYYYMMDD-HHmm}.{wav|zip|srt}`
  - zip 안 파일: `{번호 3자리}_{성우 이름}_{문단 앞 20자}.{mp3|wav}`
  - 못 쓰는 글자와 공백은 `_`로 바꾼다. 시각은 받은 시각(한국 시간)이다.
- **임시 작업:** 작업 전체(기본 성우, 기본 쉼, 채널, 문단)를 바꿀 때마다 이 브라우저에 저장한다(새 키). 읽을 때 계약으로 검사하고, 성우는 담은 성우 목록에 있을 때만 되살린다. T9 임시 작업이 있으면 한 번 옮긴다(대본은 나누지 않고 문단 1장, 2절).
- **그 밖의 상태:**
  - 담은 성우 목록 로딩·실패에는 '다시 불러오기'를 둔다. 첫 로드 실패 판정은 교훈 2026-10-21을 따른다.
  - 소유자가 없으면 `LoopbackNotice`를 보인다.
  - 키 없음·인증 실패에는 '연결 상태 보기'를 둔다.

### 5.2 T10-b (요구만, 상세는 그 라운드)

- **역할 성우:**

  - 문단을 고른다(N/M, 전체 선택).
  - 고른 문단의 성우·설정·속도·쉼을 한 번에 바꾼다.
  - 고른 문단을 지운다.
  - 되돌리기는 여러 단계다.
- **감정 태그 팔레트(P0-26):** T10-a 피드백 1로 당겼다(15.1·15.2절, '태그 도구줄'). 아래는 처음 요구다.

  - 태그를 모르는 모델이면 보내기 전에 알린다.
  - Typecast 감정, Airy 스타일, Gemini 말투 지시는 설정 칸에서 바꾼다(T10-a에 있음).

- **이어 듣기 바:**
  - 전체 이어 듣기, 현재 시간과 전체 시간.
  - 이전·다음 문단으로 이동하고, 재생 중인 문단을 카드에서 강조한다.
  - 음량.
- **최근 대본:**
  - 만들기를 누른 대본을 서버에 자동으로 보관한다.
  - 최근 20개를 목록으로 보인다.
  - 열면 지금 대본을 바꾸기 전에 확인한다. 지울 수 있다.

## 9. 수용 기준 (T10-a)

1. 빈 줄로 나뉜 대본(문단 40개, 약 9,000자)을 붙여 넣기 창으로 넣으면 문단 카드 40장이 되고, 2,000자를 넘는 덩어리는 문장 끝에서 나뉜다. 되돌리기로 원래 대본이 돌아온다.
2. 기본 성우를 고르면 기본을 따르는 모든 문단이 그 성우가 된다. 한 문단의 성우·속도·감정을 바꾸면 그 문단만 바뀌고, '기본 따르기'로 돌아간다. 카드에는 기본과 다른 값만 표식으로 보인다.
3. 다섯 공급자(Typecast·ElevenLabs·Fish Audio·Airy·Gemini)의 담은 성우로 문단을 만들 수 있다. 서버는 공급자별 상한(Airy 1,600자)과 설정 계약으로 공급자 호출 없이 거절한다.
4. '전체 만들기' 확인 창이 새로 만들 문단 수, 공급자별 예상 사용량, 저장된 결과로 쓰는 문단 수를 보인다. 새로 만들 문단이 모두 Fish Audio 무료 모델이면 창 없이 시작한다(미확인 문단이 있으면 창을 띄운다).
5. 전체 만들기는 문단을 하나씩 차례로 만들고 진행 수와 지난 시간을 보인다. '멈추기'는 지금 문단 뒤에 멈춘다. 확인 버튼을 두 번 누르거나 같은 요청을 다시 보내도 문단마다 공급자 요청은 1회다.
6. 실패·미확인·다른 생성 진행 중·대기 시각이면 그 문단에서 멈추고 이유와 문단 링크를 보인다. '이어서 만들기'는 만든 문단을 건너뛰고, 미확인이 있으면 중복 과금 경고를 보인다.
7. 화면을 떠났다 돌아오면(새로 고침 포함) 문단과 설정이 남아 있고, 만든 문단은 '만듦'으로 보이며(공급자 호출 0회) 이어서 만들 수 있다.
8. 고친 문단은 '안 만듦'이 되고, 되돌리면 다시 '만듦'이 된다(공급자 호출 0회). 쉼만 바꾸면 만든 상태가 그대로다.
9. 모든 문단을 만든 뒤 '한 파일로 받기'는 문단 사이에 지정한 쉼이 들어간 WAV를, '문단마다 받기'는 번호순 파일 zip을, '자막 받기'는 각 문단의 시작·끝이 한 파일과 맞는 SRT(태그 뺀 글)를 저장한다. 받기의 공급자 호출은 0회다. 안 만든 문단이 있으면 받기가 막히고 이유와 링크가 보인다.
10. 30분 분량(문단 60개 이상)의 저장된 결과를 1440px Chrome에서 한 파일로 잇는다. 걸린 시간과 메모리를 기록하고, 60분 측정 결과를 위험 절에 적는다.
11. 작업 요약이 문단 수(빈 문단 제외), 글자 수, 만든 문단 N/M, 예상 길이(추정), 공급자별 예상 사용량을 보이고 편집에 따라 바뀐다.
12. T9 임시 작업이 있으면 성우·설정은 기본 성우로, 대본은 문단 1장으로 옮겨진다. 그 대본·성우·설정으로 T9에서 만든 결과가 '만듦'으로 찾아진다(공급자 호출 0회).
13. 드라마 작업실의 읽기·받기·성우 고르기 창이 그대로 동작한다(회귀).
14. B 소유자는 A의 작업실 결과(`studioFindMany`·`studioAudio`)를 보지 못하고(null·`NOT_FOUND`), A가 담은 성우로 만들면 거절된다(공급자 호출 0회). 소유자가 없으면 작업실 프로시저가 모두 `UNAUTHORIZED`이고 DB 접근 0회다.
15. 자동 테스트와 브라우저 QA에서 유료 호출이 0회다. 실제 생성은 사용자 테스트에서 승인 뒤에만 한다.
16. 1440·1280·1024·768·390·320px과 라이트·다크에서 가로 넘침이 없고, 키보드만으로 붙여 넣기·성우 고르기·설정·문단 메뉴·전체 만들기 확인·받기를 쓸 수 있다. 문단 200개에서 대본 칸 입력 지연을 잰다(교훈 2026-10-07).
17. 오류 예산(콘솔·개발 오버레이·`get_errors`·서버 로그)은 0이다.

## 10. 자동 테스트

- **계약(단위):**
  - 공급자별 요청: 대본 0자, 공백만, 상한, 상한 + 1(Airy 1,600·1,601, 나머지 2,000·2,001).
  - 설정 계약 밖 값.
  - Typecast 요청의 조합 키가 T9와 같다.
  - `studioFindMany`: 0개와 201개를 거절한다.
- **API(`studio.test.ts`, 테스트 DB, 가짜 공급자):**
  - 공급자마다 성공하면 기록이 완료되고 조각을 받을 수 있다.
  - Gemini 조각 형식은 WAV다.
  - 같은 요청 id → 1회.
  - 진행 중 → `in_progress`.
  - 담지 않은 성우·다른 공급자 성우·이용 불가 → 거절, 공급자 0회.
  - `studioFindMany`는 순서를 유지하고 섞인 결과(완료·미확인·없음)를 돌려주며, 공급자는 0회다.
  - 실패 기록 블록은 하나이고, 로그 접두어는 작업실이 `[studio]`다.
  - 네 공급자 모두 60초를 넘겨도 180초 전이면 미확인이 아니고, 180초를 넘기면 미확인이다(가짜 시계).
  - 사용 이력은 다섯 공급자 모두 성공 때만 오른다.
- **격리(`studio.isolation.test.ts`):** 9절 14번.
- **화면 단위(web vitest, 순수 함수):**
  - 빈 줄 나누기: 여러 빈 줄, 앞뒤 공백, CRLF, 상한 넘는 덩어리를 문장 끝에서 나누기, 문장 끝이 없는 긴 덩어리.
  - 커서 위치 붙여넣기 나누기.
  - 나누기·합치기·이동·지우기.
  - 실제 성우·설정 계산(기본 따름, 자기 것, 기본 따르기로 되돌리기).
  - 문단 요청과 상태 계산(빈 문단, 막는 이유 순서, 보낸 뒤 고친 문단).
  - 전체 만들기 대상 계산(저장된 결과 제외, 무료만이면 창 없음).
  - 공급자별 예상 사용량 합계.
  - SRT: 시각 형식, 쉼 반영, 태그 제거, 마지막 문단 뒤 쉼 없음.
  - 파일 이름.
  - 임시 작업 읽기: 깨진 값, 없는 성우, 계약 밖 설정, T9 키 옮기기.
- **잇기:** 드라마 잇기 테스트가 옮긴 뒤에도 통과한다.

## 13. 위험과 확인할 것

- **잇기 메모리:** 30분 WAV는 약 160MB이고, 잇는 동안 조각과 결과가 함께 메모리에 있다. 계획에서 조각을 하나씩 디코딩하고 바로 16비트로 줄이는 방식(드라마 `joinSounds`)과 Blob 조각 쌓기로 최고 메모리를 재고, 60분에서 실패하면 그 한도를 화면에 알린다.
- **생성 시간:** 문단 수십 개를 차례로 만들면 몇 분 걸린다. 공급자별 문단 하나의 실제 시간(특히 Gemini의 긴 문단)은 사용자 테스트로 잰다. 180초를 넘으면 미확인이 된다.
- **Gemini:** 긴 문단(2,000자, 약 6~7분)의 출력 토큰·시간 한도를 계획에서 공식 문서로 확인한다. 넘으면 Gemini만 문단 상한을 낮춘다.
- **Airy:** 상한은 2026-10-23 공식 문서(`/v1/audio/speech` input "1–1600자")로 확인했다. T7.5 기록 1,280자와 research 문서는 계획의 문서 태스크에서 고친다.
- **문단 경계:** 공급자가 문단마다 따로 읽으므로 문단 사이 억양이 끊길 수 있다. 사용자 테스트 의견으로 compose·앞뒤 문맥을 다시 본다.
- **동시 1건:** 캐스팅·드라마의 생성이 걸려 있으면 전체 만들기가 멈춘다(의도). 시간 초과로 끊긴 Typecast 요청이 동시 1건에 들지 않는 문제(T9-03)는 다중 사용자 전(T15)에 정한다.
- **조합 키 호환:** Typecast 요청 모양을 바꾸면 T9 결과를 잃는다. 계약 테스트로 고정한다.
- **화면 성능:** 문단 200장이 한 컨텍스트를 읽으면 입력이 느려진다. 자주 바뀌는 값은 작은 컨텍스트로 나눈다(교훈 2026-10-07).
- **무료 모델 종료:** Fish `s2.1-pro-free`가 2026-11-30에 끝나면 무료 문단 기록과 프리셋 표시를 다시 본다(T95-05와 같은 원인: 옛 행 계약).

## 15. 피드백 1: 태그 도구줄과 자동 태그 추천 (Part 2, 2026-10-23)

- 요청([confirm] 중 사용자): "음성 작업실에도 태그 넣을 수 있게 각 공급사별로 사용할 수 있는 태그 보고 추가할 수 있게 해주고 자동태그 추천기능도 추가해줘". 질문을 권하자 사용자가 "바로 시작해"라고 했다. 그래서 아래 결정은 Claude가 드라마 작업실(T9.5 스펙 14·17절) 방식을 기준으로 정했고, 확인은 [confirm]에서 받는다.
- 범위: 5.2의 '감정 태그 팔레트'와 '전체 자동 태그'를 T10-a로 당긴다. 5.2의 나머지(역할 성우, 일괄 바꾸기, 이어 듣기 바, 최근 대본)와 4.2는 T10-b에 그대로 둔다. DB 변경은 없다.
- 화면 상세는 [음성 작업실 브리프](../../briefs/studio.md) 15절에 있다.

### 15.1 태그 도구줄 (문단 카드)
- **위치:** 마지막으로 대본 칸에 포커스한 문단(태그 대상) 하나의 대본 칸 바로 아래. 대상이 없으면 어느 카드에도 없다. 도구줄 안에서 포커스가 움직여도 대상은 바뀌지 않는다(드라마와 같다).
- **값:** 그 문단이 보낼 요청의 공급자·모델(자기 성우, 없으면 기본 성우)로 정한 family의 값이다. 드라마와 같은 `ACTING` 카탈로그(`drama-acting.ts`)를 쓴다.

| family (공급자·모델) | 도구줄 |
|---|---|
| Fish Audio S2.1(`s2.1-pro-free`·`s2.1-pro`), ElevenLabs v4·v3 | '소리' 알약 5개 + '소리 더 보기' 메뉴 + '분위기' 메뉴. 분위기 값은 `[값]` 태그로 넣는다 |
| Gemini | '소리'(꺾쇠 `<sigh>` 등) 알약과 메뉴. 말투는 설정 칸의 '말투 지시'에서 바꾼다(도구줄에 넣지 않는다) |
| Typecast, Airy | 안내 "이 성우는 대본 태그를 읽지 않아요. 감정은 설정에서 바꿔요"(Airy는 '말투는')와 '설정에서 바꾸기'(설정 칸을 펴고 감정·말투 칸으로, 차이 칩과 같은 길) |
| ElevenLabs multilingual v2·flash v2.5 | 안내 "이 모델은 대본 태그를 읽지 않아요. 태그는 Eleven v3·v4에서 써요" |
| 성우 없음 | 도구줄 없음 |

- **넣기:** 커서 자리에 태그를 넣는다. 커서 앞 글자가 공백이 아니면 앞에, 뒤 글자가 공백이 아니면 뒤에 공백 하나를 붙인다(브리프 15.1, 수정 묶음 P2-fix). 고른 글이 있으면 고른 글의 앞에 넣고, 고른 글은 지우지 않는다. 브라우저 되돌리기(Ctrl+Z)에 남는다(`insertText`). 넣은 뒤 포커스는 대본 칸이고, 커서는 넣은 글 뒤다. 목록 밖 태그는 손으로 쓸 수 있다.
- **모양과 키보드:** 드라마 도구줄과 같다. Tab 정지가 하나이고 방향키·Home·End로 움직인다. 알약은 44px 눌림 영역이고, 767px 이하는 한 줄 가로 넘김이다. 드라마 `drama-toolbar.tsx`의 태그 알약 부분(`TagTools`·메뉴 알약)을 두 작업실이 함께 쓰는 컴포넌트로 옮긴다. 드라마 동작은 바뀌지 않는다(회귀 확인).

### 15.2 받지 않는 태그
- **태그의 모양:** 이 절의 태그는 영어 태그만이다.
  - 대괄호: `[` + 영문자로 시작하고 영문·숫자·공백·`,'-`로 된 60자 이내 + `]`
  - 꺾쇠: `<` 또는 `</` + 영문자로 시작하고 영문·공백으로 된 30자 이내 + `>`
  - 한글·줄바꿈이 든 괄호(`<삼국지>`, `[속보]`)와 떨어진 부등호(`3 < 5, 7 > 2`)는 대본 글이라 빼지 않는다. 카탈로그 값은 모두 이 모양이다.
  - 자막(SRT) 글도 같은 모양의 태그를 모두 빼고 만든다(5.1 '글은 태그를 뺀 것'). 한글 괄호 글은 자막에 남는다.
- **보낼 때 빼는 태그:** 그 family가 받지 않는 태그를 빼고 보낸다.
  - Typecast·Airy·ElevenLabs v2·flash: 모든 태그
  - Gemini: 소리 목록에 없는 태그(대괄호 모두, 목록 밖 꺾쇠)
  - Fish S2.1·ElevenLabs v3·v4: 꺾쇠 태그 모두(Fish S2.1은 쌍 태그를 읽지 않는다, [드라마 자동 연기 조사](../../research/drama-acting-tags.md))
- **공백:** 태그 앞이 공백이거나 글 처음이면 뺀 태그 바로 뒤의 공백 한 칸까지 뺀다. 단어 바로 뒤에 붙은 태그(`그래[sighs] 네가`)는 태그만 빼서 두 단어가 붙지 않게 한다(ponytail 리뷰). 다른 글자와 줄바꿈은 그대로다. 받지 않는 태그가 없는 문단의 글은 그대로라서, 저장된 결과의 조합 키가 바뀌지 않는다.
- **보낼 글이 비는 문단:** 태그만 있는 문단(Typecast 문단의 `[pause]`)은 빈 문단처럼 만들기·찾기·받기에서 빠진다. 빈 글 요청이 저장된 결과 찾기 묶음 전체를 거절시키지 않게 한다. 카드 안내는 "태그를 빼면 보낼 글이 없어요"다.
- **카드 안내:** 뺄 태그가 있으면 대본 칸 아래에 회색 줄 "이 성우가 읽지 않는 태그 N개는 빼고 보내요"(ElevenLabs v2·flash는 "이 모델이 …")를 늘 보인다. 성우나 모델을 바꿔 생긴 경우도 같다. 대상 카드의 안내 family에서는 도구줄 자리 한 줄로 합친다(브리프 15.1, 수정 묶음 P2-fix). 화면은 수만 보이므로, 태그로 보는 모양을 좁게 정했다(위 '태그의 모양').
- **글자 수와 사용량:**
  - 예상 사용량은 보낼 글(뺀 글)로 센다(요청의 글이라 지금 `estimate`가 그대로 맞다).
  - 글자 수 표시와 길이 상한은 대본 칸 글 그대로다. 보낼 글보다 길게 세므로 더 엄격하다.
- **영향:** 받지 않는 태그가 든 문단의 저장된 결과는 조합이 바뀌어 '안 만듦'으로 보인다. 전에는 그 태그를 소리 내어 읽었다.

### 15.3 자동 태그 추천
- **버튼:** '자동 태그'(`neutral` `lg`, 경고색 `Coins`, 수정 묶음 P2-fix). 작업 설정 '대본' 칸과 1단 작업 띠에서 '대본 붙여 넣기' 옆에 둔다. 접근 이름은 "자동 태그 추천, 비용 발생"이다. 보낼 문단이 없거나, 전체 만들기가 도는 중(찾기·확인·만드는 중·멈추는 중)이거나, 429 대기 시각 전이면 잠기고(`aria-disabled`), 이유를 보인다.
- **보낼 문단:** 아래를 모두 갖춘 문단이다. 성우의 family는 보낼 요청으로 정한다.
  - 대본이 있다
  - 성우가 있고 이용할 수 있다
  - 길이 상한 안이다
  - family가 태그나 감정·말투를 받는다. ElevenLabs v2·flash 문단만 빠진다.
- **나눠 보내기:** 문단 차례대로, 글자 합계 2,000자(코드 포인트)와 50문단까지를 한 번에 보낸다. 2,000자 문단은 혼자 한 번이다. 한 번은 Gemini 텍스트 호출 1회다(`gemini-3.8-flash`, 드라마 자동 태그와 같다).
- **확인 창:**
  - 제목: "대본을 보내 태그를 추천받을까요?"
  - 본문 세 줄(수정 묶음 P2-fix): "문단 N개를 한 번에 보내요"(M = 1) 또는 "문단 N개를 M번에 나눠 보내요" / 경고색 Coins + "약 $0.01" 또는 "한 번에 약 $0.01, 모두 약 ${M×0.01}" / "Gemini 텍스트 모델(gemini-3.8-flash)을 써요. 키가 무료 등급이면 Google이 보낸 대본을 학습에 쓸 수 있어요"
  - 버튼: '취소'(첫 포커스)와 `Coins` '추천 받기'.
- **보내는 중:**
  - 차례대로 보내고, 자동 재시도는 없다. '추천 받기' 자리에 스피너와 "추천 받는 중 2/5"를 보인다.
  - '취소'는 '멈추기'가 된다. 누르면 지금 호출이 끝난 뒤 다음을 보내지 않는다.
  - 실패하면 거기서 멈춘다.
  - 받은 묶음이 하나라도 있으면 미리 보기를 열고, 안내 줄에 멈춘 이유를 적는다("문단 N부터 멈췄어요 · 이유" 또는 "문단 N부터는 보내지 않았어요").
  - 받은 묶음이 없으면 확인 창에 이유를 보인다(드라마와 같다). 429는 대기 시각을 보이고, 그 시각까지 '추천 받기'와 '자동 태그'를 잠근다. 실패 문구는 '추천'으로 쓰고, 비용이 들었을 수 있는 실패(답 형식 오류·처리 여부 미확인)에는 다시 하라고 하지 않는다.
- **서버 검사:** 서버가 문단마다 검사하고, 어긴 부분은 원래 값으로 둔다.
  - **대본:**
    - 태그를 뺀 글이 원래와 같아야 한다. 줄바꿈은 그대로여야 하고, 연속 공백의 길이 차이(태그 둘레 포함)는 허용한다. 원래 태그는 모두 남아야 한다.
    - 새 태그는 그 family의 '소리' 값만 받는다. Fish S2.1·ElevenLabs v3·v4는 '분위기' 값 `[값]`도 받는다.
    - 새 태그 수는 문단마다 max(2, ⌈태그 뺀 글자 수 ÷ 100⌉)개까지다.
    - 제안 글 전체(태그 포함)가 공급자 상한 안이어야 한다. 화면의 길이 상한(15.2)과 같은 기준이라 적용 뒤 '길이 초과'로 막히지 않는다.
  - **Gemini 말투 지시:** 목록 값이거나 짧은 영어 문구(`freePhraseOk`)여야 한다. 받으면 문단 설정 `direction`(100자)이 된다.
  - **Typecast 감정:** 그 성우·모델이 받는 값이다(v30은 `smart` 포함). 강도는 0.5·1·1.5·2다. 받으면 문단 설정이 된다.
  - **Airy 말투:** 4값 가운데 하나다. 받으면 문단 설정이 된다.
- **미리 보기 창 "자동 태그 추천":**
  - 바뀐 문단만 보인다. 머리 줄은 '문단 N · 성우 이름'이다. '대본'은 바꾼 뒤 글만 보이고 새 태그를 표시하며, 긴 글은 새 태그 둘레만 발췌한다. '감정'·'말투'·'말투 지시'는 전(줄 긋기 회색)과 후를 보인다(수정 묶음 P2-fix, critique P1). 머리와 버튼 줄은 고정하고 목록만 스크롤한다.
  - 문단마다 체크 상자가 있고 처음에는 켜져 있다. 이미 만든 결과가 있는 문단과 처리 여부 미확인 문단은 꺼져 있고, 안내 "만든 결과가 있어요. 바꾸면 다시 만들어야 해요" 또는 "처리 여부를 확인하지 못한 문단이에요. 바꾸면 다시 만들어야 해요"를 단다.
  - 고른 문단 가운데 기본 성우를 따르던 문단에 감정·말투·말투 지시 제안이 있으면, 버튼 위에 "감정·말투를 바꾼 문단 N개는 이제 기본 성우를 따르지 않아요"를 보인다.
  - 창 안내 줄은 세 가지다.
    - 바꿀 것이 없을 때: "추천할 태그가 없어요"
    - 건너뛴 문단이 있을 때: "태그를 받지 않는 문단 N개는 그대로 둬요"
    - 멈췄을 때: 멈춘 이유
  - 버튼은 '닫기'(첫 포커스)와 '고른 문단 바꾸기 (N)'이다. 고른 문단이 없으면 '고른 문단 바꾸기'가 잠긴다.
- **바꾸기:**
  - 보낸 뒤 고친 문단(글·성우·설정)과 지운 문단은 건너뛰고, 그 수를 알린다.
  - 감정·말투·말투 지시 제안은 그 문단의 설정을 바꾼다. 카드 설정 칸에서 바꿀 때와 같은 길(`ownSettings`)이다. 기본 성우를 따르던 문단은 기본 성우와 그 설정을 복사한 이 문단만의 성우가 된다. 그래서 차이 칩과 진한 성우 이름으로 보이고, '기본 따르기'로 되돌린다. 그 뒤 기본 성우·프리셋·채널을 바꿔도 이 문단은 따라가지 않는다.
  - 바꾼 것은 되돌리기 한 번으로 모두 되돌린다(문단 작업실 되돌리기 알림, 10초).
- **서버:** 새 프로시저 `studioAutoTag`를 둔다.
  - `protectedProcedure`이고 DB를 쓰지 않는다(기록·대기 시각 표 없음, 429는 화면에만 알린다).
  - 입력은 `{ paragraphs: [{ provider, model, emotions, text, direction, feel? }] }`이다.
    - 1~50개다. 모델은 그 공급자의 작업실 모델 열거형이고, 글은 공급자 상한까지, 합계는 2,000자까지다.
    - `direction`은 Gemini 문단의 지금 말투 지시이고, 다른 공급자는 빈 글이다.
    - `feel`은 Typecast 감정·강도 또는 Airy 말투다.
  - 출력은 `{ paragraphs: [{ text, direction, feel? }], skipped }`이고, 입력과 같은 수다.
  - 받을 문단이 없으면 공급자를 부르지 않는다.
  - 드라마 `dramaAutoTag`와 같은 Gemini 호출(`suggestActing`)과 검사 부품(`feelOf`·`freePhraseOk`·`tagSent`)을 쓴다.

### 15.5 수용 기준
1. Fish S2.1·ElevenLabs v3·v4 문단의 대본 칸에 포커스하면 그 아래에 '소리'·'분위기' 도구줄이 보인다. 알약을 누르면 커서 자리에 태그와 공백이 들어가고, Ctrl+Z로 되돌릴 수 있다.
2. Gemini 문단에서는 꺾쇠 소리 태그가 보인다. Typecast·Airy·ElevenLabs v2·flash 문단에서는 안내가 보이고, '설정에서 바꾸기'가 감정·말투 칸으로 간다.
3. 받지 않는 태그가 든 문단은 안내 줄을 보이고, 보낸 요청 글에 그 태그가 없다.
4. '자동 태그' 확인 창이 문단 수와 보낼 횟수를 말하고, 확인 전에는 `studioAutoTag`를 부르지 않는다.
5. 미리 보기에서 고른 문단만 바뀐다. 만든 결과가 있는 문단은 처음에 꺼져 있다. 되돌리기 한 번으로 모두 돌아간다.
6. 서버는 허용 밖 태그, 글 바뀜(줄바꿈 포함), 원래 태그 빠짐, 상한 넘김, 성우가 받지 않는 감정을 원래 값으로 돌린다.
7. 드라마 도구줄은 전처럼 동작한다.
8. 태그만 있는 Typecast 문단은 빈 문단처럼 빠지고, 다른 문단의 저장된 결과 찾기는 성공한다. `<삼국지>`·`[속보]`가 든 Typecast 문단은 그 글을 그대로 보낸다.

### 15.6 자동 테스트

- **API(라우터):**
  - 소유자가 없으면 `UNAUTHORIZED`이고 공급자 호출이 0회다.
  - 키가 없으면 `no_key`다.

  - index가 없거나 겹치면 첫 제안만 쓰고 나머지는 원래 값이다.

## 16. 피드백 2: 자동 태그를 OpenAI로, Gemini는 보조 (Part 3, 2026-10-23)
- **원인:** 사용자 테스트에서 '추천 받기'(문단 1개)가 "추천 답을 받지 못했어요. 비용이 들었을 수 있어요"로 끝났다. 개발 서버 로그에는 `studioAutoTag`가 두 번 `504 in 60s`(`[rpc] GATEWAY_TIMEOUT gemini unknown_outcome`)로 남았다. Gemini 텍스트 모델(`gemini-3.8-flash`)이 60초(`AUTO_TAG_TIMEOUT_MS`) 안에 답하지 않았다. 10월 22일 드라마 실호출 때도 503(high demand)이 두 번 났고, 같은 요청 모양이 그날 200(9.8초)이었다. 그래서 요청 모양이 아니라 Gemini 쪽 지연으로 본다. 재현은 유료라 하지 않았다.
- **사용자 결정(2026-10-23):**
  - 자동 태그 텍스트 모델을 OpenAI `gpt-6-luna`로 바꾼다. 요청한 `gpt-6.1-luna`는 OpenAI 모델 목록에 없어서 사용자가 `gpt-6-luna`를 골랐다.
  - 드라마 '전체 자동 태그'(`dramaAutoTag`)도 함께 바꾼다.
  - Gemini는 보조다. "OpenAI가 3번 정도 실패하면 Gemini로 시도"한다.

### 16.1 호출 순서 (서버 `askSuggestions` 한 곳, 두 작업실이 같이 쓴다)
한 묶음(`studioAutoTag` 한 번, `dramaAutoTag` 한 번)마다 아래 순서로 부른다.
1. OpenAI 키가 있으면 OpenAI를 최대 3번 부른다. 답을 읽어 형식이 맞으면 끝난다.
2. OpenAI 실패는 둘로 나눈다.
   - 다시 부르는 실패: 시간 초과·연결 끊김(`unknown_outcome`), 429(`rate_limit`), 5xx(`provider_error`), 답 형식 오류(`auto_tag_reply`)
   - 다시 불러도 같은 실패(남은 OpenAI 시도를 건너뛴다): 키·권한·결제·한도(`provider_auth`·`no_permission`·`quota`), 요청 거절(`provider_input`)
   - 시도 사이에 기다리지 않는다. 429의 `Retry-After`도 따르지 않는다(429는 과금되지 않는다).
3. OpenAI가 끝내 실패했거나 OpenAI 키가 없으면, Gemini 키가 있을 때 Gemini를 한 번 부른다. 지금 호출 그대로다(60초).
4. 모두 실패하면 마지막 실패를 던진다. Gemini를 불렀으면 Gemini의 오류다. 둘 다 키가 없으면 `no_key`다.
- 실패한 OpenAI 시도는 서버 로그에 한 줄씩 남긴다(`[autoTag] openai 실패 n/3 <사유>`, 깨진 답이면 사유 자리에 `auto_tag_reply`). OpenAI 키가 없어 Gemini로 가면 `[autoTag] openai 키 없음, gemini로`를 남긴다. 대본·답 글은 남기지 않는다.
- **돈:** 한 묶음의 유료 호출은 최대 4번(OpenAI 3 + Gemini 1)이다. 처리 여부 미확인(시간 초과)도 다시 부르므로 과금이 겹칠 수 있다. 이것은 사용자 결정에 따른 tts-provider "유료 호출은 자동으로 다시 하지 않는다"의 예외이고, 자동 태그 텍스트 호출에만 해당한다(ADR 0008). 화면은 지금처럼 실패한 묶음을 다시 보내지 않는다.

### 16.2 OpenAI 호출 (`providers/openai.ts`)
- **요청:** `POST https://api.openai.com/v1/responses`를 `fetch`로 직접 부른다(`fetchOk`, `redirect: "error"`). 키는 `Authorization: Bearer` 헤더다. SDK는 쓰지 않는다.
- **본문:**
  ```json
  { "model": "gpt-6-luna", "instructions": "<system>", "input": "<input>",
    "text": { "format": { "type": "json_schema", "name": "auto_tags", "schema": "<replySchemaOf>", "strict": true } },
    "reasoning": { "effort": "low" }, "max_output_tokens": 8192, "store": false }
  ```
  - `schema`는 지금 `replySchemaOf` 그대로다. strict 조건(루트 object, 모든 칸 `required`, `additionalProperties: false`)을 이미 지키고, `minItems`·`maxItems`·`anyOf`·`enum`도 지원 목록에 있다(공식 Structured Outputs 문서, 2026-10-23).
- **답 글:** `output[]`에서 `type: "message"`인 항목의 `content[]` 가운데 `type: "output_text"`의 `text`를 잇는다. 없으면(거절 `refusal` 포함) `null`이고, 서버가 `auto_tag_reply`로 본다. 모양을 읽지 못하면 처리 여부 미확인이다.
- **시간 제한:** 시도마다 45초(`OPENAI_AUTO_TAG_TIMEOUT_MS`)다. 한 묶음은 최악 3 × 45 + 60 = 195초다.
- **오류:** 상태 코드는 `reasonFromHttp`로 판정한다. 오류 본문 `{ error: { code, type } }`의 `code`·`type`을 공급자 오류 코드로 넘긴다. 429 + `insufficient_quota`는 `quota`다(`reasonFromHttp`에 한 줄 더한다).
- **키:** `OPENAI_API_KEY`(`apps/web/.env.schema`, `@optional @sensitive`, `turbo.json` `globalEnv`)다. 다른 공급자처럼 소유자가 있는 요청에만 클라이언트를 만든다. OpenAI는 TTS 공급자가 아니라서 `ProviderId`에 넣지 않는다. `Providers`에 텍스트 전용 칸 `openai`(`suggestActing`만)를 둔다.
- **오류 data:** OpenAI 오류의 `provider`는 `"openai"`다(rpc 로그 한 줄에 남는다). 마지막 실패가 OpenAI의 키·권한·결제·한도 문제이거나 둘 다 키가 없으면 `providerCode: "openai_account"`를 붙인다.
- **값의 근거(공식 문서, 2026-10-23):**
  - `gpt-6-luna`: Luna 계열 가운데 가장 빠르고 싸다. 1M 토큰당 입력 $0.10, 출력 $0.50이다.
  - Responses·Structured Outputs를 지원한다. `reasoning.effort`는 none~max이고 기본값은 medium이다.

  - `openai_account`이면 두 작업실 모두 "OpenAI 키(OPENAI_API_KEY)나 결제·한도를 확인해 주세요"를 보인다.
  - 입력 거절(`provider_input`, `auto_tag_reply` 아님)은 공급자와 상관없이 '받지 못함'(failed) 문구다. 화면은 OpenAI·Gemini를 구분하지 못하고, 기존 Gemini 입력 거절 문구는 TTS 문장용이다(계획 리뷰 medium 3).
  - 나머지는 지금 그대로다.
- 15.3의 "자동 재시도는 없다"는 화면 기준으로 그대로다. 15.4의 '실패한 묶음 자동 다시 보내기' 행도 그대로다(화면이 다시 보내지 않는다). 서버 안 다시 부르기는 16.1이다.

### 16.4 만들지 않는 것 (ponytail)
| 뺀 것 | 다시 넣을 때 |
|---|---|
| OpenAI SDK(`openai` 패키지) | 도구 호출·스트리밍이 필요할 때 |

### 16.5 자동 테스트
- **`openai.ts`:**
  - 요청 본문(모델, `strict: true`, `store: false`, `Authorization`, `redirect: "error"`)
  - 답 글 잇기와 `refusal` → `null`
  - 429 `insufficient_quota` → `quota`, 401 → `provider_auth`
  - 45초 시간 초과 → `unknown_outcome`
- **`askSuggestions`(라우터로):**
  - OpenAI 첫 시도에 성공하면 Gemini는 0회다.
  - OpenAI 두 번 실패(`unknown_outcome`, 깨진 답) 뒤 성공하면 OpenAI 3회, Gemini 0회다.
  - OpenAI 3번 실패하면 Gemini 1회이고 Gemini 제안을 쓴다.
  - OpenAI `provider_auth`면 OpenAI 1회 뒤 Gemini 1회다.
  - OpenAI 키가 없으면 Gemini만 부른다(지금 테스트 그대로).
  - Gemini 키가 없고 OpenAI가 3번 실패하면 마지막 OpenAI 오류다. 키·결제 실패는 `openai_account`다.
  - 둘 다 키가 없으면 `no_key` + `openai_account`이고 공급자 호출은 0회다.
- **화면:** `autoTagProblemText`의 `openai_account`, 확인 창 문구(두 작업실)

### 16.6 사용자 테스트 (15.8을 바꾼다)
- 15.8의 2: '자동 태그'로 추천을 받아 고른 문단만 바꾼다. 유료 OpenAI 텍스트 호출이다(묶음마다 1~3회 + 실패하면 Gemini 1회, 한 번 약 $0.01). 사용자가 직접 누른다.
- 개발 서버 로그에 `[autoTag] openai 실패`와 `[autoTag] openai 키 없음` 두 줄이 모두 없으면 OpenAI로 받은 것이다.
- 드라마 '전체 자동 태그'도 한 번 눌러 본다(선택).
