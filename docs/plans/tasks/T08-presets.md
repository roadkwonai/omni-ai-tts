## 1. 목표

성우 캐스팅의 '내 문장 듣기'에서 맞춘 성우·모델·설정에 이름을 붙여 저장하고, 같은 공급자의 다른 성우나 다음 방문에 불러와 같은 설정으로 듣는다. 지금은 화면을 떠나면 설정이 처음 값으로 돌아간다(T5). 채널마다 기본 프리셋을 하나 정해 둔다.

뒤 TASK가 그대로 쓸 것을 만든다.
- `voice_preset` 표와 프리셋 목록. 작업실(T9)이 채널을 고르면 그 채널의 기본 프리셋을, '프리셋 불러오기'로 프리셋의 성우와 설정을 한 번에 적용한다.
- 교정 모드(T11)와 내 보이스(T13)가 프리셋에 붙는다.

## 3. 데이터와 API

**테이블** (`packages/db/src/schema/preset.ts`)

| 표 | 컬럼 | 제약 |
|---|---|---|
| `voice_preset` | `id` uuid, `owner_id` text, `name` text, `provider` text(다섯 공급자 check), `saved_voice_id` uuid null → `saved_voice.id` `on delete set null`, `settings` jsonb(그 공급자 설정 전체, 모델 포함), `channel_id` uuid null → `channel.id` `on delete set null`, `created_at`, `updated_at` timestamptz 기본 now | 유니크 인덱스 `(owner_id, lower(name))`. 인덱스 `saved_voice_id`, `channel_id`(외래 키 컬럼은 자동 인덱스가 없다) |
| `channel_default_preset` | `channel_id` uuid 기본 키 → `channel.id` cascade, `preset_id` uuid → `voice_preset.id` cascade | 인덱스 `preset_id` |

- `user` 외래 키는 걸지 않는다(ADR 0004와 같다, T14에서 정한다).
- 프리셋의 공급자와 담은 성우의 공급자가 같은지, 기본 프리셋의 채널이 그 프리셋의 채널인지는 프로시저가 지킨다(같은 트랜잭션 안에서 검사하고 쓴다).
- `settings`는 쓸 때 `trial-contract.ts`의 공급자별 설정 스키마(`typecastSettingsSchema` 등)로 검사하고 정리한 값을 저장한다.

**프로시저** (모두 `protectedProcedure`, 소유자는 `context.ownerId`만. 평평한 이름 + 접두어 관례)

| 프로시저 | 입력 | 하는 일 |
|---|---|---|
| `presetList` | 없음 | 이 소유자의 프리셋 전부(서버는 정렬하지 않고 화면이 T6 `byName`으로 이름순). 한 줄: `{ id, name, provider, savedVoiceId, voice(담은 성우의 Voice 또는 null), unavailable, channelId, channelDefault, settings(쓸 수 없는 값을 처음 값으로 바꾼 것), fixed(바꾼 항목 이름들) }` |
| `presetCreate` | `{ name, channelId, channelDefault, voice, settings }`(`settings`는 공급자 구분 합집합, `voice.provider`와 같아야 함) | 한 트랜잭션에서 성우를 보관함에 담고(T7 `upsert`, 즐겨찾기·자주 사용은 그대로) 프리셋을 만든다. `channelDefault`면 그 채널의 기본을 이 프리셋으로 바꾼다. 만든 한 줄을 돌려준다 |
| `presetOverwrite` | `{ id, voice, settings }` | 한 트랜잭션에서 성우를 담고 프리셋의 성우·설정을 바꾼다. 공급자가 프리셋과 다르면 `BAD_REQUEST` |
| `presetUpdate` | `{ id, name, channelId, channelDefault }` | 이름·채널·채널 기본을 바꾼다. 채널이 바뀌거나 `channelDefault`가 false면 이 프리셋의 기본 지정을 지운다. `channelDefault`인데 `channelId`가 null이면 `BAD_REQUEST` |
| `presetDuplicate` | `{ id }` | 같은 공급자·성우·설정·채널로 새 프리셋을 만든다. 이름은 '{이름} 사본'(있으면 '사본 2', '사본 3'…, 40자를 넘으면 앞 이름을 줄인다), 채널 기본은 아니다 |
| `presetRemove` | `{ id }` | 지운다(기본 지정도 함께 지워짐). `{ deleted: true }` |

- 없는 id·남의 프리셋·남의 채널은 모두 `NOT_FOUND`(구분하지 않음)이고 아무것도 바꾸지 않는다.
- 이름 중복은 조회가 아니라 유니크 인덱스가 막고 `CONFLICT`가 된다(동시 저장 포함, T6과 같다).
- 공급자를 부르지 않는다. 무료 호출도 없고 로컬 DB만 쓴다.
- 성우 보관함의 '프리셋' 보기와 '보관함에서 빼기' 확인 창의 프리셋 수는 화면이 `presetList`로 센다. 보관함 프로시저(`savedVoice*`)는 바꾸지 않는다.

## 4. 화면과 흐름

**성우 캐스팅 `/casting` — '내 문장 듣기' 칸**
- 칸 머리의 '처음 값으로' 옆에 '프리셋' 메뉴 버튼(44px)을 둔다. 메뉴:
  - 이 공급자의 프리셋 목록(이름순, 이름과 회색 '저장할 때 성우 {이름}'). 없으면 "이 공급자 프리셋이 아직 없어요".
  - '지금 설정으로 새 프리셋 저장'.
  - 이 칸에 불러온(또는 방금 저장한) 프리셋이 있으면 "‘{이름}’에 지금 성우·설정 덮어쓰기".
  - 끝에 '프리셋 관리'(`/presets`).
- 메뉴를 열 때마다 목록을 다시 받는다. 받아 둔 목록이 없으면 목록 자리에 진행 표시, 있으면 받아 둔 목록을 그대로 보이고(다시 받는 동안 항목이 움직이지 않게) '불러오기' 때 최신 목록으로 다시 확인한다(U2). 받지 못하면 한 줄과 '다시 받기'. 저장 항목은 늘 누를 수 있다.
- **새로 저장:** 창 머리 아래에 무엇이 저장되는지 두 줄('{공급자} · {성우 이름} · {설정 요약}', "이 성우는 성우 보관함에도 담겨요"). 이름(필수, 'N / 40자')·채널(선택, 채널 목록 드롭다운, '채널 없음'이 맨 위)·'이 채널의 기본 프리셋으로'(채널을 골랐을 때만 켜짐, 꺼져 있으면 이유 한 줄. 채널을 바꾸면 체크가 풀린다) 체크. '저장하기'·'취소'. 저장 중에는 버튼이 잠긴다(두 번 눌러도 1회). 이름 중복이면 칸 아래 "같은 이름의 프리셋이 있어요". 성공하면 알림 "‘{이름}’ 프리셋을 저장했어요."
- **불러오기:** 목록에서 프리셋을 고르면 확인 창을 띄운다.
  - 바뀌는 값만 "속도 1.0 → 1.1", "모델 ssfm-v21 → ssfm-v30"처럼 보인다(이름은 옵션 칸과 같은 이름). 바뀌는 값이 없으면 "지금 설정과 같아요".
  - 지금 성우가 받지 못해 요청에서 달라지는 값은 따로 한 줄씩 알린다(예: "모델 ssfm-v30 → ssfm-v21 (이 성우에서 쓰는 값)". 계산은 기존 `requestOf`의 성우 맞춤 그대로).
  - 프리셋의 성우가 지금 성우와 다르면 "저장할 때 성우: {이름}", 성우가 비었으면 "프리셋의 성우가 보관함에서 빠졌어요".
  - 프리셋에 쓸 수 없는 값이 있었으면(`fixed`) "{항목}은 지금 쓸 수 없어 처음 값으로 불러와요".
  - '불러오기'·'취소'. '불러오기'는 최신 목록에서 그 프리셋을 한 번 더 찾고(U2), 있으면 그 공급자 설정이 바뀌고 옵션 칸이 새 값으로 다시 그려진다. 알림 "‘{이름}’ 설정을 불러왔어요."
- **불러온 프리셋 표시:** 칸 머리 아래 회색 한 줄 "프리셋 ‘{이름}’". 설정이 그 프리셋과 달라지면 " · 바뀐 값 있음". '처음 값으로'를 누르면 표시가 사라진다. 이 기억은 설정처럼 공급자마다 하나이고 화면을 떠나면 사라진다.
- **덮어쓰기:** 확인 창 "‘{이름}’ 프리셋을 지금 성우·설정으로 바꿀까요?"와 바뀌는 값('성우 A → B'와 설정 값). '덮어쓰기'·'취소'. 성공하면 알림.
- 자리는 브리프 5절 5번 '프리셋 자리'다. 칸 안 배치와 메뉴 모양은 화면 브리프에서 정한다.

**`/presets` 프리셋 (새 화면)**
- **페이지 머리:** 제목 '프리셋', 설명 한 줄(문구는 브리프).
- **목록:** 프리셋마다 한 줄. 이름, '{공급자} · {성우 이름}', 채널 이름(기본이면 '기본' 배지), 설정 요약 한 줄(모델, 처음 값과 다른 값만), 상태 배지('현재 이용 불가', '성우를 다시 골라 주세요', '처음 값으로 바뀐 값 있음'). 배치(한 목록 또는 채널별 묶음)는 브리프에서 정한다.
- **줄 동작:** '고치기'(창: 이름·채널·채널 기본, '저장하기'), '복제'(바로 만들고 알림), '지우기'(확인 창 "‘{이름}’ 프리셋을 지울까요? 이미 만든 내 문장 결과는 그대로 남아요." '취소'·'지우기'). 채널 기본으로 바꾸면 같은 채널의 이전 기본은 풀린다(창에 "지금 기본: {이름}"을 알린다).
- 화면 위 안내 한 줄: "설정 값은 성우 캐스팅의 '내 문장 듣기'에서 불러와 고친 뒤 덮어써요." '성우 캐스팅' 링크.
- **빈 상태:** "아직 프리셋이 없어요" + "성우 캐스팅의 '내 문장 듣기'에서 지금 설정을 프리셋으로 저장할 수 있어요" + '성우 캐스팅으로'(화살표 아이콘).
- **그 밖의 상태:** 로딩(뼈대)·목록 오류('다시 불러오기')·소유자 없음(`LoopbackNotice` "이 주소에서는 프리셋을 쓸 수 없어요")은 T6·T7 문법.

**`/voices` 성우 보관함**
- '보기'가 '전체·즐겨찾기·자주 사용·프리셋' 네 칸이 된다. '프리셋'은 프리셋에 쓰는 성우만 보인다. 주소 쿼리 `view=preset`. 프리셋 목록을 받는 중·실패면 '프리셋' 보기의 상태 줄에 진행·사유가 붙는다.
- '보관함에서 빼기' 확인 창(캐스팅·보관함 공통 담기 칸)에, 이 성우를 쓰는 프리셋이 있으면 "이 성우를 쓰는 프리셋 N개는 성우를 다시 골라야 해요."를 더한다. 빼면 프리셋 목록을 다시 받는다.

**앱 틀**
- 메뉴 '프리셋'을 '준비 중'에서 열린 화면으로 옮긴다(`/presets`, 아이콘 그대로, `bar: false`, '성우 보관함' 바로 뒤). 휴대폰 위 막대 4칸은 그대로다.
- 사이트맵 '준비 중'에서 프리셋을 지우고 페이지 표에 `/presets` 행을 더한다.

## 8. 수용 기준

1. 캐스팅에서 지금 성우·설정으로 프리셋을 저장하면 `/presets`에 보이고 그 성우가 보관함에 담긴다(즐겨찾기·자주 사용은 그대로). 새로 고침 뒤에도 남는다. 저장되는 값은 화면에서 들은 값이다(v21만 있는 Typecast 성우면 ssfm-v21·감정 직접, U1).
2. 같은 공급자의 다른 성우에서 프리셋을 불러오면 확인 창에 바뀌는 값과 이 성우에서 달라지는 값이 보이고, 불러오면 옵션 칸이 프리셋 설정이 된다.
3. 다음 방문(새로 고침)에 같은 성우로 불러와 들으면 그 설정으로 만든 저장된 결과가 있을 때 공급자 호출 0회로 재생된다(T5 조합 키가 같다).
4. 덮어쓰기는 프리셋의 성우와 설정을 지금 것으로 바꾼다. 다른 공급자 설정으로 덮어쓰기는 거절된다.
5. `/presets`에서 이름·채널·채널 기본 고치기, 복제('사본'), 지우기가 된다. 이름 중복(대소문자 무시)은 저장되지 않고 이유가 보인다.
6. 채널 기본 프리셋은 채널마다 하나다. 다른 프리셋을 기본으로 하면 이전 기본이 풀린다. 프리셋의 채널을 바꾸면 이전 채널의 기본이 풀린다. 채널을 지우면 프리셋은 남고 채널과 기본만 풀린다.
7. 보관함에서 프리셋의 성우를 빼면 확인 창에 프리셋 수가 보이고, 프리셋에 '성우를 다시 골라 주세요'가 붙는다. 그 프리셋도 불러오기는 된다. 덮어쓰기로 다시 성우가 붙는다.
8. 보관함의 '프리셋' 보기는 프리셋에 쓰는 성우만 보이고 주소를 새로 고쳐도 남는다.
9. 저장된 설정에 지금 계약이 받지 않는 값(없어진 모델, 범위 밖 값)이 있으면 그 값만 처음 값으로 불러오고 무엇이 바뀌었는지 알린다.
10. 프리셋을 지워도 내 문장 결과 목록과 저장된 결과 재생은 그대로다.
11. B 소유자는 A의 프리셋을 보지 못한다. A의 프리셋 id로 고치기·덮어쓰기·복제·지우기, A의 채널 id로 저장은 `NOT_FOUND`이고 A의 행은 그대로다. 소유자가 없으면 프로시저 6개가 `UNAUTHORIZED`이고 DB 접근 0회다.
12. 자동 테스트·브라우저 QA에서 유료 호출(생성·시험 생성·클론)이 0회다.
13. 1440·1280·1024·768·390·320px, 라이트·다크에서 가로 넘침이 없고(긴 프리셋 이름 포함), 키보드만으로 메뉴·창·`/presets` 동작을 쓸 수 있다.
14. 오류 예산(콘솔·개발 오버레이·`get_errors`·서버 로그) 0.

## 9. 자동 테스트

- **API(`preset.test.ts`, 테스트 DB):** 만들기 왕복(성우가 보관함에 담기고 이미 담긴 성우의 즐겨찾기·메모는 그대로), 이름 정리·40/41자·대소문자 중복 `CONFLICT`, 동시 같은 이름 두 번 → 한 행. 덮어쓰기(성우·설정 바뀜, 다른 공급자 `BAD_REQUEST`, 성우가 빠진 프리셋에 다시 붙음). 고치기(채널 바꾸면 기본 풀림, `channelDefault` + 채널 null `BAD_REQUEST`). 채널 기본 하나(두 번째 지정이 첫째를 풀음). 채널 지우기 → 프리셋 남고 `channel_id` null·기본 줄 없음. 보관함 빼기 → `saved_voice_id` null. 복제 이름('사본', '사본 2', 40자 줄이기). 지우기 → 기본 줄도 없음. 지워도 `trial_generation` 행 그대로.
- **저장 값(단위):** v21만 있는 Typecast 성우와 처음 값으로 저장 값을 만들면 `model: ssfm-v21`, `emotion: preset`이다(U1). 성우 맞춤이 없는 공급자는 설정 그대로다.
- **설정 읽기(단위):** 공급자마다 정상 값은 그대로, 없어진 모델·범위 밖 값·Typecast v21에 v21에 없는 감정 → 그 값만 처음 값이고 `fixed`에 항목 이름. 모르는 필드는 버리고 빠진 필드는 처음 값이다(둘 다 `fixed`에 넣지 않는다).
- **격리(`preset.isolation.test.ts`):** 8절 11번.
- **화면 단위(web vitest):** 바뀌는 값 비교(같음, 몇 개 다름, 성우 맞춤으로 달라지는 값), 설정 요약(처음 값과 다른 값만), `view=preset` 필터와 쿼리 변환, 빼기 문구의 프리셋 수.

## 11. 사용자 테스트 절차 (구현 뒤 드린다)

## 12. 위험과 확인할 것

- 설정 계약이 바뀌면(모델 추가·종료) 옛 프리셋은 읽을 때 처음 값으로 바뀐다. 저장 값은 덮어쓰기 전까지 그대로라 계약을 되돌리면 원래 값이 다시 보인다.
- Fish Audio 무료 모델은 2026-11-30 뒤 요청에서 `s2.1-pro`로 바뀐다(`requestOf`). 그 뒤 무료 모델 프리셋을 불러오면 비교 창의 성우 맞춤 줄로 알린다. `/presets` 요약은 저장 값 그대로라 무료 모델로 보인다(T9 메모).
- 캐스팅 '내 문장 듣기' 칸이 길어진다. 서랍(1199px 이하)·390px에서 메뉴와 창이 바닥 줄(sticky)과 겹치지 않는지 본다.
