## 1. 목표

Airy(airy.so)를 네 번째 공급자로 더한다. 지금까지 만든 기능 네 곳에서 Airy를 다른 공급자와 같은 방식으로 쓴다.

1. **연결 상태**: Airy 카드가 연결 여부와 남은 크레딧을 보인다.
2. **성우 캐스팅**: Airy 탭과 '전체' 탭의 Airy 묶음에서 성우를 찾고 기본 샘플(한국어·영어)을 듣는다.
3. **내 문장 듣기**: Airy 성우로 내 문장을 언어·말투를 골라 들어 본다. 유료라서 예상 크레딧을 확인한 뒤 만든다.
4. **성우 보관함**: Airy 성우를 담고 분류를 붙이며, 이용 가능 확인이 Airy 성우도 본다.

## 3. 데이터와 API

- **DB**: `saved_voice`와 `trial_generation`의 공급자 검사 제약에 `airy`를 더한다(마이그레이션 하나, 검사를 넓히기만 하므로 파괴적 변경이 아니다). `provider_list_cache`·`provider_cooldown`은 공급자 값이 자유 글자라 그대로다. `trial_generation.usage_unit`은 기존 `credit`을 쓴다.
- **계약** (`providers/contract.ts`, `trial-contract.ts`): `providerIdSchema`에 `airy`. 목록 입력에 `{ provider: "airy" }` 갈래(출처·조건 없음). 시험 생성 설정 스키마 `airySettingsSchema`(`model`·`language`·`style`).
- **공급자 모듈** `providers/airy.ts`:
  - `checkStatus`: 크레딧 잔액 조회 → 연결 상태와 `remaining`·`plan`.
  - `listVoices`: 공식 목록과 카탈로그를 함께 부르고 id로 샘플을 붙인다. 카탈로그 실패는 목록을 막지 않고 한 줄만 남긴다(`[voiceList] airy 샘플 카탈로그 실패: <사유>`). 성우 하나가 어긋나면 그 성우만 뺀다(tts-provider 목록 규칙).
  - `synthesize`: `POST /v1/audio/speech`에 `model`·`input`·`voice`·`language`·`style`·`response_format: "mp3"`만 보낸다. 자동 재시도 없음, 60초 제한.
  - `getVoice`: 공식 목록에서 id를 찾는다. 클라이언트 하나(요청 하나)에서 목록은 한 번만 부른다.
- **프로시저**: 새 프로시저는 없다. `providerStatus`·`voiceList`·`voiceListRefresh`·`trialCreate`·`savedVoice*`가 입력의 공급자 값으로 Airy를 받는다. 모두 기존 `protectedProcedure`이고 소유자는 `context.ownerId`다.
- **환경 변수**: `apps/web/.env.schema`에 `AIRY_API_KEY`(`@optional @sensitive`), `.env.example`에 빈 값. 키는 `apps/web/src/context.ts`의 `createProviders`에서만 읽는다.

## 4. 화면과 흐름

### 연결 상태 `/connections`
- Airy 카드: 공급자 이름, 상태 배지, 원인과 할 일, '남은 크레딧 N'(소수점이 있으면 한 자리까지), 플랜 이름. 키가 없으면 "`apps/web/.env`에 `AIRY_API_KEY`를 넣고 다시 확인해 주세요."(기존 문구 틀).
- 요약 띠의 연결 수가 넷 기준이 된다("4개 중 N개 연결됨", 기존 문구 틀).
- 카드 격자: 768px 이상 2열, 767px 이하 1열.

### 성우 캐스팅 `/casting`
- 탭에 'Airy'가 붙는다. 탭 이름 옆 인원은 다른 공급자와 같다.
- Airy 탭: 조건 줄(검색, 성별), 상태 줄(인원·'목록 새로 고침'·받은 시각), 성우 행 목록. 행은 이름, 성별, 언어(한국어·영어), ▷(한국어 샘플), 별. Typecast 탭과 같은 행 컴포넌트다.
- 성우 패널: 기본 샘플 두 개(한국어·영어), 내 문장 듣기 설정(모델·언어·말투), 담기 칸.
- '전체' 탭: Fish Audio 묶음 뒤에 Airy 묶음(처음 5명과 '모두 보기 →').
- 키가 없으면 Airy 탭은 다른 공급자처럼 'Airy 키가 없어요' 안내와 '연결 상태 보기' 링크(브리프 8절)를 보인다.

### 내 문장 듣기 (성우 캐스팅 안)
- 문장 바와 행 버튼은 T5 그대로다. Airy는 유료 표식이 붙는다(무료 모델이 없다).
- 확인 창: "예상 N크레딧 (Airy 요금 기준: 한국어 1글자 1.5크레딧)". 연결 상태가 준 남은 크레딧이 있으면 함께 보인다.
- 생성 결과는 결과 목록에 다른 공급자와 같이 쌓이고, 같은 조합은 다시 부르지 않고 저장본을 재생한다(T5).

### 성우 보관함 `/voices`
- 공급자 필터에 'Airy'가 붙는다. 담은 Airy 성우 행과 패널은 캐스팅과 같다.

## 8. 수용 기준

1. 키를 넣으면 연결 상태 Airy 카드가 '연결됨'과 남은 크레딧을 보인다. 키를 지우면 '키 없음', 틀린 키는 '키 오류'다.
2. 성우 캐스팅 Airy 탭에 공식 목록의 성우가 모두 보이고, 검색·성별 조건이 맞게 거른다.
3. 행의 ▷이 한국어 샘플을, 패널에서 영어 샘플을 재생하고 한 번에 하나만 재생된다.
4. '전체' 탭에 Airy 묶음이 마지막으로 보이고 '모두 보기 →'가 Airy 탭으로 간다.
5. 카탈로그가 실패해도 목록은 보이고 샘플만 '샘플 없음'이다(자동 테스트).
6. Airy 성우의 내 문장 듣기가 확인 창에 예상 크레딧을 보이고, 승인한 실제 호출 1회로 소리가 난다. 같은 조합을 다시 누르면 공급자를 부르지 않고 저장본을 재생한다.
7. Airy 성우를 별로 담고 분류를 붙이고, `/voices`에서 공급자 'Airy'로 거른다. 새로 고침 뒤에도 남는다.
8. 이용 가능 확인이 Airy 목록을 한 번만 부르고, 목록에 없는 id는 '현재 이용 불가'가 된다(자동 테스트).
9. 다른 세 공급자의 기존 테스트와 화면이 그대로 통과한다.

## 9. 자동 테스트

- `providers/airy.test.ts`(흉내 낸 `fetch`): 잔액 → 연결됨·남은 크레딧·플랜, 잔액 0 → 한도 부족. 401·402·403·429(`Retry-After`)·400·500·시간 초과의 사유 매핑. 목록과 카탈로그 합치기, 카탈로그 실패·모양 어긋남 → 샘플 없음, 허용 호스트가 아닌 샘플 주소 → null, 어긋난 성우 하나만 빠짐, 모두 빠지면 `provider_error`. 합성 요청 본문(필드 여섯, 다른 필드 없음)과 자동 재시도 없음. `getVoice` 찾음·없음, 여러 번 불러도 목록 호출 1회. 카탈로그 요청에 키를 보내지 않음.
- `trial-contract`·`trial-options`: Airy 설정 검사(말투·언어 범위 밖 거절), 예상 크레딧(한국어 홀수 글자 올림, 영어).
- `routers`: 목록 입력 `{ provider: "airy" }`, 키 없음 → `no_key`, 보관함 저장 검사가 Airy 샘플 호스트를 받음, DB 검사 제약이 `airy`를 받음(저장·시험 생성 기록).
- 격리: 기존 2계정 격리 테스트 묶음에 Airy 성우 저장 한 경우를 더한다(공급자 값만 다르고 소유자 규칙은 같다).
- 화면(`apps/web`): 연결 문구(크레딧 표기), 트라이얼 요청 만들기(`requestFor` Airy), 보관함 공급자 쿼리 파싱.

## 12. 위험과 확인할 것

- 공개 카탈로그는 문서에 없는 주소다. 바뀌면 샘플만 사라진다(목록은 공식 API). 그 경우 백로그에 적고 Airy에 공식 샘플 API를 확인한다.
- 공식 목록과 카탈로그의 성우 id가 같은지는 키로 첫 조회를 해야 안다. 다르면 샘플이 붙지 않으므로 QA S3에서 샘플 수를 센다.
- 공식 목록이 계정 커스텀 성우를 섞어 주는지 문서에 없다. 섞이면 샘플 없는 성우로 보인다.
- 샘플은 Ogg Opus다. Safari에서 재생되는지 사용자 테스트에서 본다. 안 되면 백로그.
- 글자를 무엇으로 세는지(코드포인트·UTF-16) 문서에 없다. 한국어는 둘이 같다. 이모지 같은 글자만 다를 수 있다.
- 요청 제한 숫자가 문서에 없다. `savedVoiceCheck`는 Airy 목록을 한 번만 부르므로 영향이 작다.
