## 1. 목표

'성우 캐스팅' 화면에서 Typecast 공개 성우 전체를 이름으로 찾고, 모델·성별·연령·콘텐츠로 거르고, 공급자가 준 기본 샘플을 한 번에 하나씩 듣는다. 뒤 TASK(T4·T5 다른 공급자, T7 담기, T8 시험 생성)가 그대로 쓸 성우 계약, 성우 카드, 샘플 플레이어, 목록 조회의 오류 처리를 만든다.

## 4. 오류

목록 조회는 연결 확인과 달리 공급자 문제를 **던진다**. `tts-provider` 오류 표대로 `ORPCError`에 `data: { provider, reason }`을 붙인다. 공급자 문제를 `UNAUTHORIZED`·`FORBIDDEN`으로 던지지 않는다.

| 경우 | 코드 | `reason` | 화면 |
|---|---|---|---|
| 키 없음 | `PRECONDITION_FAILED` | `no_key` | "Typecast 키가 없어요" + 설명 + [연결 상태] 링크 |
| 401·403 | `BAD_GATEWAY` | `provider_auth`(권한 코드면 `no_permission`) | "Typecast 키를 확인해 주세요" + [연결 상태] 링크 + '다시 불러오기' |
| 402 | `BAD_GATEWAY` | `quota` | "Typecast 사용량이 부족해요" + [연결 상태] 링크 + '다시 불러오기' |
| 429 | `TOO_MANY_REQUESTS` | `rate_limit` | "요청이 많아 잠시 막혔어요" + '다시 불러오기' |
| 400·422, 표에 없는 상태 | `BAD_GATEWAY` | `provider_error` | 공급자 장애와 같은 문구 |
| 5xx | `BAD_GATEWAY` | `provider_error` | "Typecast에 문제가 생겼어요" + '다시 불러오기' |
| 응답 검증 실패(응답 모양, 또는 공개 성우 전부) | `BAD_GATEWAY` | `provider_error` | 위와 같다. 서버 로그에는 공급자·오류 이름·필드 경로만 |
| 10초 초과, 연결 끊김 | `GATEWAY_TIMEOUT` | `unknown_outcome` | "Typecast가 응답하지 않아요" + '다시 불러오기' |
| 소유자 없음 | `UNAUTHORIZED` | — | T2와 같은 주소 안내 |
| 그 밖(500, 예상 밖 예외) | — | — | 오류 경계 `(app)/error.tsx`: "문제가 생겼어요" + '다시 시도하기'(`retry`) |

- 응답 검증은 항목 단위다(2절 '계획 리뷰에서 바꾼 것'). 응답 모양(배열이 아님, `voice_type` 없음)이 어긋나면 `provider_error`다. 공개 성우 하나의 샘플 주소만 어긋나면(https가 아니거나 공급자 호스트 typecast.ai가 아님) 그 성우의 `previewUrl`을 null로 둔다. 그 밖의 필드가 어긋난 성우는 빼고, 뺀 수와 필드 이름(배열 위치 제외, 중복 제거, 5개까지)만 한 줄 남긴다: `[voiceList] typecast 성우 N명 제외: voice_name`. 공개 성우가 하나 이상인데 모두 빠지면 `provider_error`다.
- SDK 오류 객체를 `cause`로 넘기거나 로그에 쓰지 않는다(T2 `ProviderHttpError`로 바꿔 담는 방식을 그대로 쓴다).
- `onError` 로그 정책(AF-11)은 그대로다. 의도한 `ORPCError`(500 미만)는 남기지 않는다.

## 5. 범위

DB 스키마와 소유 데이터는 바꾸지 않는다. 대조표의 DB 행(5, 7~10행)은 N/A다. 2계정 격리 테스트 행(13행)은 AC3(소유자 없음이면 `UNAUTHORIZED`이고 공급자 호출 0)으로 대신한다.

### 포함
1. **성우 계약** `providers/contract.ts`: `voiceSchema`(공급자, 성우 id, 한글 이름, 영문 이름, 성별 `male|female|null`, 연령 문자열|null, 콘텐츠 문자열 배열, 모델 배열 `{ model, emotions[] }`, 샘플 주소 URL|null)와 목록 결과 `voiceListResultSchema`(`{ provider, voices, fetchedAt }`). 공급자 오류 `data` 스키마 `{ provider, reason }`도 여기 둔다(화면이 사유를 읽는다).
2. **공급자 오류를 던지는 함수** `providers/errors.ts`: `ProviderHttpError`·시간 초과·검증 실패를 4절 표의 `ORPCError`로 바꾼다. `reasonFromHttp`를 그대로 쓴다. T2 "만들지 않는 것"이 T3로 넘긴 항목이다.
3. **Typecast 목록** `providers/typecast.ts`: `listVoices()`를 더한다. SDK 응답에서 쓰는 필드만 zod로 검사하고, `original`만 남겨 계약 모양으로 바꾼다. `ProviderClient`에 `listVoices?`를 더한다(ElevenLabs·Fish Audio는 T4·T5에서 채운다).
4. **프로시저** `voiceList`: `protectedProcedure`, 입력 `{ provider: z.literal("typecast") }`(T4·T5에서 넓힌다), 출력 `voiceListResultSchema`. 키가 없으면 공급자를 부르지 않고 `no_key`로 던진다.
5. **화면** `/casting`(브리프와 고른 시안대로):
   - `page.tsx`는 Server Component이고 제목 메타데이터("성우 캐스팅")만 둔다. 공급자·db 모듈을 부르지 않는다.
   - 클라이언트 컴포넌트 하나가 `voiceList`를 `useQuery`로 든다. 설정: `staleTime: Infinity`, `gcTime: Infinity`, `retry: false`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`, `meta: { toast: false }`. 4절의 사유 있는 오류는 화면 안에 보이고, 그 밖의 오류만 오류 경계로 던진다(`throwOnError`).
   - 검색: 한글·영문 이름 부분 일치. 앞뒤 공백을 지우고, 대소문자를 가리지 않고, 유니코드 정규화(NFC)한다. 입력이 빠르게 바뀌어도 목록 그리기가 입력을 막지 않게 한다(`useDeferredValue`).
   - 필터: 모델, 성별, 연령, 콘텐츠. 같은 축은 OR, 다른 축은 AND(REQ-02 상세). 선택지는 받은 목록에 있는 값으로 만든다(공급자가 새 값을 더해도 보인다). 값이 없는 성우(성별·연령 null)는 그 축을 고르면 빠지고, 카드에는 '정보 없음'으로 보인다.
   - 보기: 조건(검색어·필터)이 없으면 콘텐츠별 선반(인원 수 많은 순, 선반마다 앞의 5명, '모두 보기 →'는 그 콘텐츠를 고른 격자로(5명 이하 선반은 '모두 보기 →' 없음)), 조건이 있거나 상단 '전체 보기'를 누르면 결과 격자 하나다. 콘텐츠 정보가 없는 성우는 마지막 선반 "콘텐츠 정보 없음"에 둔다(브리프 5절).
   - 결과 수: 격자에서 "Typecast 성우 614명 중 N명". '조건 모두 해제'는 조건이 있을 때만, '콘텐츠별로 보기'는 조건 없이 '전체 보기'로 왔을 때만 보인다.
   - 카드: 한글 이름, 영문 이름, 성별·연령, 콘텐츠(한국어 이름), 모델별 감정 수(예: "ssfm-v30 · 감정 7"), 샘플 버튼. 614장을 모두 그리고 화면 밖 카드는 `content-visibility: auto`로 그리기를 미룬다.
   - 샘플 플레이어: 페이지에 오디오 요소 하나를 두고 모든 카드가 함께 쓴다. 상태는 대기, 불러오는 중, 재생 중, 실패, 샘플 없음이다. 다른 카드를 누르면 앞 재생이 멈춘다. 재생 중인 카드를 다시 누르면 멈춘다. 끝나면 대기로 돌아간다. 페이지를 떠나면 멈춘다. 샘플 주소가 없으면 버튼을 누를 수 없고 '샘플 없음'을 글자로 보인다(REQ-03).
   - 상태: 불러오는 중, 4절 오류(사유별), 소유자 없음 안내, 조건에 맞는 성우 없음("조건에 맞는 성우가 없어요" + '조건 모두 해제'), 목록이 비어 있음("Typecast가 준 공개 성우가 없어요").
   - 1440px 이상: 선반·격자 5열. 768~1439px: 선반은 가로로 넘기는 줄이 되고 격자는 칸 너비 약 240px 기준이다(2절 '계획 리뷰에서 바꾼 것'). 767px 이하: 필터를 '조건' 버튼 뒤로 접고(고른 조건 수를 버튼에 보인다) 격자는 1열이다(브리프 8절).
6. **오류 경계** `(app)/error.tsx`: 앱 틀 안에 "문제가 생겼어요", 설명 한 줄, '다시 시도하기'(prop `retry`, Next 16.3). 흉내 낸 응답(500)으로 확인한다.
7. **메뉴와 작업실:** '성우 캐스팅'을 `/casting` 링크로 열어 열린 화면 묶음에 옮기고 '준비 중' 표에서 지운다. 작업실 흐름 지도의 '성우' 단계를 `/casting` 링크로 바꾼다. 휴대폰 위 막대는 4칸(음성 작업실, 성우 캐스팅, 연결 상태, 더보기)이다(브리프 10절). 더보기 안에 열린 화면이 없으므로 T2 브리프 8절은 이번에도 쓰이지 않는다.

## 7. 수용 기준

- **AC1** 화면을 열면 콘텐츠별 선반(인원 수 많은 순, 선반마다 5명)이 보이고 "Typecast 성우 N명"과 선반마다의 인원 수가 실제 수와 같다. 상단 '전체 보기'로 공개 성우 전체가 격자로 보인다. 커스텀 성우(`voice_type: custom`)는 보이지 않는다.
- **AC1a** 선반의 '모두 보기 →'는 그 콘텐츠를 고른 격자로 간다. 조건을 모두 지우면 선반으로 돌아온다. 콘텐츠 정보가 없는 성우도 마지막 선반과 전체 격자에서 찾을 수 있다.
- **AC2** 키가 없으면 공급자를 부르지 않고 "Typecast 키가 없어요"와 [연결 상태] 링크가 보인다.
- **AC3** 소유자가 없는 요청(루프백이 아닌 Host, production)은 `UNAUTHORIZED`이고 공급자 호출은 0회다. 화면은 주소 안내를 보인다.
- **AC4** 공급자 401·403·402·429·5xx·시간 초과·응답 검증 실패가 4절의 코드와 사유로 바뀌고, 화면은 사유별 문구를 보인다. 한 번 실패해도 자동으로 다시 부르지 않는다.
- **AC5** '다시 불러오기'는 목록 조회를 한 번만 다시 한다. 불러오는 중에는 누를 수 없다.
- **AC6** 이름 검색은 한글·영문 부분 일치이고 대소문자와 앞뒤 공백을 가리지 않는다. 검색어를 지우면 전체로 돌아간다.
- **AC7** 필터는 같은 축 OR, 다른 축 AND다. 결과 수가 바로 바뀌고, '조건 모두 해제'가 검색어와 필터를 모두 지운다. 필터를 바꿔도 공급자를 부르지 않는다.
- **AC8** 조건에 맞는 성우가 없으면 빈 상태와 '조건 모두 해제'가 보인다.
- **AC9** 샘플을 누르면 그 성우의 기본 샘플이 재생되고 버튼이 '정지'로 바뀐다. 다른 성우를 누르면 앞 재생이 멈추고 새 샘플이 재생된다. 같은 버튼을 다시 누르면 멈춘다. 끝나면 대기로 돌아간다.
- **AC10** 샘플 주소가 없는 성우는 숨기지 않고 '샘플 없음'을 보이며 버튼을 누를 수 없다. 재생이 실패하면 그 카드에 "재생하지 못했어요"가 보이고 다시 누를 수 있다.
- **AC11** 페이지를 떠나면 재생이 멈춘다.
- **AC12** 메뉴 '성우 캐스팅'과 작업실 흐름 지도 '성우'가 `/casting`으로 간다. '준비 중' 묶음은 6개가 된다. 탭 제목은 "성우 캐스팅 · TTS Pilot"이다.
- **AC13** 예상 밖 오류는 앱 틀 안의 오류 화면("문제가 생겼어요")으로 보이고 '다시 시도하기'로 다시 그린다.
- **AC14** 1440·1280·1024·768·390 너비와 라이트·다크에서 승인 시안(`casting-shelves.png`)과 브리프 8절대로 보인다. 1439px 이하 선반은 줄 안에서만 가로로 넘어가고 페이지 가로 스크롤은 없다. 390에서는 필터가 '조건' 버튼 뒤로 접힌다. 연결 상태 카드는 1024px에서 3열이다.
- **AC15** 키보드만으로 검색, 필터, 샘플 재생·정지, '조건 모두 해제'를 쓸 수 있다. 샘플 버튼의 접근 이름에 성우 이름과 동작이 들어간다("{이름} 기본 샘플 듣기"/"정지"). 재생 상태 변화는 스크린 리더에 알린다.
- **AC16** 검색 칸 경계는 바탕 대비 3:1 이상이다.
- **AC17** 연결 상태의 ElevenLabs 카드는 지난 초기화 날짜를 보이지 않는다.
- **AC18** 클라이언트 번들에 공급자 SDK·서버 모듈·키가 들어가지 않는다.

## 8. 자동 테스트

- `providers/typecast.test.ts`(가짜 fetch): 정상 응답을 계약으로 바꿈, `custom` 제외, 항목 단위 검증(샘플 주소만 틀리면 `previewUrl: null`, 다른 필드가 틀린 성우만 빠지고 로그 한 줄, 모두 빠지면 `provider_error`), SDK 경로의 401·429·JSON이 아닌 200 응답, SDK 오류 객체가 밖으로 나가지 않음(로그에 키·헤더 없음).
- `routers/voice-list.test.ts`: 소유자 없음 `UNAUTHORIZED`이고 공급자 호출 0, 키 없음 `PRECONDITION_FAILED`/`no_key`이고 호출 0, 정상 출력이 출력 스키마를 통과.

- `apps/web` `voice-filter.test.ts`: 검색(한글·영문·대소문자·공백·NFC), 같은 축 OR·다른 축 AND, null 값 처리, 선택지 생성, 조건 0개면 전체.
- `apps/web` `connection-status` `toView`: 상태별 보기, 지난 초기화 날짜 숨김.
- `apps/web` `voice-failure.test.ts`·`sample-state.test.ts`: 오류에서 화면 사유 고르기(모르는 사유는 오류 경계로), 샘플 상태 전환(같은 성우 다시 누름은 멈춤, 실패한 성우는 다시 불러옴, 앞 성우의 늦은 실패는 무시).

## 10. 사용자 테스트 절차 (구현 뒤 드린다)

1. 개발 서버가 켜진 채로 `http://127.0.0.1:3001/casting`을 연다(강력 새로 고침 Cmd+Shift+R).
2. 메뉴 '성우 캐스팅'과 작업실 흐름 지도 '성우'로도 들어와 본다.
3. 이름으로 검색하고, 성별·연령·콘텐츠·모델을 바꿔 결과 수가 맞는지 본다.
4. 샘플을 두세 개 연달아 눌러 앞 소리가 멈추는지, 같은 버튼을 다시 누르면 멈추는지 듣는다.
5. 휴대폰 너비(또는 창을 좁혀)에서 '조건' 버튼과 카드를 본다. 다크 테마도 본다.
6. 연결 상태 화면의 ElevenLabs 카드에 지난 날짜가 없는지 본다.

## 11. 위험과 확인할 것

- **샘플 출처:** 기본 샘플은 브라우저가 `static2.typecast.ai`에서 바로 받는다. 서버 키가 쓰이지 않고 과금이 없다. 공급자가 주소 형식을 바꾸면 3절 "샘플 만료"를 다시 본다.
- **응답 크기:** 약 300KB를 계약 필드로 줄여 화면에 보낸다. 4.5MB 한도와 멀다.
- **614장 그리기:** 1440·390에서 첫 화면 그리기와 필터 반응을 계획·QA에서 잰다. 느리면 '만들지 않는 것'의 페이지 나눔을 다시 본다.
- **Typecast 응답 시간:** T2 QA에서 구독 조회가 한 번 약 9초 걸렸다. 목록도 10초 제한에 걸리면 `unknown_outcome`으로 보인다.
- **ssfm-v31:** 문서 필터에는 있으나 생성 모델이 아니다. 목록에 나오면 그대로 보이고(공급자가 준 값), 생성(T8)에서 다시 정한다.
- **메뉴 4칸:** 휴대폰 위 막대가 4칸이 된다. 390에서 글자가 한 줄에 들어가는지 QA에서 본다.
- **선반 중복:** 콘텐츠가 여러 개인 성우는 여러 선반에 나온다(시안 선택 때 알린 단점). 키는 선반마다 따로 둔다.
