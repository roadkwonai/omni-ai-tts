## 1. 목표

성우를 정리할 때 쓸 채널·카테고리·타입 항목을 `/classes` 한 화면에서 만들고, 고치고, 지운다. 새로 고침 뒤에도 남고, 다른 소유자의 항목은 보이지도 바뀌지도 않는다.

뒤 TASK가 그대로 쓸 것을 만든다.
- `channel` 테이블. 프리셋의 선택 채널·채널 기본 프리셋(T8)과 저장 대본의 선택 채널(T12)이 일반 외래 키로 가리킨다.
- `classification` 테이블(카테고리·타입). 성우 보관함(T7)과 저장 대본(T12)이 연결 테이블로 여러 개 붙인다.
- 이름 정리·중복 규칙과 입력 계약(zod). T7의 '바로 추가'가 같은 규칙을 쓴다.
- 소유 데이터 CRUD의 틀: 입력 창, 삭제 확인, 오류 표시, 2계정 격리 테스트(로드맵 4절 T6 행).

## 3. 데이터와 API

**`channel`** (`packages/db/src/schema/classification.ts`)
- `id` uuid 기본키(`defaultRandom()`), `owner_id` text not null(서버가 정한 소유자), `name` text not null, `memo` text null, `url` text null, `created_at` timestamptz not null 기본 now().
- 유니크 인덱스 `channel_name`: `(owner_id, lower(name))`. 목록 조회(`where owner_id`)도 이 인덱스의 앞부분을 쓴다.

**`classification`** (같은 파일)
- `id`, `owner_id`, `kind` text not null, `name`, `memo`, `created_at`. `url`은 없다.
- check `classification_kind`: `kind in ('category', 'type')`(저장소 관례: enum 대신 text + check).
- 유니크 인덱스 `classification_name`: `(owner_id, kind, lower(name))`.
- 마이그레이션은 `db:generate`로만 만든다. 기존 표는 바꾸지 않는다(파괴적 변경 없음).

**프로시저** (모두 `protectedProcedure`, 소유자는 `context.ownerId`만, 모든 조회·변경에 `owner_id = 소유자`)

| 프로시저 | 입력 | 출력 | 설명 |
|---|---|---|---|
| `channelList` | 없음 | 채널 배열 `{ id, name, memo, url }` | 소유자의 채널 전부. 정렬은 화면이 한다(아래) |
| `channelCreate` | `{ name, memo, url }` | 만든 채널 | 서버가 다시 정리·검사한다. 중복이면 `CONFLICT` |
| `channelUpdate` | `{ id, name, memo, url }` | 고친 채널 | 세 값을 통째로 바꾼다. 없거나 남의 것이면 `NOT_FOUND` |
| `channelDelete` | `{ id }` | `{ deleted: true }` | 없거나 남의 것이면 `NOT_FOUND` |
| `classificationList` | 없음 | 분류 배열 `{ id, kind, name, memo }` | 카테고리·타입을 한 번에. 화면이 `kind`로 나눈다 |
| `classificationCreate` | `{ kind, name, memo }` | 만든 분류 | 같은 `kind` 안에서 중복이면 `CONFLICT` |
| `classificationUpdate` | `{ id, name, memo }` | 고친 분류 | `kind`는 바꾸지 않는다(카테고리를 타입으로 옮기기 없음) |
| `classificationDelete` | `{ id }` | `{ deleted: true }` | |

- 정리·검사 함수는 zod·서버 모듈을 import하지 않는 파일(`packages/api/src/classification-rules.ts`)에 두고 화면의 입력 검사도 같은 함수를 쓴다. zod 계약(`classification-contract.ts`)은 이 함수로 만든다.
- 정렬: 화면이 `Intl.Collator("ko", { numeric: true })`로 이름순 정렬한다. DB 정렬 순서(콜레이션)에 기대지 않는다.
- 중복은 조회해서 막지 않고 유니크 인덱스 위반(Postgres 23505)을 잡아 `CONFLICT`(`data.reason: "duplicate_name"`)로 바꾼다. 두 탭에서 같은 이름을 동시에 만들어도 한 행만 남는다. `CONFLICT`는 이 저장소에서 처음 쓰는 코드다.
- 항목 수 상한은 두지 않는다(소유자 한 명, 직접 입력).

**조사 (2026-10-06, 구조 결정 근거)**
- 채널에만 붙는 것: URL(요구사항 운영 범위), 기본 프리셋·프리셋 선택 채널(REQ-08), 대본 선택 채널(REQ-06), 작업실 흐름의 첫 단계. 카테고리·타입은 이름·메모뿐인 N:M 이름표다.
- 한 테이블(A안)은 'One True Lookup Table' 문제에 걸린다. "채널만 가리키는" 외래 키를 걸 수 없다([Ben Taylor 정리](https://www.sswug.org/bentaylor/editorials/one-true-lookup-table-2)). `(id, kind)` 복합 외래 키로 막을 수는 있지만 참조마다 컬럼·check·키가 붙고 일부는 Drizzle이 지원하지 않는다([PG18 제약](https://www.postgresql.org/docs/18/ddl-constraints.html)).
- 하나만 고르는 단위와 여러 개 붙이는 라벨을 다른 자원으로 두는 것이 흔하다: GitHub 이슈의 milestone과 labels([REST](https://docs.github.com/en/rest/issues/issues#create-an-issue)), Todoist의 project와 labels([API](https://developer.todoist.com/api/v1/)).
- 대소문자 무시 유니크는 `lower()` 식 인덱스(공식 문서 예, [식 인덱스](https://www.postgresql.org/docs/18/indexes-expressional.html)). citext는 공식 문서가 대신 nondeterministic collation을 권하고 느리다고 적는다. Drizzle 1.0.0-rc.4 설치판 `uniqueIndex().on()`이 SQL 식을 받는 것을 확인했다(`pg-core/indexes.d.ts:43`).

## 4. 화면과 흐름

**`/classes` 채널·분류**
- 페이지 머리: 제목 '채널·분류'와 설명 한 줄(문구는 브리프).
- 묶음 셋(채널 → 카테고리 → 타입), 묶음마다:
  - 머리: 그룹 이름과 개수, 오른쪽 '+ {그룹} 만들기' 버튼.
  - 행: 이름, 메모(있으면 이름 아래), 채널은 URL(있으면 주소를 줄여 보이고 새 탭으로 연다, `rel="noopener noreferrer"`), 오른쪽 44px 아이콘 버튼 둘(연필 '고치기'·휴지통 '지우기', 툴팁, 접근 이름 '{이름} 고치기'·'{이름} 지우기').
  - 빈 상태: "아직 {그룹}이 없어요." + 예시(채널: '경제 한 입'·'주말 레터'처럼 내가 운영하는 채널 이름, 카테고리: 쇼핑·지식·뉴스·사연·교육, 타입: 차분함·활기참·신뢰감·캐릭터형 — GLOSSARY 예시). 그릇 모양과 문구는 브리프가 정한다.
  - 로딩: 묶음마다 자리 표시. 목록 오류: 묶음 자리에 회색 오류 문구 한 줄과 '다시 불러오기'(T5 결과 목록과 같다). 다시 받기에 성공하면 포커스를 그 묶음 머리로 옮긴다.
  - 넓은 화면에서 목록 폭은 `max-w-3xl`까지다(이름과 버튼 사이가 벌어지지 않게).
- 입력 창(만들기·고치기 같은 창):
  - 제목 '{그룹} 만들기' / '{그룹} 고치기'. 칸: 이름(필수), 채널만 URL(선택), 메모(선택, 2~3줄, 글자 수 'N / 200자'). 칸은 44px 이상이고 767px 이하에서 글자 16px(iOS 확대 방지).
  - 첫 포커스는 이름 칸. Enter는 어느 칸에서든 저장이다(메모의 줄바꿈은 공백으로 정리). 한글 조합을 끝내는 Enter는 저장하지 않는다.
  - 화면 검사(서버와 같은 함수): 빈 이름, 길이 초과, URL 형식. 문제가 있으면 그 칸 아래 이유(화면 낭독기가 읽는다)를 보이고 첫 문제 칸으로 포커스를 옮기며 저장을 보내지 않는다.
  - 저장 중에는 칸이 읽기 전용이고 '저장하기'·'취소'는 눌리지 않으며(진행 표시) 창이 닫히지 않는다. 성공하면 창이 닫히고 알림 "‘{이름}’ {그룹}을 만들었어요/고쳤어요", 목록이 다시 그려진다. 같은 이름·저장 실패면 이름 칸으로 포커스가 간다.
  - Esc·취소는 저장하지 않고 닫는다. 바깥 누르기는 값을 바꾸지 않았을 때만 닫는다. 포커스는 연 버튼으로 돌아간다(없어진 항목이면 묶음의 '만들기').
- 삭제 확인 창: "‘{이름}’ {그룹}을 지울까요? 메모와 URL도 함께 지워지고 되돌릴 수 없어요."(분류는 "메모도 함께…") 첫 포커스는 '취소'. '지우기'를 누르면 지우는 동안 버튼이 눌리지 않고, 성공하면 알림 "‘{이름}’ {그룹}을 지웠어요", 포커스는 다음 행 → 이전 행 → 그 묶음의 '만들기'. 실패하면 창을 닫지 않고 이유를 보이며 포커스는 '취소'.
- 소유자 없음(루프백이 아닌 주소): 세 묶음 대신 기존 `LoopbackNotice` 하나("이 주소에서는 채널·분류를 쓸 수 없어요").
- 긴 내용: 이름 40자·메모 200자는 줄바꿈해 다 보인다. URL은 한 줄 말줄임이고 전체 주소는 툴팁(title)으로, 접근 이름은 보이는 주소 + "(새 탭)"이다.

**앱 틀**
- 메뉴 '채널·분류'를 '다음에 열릴 화면'에서 열린 화면으로 옮긴다(`/classes` 링크, 아이콘 그대로). 1200px 이상·768~1199px 사이드바에는 열린 화면 목록에 보인다.
- 767px 이하: 위 막대는 4칸 그대로, '채널·분류'는 더보기를 펼친 안쪽 맨 위 '열린 화면' 줄. `/classes`에 있으면 더보기 버튼이 활성 표현이고 접근 이름은 "더보기, 현재 채널·분류"다. 더보기 안 링크를 누르면 포커스는 더보기 버튼으로 간다.
- 작업실 흐름 지도의 '채널' 단계를 `/classes` 링크로 바꾼다.
- 사이트맵의 '준비 중' 표에서 채널·분류 두 줄을 지우고 페이지 표에 `/classes` 행을 더한다.

## 8. 수용 기준

1. 채널·카테고리·타입을 각각 만들고, 이름·메모(채널은 URL도)를 고치고, 지울 수 있다. 새로 고침 뒤에도 그대로다.
2. 목록은 그룹마다 이름순이다(가나다, '2화' < '10화').
3. 같은 그룹 안의 같은 이름(대소문자·앞뒤·연속 공백만 다른 것 포함)은 만들기·고치기 모두 거절되고 입력이 남는다. 다른 그룹의 같은 이름은 된다.
4. 이름 0자·41자, 메모 201자, URL `javascript:`·`ftp:`·501자는 화면과 서버 모두 거절한다. 빈 메모·빈 URL은 없음으로 저장된다.
5. 지우기는 확인 창을 거친다. 취소·Esc는 아무것도 바꾸지 않는다.
6. B 소유자는 A의 항목을 목록에서 보지 못하고, A의 id로 고치기·지우기를 하면 `NOT_FOUND`이며 A의 행은 그대로다. B는 A와 같은 이름을 만들 수 있다.
7. 소유자가 없으면 프로시저 8개가 모두 `UNAUTHORIZED`이고 DB 접근이 0회다. 화면은 주소 안내 하나다.
8. 저장·삭제가 실패하면 성공 알림이 없고, 입력 창의 값이 남는다.
9. 메뉴(세 너비)와 작업실 흐름 지도 '채널'에서 `/classes`로 간다. 휴대폰 위 막대는 4칸이고 '채널·분류'는 더보기 안 '열린 화면'에 있다. '준비 중' 목록에 채널·분류가 없다.
10. 1440·1280·1024·768·700·390·320px, 라이트·다크에서 가로 넘침이 없고(700px은 입력 창이 아래 시트로 화면 폭을 채운다), 키보드만으로 만들기·고치기·지우기를 끝낼 수 있으며 포커스가 4절대로 돌아간다. 한글 조합을 끝내는 Enter로는 저장되지 않는다(Chrome·Safari).
11. 오류 예산(콘솔·개발 오버레이·`get_errors`·서버 로그) 0.

## 12. 위험과 확인할 것

- `lower()`는 DB의 문자 분류(ctype)를 따른다. 한글은 영향이 없고 영문 대소문자만 같게 본다. 테스트 DB에서 확인한다.
- 23505 잡기: Drizzle 1.0.0-rc.4는 pg 오류를 `DrizzleQueryError.cause`에 넣는다. 코드(`cause.code`)와 제약 이름(`cause.constraint`)으로 이름 인덱스 위반만 `CONFLICT`로 바꾼다(계획 리뷰에서 설치판으로 확인).
- `CONFLICT`는 rpc 오류 로그(4xx는 남기지 않음)와 클라이언트 전역 처리(조회 오류 알림만 있고 변경 오류 처리는 없음)에 걸리지 않는다(계획 리뷰에서 확인).
- 입력 창 컴포넌트(`dialog`/`drawer`)를 `packages/ui`에 더하면 base-lyra 판과 접근성(포커스 갇힘, Esc)을 확인한다.

## 13. 뒤 TASK가 지킬 것 (로드맵 메모로 옮긴다)

- T7: 성우 연결 테이블은 `channel`·`classification` 각각에 외래 키 `on delete cascade`(연결만 풀림, 성우는 남음)와 분류 쪽 id 인덱스(외래 키 컬럼은 자동 인덱스가 없다). 연결할 때 항목의 소유자가 같은지 검사한다. 삭제 확인 창에 연결 수를 더한다.
- T8: 프리셋의 선택 채널·채널 기본 프리셋은 `channel` 외래 키 `on delete set null`. 서로 가리키는 구조(채널 ↔ 프리셋)를 피할지 T8 설계에서 정한다.
- T12: 저장 대본의 선택 채널은 `channel` 외래 키, 분류는 연결 테이블.
- T14: `owner_id = 'local-admin'` 행을 실제 사용자 id로 옮기고, 그때 `user` 외래 키를 걸지 정한다(`channel`·`classification`·`trial_generation`).
