## 1. 목표

내 목소리를 브라우저에서 녹음하거나 파일로 올려 공급자에 클론을 만들고, 성우 보관함에 담아 프리셋·문단 작업실·드라마에서 다른 성우처럼 쓰고, 필요 없으면 지운다. 원본 녹음은 앱에 남기지 않는다. 클론은 앱이 만든 것만 내 보이스로 보이고(소유 매핑), 지우는 동안과 지운 뒤에는 새 합성에 쓰이지 않는다.

지금은 메뉴의 '내 보이스'가 '준비 중'이고, 공급자 웹에서 만든 클론만 성우 캐스팅 '내 계정'에서 담아 쓸 수 있다.

## 4. 상태

내 보이스 한 개(`my_voice` 행)의 상태는 앱 기준으로 정규화한다. 공급자가 주지 않는 진행률·완료 시간은 만들지 않는다.

| 상태 | 뜻 | 합성 | 화면 행동 |
|---|---|---|---|
| `sending` 보내는 중 | 요청을 선점하고 공급자를 부르는 중 | 불가 | 없음(5분 지나면 `unknown`) |
| `processing` 처리 중 | 공급자가 받았지만 학습 중(Fish `created`·`training`) | 불가 | '상태 확인', 지우기 |
| `ready` 사용 가능 | 공급자 확인 끝. 보관함에 담김 | 가능 | 내 문장으로 들어보기, 지우기 |
| `failed` 실패 | 공급자가 거절했거나 학습 실패, 품질 검사 실패 | 불가 | 사유, 목록에서 치우기(공급자가 id를 줬으면 공급자에서도 지운다) |
| `unknown` 처리 여부 미확인 | 응답을 받지 못함(시간 초과·연결 끊김) | 불가 | "공급자 쪽에 만들어졌을 수 있어요" 안내, 목록에서 치우기 |
| `deleting` 삭제 대기 | 지우기를 눌렀고 공급자 삭제가 끝나지 않음 | 불가 | 다시 시도 |

- `unknown`은 공급자 id를 모르므로 앱이 지울 수 없다. 이름으로 찾아 내 것으로 만들지 않는다(REQ-13 7번). 안내 문구에 공급자 웹에서 확인하고 지우는 방법을 적는다. '목록에서 치우기'는 앱 행만 지운다.
- `unknown`과 공급자 id가 없는 `failed` 행을 치우는 것은 공급자 호출이 없다. 공급자가 id를 준 `failed`(Fish 품질 실패 등)는 치울 때 공급자에서도 지운다(계획 리뷰 1회차).
- ElevenLabs의 '검증 필요'는 T13-b에서 더한다.

## 5. 화면과 흐름

### 5.1 내 보이스 `/my-voices`
- 메뉴 '내 보이스'(마이크 아이콘)를 '준비 중'에서 연다.
- 목록 줄: 이름, 공급자, 상태, 만든 날, 연결된 프리셋 수. 최근 만든 순. 한 사람의 클론 수는 작아(Gemini 200 상한) 나눠 받지 않는다.
- 빈 상태: "아직 만든 내 보이스가 없어요" + '만들기'. 불러오는 중·오류(다시 시도)·로컬 관리자 모드가 아닐 때(비인가)를 구분한다.
- 페이지를 열 때 `processing` 줄은 공급자 상태를 한 번 조회한다(무료, 자동 재시도 없음).
- 줄의 '보관함에서 보기'는 성우 보관함의 그 성우로 간다(메모·분류 편집은 거기서).
- 성우 보관함에서 클론을 직접 빼면 내 보이스 줄은 그대로 사용 가능이고, ⋯ 메뉴에 '성우 보관함에 다시 담기'가 생긴다(계획 2.3).

### 5.2 만들기 창
한 창에서 단계로 진행하고, 앞 단계로 돌아가도 고른 값과 원본은 유지한다. 창을 닫으면 원본(Blob, object URL)과 마이크를 정리한다.

1. **공급자·이름**: Fish Audio / Gemini 중 하나, 이름 1~30자. 공급자별 길이·준비물(Gemini는 동의 문장 녹음이 하나 더)을 보인다.
2. **원본**: '녹음' 또는 '파일 고르기'. 녹음은 버튼을 누를 때 마이크 권한을 요청하고, 경과 시간과 상한을 보이고, 상한에 닿으면 멈춘다. 읽을 거리로 짧은 추천 문단을 보인다. 파일은 브라우저가 열 수 있는 오디오면 받아 WAV로 바꾸고, 길이가 공급자 범위 밖이면 이유를 보이고 다음으로 가지 않는다. 다시 녹음·파일 바꾸기를 지원한다.
3. **(Gemini만) 동의 녹음**: ko-KR 동의 문장을 크게 보이고 같은 방식(녹음·파일)으로 받는다.
4. **듣기·동의**: 원본(과 동의 녹음)을 들어 본다. "제 목소리이고, {공급자}에 보내 클론을 만드는 데 동의합니다" 체크와 보낼 공급자를 보인다. 체크 전에는 '보내기'를 막는다.
5. **보내기**: 요청 id를 만들고 보낸다. 결과는 사용 가능·처리 중·실패·미확인 중 하나로 창에 보이고, 목록이 갱신된다. 보내는 중에 창을 닫아도 요청은 그대로 가고 목록에 `sending`으로 남는다.

### 5.3 원본 처리 (브라우저)
- 녹음은 `MediaRecorder` 기본 형식으로 받은 뒤 `AudioContext.decodeAudioData`로 풀고 24kHz 모노로 바꿔 16비트 PCM WAV로 만든다. 파일도 같은 길로 간다.
- 멈춤·창 닫기·페이지 떠나기에 모든 `MediaStreamTrack`을 `stop()`하고, object URL은 바꿀 때와 닫을 때 `revokeObjectURL`한다.
- 마이크 권한 거부, 마이크 없음, 풀 수 없는 파일, 무음(앱 기준 최대 진폭이 아주 작음), 너무 짧음·김을 각각 다른 문구로 보인다.

### 5.4 보내기와 중복 막기 (서버)
- 입력: 요청 id(uuid), 공급자, 이름, 동의 확인, 원본 `File`, (Gemini) 동의 녹음 `File`. 소유자는 `context.ownerId`에서만.
- 순서: 입력 검사(WAV 머리말·형식 24kHz 모노 16비트·길이·크기) → `my_voice` 행을 `sending`으로 insert해 선점(`(owner_id, request_id)` 유니크, 소유자별 진행 중 1건 부분 유니크) → 공급자 호출(자동 재시도 없음) → 결과 저장.
- 같은 요청 id가 다시 오면 공급자를 부르지 않고 그 행의 상태를 돌려준다. 같은 id에 다른 입력(공급자·이름·원본과 동의 녹음의 sha256)이면 `BAD_REQUEST`.
- `ready`가 되면 같은 트랜잭션에서 성우 보관함에 담는다. 이미 같은 (공급자, voice id)가 담겨 있으면 그 행을 쓴다.
- 공급자 429는 `provider_cooldown`에 대기 시각을 적는다. 잔액·권한·입력 거절은 사유로 보이고 다시 부르지 않는다.
- 5분 넘은 `sending`은 다음 요청에서 `unknown`으로 옮긴다(T5와 같다).

### 5.5 상태 확인
- `processing` 줄의 '상태 확인'과 페이지 열 때 조회는 `GET`(무료)만 부른다. `trained` → `ready`(보관함에 담기), `failed` → `failed`. 공급자가 없다고 하면 `failed`(사유 '공급자에 없음').

### 5.6 들어보기
- `ready` 줄의 '내 문장으로 들어보기'는 성우 캐스팅의 시험 생성을 그 성우로 연다(대본 입력, 예상 사용량 확인, 한 번 생성). 클론에는 기본 샘플이 없다고 적는다. 원본은 앱에 없으므로 만든 뒤에는 원본 듣기를 제공하지 않는다.

### 5.7 지우기
- 확인 창: 이름, 공급자, 연결된 프리셋 수와 이름, "공급자에서 지운 클론은 되돌릴 수 없어요", "이미 만든 오디오는 지워지지 않아요". 기본 초점은 '취소'.
- 순서: 행을 `deleting`으로 바꾸고 보관함 행을 이용 불가로 표시해 새 합성을 막는다(같은 트랜잭션) → 공급자 `DELETE`(자동 재시도 없음) → 성공 또는 공급자 404면 `my_voice`와 보관함 행을 지운다(프리셋은 `on delete set null`, 분류·채널 연결은 cascade). 실패·미확인이면 `deleting`으로 남기고 '다시 시도'를 보인다.
- `deleting` 동안 보관함 확인(`savedVoiceCheck`)이 그 성우를 다시 이용 가능으로 되돌리지 않는다.

## 6. 소유권과 보안 (REQ-01, REQ-13, tts-provider)

- 모든 프로시저는 `protectedProcedure`, 소유자는 `context.ownerId`. 상태 확인·지우기(치우기 포함)·보관함에 다시 담기의 입력은 `my_voice` 행 id이고 `and(id, owner_id)`로 찾은 공급자 voice id만 공급자에게 보낸다. 없으면 `NOT_FOUND`.
- 매핑의 voice id는 앱이 부른 만들기 응답에서만 기록한다. voice id를 입력받아 등록하는 기능은 없다.
- Fish Audio는 `visibility: "private"`를 명시해 보낸다. 공개·공유 옵션은 화면에 없다. Fish `references`(즉석 클론)는 쓰지 않는다.
- 합성 막기: 시험 생성·작업실·드라마 세 합성 경로가 공통 검사(`cloneBlocked`)로, 요청 voice id가 `my_voice`에 있으면서 '내 것이고 `ready`'가 아니면 공급자를 부르지 않고 거절한다([계획](T13-my-voice-plan.md) 2.3). 지우기 시작 때 보관함 행도 이용 불가로 만든다.
- 보관함 담기: Gemini 클론(`account`)도 성우 보관함의 즐겨찾기·메모·채널·분류·프리셋을 쓸 수 있게 담기 규칙을 넓히되, 공개 출처만 있던 공급자의 `account` 성우는 보관함에 쓰는 모든 길(담기·연결·프리셋·내 보이스)에서 내 `my_voice` 매핑이 있을 때만 받는다.
- 동의 기록: 동의 시각, 공급자, 동의 문구 판(앱 상수). Gemini는 동의 녹음을 보냈다는 것만 남기고 녹음은 남기지 않는다.
- 업로드 검사는 서버가 다시 한다: 파일 앞 바이트(RIFF/WAVE, PCM), 표본율·채널·비트, 길이(바이트로 계산), 크기 상한(60초 WAV 약 2.88MB + 머리말, Gemini 원본+동의 합계 4MB 이내).
- 로그에는 공급자·사유·필드 경로만 남긴다. 원본 바이트·base64·응답 본문을 남기지 않는다.
- 이 라운드는 34행 security 리뷰 대상이다.

| 경우 | 처리 |

| 공급자 성공 뒤 DB 저장 실패 | 행은 `sending`으로 남아 5분 뒤 `unknown`. 다시 부르지 않는다 |
| 지운 클론을 쓰던 프리셋·문단·드라마 화자 | 성우 없음 안내, 만들기 막힘(Q-03) |

## 10. 구조 (계획에서 확정)

- DB: 새 표 `my_voice`(owner_id, provider, provider_voice_id, name, status, reason, request_id, fingerprint, consent_at, consent_version, 시각). 보관함 행은 (소유자, 공급자, 공급자 id)로 찾는다(계획 2.1).
- API: `myVoiceList`, `myVoiceCreate`(File 입력), `myVoiceCheck`, `myVoiceDelete`(치우기 포함), `myVoiceSave`(보관함에 다시 담기). 공급자 모듈에 `cloneCreate`·`cloneGet`·`cloneDelete`(Fish, Gemini).
- 화면: `app/(app)/my-voices/page.tsx`, 목록·만들기 창·지우기 확인 컴포넌트, 브라우저 녹음·WAV 변환 lib.

## 11. 수용 기준

1. Fish Audio·Gemini 각각 녹음 또는 파일로 만든 클론이 사용 가능이 되면 성우 보관함에 담기고, 프리셋·작업실에서 고를 수 있다. 드라마 화자 성우로도 고를 수 있다(장면 연기는 Fish 전용이라 Fish 클론만, 혼합 대본 읽기는 둘 다 — 2026-11-18 통합 확인에서 바로잡음).
2. 같은 요청 id를 두 번 보내도(동시 포함) 공급자 클론 호출은 1회다. 다른 요청 id 둘을 동시에 보내도 진행은 1건이다.
3. 원본은 DB·디스크에 없다(표 컬럼·로그·임시 파일 없음). 창을 닫으면 마이크가 꺼지고 object URL이 해제된다.
4. 지우기를 시작하면 그 클론으로 시험 생성·작업실·드라마 생성이 공급자를 부르지 않고 막힌다(보관함에 다시 담은 행으로 보내도 같다). 삭제가 확인되면 보관함에서 빠지고 프리셋은 '성우를 다시 골라 주세요'가 된다. 실패하면 삭제 대기로 남고 다시 시도할 수 있다.
5. 다른 소유자(B)는 A의 내 보이스 행을 보거나 확인·지우기·치우기를 할 수 없고(`NOT_FOUND`, 공급자 호출 0회), 소유자 없는 요청은 `UNAUTHORIZED`다.
6. Fish 요청에 `visibility=private`가 들어가고 `references`는 없다.
7. 공급자 오류(401·403·402·429·5xx·시간 초과)가 tts-provider 표의 코드·사유로 바뀌고 화면은 사유별 문구를 보인다.
8. 원본 길이·형식이 공급자 범위 밖이면 브라우저가 막고, 서버도 다시 막는다.

## 12. 자동 테스트 (vitest)

- API: 만들기(성공·processing·실패·품질 실패·unknown·같은 id 재생·다른 입력 같은 id·동시 1건), 상태 확인, 지우기(성공·404·실패 뒤 대기·재시도), 치우기, 보관함 자동 담기·지운 뒤 프리셋 null, 시험 생성·작업실·드라마 막기(삭제 대기, 다시 담은 행, 남의 클론 id), 담기·프리셋의 클론 매핑 검사와 회귀, `savedVoiceCheck`가 클론을 되살리지 않음, 격리(B·소유자 없음). 공급자는 `vi.stubGlobal("fetch")`로만.
- 공급자 모듈: Fish multipart 필드(`visibility=private`, `train_mode=fast`, `references` 없음), Gemini JSON(`store: true`, base64, mime), 오류 매핑.
- 화면 lib: WAV 인코딩(머리말·표본율·길이), 길이 판정, 무음 판정.

## 13. 테스트 시나리오 (브라우저 QA, 가짜 응답, 유료·상태 변경 호출 0회)

공급자 호출은 가짜 RPC로 대신하고 만들기·지우기 버튼은 가짜 응답에서만 누른다.

1. 빈 목록 → 만들기 → Fish·이름 → 파일(20초) → 듣기 → 동의 → 보내기 → 사용 가능 → 보관함에 보임.
2. Gemini → 원본 파일 → 동의 녹음 파일 → 동의 → 보내기 → 사용 가능.
3. 녹음: 마이크 권한 허용(가짜 장치)·거부·장치 없음, 상한 도달 자동 멈춤, 다시 녹음.
4. 너무 짧음(5초)·김(Gemini 40초)·풀 수 없는 파일·무음.
5. 처리 중 → 상태 확인 → 사용 가능. 실패·미확인 줄의 안내와 치우기.
6. 지우기 확인 창(연결 프리셋 2개 표시, 기본 초점 취소) → 삭제 대기(가짜 실패) → 다시 시도 → 사라짐, 프리셋 '다시 골라 주세요', 그 클론을 쓰던 `/studio` 문단과 `/drama` 화자는 성우 없음 표시·만들기 막힘. 실패 줄의 '목록에서 치우기'.
7. 보내는 중 두 번 누르기(한 번만 감), 다른 만들기 진행 중 안내, 429 대기.
8. 너비 1440·1024·390, 라이트·다크, 키보드만으로 만들기 창 끝까지, Esc·포커스 복귀, 200% 확대.

## 14. 사용자 테스트 (구현 뒤, 각각 승인 뒤)

1. Fish Audio: 본인 녹음으로 클론 만들기 → 작업실에서 한국어 한 문단 생성·청취 → 지우기. (클론 만들기·생성·지우기 실제 호출 승인)
2. Gemini: 원본·동의 녹음으로 클론 만들기 → 한국어 생성·청취 → 지우기. 계정 등급이 무료면 실패 안내가 맞는지 본다.
3. 계정이 막혀 실제로 만들지 못한 공급자는 '미검증'으로 보고하고 T13을 완료로 치지 않을지 사용자와 정한다(REQ-13 수용 문장).

## 15. 위험과 확인할 것

- Fish 무료 플랜이 API 클론을 거절할 수 있다(문서에 없음). 사용자 테스트 1에서 처음 안다.
- (해결 2026-11-18) Gemini 맞춤 성우는 합성 요청의 `speech_config[].voice`에 맨 `voice_…` id로 넣는다. 지금 Gemini 생성 코드를 바꾸지 않는다([계획](T13-my-voice-plan.md) 2.2).
- Safari `MediaRecorder`(mp4/aac)를 `decodeAudioData`가 푸는지 QA에서 확인한다. 안 되면 파일 고르기를 안내한다.
- 한국어 클론 품질은 공급자 문서에 언급이 없다. 사용자 청취로만 판단한다.
- 클론 요금은 공급자 문서에 없다. 실제 차감은 사용자 테스트 때 공급자 화면으로 본다.
