## 1. 목표

문단 작업실에서 만든 작업에 제목을 붙여 서버에 저장하고, 나중에 찾아 작업실에 그대로 다시 열거나 지금 작업 끝에 이어 넣는다. 저장한 대본을 열어 고쳐도 '저장'을 누르기 전에는 원본이 바뀌지 않는다. 만들기를 누른 작업은 최근 대본으로 자동으로 남아, 이름을 붙이지 않았어도 되찾을 수 있다.

지금은 작업실의 대본이 브라우저에 하나만 남는다(임시 작업). 다른 대본을 붙여 넣으면 앞 작업은 되돌리기 10초가 지나면 사라진다.

## 3. 대본과 작업의 관계

- **임시 작업**은 지금처럼 브라우저 키 `tts-pilot:studio:v2:work`에 하나 남는다. 여기에 두 칸을 더한다(키·판 번호는 그대로, 없어도 읽는다).
  - `id`: 작업 id. 작업을 통째로 바꿀 때(붙여 넣기 '전체 바꾸기', 보관함에서 '바꾸기') 새로 받는다. 최근 대본은 작업 id마다 한 줄이다. 최근 대본을 바꾸기로 열면 그 작업 id를 이어 쓴다.
  - `linked`: 연결된 대본(대본 id, 제목, 판 번호, 저장할 때의 작업 지문). 바꾸기로 저장 대본을 열거나 새 대본으로 저장하면 생긴다. 연결된 대본을 지운 것을 알게 되면 비운다.
- **저장 안 됨**은 지금 작업의 지문(작업 id·연결 칸을 뺀 작업 전체)이 연결된 대본의 지문과 다를 때다. 되돌려서 같아지면 다시 저장됨이다.
- **원본 보존:** 저장 대본은 '저장'·'덮어쓰기'로만 바뀐다. 열기·넣기는 작업으로 복사할 뿐이다. 이어 넣기는 연결을 바꾸지 않는다.

## 4. 화면과 흐름

상세 모양·문구·키보드는 브리프. 여기서는 동작만 정한다.

### 4.1 대본 보관함 `/scripts`

- 메뉴 '대본 보관함'(지금 '준비 중' 항목을 '드라마 작업실' 다음 열린 화면으로). 페이지 머리, 구역 전환 '저장한 대본'·'최근 만든 대본'.
- **저장한 대본:** 검색 칸(입력을 멈추고 0.3초 뒤 찾음), 채널 고르기, 분류 고르기(카테고리·타입 여러 개. 같은 그룹 안은 하나라도 맞으면, 그룹끼리는 모두 맞아야 한다 — 성우 보관함 `filterSaved`와 같다). 줄마다 제목, 원문 첫 부분 미리 보기, 문단 수·글자 수, 채널, 분류 칩, 바꾼 시각. 아래로 내리면 다음 30개를 받는다(무한 스크롤, 끝에 '더 보기' 버튼도 둔다).
- 줄 동작: '작업실에서 열기'(→ `/studio?script=<id>`, 4.3 바꾸기), 고치기(창: 제목·채널·분류), 복제(창 없이, 분류도 복사), 지우기(확인 창). 원문은 여기서 고치지 않는다. 작업실에서 열어 고치고 저장한다.
- **최근 만든 대본:** 최대 20줄. 줄마다 첫 문장, 문단 수, 만든 시각. 동작은 '작업실에서 열기', '보관함에 저장'(제목·채널·분류 창), 지우기(확인 창). 검색·거르기는 없다.
- 빈 상태·불러오는 중·오류·소유자 없음(주소 안내)을 각각 보인다. 검색 결과 없음은 빈 상태와 문구가 다르다.

### 4.2 작업실 '대본' 메뉴

- 작업실 머리의 채널·프리셋 옆. 연결된 대본이 있으면 버튼에 그 제목, 저장 안 됨이면 표식과 '저장 안 됨'.
- 항목: '저장'(연결된 대본이 있고 저장 안 됨일 때만 누를 수 있다), '새 대본으로 저장…'(제목·채널·분류 창. 제목 처음 값은 첫 문장 앞 100자, 채널은 작업 채널), '보관함에서 넣기…', '대본 보관함' → `/scripts`.
- 저장은 현재 작업을 그대로 보낸다. 만들기·숫자 검수 상태와 상관없다. 빈 작업(비지 않은 문단 0개)은 저장할 수 없다.

### 4.3 보관함에서 넣기와 바꾸기

- '보관함에서 넣기' 창: 4.1과 같은 검색·목록(저장한 대본·최근, 무한 스크롤). 고르면 미리 보기(문단 N개, 글자 수)와 넣는 방식 '이어 넣기' | '바꾸기'(처음 값 이어 넣기. 지금 대본이 비었으면 늘 바꾸기). 붙여 넣기 창과 같은 말과 경고를 쓴다.
- **이어 넣기:** 고른 대본의 문단을 끝에 붙인다(끝 빈 문단 자리부터). 문단마다 글·자기 성우와 설정·쉼·화자·숫자 검수 결정을 가져오고 문단 id는 새로 받는다. 성우를 따로 고르지 않은 문단은 지금 기본 성우를, 쉼을 비운 문단은 지금 문단 뒤 쉼을 따른다. 없는 화자는 그 성우와 함께 화자 목록에 더한다(20명까지, 넘으면 그 문단의 화자를 비운다). 합쳐 200문단을 넘으면 넘는 문단은 넣지 않고 알린다. 연결된 대본은 그대로다. '되돌리기' 알림 10초.
- **바꾸기:** 작업 전체(기본 성우·쉼·채널·화자·문단)를 그 대본으로 바꾼다. 저장 대본이면 연결된 대본이 되고, 최근 대본이면 연결이 없다(작업 id는 그 최근 대본 것). '되돌리기' 알림 10초(되돌리면 연결도 되돌린다).
  - 지금 작업이 연결된 대본과 다르면(저장 안 됨) 먼저 미저장 경고 창: '저장하고 바꾸기'·'저장하지 않고 바꾸기'·'취소'. 저장이 충돌하면 4.4 충돌 창으로 간다.
  - 연결된 대본이 없고 지금 작업에 글이 있으면 '지금 작업을 바꿔요'만 확인한다(최근 대본·되돌리기로 되찾을 수 있다는 안내).
- `/scripts`의 '작업실에서 열기'는 작업실이 열리면 같은 바꾸기 확인을 거친다. 작업실은 주소의 `script`를 한 번 읽은 뒤 주소에서 뺀다.
- 성우 보관함에서 뺀 성우는 임시 작업을 되살릴 때와 같은 규칙(`checkedWork`)으로 비우고 같은 안내를 한다.

### 4.4 저장과 충돌

- '저장'은 연결된 대본의 판 번호를 함께 보내고, 서버는 그 판일 때만 바꾸고 판을 하나 올린다.
- **충돌**(다른 곳에서 먼저 저장): 창 "다른 곳에서 이 대본을 먼저 저장했어요". '새 대본으로 저장'(제목 '{제목} 사본'으로 새 대본 창), '덮어쓰기'(판 조건 없이 지금 작업으로 바꾸고 판을 올린다), '취소'(아무것도 바꾸지 않음). 어느 쪽도 묻지 않고 사라지지 않는다.
- **지워진 대본:** "보관함에서 지워진 대본이에요" — '새 대본으로 저장'·'취소'. 연결을 비운다.
- 제목·채널·분류만 바꾸는 `/scripts` 고치기는 판을 올리지 않는다(작업실 저장과 충돌하지 않는다).

### 4.5 최근 대본 자동 보관

- 만들기(카드 만들기, 전체 만들기·이어서 만들기)가 공급자 요청을 하나라도 보낼 때, 그 작업을 작업 id의 최근 대본으로 보관한다(있으면 덮어쓰고 시각을 올린다). 한 번의 만들기에 한 번이다. 저장된 결과만 트는 것은 보관하지 않는다.
- 20개를 넘으면 가장 오래된 최근 대본을 지운다.
- 보관이 실패해도 만들기를 막거나 알리지 않는다(다음 만들기에 다시 보관한다).

## 5. 성능 (상한 없는 목록)

- 목록 API는 요약 칸만 돌려준다(제목, 원문 앞 160자, 문단 수, 글자 수, 채널, 분류, 바꾼 시각). 작업 전체(jsonb)는 하나를 열 때만 받는다.
- 커서 방식으로 30개씩 받는다(바꾼 시각 + id 순서. 건너뛰기 방식 아님). 화면은 TanStack Query의 무한 목록으로 붙여 간다.
- 검색은 제목·원문 칸에 trigram 인덱스를 둔다(`pg_trgm`, 한글 확인: 로컬 PostgreSQL 18, 2026-11-18). 검색어가 3자 이상이면 인덱스를 타고, 1~2자는 그 소유자 행만 차례로 본다. `%`·`_`는 글자 그대로 찾는다. 확장 도입은 ADR로 남긴다.
- 원문 검색 칸(`body`)은 저장할 때 서버가 문단 글로 만든다(클라이언트가 따로 보내지 않는다).
- 긴 목록 줄은 화면 밖 렌더링을 미룬다(`content-visibility`). 가상 목록은 쓰지 않는다.

## 6. 오류와 경계

| 경우 | 서버 | 화면 |
|---|---|---|
| 같은 제목 | CONFLICT `duplicate_name` | 창 안 "같은 이름의 대본이 있어요" |
| 판이 다름 | CONFLICT `stale` | 4.4 충돌 창 |
| 없는 대본·남의 대본 | NOT_FOUND(구분하지 않음) | 지워진 대본 처리(4.4) 또는 "이미 지워졌거나 찾을 수 없어요" |
| 남의 채널·분류 | NOT_FOUND | 창 안 오류 |
| 대본 상한 | BAD_REQUEST | 저장 전 화면에서 먼저 막는다 |

- 대본 하나의 상한: 비지 않은 문단 1~200개, 문단 글 10,000자(만들기 상한 2,000자는 작업실이 따로 막는다), 화자 20명, 분류 50개, 작업 JSON 2 MB. 서버가 입력에서 검사한다.
- 서버는 작업 칸을 정해진 모양(zod)으로 검사해 저장하고, 화면은 읽을 때 `readWork`로 한 번 더 검사한다.
- 모든 프로시저는 `protectedProcedure`와 서버가 정한 `context.ownerId`로만 소유자를 정한다.

## 7. 범위

### 포함

- `/scripts` 화면, 메뉴 열기, 작업실 '대본' 메뉴와 창 넷(새 대본으로 저장, 보관함에서 넣기, 미저장 경고, 충돌).
- 새 표(저장 대본·최근 대본)와 분류 연결 표, 마이그레이션, 프로시저(목록·하나 받기·만들기·저장·고치기·복제·지우기·최근 보관), 2계정 격리 테스트.
- 임시 작업에 작업 id·연결된 대본 칸.
- 문서: GLOSSARY(저장 대본·최근 대본·대본 보관함·임시 작업·연결된 대본, 2026-11-18 반영), `docs/domain/project.md`, 사이트맵, 로드맵, ADR(검색 인덱스).

### 만들지 않는 것 (ponytail)

- 드라마 장면 저장(백로그 T12-01).
- 판 기록·이전 판으로 되돌리기, 두 판 비교·합치기. 충돌은 세 갈래 선택으로 끝낸다.
- `/scripts`에서 원문 직접 편집, 대본 미리 듣기.
- 파일 가져오기·내보내기(200,000자 가져오기는 작업실에 없어 Q-02 안에서 지운다), 폴더, 즐겨찾기, 공유.
- 저장 대본 개수 상한, 가상 목록, 서버 전문 검색(형태소).
- 페이지를 떠날 때의 경고, 자동 저장(임시 작업이 맡는다).
- 생성 결과(소리)를 저장 대본에 묶기. 다시 열고 같은 조합으로 만들면 지금처럼 저장된 결과를 다시 쓴다.

## 8. 구조 (계획에서 확정)

- DB: 표 하나에 종류(`saved`·`recent`)를 두는 안과 두 표로 나누는 안을 계획에서 정한다. 어느 쪽이든 저장 대본은 (소유자, 소문자 제목) 유일, 최근 대본은 (소유자, 작업 id) 유일, 목록 인덱스(소유자, 종류, 바꾼 시각 desc, id desc), 채널 외래 키 인덱스, trigram 인덱스, 분류 연결 표(양쪽 cascade, 역방향 인덱스).
- API: `packages/api`에 `script` 라우터. 작업 모양 zod는 서버 계약 파일에 두고 화면 `Work` 타입과 맞춘다.
- 화면: `/scripts` 페이지(Server Component 껍데기 + Client 목록), 작업실 '대본' 메뉴·창, `WorkProvider`의 바꾸기·이어 넣기·연결 상태, 만들기 경로의 최근 보관.

## 9. 수용 기준

1. 작업실에서 '새 대본으로 저장'하면 `/scripts` 목록 맨 위에 나오고, 작업 머리에 그 제목이 보인다.
2. 저장 대본을 바꾸기로 연 뒤 문단을 고치면 '저장 안 됨'이 되고, `/scripts`에서 다시 열거나 새로 고친 화면의 그 대본은 고치기 전 그대로다. '저장'을 누른 뒤에만 바뀐다.
3. 고친 것을 되돌려 저장한 내용과 같아지면 '저장 안 됨'이 사라진다.
4. 저장 안 됨 상태에서 다른 대본을 바꾸기로 열면 미저장 경고가 뜨고, 세 갈래가 각각 그대로 동작한다.
5. 두 탭에서 같은 대본을 고쳐 차례로 저장하면 두 번째 탭에 충돌 창이 뜬다. '새 대본으로 저장'·'덮어쓰기'·'취소'가 각각 동작하고 첫 탭의 저장은 '덮어쓰기'를 고르기 전까지 남는다.
6. 이어 넣기는 고른 대본의 문단을 성우·설정·쉼·화자·숫자 검수 결정과 함께 끝에 붙이고, 연결된 대본과 기본 성우를 바꾸지 않는다. 200문단 상한과 화자 20명 상한을 넘으면 알린다.
7. 숫자 검수 결정이 있는 대본을 저장하고 다시 열면 결정과 발음용 대본이 저장 전과 같다.
8. 만들기를 누르면 최근 만든 대본에 그 작업이 하나 생기고, 같은 작업으로 다시 만들면 줄이 늘지 않고 시각만 바뀐다. 21번째가 생기면 가장 오래된 것이 지워진다.
9. 검색은 제목·원문 어디에 있어도 찾고, 채널·분류 거르기와 함께 쓸 수 있다. 1~2자 검색어도 찾는다.
10. 대본이 30개를 넘으면 내려갈 때 다음 30개가 붙고, 목록 응답에 작업 전체가 들어 있지 않다.
11. 복제·고치기(제목·채널·분류)·지우기가 동작하고, 같은 제목은 막힌다.
12. 다른 소유자의 대본은 목록에 없고, 받기·저장·고치기·복제·지우기·최근 보관이 모두 NOT_FOUND다.
13. 결정이 없는 작업의 만들기 요청과 조합 키는 T12 전과 바이트 단위로 같다(임시 작업에 더한 칸이 요청에 들어가지 않는다).

## 10. 자동 테스트 (vitest)

- 서버: 프로시저 단위 테스트(만들기·제목 중복·판 조건 저장·충돌·덮어쓰기·복제 이름·지우기·목록 커서·검색 `%`·`_`·거르기·최근 보관 덮어쓰기와 20개 정리·상한 거절), 2계정 격리 테스트(`script.isolation.test.ts`).
- 화면 lib: 작업 지문(연결 칸 제외, 되돌리면 같음), 이어 넣기(id 새로, 화자 합치기와 20명, 200문단), 바꾸기·되돌리기의 연결 복원, `readWork`가 새 칸을 검사하고 옛 작업을 그대로 읽음, 요청 바이트 동일 회귀.

## 11. 테스트 시나리오 (브라우저 QA, 가짜 응답, 유료 호출 0회)

- 정상: 새 대본으로 저장 → `/scripts`에 보임 → 고치기·복제·지우기 → 작업실에서 열기(바꾸기) → 고치기 → 저장 안 됨 → 저장.
- 빈: 대본 없음(두 구역), 검색 결과 없음, 빈 작업은 저장 잠김.
- 오류: 목록 오류 '다시 불러오기', 같은 제목, 충돌(두 탭), 지워진 대본에 저장.
- 경계: 200문단 이어 넣기, 화자 21명째, 1·2자 검색, `%` 검색, 30개 넘는 목록 스크롤, 최근 21번째.
- 너비 390·768·1440, 라이트·다크, 키보드만으로 저장·넣기·충돌 창 고르기, 창 닫은 뒤 포커스 복귀.
- 만들기는 가짜 RPC로만 한다(최근 보관 확인). `window.__sent`에 유료 생성 0.

## 12. 사용자 테스트 (구현 뒤 드린다)

1. 대본을 '새 대본으로 저장'하고 `/scripts`에서 찾는다(제목·본문 검색, 채널·분류 거르기).
2. 작업실에서 열어 고친 뒤, 저장하지 않고 다른 대본을 열어 미저장 경고를 본다. 원본이 그대로인지 확인한다.
3. 두 탭에서 같은 대본을 고쳐 충돌 창을 본다.
4. 다른 대본을 이어 넣고, 만들기를 눌러 최근 만든 대본에 생기는지 본다(만들기는 원하실 때만).
