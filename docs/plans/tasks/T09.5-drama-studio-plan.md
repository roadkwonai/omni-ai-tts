# T9.5 드라마 작업실 (Fish Audio Drama 3) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/drama`에서 화자 1~4명의 줄 단위 대본을 Fish Audio 한 요청으로 연기시켜 장면 WAV를 저장하고, 시각 정보로 줄마다 자른 대사 WAV를 받는다. 같은 대본의 테이크를 여러 개 만들어 줄마다 고른다.

**Architecture:**
- `packages/db`: `trial_generation`에 `kind = 'drama'`, `script`·`segments` jsonb, 드라마 목록 부분 인덱스. 마이그레이션 하나.
- `packages/api`:
  - `drama-script.ts`(새, zod·node 모듈 없음): 상수, 보낼 글 조립, 청크 합치기, 줄 나누기, WAV 머리·자르기, 사용량. 화면도 값으로 가져간다.
  - `drama-contract.ts`(새): 요청·출력 zod.
  - `trial.ts`: 실패 기록 한 곳(E7), 선점·늦은 결과·조각·사용 이력을 kind·성우 여럿으로 일반화, 드라마 목록.
  - `providers/fish-audio.ts`: `synthesizeScene`(시각 정보 SSE, PCM).
  - `routers/drama.ts`(새): 프로시저 넷.
- 화면: 순수 함수 `lib/drama-view.ts`·`lib/drama-zip.ts`, `DramaProvider`(상태·데이터·생성), 화자 줄·성우 고르기 창·대본·붙여 넣기·연기 지시 칸·하단 막대·확인 창·무대·이전 테이크.

**Tech Stack:** Next.js 16.3 App Router(React Compiler), React 19.3, oRPC 1.15.4, TanStack Query 5.103, zod 4.6.5, drizzle-orm·drizzle-kit 1.0.0-rc.4, Postgres 18(로컬 5433), vitest 5, shadcn `base-lyra`(Base UI 1.8.0), Tailwind CSS 4, Biome 2, Node 24.22.0(undici 7.29.1). 새 의존성 없음.

## 스펙과 다른 점 (계획 리뷰에서 확인한다)

1. **값과 순수 함수는 zod 없는 `drama-script.ts`에 둔다.** 스펙 7절은 상한 상수를 `drama-contract.ts`에, WAV 자르기를 `drama-view.ts`에 두었다. 화면은 zod에 의존하지 않으므로(T9 '스펙과 다른 점' 1) 상수·조립·나누기·WAV 머리와 자르기를 한 파일에 두고 api와 web이 함께 쓴다. `cutWav` 테스트는 api 쪽에서 돈다.
2. **유료 모델 둘(`drama-3`·`s2.1-pro`) 모두 동전 표식·확인 창·추정 금액을 쓴다.** 스펙 4절 일부가 "Drama 3는"이라 적었지만 2절 확인 창 행과 8절 4번이 두 모델 모두다.
3. **Fish 장면 요청은 180초 시간 초과로 끊지 않고, 따로 둔 300초 상한(`SCENE_LATE_MAX_MS`)으로만 끊는다.** `runTrial`의 신호를 넘기면 180초에 요청이 끊겨 늦은 결과(스펙 2절·8절 10번)가 오지 않는다. 반대로 아무 신호도 없으면 끝이 없다. undici 7.29.1의 본문 300초는 데이터 사이의 공백 시간이고(`client-h1.js` `onBody`마다 `refresh()`), SSE는 머리가 바로 오기 때문이다(계획 리뷰 E2·P8). 300초 상한은 T9 화면의 6분 다시 받기 창 가정을 지킨다.
4. **무료 기간(2026-11-30 KST) 뒤 `s2.1-pro-free`는 `free_ended`로 거절한다.** 스펙 5절 표에 없는 경우다. T5 `trialCreate`와 같다.
5. **"다른 생성이 진행 중이에요"와 대기 시각은 오류 줄이다.** 스펙 4절은 막는 이유에 넣었다. 화면은 다른 탭의 진행을 모른다. 이 화면이 만드는 중이면 버튼이 '연기하는 중 · N초'로 잠긴다(T9 '스펙과 다른 점' 6).
6. **줄이 있는 화자는 뺄 수 없다.** 스펙에 없는 상태다. 그 화자의 줄을 지우거나 다른 화자로 바꾼 뒤에 뺀다. 이유 문구는 브리프가 정한다.
7. **쓸 수 없는 성우의 화자 이름은 화면이 찾는다.** 서버는 사유 `voice_unavailable` 하나만 준다(오류 계약을 바꾸지 않는다). 화면은 담은 성우 목록을 다시 받아 성우가 없거나 이용 불가인 첫 화자로 스펙 5절 문구를 만든다. 못 찾으면 "성우를 쓸 수 없는 화자가 있어요. 다시 골라 주세요".
8. **'Fish Audio 전체' 탭은 `ServerVoiceList`를 그대로 쓴다.** 스펙 7절 파일 표에 없는 `server-voice-list.tsx`에 판별 유니온 prop(`onChoose` 또는 `pick`)을 더한다. `pick`이면 `CastingWorkspace`(옆 패널) 없이 목록만 그리고, 행을 누르면 `pick(voice)`를 부른다. 캐스팅 동작은 그대로다.
9. **공통 도우미를 옮기거나 넓힌다.** `studio-provider.tsx`의 `saveBlob`·`loadStored`·`store`를 `lib/browser.ts`로 옮긴다(코드 그대로). `lib/studio-view.ts`의 `safeName`·`kstStamp`를 내보내고, `fetchAudio`에 형식 인자(기본 `audio/mpeg`), `pickableVoices`·`savedOf`에 공급자 인자(기본 `typecast`), `unknownNoteOf`에 만료 문구 인자(기본 `STUDIO_TEXT.unknownExpired`)를 더한다.
10. **Enter는 어느 줄에서든 그 줄 바로 뒤에 다음 화자의 새 줄을 만든다.** 스펙 4절은 마지막 줄만 적었다. 한글 입력 조합 중(`isComposing`·keyCode 229)의 Enter는 무시한다. 쪼갤지(커서 뒤 글을 새 줄로)는 브리프 DN-4.
11. **붙여 넣기 '바꾸기'의 화자 규칙은 브리프(사용자 확인)가 정한다.** 스펙 4절("처음 보는 이름은 새 화자")대로면 기본 화자 '화자 1·2'가 남아 사용자 테스트 1→2번에서 화자가 넷이 되고 막힌다(계획 리뷰 P5). 초안: 붙여 넣은 이름 순서로 화자를 다시 만들고, 이름이 같으면 성우를 잇는다. 겹치는 이름이 하나도 없으면 지금 화자의 성우를 순서대로 잇는다. 미리 보기에 화자마다 성우가 이어지는지 보인다.
12. **줄 나누기는 글자 수가 아니라 글자를 비교한다.** 스펙 2절은 "대사 글자 수만큼 차례로 배정"이다. 수만 맞추면 지시를 소리 내 읽거나 숫자를 읽은 글로 돌려줄 때 틀린 파일이 '맞음'으로 나간다(계획 리뷰 E3, 스크래치로 재현). 자료 두 벌의 구간은 그대로다.
13. **나누지 못함이 되는 경우를 더한다.** 지시뿐인 줄(대사 글자 0), 대사에 쌍 태그 이름과 같은 영어 단어(`soft`·`slow`·`fast`·`stress`·`whisper`·`emphasis`·`forceful`, 단어의 일부 포함)가 있는 줄, 시각이 거꾸로 가거나 장면 길이를 넘는 정렬. 셋 다 틀린 파일을 내보낼 수 있는 경우다(E4·E8·E15). 앞의 둘은 만들기 전에 막대에 경고 한 줄을 보인다(막지 않는다).
14. **장면 글자 ÷ 속도 ≤ 2,000.** 2,000자를 속도 0.5로 만들면 오디오가 32MiB를 넘어 유료 호출 뒤 버려진다(자료로 잰 말 빠르기 초당 약 9자, 계획 리뷰 E6). 계약과 막는 이유에 `sceneChars ≤ floor(2,000 × min(1, speed))`를 둔다. 속도 1 이상이면 스펙 상한과 같다.
15. **코드 이름은 `speakers`·`speaker`다.** GLOSSARY '화자(Speaker)'는 '배역'(cast)을 피한다. 스펙 3절 계약의 `cast` 칸 이름도 Task 12에서 함께 고친다.
16. **메뉴는 `bar: false`다.** 767px 이하 위 막대는 4칸 계약(bar 셋 + 더보기, T6 스펙 2절, `app-nav.tsx:37`)이다. 사이드바·더보기에서 '음성 작업실' 바로 아래다.

## Global Constraints

- 커밋은 라운드 끝에 한 번 한다. 태스크 경계는 장부에 tree SHA로 적는다. 도구는 `.superpowers/sdd/T09.5-drama-studio-plan/tools/`(`snap.sh`·`pkg.sh`·`testdb.env`·`next-mcp.py`, 코디네이터가 두었다).
- 비밀값: `apps/web/.env`·`packages/db/.env`를 읽거나 출력하지 않는다. 테스트 DB 주소는 `source .superpowers/sdd/T09.5-drama-studio-plan/tools/testdb.env`로만 넘기고, 증거에는 "로컬 5433 `tts-pilot-app_test`"만 적는다.
- 공급자와 개발 서버:
  - 실제 공급자를 부르지 않는다. 테스트의 공급자는 가짜 `synthesizeScene`(라우터)과 `fetchMock`(공급자 모듈)뿐이다.
  - 구현 서브에이전트는 개발 서버(`127.0.0.1:3001`)로 어떤 요청도 보내지 않고, 서버를 끄거나 켜지 않는다. `pkill`·`killall`·`.next` 삭제 금지.
  - `pnpm build`·DB 명령(`db:generate`·`db:migrate`·`psql`)·`shadcn add`·런타임 확인은 코디네이터만 한다.
  - 실제 생성은 사용자 테스트(스펙 11절)에서 사용자가 공급자·모델·UTF-8 바이트·횟수를 보고 승인한 뒤에만 한다.
- 로컬 관리자 모드: 소유자는 `context.ownerId`에서만 얻는다. 모든 select·update·delete에 `owner_id` 조건을 건다. 프로시저 넷 모두 `protectedProcedure`다. Server Action·새 Route Handler를 만들지 않는다.
- 화면별 기록: 드라마는 `kind = 'drama'` 행만 읽고 지운다. 내 문장 듣기·음성 작업실의 조회는 지금 그대로 자기 kind만 본다. 동시 1건(`trial_generation_one_pending`)은 세 화면을 합쳐 센다.
- `drama-script.ts`는 zod·`node:*`·`Buffer`를 쓰지 않는다(화면 번들). 바이트는 `Uint8Array`·`DataView`로 다룬다. 화면은 계약 파일에서 `import type`만 한다.
- 모델 값은 `DRAMA_MODELS` 셋뿐이고 Fish `model` 헤더에 그대로 넣는다. 철자가 틀리면 Fish가 유료 `s2.1-pro`로 조용히 바꾼다.
- 로그는 한 줄이다: 라우터 `[drama] <단계> 실패: <오류 이름> <DB 코드>`(`guard`), 공급자 예외는 공통 틀 `runTrial`의 `[trial] fish_audio 생성 실패: <이름>` 그대로, 정렬 버림은 `[drama] 정렬 버림: <이유>`. 대본·성우 id·글·오디오를 로그나 `ORPCError`의 `cause`·`data`에 넣지 않는다.
- 상한: 화자 1~4, 이름 1~20자, 장면 이름 0~40자, 줄 1~50, 대사 1~300자, 지시 0~60자, 장면 합계 `floor(2,000 × min(1, speed))`자(지시 포함, NFC 정리 뒤 코드 포인트, 화자 표식 제외). 원문은 각 상한 × 4 UTF-16 단위까지만 받는다. 오디오 32MiB(`STUDIO_AUDIO_MAX`), 조각 3MiB(`STUDIO_PART_BYTES`), 조각 번호 0~10.
- 캐시 키: 무효화는 `orpc.dramaList.key()`. 담은 성우 목록 갱신은 기존 `writeBack`만 쓴다.
- 입력 지연: 줄 목록은 `LinesProvider`의 작은 컨텍스트에만 둔다. 화자 줄·무대·이전 테이크는 줄을 읽지 않는다. 막대는 `useDeferredValue(lines)`를 읽는다.
- 화면 규칙: 색·간격·반경은 토큰과 Tailwind 기본 눈금만, 원시 hex·임의 값 금지, 굵기는 `font-normal`·`font-bold`. 인터랙티브 요소 44px 이상, 입력 칸은 767px 이하 `text-base md:text-sm`, `focus-visible` 표시, 오류·경고 글은 `text-warning`. 돈이 드는 동작에 `Coins` 표식. 가짜 진행률 없음. 한 번에 한 오디오만 재생(`usePlayer().stop`).
- 파일을 고친 뒤 `pnpm exec biome check --write <파일들>`.
- 패키지: 앱 `web`, API `@tts-pilot-app/api`, DB `@tts-pilot-app/db`. 테스트 `pnpm --filter @tts-pilot-app/api test [파일]`·`pnpm --filter web test [파일]`, 타입 `pnpm --filter <이름> check-types`. DB 테스트는 `TEST_DATABASE_URL`이 있을 때만 돌고 skipped는 통과가 아니다. web vitest는 `@/` 별칭을 못 푼다(`lib/*.ts`끼리는 상대 경로).
- ponytail: 스펙에 없는 추상화를 만들지 않는다. 의도한 한계는 `shortcut:` 주석으로 남긴다.

## 설치본·자료로 확인한 것

1. SSE 모양(`fish-drama-pcm-2026-10-22/events.json`): 이벤트 13개. 칸은 `audio_base64`·`content`·`alignment{segments[{text,start,end}],audio_duration}`·`chunk_seq`·`chunk_audio_offset_sec`. 청크 0은 세그먼트 1→4→4→9→14→23→25→26개로 누적 스냅샷을 보내고, 청크 1(오프셋 9.845260770975056초)은 1→1→5→6→7개다. 합치면 33개(`words.json`). 마지막 이벤트는 오디오가 빈 문자열이다. 오디오 이벤트는 청크 표시와 맞물리지 않으므로 오프셋은 `chunk_audio_offset_sec`로만 더한다(청크 0의 오디오 합 10.57초 ≠ 청크 0 `audio_duration` 9.845초). 블록 구분은 빈 줄, `data:` 줄만 읽고 `[DONE]`·빈 데이터는 건너뛴다(`pcm-check.mjs`).
2. PCM은 16비트 모노 44.1kHz little-endian이고 1,190,720바이트(595,360샘플) = 13.500226757369614초 = 마지막 청크 오프셋 + `audio_duration`.
3. 시각 정보에는 지시(`[놀라며]`·`[sighs]`·`[laughs]`)가 나오지 않고, 쌍 태그 이름이 앞뒤 세그먼트에 붙는다(`whisper팀장님은`, `셔whisper`, spike `whisper지갑아`·`하다whisper`). 길이 0초 세그먼트가 있다(spike `이` 6.08–6.08 등).
4. 자료 두 벌의 청크 경계는 모두 줄 시작이다. 줄 가운데 경계는 합성 자료로만 본다.
5. undici 7.29.1(`node_modules/.pnpm/undici@7.29.1`): `bodyTimeout`·`headersTimeout` 기본 300e3(`lib/dispatcher/client.js:261-262`), 본문 타이머는 조각마다 `refresh()`(`client-h1.js:697-701`). zod 4.6.5: `.default()`는 `undefined`만 바꾸고 `null`은 그대로라 `{chunk_seq: null}`·`{alignment: {}}`가 엄격한 스키마에서 실패한다.
6. `trial.ts`: `claim`이 `TrialRequest`에서 행을 만든다, `saveLate(db, ownerId, id, voiceId, late)`·`completeLate`가 `kind = 'studio'`·`audio/mpeg`에 묶여 있다, `recordUse`가 Typecast 한 명, `audioPart`가 작업실 행만. 실패 기록 블록이 둘이다(E7). `saveLate`는 `studio.ts:156`과 `trial-studio.test.ts`에서 부른다(`routers/studio.test.ts:515`는 주석).
7. `runTrial(provider, call, { timeoutMs, onLate })`는 제네릭이고 시간 초과에 `onLate(started)`를 부른 뒤 `unknown_outcome`을 던진다. HTTP 오류는 `trialReason`(402 → `quota`, 429 → `rate_limit` + `retryAt`). 그 밖의 예외는 `[trial] <provider> 생성 실패` 로그 뒤 `unknown_outcome`이다.
8. oRPC 1.15.4 `validateOutput`은 파싱 결과를 돌려준다. 그래서 음성 작업실 출력 스키마가 `replayStudio`의 `segments`를 걸러 낸다. `saved_voice`는 unique(owner_id, provider, voice_id)다.
9. `RowList`의 `select`는 `(voice, row)`를 받는다. `ServerVoiceList`는 목록을 `CastingWorkspace`의 렌더 함수 안에서 그린다(`server-voice-list.tsx:318-325`).
10. `studioProblemText`는 끝에서 `trialProblemText("typecast", …)`로 넘긴다. `usageText`가 `usd_micro`를 달러로 적는다.

### Task 21: 잇기 모듈 (`drama-join.ts`)

**Files:** Create `apps/web/src/lib/drama-join.ts`, `apps/web/src/lib/drama-join.test.ts`.

**Interfaces:**
- Consumes: `wavHeader`, `DRAMA_SAMPLE_RATE`, `WAV_HEADER_BYTES`(`@tts-pilot-app/api/drama-script`, 화면 번들에 이미 쓰인다).
- Produces:
  - 상수 `GAP_DEFAULT = 0.3`, `GAP_MAX = 5`, `SILENCE`, `EDGE_SECONDS`(Global Constraints 값).
  - `gapOf(value: unknown): number | null` — 유한한 수 또는 앞뒤 공백을 뺀 빈 글이 아닌 수 글(`Number`)만 받는다. 0~`GAP_MAX`로 자르고 0.1 단위로 반올림한다. 그 밖(빈 글, 글자, NaN, Infinity, 객체)은 null.
  - `gapText(seconds: number): string` = `seconds.toFixed(1)`.
  - `monoOf(channels: readonly Float32Array[]): Float32Array` — 하나면 그 배열 그대로, 여럿이면 샘플마다 평균, 없으면 길이 0.
  - `trimSilence(samples: Float32Array, rate?: number): Float32Array` — 절대값이 `SILENCE`보다 큰 첫·끝 샘플을 찾아 앞뒤로 `Math.round(EDGE_SECONDS * rate)` 샘플을 남긴 부분 뷰(`subarray`). 큰 샘플이 없으면 길이 0.
  - `pcm16(samples: Float32Array): Uint8Array<ArrayBuffer>` — 샘플마다 Global Constraints의 16비트 값, 리틀 엔디언.
  - `joinWav(parts: readonly Uint8Array<ArrayBuffer>[], gaps: readonly number[]): Uint8Array<ArrayBuffer>[]` — `[wavHeader(전체 데이터 바이트), parts[0], 무음0, parts[1], …]`. `parts[i]`(16비트 PCM) 뒤에 `gaps[i]`초 쉼(마지막 part 뒤는 넣지 않는다, `gaps`가 모자라면 0), 넣는 무음 샘플은 Global Constraints 식, 무음은 0으로 채운 `Uint8Array`(길이 0이면 넣지 않는다). 화면은 `new Blob(joinWav(…), { type: "audio/wav" })`로 쓴다.
  - 브라우저: `joinSounds(sounds: readonly { blob: Blob; gap: number }[]): Promise<Blob>` — `OfflineAudioContext(1, 1, DRAMA_SAMPLE_RATE)` 하나로 줄을 **차례로** `decodeAudioData`(결과는 44.1kHz로 맞춰지고 원본 채널 수를 지킨다) → 채널마다 `getChannelData` → `monoOf` → `trimSilence` → `pcm16`. 다 모으면 `new Blob(joinWav(parts, gaps), { type: "audio/wav" })`. 하나라도 실패하면 거절한다. 단위 테스트가 없다(jsdom에 Web Audio 없음, QA J1·J4). `shortcut:` 주석: 16비트 조각은 모두 쥔다(50줄 × 20초면 약 90MB + Blob 복사), 탭이 죽으면 조각을 더 일찍 Blob으로 넘긴다.
