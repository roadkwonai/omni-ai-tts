## 1. 목표

`/studio`에서 대본(최대 2,000자)과 담아 둔 Typecast 성우·설정으로 실제 한국어 음성을 만들고, 듣고, 내려받는다. 두 번 눌러도 공급자 요청은 1회이고, 다시 듣기와 내려받기는 생성 API를 다시 부르지 않는다.

뒤 TASK가 그대로 쓸 것을 만든다.
- 문단 카드 틀(번호·성우·대사·감정 표식)과 하단 막대. 문단 추가·분할·결합(P1-04~06)이 카드를 늘린다.
- 작업실 생성 경로(`studio*` 프로시저, 나눠 받기). T10이 다른 공급자를 붙인다.
- 감정 팔레트 틀. T10이 대괄호 태그 공급자에 쓴다.

## 3. 데이터와 API

**테이블** (마이그레이션 1개)

| 표 | 바꾸는 것 |
|---|---|
| `trial_generation` | `kind` text not null 기본 `'trial'`, check `kind in ('trial','studio')`. 작업실 목록용 부분 인덱스 `(owner_id, created_at desc) where kind = 'studio'`. 기존 행은 `trial` |
| `saved_voice` | `last_used_at` timestamptz null, `use_count` integer not null 기본 0 |

- 동시 1건 부분 유니크(`trial_generation_one_pending`)는 그대로라 두 화면을 합쳐 센다.
- 오디오(`audio` bytea)를 조각으로 읽을 때 압축 해제 비용이 없는지(`substring`, 컬럼 저장 방식)는 계획에서 확인한다.
- 이름은 그대로 `trial_generation`이다(표 이름 바꾸기는 하지 않는다). GLOSSARY '생성 기록'이 두 화면의 기록을 함께 뜻한다.

**프로시저** (모두 `protectedProcedure`, 소유자는 `context.ownerId`만)

| 프로시저 | 입력 → 출력 | 하는 일 |
|---|---|---|
| `studioCreate` | `{ requestId: uuid, request }` → `{ id, createdAt, usage, bytes }` | 유일한 유료 경로. T5 `trialCreate` 순서(재생 확인 → 대기 시각 → 추정 → 선점 → 합성 → 저장)에 성우 검사를 더한다. 오디오는 돌려주지 않는다 |
| `studioFind` | `request` → 위 출력 또는 `null` | 같은 조합의 저장된 결과. 공급자를 부르지 않는다 |
| `studioList` | 없음 → `{ id, createdAt, status('done'·'unknown'), usage, bytes, request }[]` | 최근 20개(완료와 처리 여부 미확인). 공급자를 부르지 않는다 |
| `studioAudio` | `{ id, part }` → 오디오 조각(File) | 3MiB 조각. 0번 조각을 받을 때 보관 기간을 늘린다(T5 `audioOf`와 같다) |
| `studioDelete` | `{ id }` → `{ deleted: true }` | 진행 중이 아닌 기록을 지운다 |

- `request`는 T5 Typecast 요청 계약(`provider: 'typecast'`, `voiceId`, `settings`)에 대본 `text`(NFC 정리 뒤 1~2,000 코드포인트)를 더한 작업실 요청이다. 이번에는 Typecast만 받는다.
- 없는 id·남의 기록·만료·완료가 아닌 기록의 조각은 `NOT_FOUND`(구분하지 않음).
- 작업실 결과의 오디오 상한은 32MiB(T5는 4MiB). 넘으면 T5와 같은 `audio_too_large`로 버린다.
- 성공하면(늦은 성공 포함) 같은 소유자·공급자·voice id의 `saved_voice`에 `use_count + 1`, `last_used_at = now()`. 보관함에서 빠졌으면 바꾸지 않는다.
- `savedVoiceList` 출력에 `lastUsedAt`(iso 또는 null)·`useCount`를 더한다.

## 4. 화면과 흐름

**`/studio` 음성 작업실**
- **머리:** 제목 '음성 작업실'. 오른쪽에 채널 고르기('채널 없음'이 맨 위, 채널이 하나도 없으면 '채널·분류에서 만들기' → `/classes`. `/voices` 드롭다운과 같다)와 '프리셋' 메뉴(T8 메뉴: Typecast 프리셋 목록·'지금 설정으로 새 프리셋 저장'·덮어쓰기·'프리셋 관리').
- **문단 카드(1장):**
  - 머리줄: `1` · 성우 버튼(이름 · Typecast. 없으면 '성우 고르기') · 감정 표식(기본값과 다를 때만) · '설정'(펼침).
  - '설정'을 펼치면 T5 Typecast 설정 칸(모델·감정 팔레트·강도·언어·속도·음높이·음량)과 '처음 값으로'.
  - 감정 팔레트: 뱃지마다 이름과 설명(브리프). 지금 값은 눌린 상태. 강도는 '자동'이 아닐 때만 보인다.
  - 대본 칸: 글자 수 `1,234 / 2,000자`. 2,000자를 넘어도 입력은 막지 않고(붙여 넣은 글이 잘리지 않게) 생성만 막는다.
- **성우 고르기 창:** 담은 Typecast 성우 목록(최근 사용 순 → 즐겨찾기 → 담은 순). 줄마다 이름, 조건 요약, '최근 사용 3일 전 · 12회'(사용 이력이 있을 때). 이용 불가 성우는 흐리게, 고를 수 없음, 이유 한 줄. 기본 샘플 재생. 담은 성우가 없으면 "담은 Typecast 성우가 없어요" + '성우 캐스팅에서 담기' → `/casting`.
- **하단 막대(화면의 초점 하나):**
  - 왼쪽: 결과 플레이어(브라우저 기본 오디오 조작: 재생·정지·탐색·볼륨)와 '내려받기'. 결과가 없으면 "음성을 만들면 여기서 들을 수 있어요".
  - 오른쪽: 주 버튼 '음성 만들기'(동전 표식 + 예상 크레딧). 같은 조합의 저장된 결과가 있으면 '저장된 결과 열기'(동전 없음, 공급자 호출 0회).
  - 막는 이유 한 줄: 성우를 골라 주세요 / 대본을 먼저 써 주세요 / 2,000자를 넘었어요(n자) / 현재 이용 불가 성우예요 / 다른 생성이 진행 중이에요 / 공급자 대기 시각까지.
- **생성:** 누르면 T5 확인 창(대본 앞 100자와 총 글자 수, 성우, 설정 요약, 예상 크레딧, 남은 크레딧, 기본 샘플). '크레딧 쓰고 만들기' → 요청 중에는 지난 시간만 보인다("만드는 중 · 12초", 가짜 진행률 없음). 성공하면 조각을 받아 플레이어에 올리고 알림 "음성을 만들었어요"(자동 재생하지 않는다).
- **이전 결과(카드 아래):** 최근 20개. 줄마다 시각, 성우, 대본 첫 줄, 크레딧(추정), '재생'(플레이어에 올림), '내려받기', '지우기'(확인 창). 처리 여부 미확인 기록은 상태 배지와 "늦게 도착하면 여기서 완료로 바뀌어요"를 보이고 재생·내려받기가 없다.
- **내려받기:** 그 결과의 조각을 받아(받아 둔 것이 있으면 그대로) 파일 이름 규칙으로 저장한다. 생성 API를 부르지 않는다.
- **임시 작업:** 대본·성우·설정·채널은 바꿀 때마다 이 브라우저에 저장한다.
- **그 밖의 상태:** 담은 성우 목록 로딩·오류('다시 불러오기'), 소유자 없음(`LoopbackNotice` "이 주소에서는 음성 작업실을 쓸 수 없어요"), 키 없음·인증 실패는 오류 줄에 '연결 상태 보기' → `/connections`.

**앱 틀·다른 화면**
- 1차 버튼 hover 토큰(CS-07)은 공용 `Button`에서 고쳐 앱 전체에 적용된다.
- 사이트맵: `/studio` 행을 편집기로 바꾸고 예외 표의 흐름 지도 세 줄을 지운다.

## 8. 수용 기준

1. 담은 Typecast 성우와 대본으로 '음성 만들기' → 확인 → 결과가 플레이어에 올라오고 재생·정지·탐색·볼륨이 된다. 이전 결과에 한 줄이 생긴다.
2. '내려받기'는 파일 이름 규칙의 `.mp3`를 저장하고, 공급자 호출이 0회다. 새로 고침 뒤 이전 결과에서 다시 내려받아도 0회다.
3. 빈 대본(공백만 포함), 2,001자, 성우 없음, 이용 불가 성우는 버튼이 잠기고 이유가 보인다. 서버도 같은 입력을 공급자 호출 없이 거절한다.
4. 확인 창의 버튼을 빠르게 두 번 누르거나 같은 요청 id를 다시 보내도 공급자 호출은 1회다. 캐스팅에서 내 문장을 만드는 중이면 작업실 생성은 '다른 생성이 진행 중'으로 막힌다.
5. 같은 성우·설정·대본으로 다시 누르면 '저장된 결과 열기'가 되고 공급자 호출이 0회다.
6. 3MiB를 넘는 결과도 조각으로 받아 원본과 같은 바이트로 재생·내려받기가 된다(조각 하나는 3MiB 이하).
7. 시간 초과는 '처리 여부 미확인'이고 자동으로 다시 요청하지 않는다. 그 뒤 도착한 오디오는 같은 기록에 저장돼 이전 결과에서 완료로 보인다.
8. 생성이 성공하면 그 성우의 사용 횟수가 1 오르고 최근 사용 시각이 바뀐다. 성우 고르기 창이 최근 사용 순이다. 저장된 결과 열기와 내 문장 듣기는 세지 않는다.
9. 프리셋을 불러오면 성우와 설정이 함께 바뀐다. 성우가 비었거나 이용 불가면 성우 칸이 비고 안내가 보인다. 채널을 고르면 그 채널의 기본 프리셋 '불러오기' 창이 뜬다.
10. 감정 팔레트는 그 성우·모델이 받는 감정만 보이고, 누르면 카드 감정 표식과 확인 창 설정 요약이 바뀐다. v21 성우에는 '자동'이 없다.
11. 새로 고침해도 대본·성우·설정·채널이 남는다. 보관함에서 뺀 성우는 되살리지 않는다.
12. 1차 버튼 hover가 라이트 brand-600, 다크 brand-300이다(앱 전체).
13. B 소유자는 A의 작업실 결과 목록·조각·지우기에 손대지 못하고(`NOT_FOUND`, A의 행 그대로), A가 담은 성우로 생성하면 거절된다(공급자 호출 0회). 소유자가 없으면 프로시저 5개가 `UNAUTHORIZED`이고 DB 접근 0회다.
14. 자동 테스트·브라우저 QA에서 유료 호출이 0회다. 실제 생성은 사용자 테스트에서 승인 뒤에만 한다.
15. 1440·1280·1024·768·390·320px, 라이트·다크에서 가로 넘침이 없고(긴 성우 이름·대본), 키보드만으로 성우 고르기·설정·팔레트·생성 확인·이전 결과를 쓸 수 있다.
16. 오류 예산(콘솔·개발 오버레이·`get_errors`·서버 로그) 0.

## 9. 자동 테스트

- **계약(단위):** 작업실 요청의 대본 0자·공백만·1자·2,000자·2,001자, NFC 정리 뒤 길이, 조합 키에 `kind`가 들어가 같은 요청이라도 `trial`·`studio` 키가 다르다.
- **API(`studio.test.ts`, 테스트 DB, 공급자는 가짜):**
  - 같은 요청 id 두 번 → 공급자 1회, 같은 결과.
  - 진행 중 기록이 있으면(내 문장 `trial` 포함) `in_progress`.
  - 같은 조합 `studioFind` → 저장된 결과, 공급자 0회.
  - 담지 않은 성우·이용 불가 성우·다른 공급자 → 거절, 공급자 0회, 기록 없음.
  - 시간 초과 → `unknown`, 뒤늦은 성공 → 같은 행이 `done`이 되고 사용 이력 1회. 뒤늦은 실패 → `unknown` 그대로.
  - 조각: 3MiB를 넘는 오디오의 조각을 이어 붙이면 원본 바이트와 같다. 범위 밖 조각 번호는 `NOT_FOUND`.
  - 사용 이력: 성공 1회에 `use_count` 1 증가·`last_used_at` 갱신, 저장된 결과 찾기·실패·미확인은 그대로.
  - 목록: 최근 20개, 완료·미확인만, `trial` 기록은 나오지 않는다. 지우기는 진행 중이 아닐 때만.
  - 32MiB 초과 오디오 → `audio_too_large`, 기록 실패.
- **격리(`studio.isolation.test.ts`):** 8절 13번.
- **화면 단위(web vitest):** 막는 이유 순서, 글자 수 표시, 파일 이름(못 쓰는 글자·공백·20자 자르기·한국 시간), 감정 뱃지 목록(v30·v21·성우 `emotions`), 임시 작업 읽기(깨진 값·없는 성우·계약 밖 설정), 성우 정렬(최근 사용 → 즐겨찾기 → 담은 순).

## 11. 사용자 테스트 절차 (구현 뒤 드린다)

먼저 알린다: 이번에 없는 것과 그 TASK — 문단 추가·나누기·합치기(P1-04~06), 대본 저장(T12), 숫자 발음 검수(T11), 다른 공급자 생성(T10), WAV(T10 또는 요청), 일일 한도(넣지 않기로 함).

1. 성우 캐스팅에서 Typecast 성우 하나를 담고 `/studio`에서 고른다.
2. 짧은 대본(약 50자)을 쓰고 '음성 만들기' → 확인 창의 예상 크레딧(약 50)을 보고 만든다. **실제 유료 호출 1회, 승인 뒤.** 확인 창 버튼을 빠르게 두 번 눌러 본다.
3. 플레이어로 듣고 탐색·볼륨을 써 본 뒤 '내려받기'. 파일 이름과 재생을 확인한다.
4. 같은 대본으로 다시 누르면 '저장된 결과 열기'가 되는지 본다.
5. 대본을 비우거나 2,001자를 붙여 넣어 막히는지 본다.
6. 새로 고침해 대본·성우·설정이 남는지, 성우 고르기 창에 사용 횟수가 보이는지 본다.
7. (선택, 승인 뒤) 1,500~2,000자 대본 1회: 실제 걸린 시간·파일 크기·나눠 받기를 확인한다. 약 1,500~2,000크레딧.

## 12. 위험과 확인할 것

- Typecast 일반 생성 소요 시간은 문서에 없다. 180초는 추정이라 사용자 테스트 7번으로 확인하고 필요하면 고친다.
- 늦은 결과 저장은 서버 프로세스가 살아 있어야 한다. 로컬은 확실하고, 배포 환경(Vercel)은 응답 뒤 작업 유지(`after`)와 최대 실행 시간이 필요하다(T15 메모).
- 큰 오디오가 DB에 쌓인다(2,000자 약 12~16MB 추정 × 30일). 로컬은 문제없고 운영 저장 용량은 T15·P1-02에서 정한다.
- bytea 조각 읽기가 매번 전체를 풀면 느리다. 계획에서 저장 방식과 실제 시간을 잰다.
- 동시 1건을 두 화면이 나눠 써서, 캐스팅에서 긴 시험 생성이 걸려 있으면 작업실이 막힌다(5분 지나면 T5 규칙으로 미확인 처리).
- 기존 컴포넌트(`Options`·`TrialConfirm`·`PresetMenu`)가 캐스팅 상태(`useTrial`)에 묶여 있다. 작업실 상태로도 쓰게 바꿀 때 캐스팅 동작이 바뀌지 않는지 회귀 테스트로 본다.

## 13. 뒤 TASK가 지킬 것 (로드맵 메모로 옮긴다)

- T10: 작업실 생성 경로(`studio*`, 나눠 받기)에 다른 공급자를 붙인다. 감정 팔레트 규칙(커서 위치에 태그와 공백, 목록 밖 태그 허용, 태그를 모르는 모델로 바꾸면 알림). WAV 등 형식 고르기.
- T11: 검수는 작업실 카드 안에 연다(흐름 지도는 없앴다). 교정 뒤 글자 수로 예상 사용량을 다시 센다.
- T12: 저장 대본을 작업실 카드에 넣거나 바꾼다. 임시 작업과 저장 대본을 구분한다.
- T14: `trial_generation`의 작업실 행도 소유자 이전 대상이다. 성우 검사(담은 성우)는 '이 소유자가 담은 성우'라는 앱 수준 일관성 검사이고, 담은 성우의 voice id도 원래 클라이언트가 보낸 값(`savedVoiceSave`)이라 공급자 소유(Typecast `uc_` 커스텀 등) 검증이 아니다. 소유자가 여럿이 되면 저장 때나 합성 전에 Typecast `getVoiceV3`의 `voice_type=original`이거나 앱 클론 매핑에 있는 성우만 허용한다.
- T15: 늦은 결과 저장을 배포 환경에서 유지하는 방법(`after`), 함수 최대 실행 시간(180초 + 저장), 오디오 저장 용량과 보관 기간(P1-02).
- P1-04~06: 카드 추가·분할·결합. 문단마다 요청을 나눌지 compose를 쓸지 그때 정한다.
