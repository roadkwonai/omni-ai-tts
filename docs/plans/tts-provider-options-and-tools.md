# 공급자별 생성 옵션과 제작 도구 확장

**목표:** 기본 TTS의 설정 누락을 해소하고 성우 선택부터 연출·출력까지 같은 작업실에서 조절한다. 개인용 P0를 유지하면서 추천·가져오기·목소리 찾기·변환의 후속 UX를 미리 설계한다.

**근거:** [Typecast 옵션 조사](../research/typecast-api-options.md), [ElevenLabs 옵션 조사](../research/elevenlabs-api-options.md), [UI 브리프](../briefs/tts-provider-settings.md), [기존 구현 계획](tts-ui-first-implementation.md). 공식 명세가 API 지원의 근거이고 참고 화면은 배치와 작업 흐름의 근거다.

## 최신 HTML 반영 상태 (2026-09-26)

[전체 흐름 브리프](../briefs/tts-production-tools.md)에 따라 여섯 도구를 입력·검토·적용 흐름으로 확장했다. 추천/찾기/변환 결과는 여전히 명시적 시연이다. 로컬 음성 선택·재생·녹음, TXT/CSV/SRT/DOCX 읽기, 화자/성우 배정과 작업실 문단 계획, 규칙 기반 감정 편집은 브라우저에서 동작한다. 아래 표의 실제 공급자 API 연결 우선순위는 유지한다.

## 이번 반영과 실제 기능 개발의 경계

| 기능 | 이번 HTML/설계 | 실제 연결 순서 |

| 내 목소리 복제 | 기존 단계형 생성/검증/사용/삭제 흐름 유지, 작업실 진입 연결 | P0 필수 유지 |
| API의 감정·연출 | 공식 감정 모드/지시·태그, 모델 조건과 설명 | P0 설정 계약에 포함 |
| 대본 맞춤 성우 추천 | 후보 3명·추천 이유·샘플/선택 분리 시연 | P0 완료 후 우선 상세 구현. Typecast 공식 추천 API와 개인 분류 기반 후보부터, 대본 전체 분석은 별도 설계 |
| 문단별 감정 자동화 | 자동/수동 전환, 제안 검토·수정·적용 흐름 | 문단 모델과 공급자 표현 지원이 갖춰진 뒤. 별도 분석 비용/모델은 아직 선정하지 않음 |
| 목소리 찾기 | 음성 파일/URL 방식, 유사 후보 비교·선택 흐름 | 공식 유사 성우 탐색 API 지원 범위부터. 동일 인물/성우 확인 기능으로 표현하지 않음 |
| 보이스 체인저 | 원본·대상 성우·모델/출력·전후 비교 흐름 | 별도 speech-to-speech API 지원 공급자부터 연결. TTS 설정으로 위장하지 않음 |
| 대본 가져오기·화자 감지 | 감지 ON/OFF, 문단 미리보기·화자별 성우 배정 흐름 | TXT 붙여넣기/명시적 화자 표기부터; DOCX/SRT/CSV 파서·문단 합성은 순차 구현 |
| Vrew식 대본·자막 편집 | 이번 확장 대상 아님 | 사용자가 다음 요청에서 상세 범위 결정. 기존 자막 TODO 유지 |

## 첨부 화면 10개에서 채택할 설계

2026-09-26 사용자 첨부 이미지의 가시 내용과 [gowith153 소개 페이지](https://tts.gowith153.com/)를 재확인했다. 공개 가이드 전체 펼치기로 설명을 읽었으며 로그인 이후 동작은 확인하지 않았다.

| 이미지 | 관찰 | 적용 |
|---|---|---|
| 1 | 감정·속도·세부 조절·재생성·발음·쉼을 가까이 배치 | 생성 설정을 편집기 가까이 두고 표현과 출력 분리. 재생성은 이전 결과 보존 및 새 요청 안내. 피치/쉼은 공식 API 또는 후처리 여부 구분 |
| 2 | Eleven Multilingual v2에 속도·안정성·유사성·스타일·화자 증폭 | 각각 설명과 값 표시, 초기화 제공. 스크린샷의 오디오 효과는 현재 API 필드 근거 없이 추가하지 않음 |
| 3 | Eleven v3에서는 설정 수와 안정성 의미가 다름 | 모델별 컨트롤 교체, 지원하지 않는 값 제외. 화면에 없는 옵션을 API 미지원이라고 단정하지 않고 명세/가이드 충돌 기록 |
| 4 | 문단별 성우·속도·피치·감정과 별도 제작 도구 | 초기 전체 대본 설정을 명확히 표시하고 문단별 덮어쓰기는 후속 문단 모델에서 도입 |
| 5 | 가져오기→성우/복제→연출→출력 순서 | 기본 제작 순서를 유지하며 필요한 도구로 진입. 요금·완료 시간·성우 수·자막 정확도 광고 수치는 가져오지 않음 |
| 6 | 추천 후보 3명, 이유·샘플·선택 | 현재 언어/공급자/개인 분류에 맞는 후보와 설명. 검증되지 않은 일치율은 표시하지 않음 |
| 7 | 목소리 찾기와 변환이 연결됨 | 유사 후보 탐색과 실제 음성 변환을 분리, 원본/생성 결과 비교 |
| 8 | 감정 자동화와 직접 감정 선택 | API 자동 표현과 앱의 문단 감정 분석을 구분. 자동 제안을 덮어쓰고 되돌릴 수 있게 설계 |
| 9 | 공급자별 복제 탭·마이크/파일·이름·동의 | 기존 P0 복제에 공급자 조건/원본 확인/소유권/처리 상태 유지. 단순 Voice ID 입력으로 소유권을 부여하지 않음 |
| 10 | 대본 파일·화자 감지·역할별 배정·문단 분할 | 원문→파싱 미리보기→화자 수정/배정→확정. 감지 OFF에서 원문 유지, 알려지지 않은 화자 확인 |

Typecast에는 `GET /v1/voices/recommendations`가 확인됐다. 추천 설명은 1~500자, 후보 수는 1~10명이며, 반환 score를 검증된 정확도 퍼센트로 바꾸지 않는다. 상세 모델/감정/샘플은 성우 상세에서 확인한다. Typecast v30 Smart Emotion은 직접 지원하지만 문단별 제안 검수와 양사 통합 감정 분석은 앱 작업이다.

## 설정 적용 계약

- 공급자·모델 capability 목록에서 표시, 범위, 기본값, 상호 배타성, 계정 조건을 결정한다. 공식 문서가 충돌하면 조사 문서와 UI에 제한을 표시하고 실제 검증 전 지원을 확정하지 않는다.
- 사용자 설정, 대본/성우에서 가져오는 값, 서버 자동 값, 별도 엔드포인트로 분류한다. 모든 API 필드를 임의 조절기로 노출하는 것은 아니다.
- 피치와 속도의 단위는 공급자 명세 그대로 보존한다. 동일한 슬라이더 비율로 억지 변환하지 않는다. 생략/null/0이 다른 옵션은 별도 켜기/끄기와 숫자 입력으로 표현한다.
- 프리셋은 공급자·모델·설정의 구조화한 값을 보관한다. 고급 옵션이 빠지는 부분 저장을 금지한다. 실제 요청 문맥과 이전 요청 ID는 작업에 종속되므로 재사용 프리셋의 저장 범위를 분리한다.
- 생성 시점의 유효 설정을 스냅샷에 넣는다. 설정 변경 후 이전 결과를 최신 결과로 표시하지 않는다. 자동 재합성하지 않는다.
- 계정별 한도·형식 권한·모델/성우 호환성은 서버에서 다시 검증한다. HTML은 시연 데이터이며 실제 권한 판정을 보장하지 않는다.
- 참고 스크린샷의 '스마트 감정', '오디오 효과', '피치', '쉼'이 양사에 동일한 API 인자로 존재한다고 추정하지 않는다. 후처리 기능은 원본 보존과 출력 재인코딩을 별도 설계한다.

## 다음 구현 파일과 검증

[기존 계획](tts-ui-first-implementation.md)의 작업 2/4/6을 확장한다. UI는 `apps/web/src/features/tts/components/generation-settings.tsx`, 모델 계약은 `apps/web/src/features/tts/capabilities.ts`, 서버 매핑은 `packages/api/src/services/tts/{typecast,elevenlabs,types}.ts`에 둔다. 실제 수정은 해당 개발 라운드에서 한다.

- [ ] 공식 필드 inventory별로 UI 또는 서버 책임·후속 기능 매핑을 대조한다. 신규 API 필드 추가 시 문서와 capability를 같이 갱신한다.
- [ ] 공급자/모델 전환에서 미지원 필드 제거, 지원값 보존, 자동/수동 상호 배타, nullable 무음 제거, 0/상한/상한 초과/소수·정수 경계를 검증한다.
- [ ] 전체 설정 프리셋 저장/복원/초기화와 생성 스냅샷을 검증한다. 문맥/요청 ID는 다른 대본으로 재사용되지 않게 한다.
- [ ] 실제 API 연결 전에 request payload를 계약 테스트로 확인한다. 한 공급자의 필드가 다른 공급자 payload로 유출되지 않게 한다.
- [ ] 1440px와 390px에서 긴 출력 형식·설명·고급 영역·오류, 키보드 전환과 포커스를 검사한다.
- [ ] 본인 클론·추천·찾기·체인저·가져오기에서 실제 연결과 시연 상태를 구분한다. 파일 업로드/마이크/과금 API는 명시적 행동에서만 실행한다.
