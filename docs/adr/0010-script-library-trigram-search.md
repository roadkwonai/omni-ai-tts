# 0010. 대본 보관함은 표 하나에 종류를 두고, 검색은 pg_trgm 부분 일치로 한다

- 상태: 결정(2026-11-18, 저장 상한은 사용자 결정, 구조는 설계). 관련: [T12 스펙](../plans/tasks/T12-script-library.md) 2·5절, [T12 계획](../plans/tasks/T12-script-library-plan.md), Q-02.

## 맥락
- 사용자는 저장 대본 개수 상한을 두지 않고 성능으로 해결하라고 했다(2026-11-18). 대본 하나는 문단 200개까지라 작업 JSON이 수백 KB가 될 수 있다.
- 검색은 제목과 원문 전체에서 한다. 한국어는 PostgreSQL 전문 검색(`to_tsvector`)에 형태소 사전이 없어 낱말 중간("날씨"가 "오늘날씨는"에 든 경우)을 찾지 못한다.
- 최근 대본과 저장 대본은 같은 작업 모양을 담고, 같은 목록·열기·지우기 코드를 쓴다. 다른 것은 제목·채널·분류·판 번호의 유무와 개수 정리뿐이다.

## 결정
- 표 `script` 하나에 `kind`(`saved`·`recent`)를 둔다. 제목 유일은 `kind = 'saved'` 부분 유일 인덱스로, 최근 대본의 작업 하나당 한 줄은 `kind = 'recent'` 부분 유일 인덱스로 막는다.
- 원문 검색 칸 `body`를 작업 JSON과 따로 두고 저장할 때 서버가 만든다. 목록은 작업 JSON을 읽지 않는다.
- `pg_trgm` 확장을 켜고 `title`·`body`에 GIN trigram 인덱스를 둔다. 검색은 `ILIKE '%…%'`(`%`·`_`는 이스케이프)다. 3자 이상이면 인덱스를 타고, 1~2자는 소유자 행을 차례로 본다.
- 목록은 (바꾼 시각, id) 커서로 30개씩 받는다.

## 버린 안
- 두 표(저장·최근): 같은 작업 모양과 열기 코드를 두 번 쓰고, 최근 → 저장 변환을 표 사이 복사로 해야 한다.
- 전문 검색(`tsvector`, `simple` 사전): 띄어쓰기 단위라 한국어 부분 일치를 못 한다.
- 검색 인덱스 없이 `ILIKE`만: 대본이 늘면 매 검색이 모든 원문을 훑는다.

## 결과
- 마이그레이션에 확장 생성(`CREATE EXTENSION IF NOT EXISTS pg_trgm`)이 들어간다. 로컬 PostgreSQL 18(en_US.utf8)에서 한글 trigram을 확인했고, Neon 개발 브랜치 확인은 T15 배포 전에 한다.
- 1~2자 검색은 대본이 아주 많아지면 느려질 수 있다(개인 작업실 규모에서는 문제 없음으로 본다).
