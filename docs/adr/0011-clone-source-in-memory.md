# 0011. 클론 원본은 브라우저에서 WAV로 바꿔 앱 서버 메모리로만 공급자에 보낸다

- 상태: 결정(2026-11-18, 전송 방식·길이는 사용자 결정, 형식은 설계). 관련: [T13 스펙](../plans/tasks/T13-my-voice.md) 2·5.3·7절, [클론 조사](../research/clone-api-2026-11.md), REQ-13 8번, [ADR 0002](0002-orpc-only-api.md).

## 맥락
- 원본 녹음은 본인 목소리라 앱에 영구 보관하지 않아야 한다(REQ-13 8번). 성공·실패·취소·시간 초과마다 정리 기한을 구현 전에 정해야 한다.
- Vercel 함수의 요청 본문은 4.5MB까지다. 24kHz 모노 16비트 WAV는 1초에 48KB라 60초가 약 2.88MB다.
- 브라우저 녹음(`MediaRecorder`)은 Chrome이 webm/opus, Safari가 mp4/aac를 낸다. 이 형식을 받는다고 문서에 적은 공급자는 없다. Gemini는 wav·mpeg 예시와 24kHz 모노 16비트 WAV 권장, Fish Audio는 wav·mp3·m4a·opus다(2026-11-18 조사).
- 공급자 권장 길이: Gemini 참조 10~30초, Fish Audio 클립당 10초 이상(1~2분 권장).

## 결정
- 브라우저가 녹음·파일을 `decodeAudioData`로 풀어 24kHz 모노 16비트 PCM WAV로 만든다. 서버는 변환하지 않는다.
- 브라우저는 WAV를 oRPC 프로시저의 `File` 입력(멀티파트 바이너리)으로 보낸다. 서버는 요청 메모리에서 머리말·형식·길이·크기를 다시 검사하고 같은 요청 안에서 공급자에 보낸다. DB·디스크·외부 저장소에 쓰지 않고, 원본 URL을 만들지 않으며, 바이트를 로그에 남기지 않는다.
- 길이 상한은 공급자별이다: Gemini 참조 10~30초(동의 녹음 1~20초), Fish Audio 10~60초. 요청 본문은 4MB를 넘지 않는다.
- 공급자 호출은 120초에서 끊고 결과를 '처리 여부 미확인'으로 둔다.

## 버린 안
- 저장소(Blob 등)에 잠시 올린 뒤 전달: 1~2분 넘는 원본을 받을 수 있지만 새 서비스 의존, 업로드 토큰 라우트(로컬 관리자 모드의 Route Handler 금지 예외), 만료 원본 정리가 생긴다. 지금 길이로는 필요 없다.
- 녹음 형식 그대로 전송: 공급자가 받는다는 근거가 없고 공급자마다 다르게 실패한다.
- 서버 변환(ffmpeg): 디스크 임시 파일과 실행 파일 의존이 생기고 메모리 전용 원칙을 깬다.
- 공급자마다 같은 10~30초: 안내는 단순하지만 Fish Audio 권장 길이보다 짧다.

## 결과
- 원본은 브라우저 메모리(Blob·object URL)와 서버 요청 메모리에만 잠깐 있다. 공급자 쪽 보관은 공급자 정책을 따르므로 화면에 따로 알린다.
- 1분이 넘는 원본은 받을 수 없다. 긴 원본이 필요해지면(전문 클론 P3-04, 녹음 가이드 P1-15) 이 결정을 다시 본다.
- Typecast(WAV·MP3, 5~150초)와 ElevenLabs(형식 목록 없음, MP3 권장)도 같은 WAV를 받을 수 있어 T13-b에서 이 길을 그대로 쓴다. 150초까지 받으려면 이 ADR을 고친다.
- Safari 녹음을 `decodeAudioData`가 풀지 못하면 파일 고르기로 안내한다.
