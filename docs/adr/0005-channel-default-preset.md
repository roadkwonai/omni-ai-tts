# 0005. 채널 기본 프리셋은 연결 표로 둔다

- 상태: 결정(2026-10-14). 관련: [T8 스펙](../plans/tasks/T08-presets.md) 2·3절, [ADR 0004](0004-channel-classification-storage.md).

## 맥락
- ADR 0004가 채널 ↔ 프리셋이 서로 가리키는 구조를 피할지 T8 설계로 미뤘다. 프리셋은 채널 하나를 고를 수 있고(`voice_preset.channel_id`), 채널은 기본 프리셋을 하나 가진다.

## 결정
- 채널 기본 프리셋은 연결 표 `channel_default_preset`에 둔다. 기본 키는 `channel_id`(채널마다 하나)이고 `preset_id`는 유니크 인덱스다(프리셋은 한 채널의 기본만 된다). 두 외래 키 모두 `on delete cascade`다.
- `voice_preset.channel_id`는 일반 외래 키(`on delete set null`)로 그대로 둔다.

## 이유
- 채널이 프리셋을 가리키고 프리셋이 채널을 가리키면 어느 쪽을 먼저 지우고 만들지 순서가 꼬이고 외래 키 관계 정의도 서로를 기다린다. 따로 둔 표는 어느 쪽을 지워도 그 줄만 지워진다.

## 버린 안
- `channel.default_preset_id`: 채널 ↔ 프리셋 상호 참조가 된다. 지우기 순서와 관계 정의가 꼬인다.
- 프리셋 표의 표시 칸(`is_default`): 채널을 지운 뒤에도 기본 표시가 남고, 채널마다 하나라는 제약을 인덱스가 아니라 코드가 지켜야 한다.

## 결과
- 기본 프리셋의 채널이 그 프리셋의 채널과 같은지는 표 제약이 아니라 프로시저가 같은 트랜잭션에서 지킨다(`routers/preset.ts` `setDefault`). 프리셋의 채널을 바꾸거나 비우면 이전 채널의 기본 지정이 먼저 풀린다.
- 소유자 컬럼이 없는 연결 표라, 지정할 때 프로시저가 채널이 내 것인지 검사한다(ADR 0004의 `saved_voice_channel`과 같다).
