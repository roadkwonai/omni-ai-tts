# 0007. 문단 결과 오디오는 서버가 저장하고 한 파일로 잇는 일은 브라우저가 한다

- 상태: 결정(2026-10-23). 관련: [T10 스펙](../plans/tasks/T10-paragraph-studio.md) 2·13절, [ADR 0002](0002-orpc-only-api.md), [ADR 0006](0006-studio-audio-in-generation-record.md).

## 맥락
- 문단 작업실(T10)은 대본을 문단 수십 개로 나눠 문단마다 만들고, 사용자가 한 파일(WAV)로 받는다. 긴 나레이션은 30분 분량이 목표다(30분 WAV는 약 160MB).
- ADR 0002와 `tts-provider`는 긴 음성 결합을 "Blob 저장소와 백그라운드 작업(P1-04)"으로 설계한다고 적었다. 그 저장소(P1-02)는 아직 정하지 않았고, Vercel 함수는 응답 4.5MB 상한을 가진다(ADR 0006).

## 결정
- 서버는 문단 결과 오디오만 저장한다(`studioCreate`가 문단 하나, `studioAudio`가 3MiB 조각). 한 파일로 잇기·쉼 넣기·문단별 zip·자막(SRT) 만들기는 브라우저 Web Audio에서 한다. 드라마 작업실의 `sound-join.ts`·`zip-store.ts`를 같이 쓴다.
- 서버에 합친 결과를 남기지 않는다. 받을 때마다 브라우저가 저장된 문단 결과 오디오를 받아 잇는다(마지막 잇기 결과 하나는 화면이 기억해 다시 디코딩하지 않는다).

## 버린 안
- Vercel Blob에 저장하고 백그라운드 작업(ffmpeg)으로 잇기: 새 서비스·계정·환경변수와 작업 상태 표가 든다. 영구 보관을 정하는 P1-02에서 다시 본다.
- 요청 안에서 서버가 잇기: 30분 결과는 응답 4.5MB 상한과 함수 실행 시간을 넘는다.

## 결과
- 한계: 잇는 동안 조각과 결과가 탭 메모리에 함께 있다. 조각을 하나씩 디코딩해 16비트로 줄이는 방식으로 30분을 목표로 하고, 60분에서 실패하면 그 한도를 화면에 알린다. T10-a 브라우저 QA(2026-10-23, 개발 모드, 문단 60개 신호음 결과)에서 30분은 3.9초·WAV 161MB·최고 JS 힙 314MB, 60분은 5.9초·320MB·334MB로 둘 다 이어졌으므로 한도 알림은 두지 않았다. 받는 중 페이지를 떠나거나 탭을 닫으면 잇기가 끊기고 서버에는 아무것도 남지 않아 처음부터 다시 받는다.
- T15-b(2026-11-19): 위 수치(최고 JS 힙, 개발 모드, 데스크톱 Chrome)로 배포 전 측정을 닫았다. 신호음 하네스가 남아 있지 않고 데모 샘플은 몇 초라 30분을 만들 수 없었다. 탭 전체 메모리(디코딩한 오디오 버퍼 포함)와 휴대폰 메모리는 재지 않았다. P1-02에서 다시 본다.
- 이점: 서버 저장은 문단 단위라 ADR 0006의 조각 받기를 그대로 쓰고, 문단 하나만 바꿔도 나머지는 저장된 결과를 다시 쓴다(공급자 0회).
- ADR 0002의 "긴 음성 결합은 Blob 저장소와 백그라운드 작업" 문장은 이 범위(문단 작업실의 한 파일 받기)에서는 쓰지 않는다. 영상 렌더링이나 서버 후처리(ffmpeg 음량 정규화·형식 변환)가 필요해지면 그때 Blob·백그라운드 작업을 새 ADR로 정한다.
- 탭 메모리 한계에 닿거나 받는 중 끊김이 문제가 되면 이 결정을 다시 본다(P1-02).
