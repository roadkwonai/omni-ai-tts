# 공개 데모는 공급자 키 없는 별도 배포로 연다

포트폴리오 방문자가 로그인 없이 작업실을 써 보게 하되(사용자 2026-11-19), 소유자 로그인은 밖에 내놓지 않는다. 같은 코드를 두 번째 Vercel 프로젝트와 따로 만든 Neon DB로 배포하고, 그 환경에는 공급자 키를 넣지 않아 유료 호출이 구조적으로 일어날 수 없게 한다. 공개 주소 `omni-ai-tts.vercel.app`은 공개 데모(소개 페이지 + 데모 작업실)가 쓰고, 본인용 작업실은 알리지 않는 별도 주소로 옮긴다. 공개 데모의 데이터는 예시 데이터 브랜치에서 매일 다시 만든다(GitHub Actions + Neon 브랜치, 앱에 새 경로를 만들지 않는다).

## 고려한 대안
- 본인용 배포에 데모 계정 자동 로그인: 배포는 하나지만 운영 DB와 공급자 키를 함께 쓰므로, 유료·상태 변경 프로시저마다 데모 계정을 막는 검사가 하나라도 빠지면 과금된다.
- 본인용이 `omni-ai-tts`를 그대로 쓰고 데모는 `-demo` 주소: 바꿀 설정은 적지만 포트폴리오에 거는 주소가 `-demo`가 된다.
- Vercel Cron + 초기화 경로: 공개 주소에 새 경로가 생기고 "새 Route Handler 금지" 규칙의 예외가 된다.

## 결과
- 같은 코드가 환경 변수로 두 모드(본인용, 공개 데모)를 가진다. 공개 데모에서는 세션 없이 예시 소유자로 들어가고, 로그인 경로를 막으며, 만들기·시험 생성은 데모 샘플을 돌려주고, 클론은 막는다. 본인용에서는 소개 페이지 없이 `/`가 로그인으로 가고 검색 노출을 막는다.
- 배포·릴리스 스크립트가 프로젝트 둘을 다뤄야 한다.
- 방문자가 저장한 내용은 다음 초기화까지 다른 방문자에게 보인다.
- 같은 코드라 본인용 배포에 데모 모드가 잘못 켜지면 실제 데이터가 로그인 없이 열린다. 그래서 데모 모드는 공급자·OpenAI 키가 하나라도 있으면 소유자를 정하지 않고, 배포 스크립트가 대상별로 모드와 키 이름을 검사한다.
