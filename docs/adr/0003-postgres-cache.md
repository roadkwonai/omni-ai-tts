# 공급자 목록과 내 문장 듣기 결과는 Postgres에 캐시하고, Next.js `use cache`는 쓰지 않는다

공급자 성우 목록 조회와 내 문장 듣기(시험 생성)는 공급자의 요청 한도와 크레딧을 쓴다. 그래서 같은 조회와 같은 듣기를 다시 부르지 않도록 캐시를 세 단으로 둔다(2026-10-04 사용자 결정 "Postgres 3단 캐시").
- 브라우저 메모리: TanStack Query, 지금 그대로.
- 서버 목록 캐시: Postgres 표.
- 듣기 결과 저장: Postgres 표.

저장소는 이미 쓰는 Postgres다. 개발은 로컬 컨테이너, 배포는 Neon이다. 새 서비스·계정·의존이 없고, 재시작과 배포에도 남으며, 서버 인스턴스끼리 공유된다. 1인 사용 규모는 Neon 무료 한도(저장 1GB, 송신 5GB/월)의 한 자릿수 %다.

구현 방식은 다음과 같다(목록 캐시는 T4, 듣기 결과는 T5에서 만든다).

**브라우저**
- 같은 탭에서 화면을 오가면 다시 묻지 않는다.
- 들은 오디오는 탭 메모리에서 다시 재생한다.

**서버 목록 캐시**
- 키: 공급자, 목록 종류, 정렬한 필터, 페이지, 계약 판.
- 값: 계약 스키마(zod)로 검사한 응답 JSON, 받은 시각, 만료 시각. 읽을 때도 검사하고, 계약이 바뀌면 판 번호로 옛 캐시를 버린다.
- 기본 유지 시간은 24시간이고 화면의 '목록 새로 고침'으로 갱신한다.
- 같은 키의 동시 요청은 공급자 호출 하나로 합친다.
- 공급자가 실패하면 오류는 저장하지 않는다. 지난 목록이 있으면 받은 시각과 함께 보인다. 429의 `Retry-After` 시각까지는 그 공급자를 부르지 않는다.
- 만료 행은 쓰기 때 함께 지운다(cron 없음).
- 공개 목록은 소유자 없이 공용 키를 쓰고, 계정·내 성우 목록은 소유자를 키에 넣는다.

**듣기 결과**
- 공급자, 성우, 모델, 정리한 설정, 문장의 해시를 소유자별 키로 쓴다.
- 오디오(bytea)는 유료 호출 선점 기록 행(요청 id)에 함께 둔다.
- 같은 조합을 다시 누르면 저장본을 재생하고 공급자를 부르지 않는다(크레딧 0, 화면에 '저장된 결과'). '새로 만들기'를 누를 때만 크레딧 경고를 거쳐 다시 생성한다.

## Considered Options
- **Next.js Cache Components(`'use cache'`):** 설치된 16.3.6 문서와 공식 스킬(`next-cache-components-adoption`·`optimizer`)로 확인했고, Route Handler가 부르는 함수에서 동작은 한다. 그래도 쓰지 않는 이유는 다섯 가지다.
  - 저장이 프로세스 메모리(기본 50MB LRU)라 재시작·코드 수정·새 빌드 때 사라진다. 사라지면 다음 요청이 조용히 유료 호출이 된다.
  - Vercel에서 공유하려면 유료 Runtime Cache(`'use cache: remote'`)가 필요하다. 항목 2MB에 축출이 있다.
  - production에서 캐시 안에서 던진 오류의 메시지와 `code`가 가려져, 공급자 오류 분류(`reason`, `Retry-After`)가 깨진다.
  - `packages/api`가 `next/cache`에 묶인다.
  - 페이지 껍데기 같은 정적 부분은 크레딧과 무관하므로 T15 성능 점검 때 다시 본다.
- **Upstash Redis(무료 50만 명령/월, 256MB):** 가장 빠르다. 하지만 새 서비스·계정·환경변수와 로컬 대용품이 든다. 1인 규모에서는 Postgres로 충분하다.
- **SQLite·Turso:** DB가 둘이 된다. Vercel 서버리스는 파일 시스템이 휘발된다.
- **Neon UNLOGGED 표:** 무료 플랜은 5분 쉬면 컴퓨트가 정지하고, 그때 내용이 비워진다.
- **Zustand(persist):** TanStack Query와 같은 일을 겹쳐 한다.
- **TanStack Query persist(IndexedDB):** 새로 고침에도 서버 호출을 없애지만, 서버 목록 캐시가 이미 공급자 호출을 막는다. 필요해지면 성우 목록만 저장하는 방식으로 더한다.

## Consequences
- 첫 DB 표가 T4의 목록 캐시가 된다. 소유 데이터 격리 테스트(소유자를 키에 넣는 목록)도 T4부터 한다.
- Neon 무료 플랜은 5분 쉬면 정지해서, 첫 요청에 수백 ms가 더 걸린다. 1인 사용에서는 받아들인다.
- 이 조건이 되면 다시 검토한다.
  - 오디오 저장이 약 500MB이거나 월 송신이 3GB에 가까워진다: 오디오를 Vercel Blob(비공개)이나 Neon Object Storage로 옮긴다.
  - 목록 읽기가 병목이 된다: 목록 앞단에 Redis를 둔다.
  - 새 외부 서비스가 필요하다: 사용자 확인 뒤 새 ADR을 쓴다.
- Typecast·ElevenLabs·Fish Audio 약관에는 생성 오디오를 같은 앱에서 저장·재생하는 일을 명시적으로 금지하는 문구가 없다. 세 공급자 모두 이를 명시적으로 허용하는 문구도 없어 약관이 보관을 보장한다고 해석하지 않는다. ElevenLabs 개발 블로그는 입력 해시를 캐시 키로 써 같은 오디오가 두 번 청구되지 않도록 권한다. T5는 결과를 Postgres에 마지막 재생 후 30일 보관하고 사용자가 지울 수 있게 한다. 소유자에게만 결과를 돌려주며 다른 사용자에게 공개하지 않는다.
