# TTS Pilot UI/UX 브리프 초안

- 상태: 개인용 범위 확정(2026-09-26), 실제 서비스 구현 전. 상세 HTML 설계는 [HTML 브리프](tts-html-prototype.md)가 최신이며 아래 3단 배치는 이전 구조 제안이다.
- 대상: `apps/web`, 주요 예정 화면 `/studio`.
- 모드: Operate — 반복적인 음성 제작 작업을 끝내는 도구.
- 근거: [요구사항](../plans/tts-service-requirements.md), 루트 `DESIGN.md`, [참고 조사](../research/tts-references.md).
- UI/UX 기획·개발·검토는 **bts-ui → impeccable** 절차를 따른다. 내 클론 보이스 생성·관리도 같은 시각 시스템의 초기 필수 화면이다.

## 사용자와 성공 장면

여러 콘텐츠 채널을 운영하는 한국어 제작자가 매번 성우를 다시 찾고 숫자 발음을 고치는 시간을 줄인다. 성공 장면은 '내 채널 프리셋 선택 → 저장 대본 불러오기 → 숫자 교정 검수 → 생성·다운로드'다. 필요한 경우 성우 샘플을 비교한 후 즐겨찾기에 등록한다.

현재 확인한 사실: 앱은 BTS 기본 화면이며 Pretendard Variable 파일·라이선스와 `next/font/local` 설정이 이미 있다. 새 폰트 의존성을 추가하지 않고 기존 자산을 재사용한다. 구현 시 `html lang="ko"`와 전역 폰트 적용을 함께 확인한다.

## 시각 방향

- `DESIGN.md`의 흰색/중립색 표면, 파란색 주요 행동, 헤어라인 테두리, 평면 카드와 명확한 텍스트 위계를 활용한다.
- 제목·본문·숫자 표시 모두 Pretendard. 참고 문서의 Wanted Sans display와 Pretendard JP 우선순위는 사용자 지시에 따라 채택하지 않는다.
- 본문·대본 16px, 보조 14px, 화면 제목 24~28px을 출발점으로 제안한다. 읽기 영역 줄 간격은 1.6 수준으로 충분히 확보하고 최종 토큰으로 명명한다.
- 간격 8/12/16/24/32, 반경 8/12의 기존 참조값을 우선 사용한다. 스타일 코드에 임의 값을 흩뿌리지 않는다.
- 장식 이미지·그라디언트·통계 카드보다 대본 편집 공간과 성우 목록을 우선한다. 공급자 배지는 이름을 명시한다.
- 초기 라이트 테마를 기준으로 설계한다. 기존 다크 테마를 유지한다면 대비와 선택/오류 상태도 함께 검증한다.
- Vrew에서는 텍스트를 직접 편집하고 결과를 빠르게 확인하는 작업 방식을 참고한다. 영상 편집기 자체는 초기 범위가 아니다.

## 정보 구조와 예정 화면

| 화면 | 예정 URL | 주요 내용 |
|---|---|---|
| 음성 작업실 | `/studio` | 성우 선택, 대본, 교정, 설정, 생성 결과 |
| 성우 보관함 | `/voices` | 양사 탐색, 즐겨찾기, 카테고리·타입·채널·프리셋 필터, 메모 |
| 내 보이스 | `/voices/mine` | 개인 클론 목록, 만들기, 상태/검증, 시험 청취, 작업실 사용, 삭제 |
| 대본 보관함 | `/scripts` | 저장·검색·편집·복제·작업실로 불러오기 |
| 프리셋 | `/presets` | 공급자별 생성 설정, 채널 기본값, 사용 성우 |
| 채널·분류 관리 | `/library` | 채널, 카테고리, 타입 생성·수정·정리 |
| 연결 상태·설정 | `/settings` | 공급자 연결 상태, 지원 모델, 사용량 조회가 가능할 때 표시 |

모든 제작/개인 화면은 로그인 보호 대상이다. 기존 `/dashboard`는 스튜디오로 연결하는 방향을 제안하되 URL 호환성은 구현 단계에서 정한다. 메뉴가 핵심 작업을 밀어내지 않도록 데스크톱에서는 얇은 내비게이션으로 두고 모바일에서는 접는다.

## 작업실 구성안

```text
상단: 작업 제목 / 채널 / 저장 상태                 프리셋 불러오기
┌────────────────┬────────────────────────┬────────────────┐
│ 성우 선택       │ 대본                    │ 생성 설정       │
│ 공급자·검색     │ 저장 대본 불러오기       │ 공급자·모델     │
│ 필터·즐겨찾기   │ 원문 편집                │ 지원 옵션       │
│ 샘플 재생       │ 숫자 교정 · 변경 비교    │ 최종 글자 수    │
│ 현재 성우 표시  │ 최종 발음용 대본 확인    │ 예상 사용량     │
│                │                        │ 음성 만들기     │
├────────────────┴────────────────────────┴────────────────┤
│ 생성 결과: 성우·생성 시각 / 플레이어 / 형식 / 다운로드      │
└─────────────────────────────────────────────────────────┘
```

이 배치는 제안 와이어프레임이며 완성 시안이 아니다. 대본을 가장 넓게 배치하고 주요 행동은 '음성 만들기' 하나로 집중한다. 상세 고급 설정은 접어서 성우 탐색·교정 흐름을 가리지 않게 한다.

## 핵심 상호작용

1. **샘플 듣기와 선택을 분리한다.** 재생 버튼은 샘플만 재생하고 행 선택은 사용할 성우를 바꾼다. 즐겨찾기 버튼도 독립적으로 동작한다.
2. **필터 정의를 명확히 한다.** 여러 필터 축은 AND, 한 축의 다중 선택은 OR로 제안한다. 적용 중인 필터와 전체 초기화를 항상 확인할 수 있다.
3. **불러오기는 덮어쓰기를 숨기지 않는다.** 대본은 삽입/교체를 선택하고 프리셋은 적용될 설정을 보여 준다. 미저장 편집을 잃기 전 확인한다.
4. **교정 검수는 차이를 중심으로 한다.** 변경 개수, 원문→제안, 규칙 종류, 적용/유지/직접 수정, 전체 되돌리기를 제공한다. 색만으로 차이를 전달하지 않는다.
5. **생성 결과는 입력 스냅샷과 연결한다.** 생성 중 편집을 허용하되 새 입력과 기존 결과를 분리한다. 변경 후에는 결과에 '이전 대본으로 생성됨'을 표시한다.
6. **프리셋으로 분류하는 요구를 노출한다.** 보관함에서 '프리셋에 사용 중' 필터와 프리셋 이름을 보여 주고, 즐겨찾기한 성우로 프리셋 만들기를 제공한다.
7. **다운로드는 결과 재사용이다.** 형식 변경이 재생성을 필요로 하면 추가 요청임을 알린다. 파일 확장자만 바꾸는 변환은 금지한다.

## 내 클론 보이스 만들기 (초기 필수)

- 성우 보관함의 '내 보이스' 탭과 작업실 성우 선택 영역에서 진입한다. 과정은 **공급자/이름 → 녹음 또는 파일 → 원본 청취·확인 → 클론 생성 → 필요 시 검증 → 시험 청취·작업실 사용**이다.
- PC에서는 단계형 다이얼로그, 모바일에서는 전체 화면 시트로 제안한다. 마이크 권한은 녹음 시작 시 요청하고 거부 시 파일 업로드를 제공한다. 녹음 중 경과 시간·입력 상태, 정지·재녹음·취소를 명확히 표시한다.
- 공급자별 녹음 조건·지원 형식·생성 가능 여부를 입력 전에 보여 준다. 사용자가 생성할 공급자와 본인 음성임을 확인한 후 전송한다. 업로드 진행률과 클론 처리 상태를 분리하고 근거 없는 완료 퍼센트를 표시하지 않는다.
- '원본 녹음 듣기'와 '클론 목소리로 시험 생성'을 다른 버튼으로 둔다. 합성 샘플이 없는 보이스는 명시적인 시험 생성 후 들을 수 있고 예상 사용량을 표시한다.
- 목록의 상태는 생성 중/검증 필요/사용 가능/실패/처리 여부 미확인/삭제 대기로 표현한다. 사용 가능한 보이스만 작업실에서 선택할 수 있다. 검증 필요 상태에는 공급자별 후속 행동과 상태 새로고침을 제공한다.
- 사용 가능 보이스는 즐겨찾기·카테고리·타입·채널·프리셋에 연결한다. 삭제 전 영향받는 프리셋을 표시하고, 공급자 삭제가 확인될 때까지 완료로 표시하지 않는다.
- 필수 실패 상태: 마이크 거부·지원 안 되는 녹음 형식·빈/무음 파일·용량/길이 초과·슬롯 부족·플랜 제한·검증 실패·생성 응답 유실·삭제 실패. 중복 생성 재시도를 자동 실행하지 않는다.
- 접근성 검증에는 녹음 시작/종료 안내, 다이얼로그 포커스, 처리 상태 알림, 키보드로 업로드·취소·시험 청취를 포함한다. 원본 임시 보관/정리와 제공사 보관 범위를 구분해 안내한다.

## 반응형·접근성

- 1200px 이상: 성우/대본/설정 3단. 768~1199px: 대본 중심 2단 + 성우 선택 시트. 768px 미만: 단일 열, 성우·대본·설정 전환과 하단 생성 행동. 이 값은 앱 제안이며 원티드 공식 수치라는 주장을 하지 않는다.
- 1440px과 390px에서 별도 검증. 긴 성우 이름, 긴 프리셋 제목, 빈 목록, 다수 분류 칩이 레이아웃을 깨뜨리지 않아야 한다.
- 키보드만으로 검색→샘플→성우 선택→교정 승인→생성→다운로드가 가능해야 한다.
- 아이콘 버튼 이름, 플레이어 접근 가능한 컨트롤, 모달 포커스 복귀, 오류 메시지 연결, 생성 상태 알림을 제공한다.
- 작은 터치 대상 방지(주요 조작 44px 목표), 본문 대비 4.5:1 목표, 색 외 텍스트 상태 제공, reduced-motion 존중.
- 자동 재생하지 않는다. 새 샘플 재생 시 기존 오디오를 정지한다. 생성 완료 알림 때문에 포커스를 이동시키지 않는다.

## 필수 상태와 문구 예시

| 상태 | 화면 대응 |
|---|---|
| 처음 방문 | '목소리를 들어 보고 첫 성우를 선택해 주세요'와 성우 탐색 행동 |
| 즐겨찾기 없음 | '자주 쓰는 성우를 모아 보세요' / 성우 찾기 |
| 검색 결과 없음 | 검색어·필터 요약 / 필터 초기화 |
| 샘플 없음 | 재생 대신 '기본 샘플이 없어요'. 별도 시험 생성 안내 |
| 저장 중/실패 | '저장 중…' / '저장하지 못했어요. 다시 시도해 주세요'. 성공하지 않았는데 저장됨 표시 금지 |
| 교정 없음 | '교정할 숫자를 찾지 못했어요' — 오류와 구분 |
| 한도 초과 | 최종 대본 글자 수와 상한, 분량 줄이기 안내 |
| 생성 중 | 취소 지원 여부와 무관하게 요청 중 상태 표시. 임의 퍼센트 없음 |
| 응답 유실 | '생성 여부를 확인하지 못했어요. 다시 만들면 사용량이 추가될 수 있어요' |
| 임시 결과 | '페이지를 떠나기 전에 음성 파일을 내려받아 주세요' |
| 공급자 장애 | 해당 공급자 상태를 표시하고 다른 공급자는 사용 가능 |

## 구현 전 남은 결정

- 개인용·서버 키 방식 확정. 공개 가입·결제·팀은 후속으로 유지한다.
- 제안한 작업실 중심 구조와 메뉴 수의 적절성. 사용자 사용 흐름 기준으로 브리프 확정.
- 오디오 영구 보관 필요 여부와 보관소/보존 기간. 초기 임시 다운로드 방식의 한계를 명시.
- 최종 화면 구현 전 디자인 토큰 매핑. `DESIGN.md`는 이번 계획 작업에서 덮어쓰지 않는다.

HTML 시안을 먼저 검토하고, 확정한 동작과 상태를 실제 앱 화면으로 옮긴다. 후속 영상·자막 기능 상세 설계는 P0가 끝난 뒤 진행한다.
