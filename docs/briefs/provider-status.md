## 1. 누가, 무엇을
본인 한 명이 세 공급자를 지금 쓸 수 있는지, 아니면 무엇을 고쳐야 하는지 본다. 이 화면에 오는 때는 셋이다: 처음 설정할 때, 키를 바꾼 뒤, 다른 화면에서 공급자 문제가 났을 때.

## 2. 결과와 증거
성공은 둘 중 하나다. 세 카드가 연결됨이고 남은 사용량이 보이거나, 안 되는 카드에 원인과 고칠 방법이 보인다. 보이는 값은 공급자가 준 것만 쓴다. 단위가 문서에 없으면 붙이지 않는다(Fish Audio 크레딧).

## 3. 방향
화면을 **요약 띠 한 줄 + 같은 무게의 카드 3장**으로 짠다(구성 추첨 후보 6번, 2026-10-04 사용자 선택).
- 띠가 "몇 개가 되고 무엇이 안 되는지"를 먼저 한 줄로 말하고, 카드가 공급자마다 원인·할 일·사용량을 말한다. 띠는 문제의 공급자 이름과 상태 이름만 말하고 원인과 할 일은 카드만 말한다(같은 내용을 두 번 말하는 위험을 줄인다).
- 공급자마다 따로 뜨고 따로 다시 확인한다. 한 카드의 실패가 다른 카드를 가리지 않는다.
- 장식은 없다. 요약 띠, 상태 배지, 원인과 할 일, 사용량 숫자만 둔다.

## 4. 범위와 하지 않을 것
포함: `/connections` 한 화면, 메뉴의 '연결 상태' 링크와 휴대폰 더보기 동작, 페이지 제목. 하지 않을 것은 아래와 같다.
- 키 입력·표시
- 메뉴·머리의 상태 점
- 사용량 그래프나 내역
- '모두 다시 확인' 버튼(스펙 2절, 2026-09-30 사용자 확정)
- 자동 주기 확인
- 원래 브랜드의 이름이나 로고

## 5. 구성
- **페이지 머리(`PageHeader`, 앱 틀 브리프 2절):** 제목은 "연결 상태", 설명은 "공급자 키는 서버 환경변수에서 관리해요. 이 화면에서는 키를 입력하거나 보여 주지 않아요." 머리에 동작 버튼은 없다.
- **요약 띠:** 머리 아래 본문 너비 한 줄. 옅은 청록 바탕(`primary-subtle`. 처음에는 대표 색 8% 알파였으나 채도가 빠져 2026-10-04 finish 리뷰로 시안 채도의 불투명 틴트로 바꿨다. 라이트 청록 글자 4.73:1), 반경 12px, 앞에 채운 정보 아이콘, 굵은 청록 요약과 회색 문제 목록. 버튼과 닫기는 없다.

  | 상황 | 굵은 요약 | 회색 목록 |
  |---|---|---|
  | 첫 확인 중(결과가 아직 없는 카드가 하나라도 있다) | 연결 상태를 확인하고 있어요 | (없음) |
  | 모두 연결됨 | 3개 모두 연결됨 | (없음) |
  | 그 밖 | 3개 중 {N}개 연결됨 | 안 되는 공급자를 카드 순서로 "{공급자} {상태 이름}"으로 적고 " · "로 잇는다. 예: "ElevenLabs 키 오류 · Fish Audio 키 없음" |

  - 다시 확인 중에는 이전 요약을 그대로 둔다(카드가 이전 결과를 두는 것과 같다).
  - 조회 자체 실패(6절 마지막 행)는 "확인 실패"로 센다.
  - 소유자 없음이면 띠를 두지 않는다(카드 대신 안내 하나).
  - 좁은 너비에서는 회색 목록이 다음 줄로 내려간다.
- **카드 3장:** Typecast, ElevenLabs, Fish Audio 순이다. 1024px 이상은 한 줄 3열, 768~1023px는 2열, 767px 이하는 1열이다(T3에서 CS-04 반영, 2026-10-04). 카드 높이는 줄마다 맞추고, 버튼은 카드 바닥에 붙어 한 줄에 선다.
- **카드 안 순서:**
  1. 공급자 이름(굵게)
  2. 상태 배지(아이콘 + 글자), 이름 아래 줄
  3. 원인 한 줄과 할 일
  4. 공급자 오류 코드(있을 때, 코드 칩)
  5. 잔여 사용량(있을 때, 굵게)
  6. 확인 시각(회색)
  7. '다시 확인하기' 버튼(카드 너비를 채우는 청록 테두리 버튼)

## 6. 상태와 표현
| 상태 | 배지 | 본문 |
|---|---|---|
| 연결됨 | success, 체크 아이콘, "연결됨" | 잔여 사용량과 확인 시각 |
| 키 없음 | neutral, 열쇠 아이콘, "키 없음" | "서버에 키가 없어요. `apps/web/.env`에 `…_API_KEY`를 넣고 다시 확인해 주세요." 변수 이름은 복사할 수 있는 코드 글꼴이다 |
| 키 오류·권한 부족·한도 부족 | warning, 경고 아이콘, 상태 이름 | 원인과 공급자 대시보드에서 할 일. 한도 부족이면 사용량도 보인다 |
| 요청 제한 | warning, 경고 아이콘, "요청 제한" | "잠시 뒤 다시 확인해 주세요." 기다릴 초를 받으면 확인 시각에 더한 시각으로 "오후 3:12:35 이후 다시 확인해 주세요." |
| 공급자 장애 | warning, 경고 아이콘, "공급자 장애" | "{공급자} 서버에 문제가 생겼어요. 잠시 뒤 다시 확인해 주세요." |
| 확인 실패 | warning, 경고 아이콘, "확인 실패" | "연결 상태를 확인하지 못했어요. 잠시 뒤 다시 확인해 주세요." 응답 검증 실패도 여기 들므로 "응답을 받지 못했어요"라고 하지 않는다 |
| 조회 자체 실패(자체 서버 500, 연결 끊김, CSRF 403) | 확인 실패와 같다 | 확인 실패와 같은 문구와 '다시 확인하기' |
| 확인 중(첫 확인) | — | 카드 자리를 유지하는 `Skeleton`. 레이아웃이 밀리지 않는다 |
| 확인 중(다시 확인) | 이전 결과를 유지한다 | 버튼 안에 `Spinner`와 "확인 중". 그 카드의 버튼만 누를 수 없다 |
| 소유자 없음 | — | 카드 대신 `Empty` 하나: 제목 "이 주소에서는 공급자 연결을 확인할 수 없어요", 설명 "개발 서버(`pnpm dev`)를 127.0.0.1 또는 localhost 주소로 열어 주세요." 전역 알림은 없다 |

- 공급자가 준 오류 코드(예: `invalid_api_key`, `HTTP 503`)는 원인 줄 아래 작은 글자로 보인다. 키 값은 어디에도 보이지 않는다.
- 배지는 shadcn `badge`다. 같은 색의 옅은 바탕(`success-subtle`·`warning-subtle`, 시안 채도의 불투명 틴트. 2026-10-04 finish 리뷰로 10% 알파에서 바꿈) 위에 같은 색 글자를 쓴다(`DESIGN.md` "연한 틴트 + 진한 동색 글자" 쌍). 연결됨은 초록, 경고 상태는 주황, 키 없음은 회색이다. 반경 6px, 굵은 글자.
- 상태색 글자와 아이콘은 새 success·warning 토큰을 쓴다(스펙 2절 상태 색). 라이트·다크 모두 카드 바탕과 옅은 바탕에서 4.5:1 이상이다(값은 T2 계획 Task 7).

## 7. 값의 범위와 형식
| 값 | 형식 |
|---|---|
| Typecast | "{플랜} 플랜 · 남은 크레딧 1,234 / 전체 10,000" |
| ElevenLabs | "남은 글자 12,345 / 전체 100,000 · 10월 12일 초기화". 초기화 시각이 없으면 뒤를 뺀다. 한도 확장으로 잔여가 0 이하인 연결됨은 "남은 글자 0 / 전체 M · 한도를 넘겨 사용 중"이다(요금 문구는 공급자 문서 근거가 없어 쓰지 않는다) |
| Fish Audio | 굵은 "API 충전 잔액 12.34", 그 아래 보통 굵기 "웹 free 플랜 · 남은 웹 크레딧 10,000 / 전체 8,000", 그 아래 작은 글자 "fish.audio 웹 플랜 크레딧은 API 충전 잔액과 별개예요." 앱이 쓰는 값(API 충전 잔액)을 위에 굵게 둔다. 충전 잔액은 소수 둘째 자리까지 버림으로 보인다(실제보다 크게 보이지 않게). 웹 플랜 조회에 실패하면 둘째 줄이 빠지고 안내는 "fish.audio 웹 플랜 크레딧은 확인하지 못했어요. 이 값은 API 충전 잔액과 별개예요."가 된다(두 값이 별개라는 안내는 남긴다). 웹 크레딧은 추가 크레딧 때문에 남은 값이 전체보다 클 수 있고, 공급자 웹 화면과 같게 그대로 보인다. 플랜 이름(공급자 값)과 `fish.audio`는 번역하지 않는다(`translate="no"`). API 생성이 웹 크레딧을 쓰지 않는지는 공식 문구가 없어 화면에서 단정하지 않는다(2026-10-04 후속 수정) |
| 확인 시각 | "오후 3:12:05 확인". 초까지 보여 같은 결과가 다시 와도 확인이 돌았는지 알 수 있다. 같은 날이 아니면 "9월 30일 오후 3:12 확인" |

- 숫자는 `ko-KR` 천 단위 구분을 쓴다.
- 0도 "0"으로 보인다. 값이 없을 때만 줄을 뺀다.
- 큰 수(10억 이상)와 긴 오류 코드가 320px에서 줄바꿈된다.

## 8. 상호작용과 접근성
- '다시 확인하기' 버튼의 접근 이름에 공급자를 넣는다(예: "Typecast 다시 확인하기"). 44px 이상이고 hover와 `focus-visible`이 보인다.
- 알림: 페이지에 `aria-live="polite"` 영역을 하나 둔다. 사용자가 누른 확인의 결과만 한 문장으로 알린다(예: "ElevenLabs: 키 오류"). 첫 로드의 결과 세 개는 알리지 않는다. 화면에 바로 보이고, 셋이 겹쳐 읽히기 때문이다.
- 상태를 색만으로 구분하지 않는다. 글자, 아이콘 모양, 배지 바탕이 함께 바뀐다.
- `prefers-reduced-motion`이면 스피너와 스켈레톤을 움직이지 않는다.
- 요약 띠는 알림 영역이 아니다(`aria-live` 없음). 첫 로드의 요약은 화면에 보이고, 사용자가 누른 확인의 결과는 위 알림 영역 한 곳에서만 읽힌다.
- **메뉴:** '연결 상태'가 링크가 되고 열린 화면 묶음(음성 작업실 아래)으로 올라간다. 나머지 '준비 중' 메뉴 7개는 접힌 묶음 "다음에 열릴 화면"에 둔다(사이트맵 "예외", 2026-10-03 사용자 결정, 2026-10-04 표현 개정). 휴대폰 위 막대는 음성 작업실·연결 상태·더보기 3칸이다.
  - 휴대폰 더보기는 이동·Esc·바깥 누르기로 닫힌다. Esc로 닫히면 포커스가 더보기 버튼으로 돌아간다(T2 당시 더보기 안에 링크가 없어 이동은 늘 위 막대 링크로 일어나고 포커스는 누른 링크에 남는다. 더보기 안에 링크를 두는 TASK가 이동 뒤 포커스를 정한다. T6에서 적용(`/classes`): 더보기 안 링크를 누르면 포커스는 더보기 버튼으로 간다). 열린 동안 Tab은 더보기 버튼과 펼친 내용 안에서만 돈다(impeccable-map 햄버거 메뉴, 2026-10-03 사용자 결정).
  - 더보기 안 화면에 있을 때 더보기 버튼에 현재 위치를 표시하는 규칙(활성 메뉴와 같은 표현, 스크린 리더에는 "더보기, 현재 {화면}")은 둔다. T2 당시에는 열린 화면이 모두 막대에 있어 해당하는 화면이 없었다. T6에서 적용(`/classes`): '채널·분류'가 더보기 안에 있어 이 규칙이 쓰인다.
- **탭 제목:** "연결 상태 · TTS Pilot".
- **쓰는 상호작용:** 버튼과 링크의 hover·`focus-visible`, 메뉴 묶음 펼치기, 휴대폰 더보기(위 메뉴), 카드 안의 확인 중 표시, 알림 영역.
  - 쓰지 않는 것: 새 툴팁(아이콘만 있는 버튼이나 줄여 쓴 값이 없다), 모달·드로어(되돌리기 어려운 동작이 없다), 성공 토스트(결과는 카드와 알림 영역에 보인다).
  - 이 화면의 조회는 전역 오류 알림을 띄우지 않는다. 오류는 카드가 보인다.

## 9. 시각 자산
- **서체:** T1의 Pretendard 가변 판(`next/font/local`로 자체 호스팅, OFL)만 쓴다. 굵기는 400과 700뿐이다. 새 서체는 없다. 사용량 숫자와 확인 시각은 `tabular-nums`로 자리를 맞춘다. 변수 이름과 오류 코드는 기본 모노 글꼴의 코드 칩이다.
- **이미지:** 없다. 장식을 두지 않는 화면이다(3절). 시안에도 사진·일러스트·질감 영역이 없어 plate가 없다.
- **아이콘:** `iconLibrary`(lucide) 한 벌이다. 요약 띠 `Info`(대표 색으로 채운 원), 연결됨 `CircleCheck`, 키 없음 `KeyRound`, 나머지 경고 `TriangleAlert`. 배지와 버튼 안 아이콘은 `data-icon`으로 크기를 맞추고 글자와 함께 보인다.
- **모션:** 상태가 바뀔 때만 쓴다. 확인 중 `Spinner`, 첫 확인의 `Skeleton`, 버튼 바탕색 바뀜(150ms `cubic-bezier(0.3,0,0,1)`)뿐이다. `prefers-reduced-motion`이면 모두 멈춘다(8절).

## 10. 제약
- 토큰만 쓴다. 원시 색 값이나 임의 Tailwind 값을 새로 넣지 않는다.
- 토큰은 리디자인으로 값이 바뀌고(시맨틱 이름 구조는 그대로), 새로 더하는 이름은 `success`·`warning`과 바탕용 `success-subtle`·`warning-subtle`·`primary-subtle`이다(2026-10-04 finish 리뷰). 요약 띠와 활성 메뉴의 옅은 청록은 `primary-subtle`이다(메뉴 `sidebar-accent`가 같은 값). 값과 대비는 T2 계획 Task 7. `DESIGN.md` 반영은 라운드의 DESIGN.md 갱신 행에서 merge로 더한다(덮어쓰지 않는다).
- 프리미티브는 `packages/ui`의 `Card`, `Skeleton`, `Button`(`outline` 변형을 청록 테두리로 바꾼다), `Empty`와 새로 더하는 `badge`, `spinner`를 쓴다. 요약 띠는 이 화면 하나만 쓰므로 프리미티브로 만들지 않고 화면 컴포넌트 안에 둔다. 새로 더하는 것은 `.agents/skills/shadcn/SKILL.md` 절차와 `pnpm --filter @tts-pilot-app/ui exec shadcn add`로 한다.
- 아이콘은 `components.json`의 `iconLibrary`를 쓴다.
- 문구는 제품 보이스(`-어요`)를 쓰고 원래 브랜드 이름은 쓰지 않는다. 긴 문구와 코드가 좁은 너비에서 줄바꿈된다.
- 이 브리프에서 정하지 않은 문구나 색을 구현하는 쪽이 새로 만들지 않는다. 필요하면 묻는다.

## 11. Direction contract

개발 전용이다. 구현 소스, 브라우저로 가는 산출물(주석, 숨은 DOM, `data-*`, 메타데이터 포함)에 옮기지 않는다. 리뷰어와 documenter는 이 브리프에서 받는다.

- **THESIS:** 답이 먼저 오는 연결 점검표. 맨 위 한 줄이 "몇 개가 되고 무엇이 안 되는지"를 말하고, 같은 무게의 카드 셋이 공급자마다 고칠 방법을 말한다. 상태 점과 대시보드식 숫자 타일을 늘어놓는 관리자 화면을 거절한다.
- **OWN-WORLD:** 아주 옅은 회색 바탕 위 흰 표면, 16px 카드와 12px 띠, 8px 버튼. 글자는 검정 85·60% 두 단계와 400·700 두 굵기. 청록 한 색이 1차 동작·활성 메뉴·요약 띠·포커스만 맡고, 상태는 초록·주황·회색의 옅은 바탕 + 같은 색 글자 배지로만 말한다.
- **STORY:** 키를 바꾼 뒤나 다른 화면에서 공급자 문제가 났을 때 들어와, 띠 한 줄로 전체를 알고, 안 되는 카드에서 원인과 넣을 변수 이름을 읽고, 고친 뒤 그 카드만 다시 확인한다.
- **FIRST VIEWPORT:** 왼쪽 256px 흰 사이드바(글자 로고, 활성 '연결 상태', 접힌 "다음에 열릴 화면", 바닥 테마와 로컬 관리자). 본문은 제목 "연결 상태"와 회색 설명, 그 아래 본문 너비의 청록 요약 띠, 그 아래 같은 높이 카드 셋. 1차 동작은 각 카드 바닥의 '다시 확인하기'이고 셋이 한 줄에 선다.
- **FORM:** 요약 띠 + 카드 3장, 공명 순 후보 7개 가운데 6번, seed `3b1df964`(surface, operate).
- **FINISH:** unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
