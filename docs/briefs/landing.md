# 랜딩 브리프 (4판, 증명 장면)

- 1판 2026-11-18(T15-a), 2판 2026-11-19(T15-a2 공개 데모), 3판 2026-11-19(기능·매력 소개 재구성, 커밋 5824b2e). **4판 작성 2026-11-19, 상태: 사용자 확인(2026-11-19, "확인, 이대로 만들기").** 근거: [랜딩 4판 기획 제안](../plans/landing-v4-proposal.md)(사용자 2026-11-19 "1·2단계 모두", Airy "'다른 문장' 표시 유지", 데모 "예시 대본 열린 채로"), 사용자 추가 요청 "필요하면 gpt-image로 이미지도 기획·생성해 임팩트 있게".
- 모드: Persuade. 시각 기준: `DESIGN.md`(청록·Pretendard·마스코트 세계 유지). 새 시각 언어는 **파형 하나**만 더한다.
- 보조: landing, animation (visual-critique·ui-design 미설치)
- 바꾼 이유: 3판은 기능을 빠짐없이 **설명**하지만 **증명**이 약하다. 방문자가 만지는 곳 1곳(히어로 칩), 소리가 나는 곳 1곳, 숫자 없음, 데모는 빈 화면에서 시작한다.

## 1. 누가, 무엇을
- **방문자:** 포트폴리오 링크로 온 사람(채용 담당자, 개발자), 한국에서 접속. 1분 안에 "소리는 어떤가 → 무엇이 다른가 → 얼마나 잘 만들었나"를 몸으로 확인하고 데모로 들어간다.
- **콘셉트:** 들려주고(Listen) → 만져 보게 하고(Try) → 숫자로 증명한다(Trust). 장면마다 '▶ 듣기'나 '직접 해 보기'가 하나 있고, 마스코트가 장면 안내자로 나온다. 글은 장면마다 한두 줄로 줄인다.

## 2. 결과와 증거
- 성공: 히어로에서 성우 둘 이상을 비교해 듣고, 숫자 놀이터에 한 번 이상 입력하고, '데모 작업실 열기'로 예시 대본이 열린 작업실에 들어간다.
- 증거는 사실만: 실제 샘플, 브라우저에서 실제로 도는 숫자 읽기 엔진, 실측 수치(코드 줄 수·테스트 수는 구현 때 명령으로 다시 세어 적는다). 후기·로고 월·사용자 수 없음.
- 공개 데모는 음성 서비스를 부르지 않는다는 사실을 숨기지 않는다(3판 문구 유지).

## 5. 상호작용과 모션
- 자동 재생 없음. 재생은 한 번에 하나(새 재생이 이전 재생을 멈춘다, 장면 1·3·4 공통 플레이어). 재생 중 다른 섹션으로 스크롤해도 계속, 멈춤 버튼은 그 줄에.
- 파형: 줄마다 미리 뽑은 막대 값(64개 안팎, 샘플 파일에서 한 번 계산해 코드 상수로)으로 그린 SVG/CSS 막대. 재생 중에는 진행 위치까지 `primary`로 칠한다. Web Audio·캔버스 없이(새 의존성 없음). 움직임 줄이기에서는 칠하기만(막대 높이 애니메이션 없음).
- 숫자 놀이터: 입력은 디바운스 없이 즉시 계산(순수 함수, 200자 제한). 결과 영역은 `aria-live="polite"`. 예시 칩은 입력칸을 그 문장으로 바꾸고 포커스는 입력칸에.
- 비용 재현: 실제 앱의 `ConfirmDialog`를 쓰되 서버 호출 없는 로컬 상태. '다시 해 보기'로 처음 상태.
- 드라마 줄 강조: `timeupdate`로 현재 줄을 정하고 `aria-current`. 자막은 화면 글자(읽기 순서 유지).
- 모션은 기존 reveal 한 번만. 스크롤 연동 이동·패럴랙스·무한 반복 없음.

## 7. 데모 쪽 보완
- '데모 작업실 열기'(막대·장면 10)는 `/studio?example=1`. 공개 데모에서 이 주소로 들어오면 작업실이 비어 있을 때 **예시 대본(코드 상수, 숫자·연기 태그가 든 3문단)**을 문단 카드로 채워 연다. 사이드바로 들어오면 지금처럼 빈 상태. 본인용(데모 아님)에서는 `example`을 무시한다.
- 테스트 수 문구는 실측으로 맞춘다.
- 데모 DB QA 잔재 정리(UX-01)는 DB 작업이라 이 라운드 밖(백로그 유지).

## 9. 단계
- **1단계(유료 호출 없음):** 장면 1·2·5·6·7, 10의 데모 시작, 그림 ①②④⑤. 장면 3·4 자리에는 3판의 해당 내용(크롭·짝 카드)을 잠시 둔다.

## 12. 구현 경계 (재사용)
- 카피·샘플 목록·파형 값·예시 대본은 `apps/web/src/lib/landing-content.ts`(필요하면 `landing-waveforms.ts`)에 상수로 둔다.
- 숫자 놀이터는 `apps/web/src/lib/number-reading.ts`의 `readingItems`를 그대로 부른다. 엔진은 고치지 않는다. 발음용 글을 만드는 작업실 함수(`paragraph-script`의 `spokenPartsOf`)는 서버 통신·성우 모듈을 끌어와 랜딩 번들이 커지므로 규칙만 `try-reading.ts`에 옮기고, 두 결과가 같은지는 테스트가 지킨다(구현 2026-11-19, 코드 리뷰 반영). 확인 필요 항목은 작업실처럼 자동 적용하지 않고 원문과 이유 한 줄로 보인다.
- 히어로 발음용 글('삼 분기' 등)은 샘플 소리를 만들 때 실제로 보낸 글이다. 엔진 결과('삼분기')와 띄어쓰기가 다를 수 있다.
- 구현 결정(2026-11-19): 막대 '데모 써 보기'는 다른 세션 파일(`landing-bar.tsx`)이라 이번에는 `/studio` 그대로다. 히어로와 마지막 행동만 `/studio?example=1`로 간다(백로그). 2026-11-20 UX-13으로 막대도 `/studio?example=1`·'데모 작업실 열기'로 맞췄다. 연기 샘플 4개와 드라마 장면은 Fish Audio `s2.1-pro-free`로 사용자 승인 호출 5회에 만들었다(`public/samples/landing/`).
- 재생은 장면 1·3·4가 같은 작은 훅 하나를 쓴다(한 번에 하나 재생). 기존 `hero-card`의 오디오 로직이 있으면 그것을 옮겨 쓴다.
- 비용 재현은 앱의 `ConfirmDialog`와 `Badge`를 쓴다.
- 새 섹션은 `components/landing/`에, 기존 `Section`·`Reveal`·`Shot`을 쓴다. `landing.css`·`landing-bar.tsx`·`tagline.tsx`는 고치지 않는다.
- 예시 대본 채우기는 작업실 쪽 화면 코드만 고친다(서버·DB 변경 없음). 막대 링크는 `NAV_ITEMS`/CTA 상수로.
