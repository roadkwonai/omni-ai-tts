# 채널·분류 브리프 (T6)

- 작성: 2026-10-06. 상태: **사용자 확인(2026-10-06, "확인, 이대로")**.
- 2026-10-06 critique 반영(사용자 선택): 묶음 머리 아래 예시 한 줄을 항목이 있어도 남기고(빈 상태 그릇은 첫 줄만), 고치기 창의 채널 주소는 푼 주소로 보여 주고 그대로 저장한다. 스펙: [T6 스펙](../plans/tasks/T06-channels-and-classifications.md)(4·5절이 화면 동작의 정본), 계획: [T6 계획](../plans/tasks/T06-channels-and-classifications-plan.md)('브리프로 넘길 결정' B1~B6을 이 브리프가 정한다).
- 모드: Operate. 시각 기준: `DESIGN.md`와 [앱 틀 브리프](app-shell.md). 새 시각 세계·시안은 없다. 기존 화면(연결 상태 카드, 성우 캐스팅의 결과 목록·확인 창) 문법을 그대로 쓴다.
- 사이트맵: [사이트맵](site-map.md). 이 화면에서 나가는 링크는 채널 주소(새 탭)뿐이다.
- 예전 HTML 시안 브리프 [성우별 채널·분류 연결](tts-voice-classification.md)의 성우 연결·필터·연결된 성우 수는 T7 범위다. 이 화면에는 없다.

## 1. 누가, 무엇을
본인 한 명이 성우와 대본을 정리하기 전에 쓸 이름표를 미리 만든다. 오는 때는 둘이다: 처음 채널을 운영하기 시작할 때, 새 카테고리·타입이 필요해졌을 때. 한 번 만들면 자주 오지 않는 설정 화면이다.

## 2. 결과와 증거
성공은 세 묶음 목록에 만든 이름이 이름순으로 보이고, 새로 고침 뒤에도 남는 것이다. 항목마다 이름, 메모, (채널만) 채널 주소가 보인다. 숫자는 묶음마다 항목 개수 하나뿐이다.

## 3. 방향
- 한 화면에 **세 묶음을 위아래로**(채널 → 카테고리 → 타입) 둔다(사용자 결정). 탭으로 숨기지 않아 세 목록을 한 번에 훑는다.
- 묶음은 같은 무게다: 머리(이름·개수·만들기 버튼) + 흰 목록 그릇. 장식, 일러스트, 설명 카드는 없다.
- 만들기·고치기는 같은 입력 창, 지우기는 확인 창이다. 행 안에서 바로 고치지 않는다(사용자 결정 "입력 창").

## 4. 범위와 하지 않을 것
포함: `/classes` 한 화면, 메뉴 '채널·분류' 열기(앱 틀), 작업실 흐름 지도 '채널' 링크. 하지 않을 것은 스펙 6절 그대로다. 화면에서 특히 두지 않는 것:
- 성우·대본에 붙이기, 연결된 성우 수, '성우 보기'(T7)
- 검색, 끌어서 순서 바꾸기, 여러 개 한꺼번에 지우기, 기본 항목 미리 넣기
- 채널 아이콘·색, 외부 플랫폼 연결

## 5. 구성
- **페이지 머리(`PageHeader`):** 제목 "채널·분류". 설명(B4) "성우와 대본을 정리할 이름표를 만들어요. 채널은 하나를 골라 쓰고, 카테고리·타입은 여러 개 붙여요." 머리에 동작 버튼은 없다.
- **본문 폭:** `max-w-3xl`까지. 묶음 사이 간격은 목록 안 간격보다 넓게 둔다.
- **묶음 머리(B2):** 왼쪽 묶음 이름 20px 굵게 + 회색 보통 굵기 "N개"(`tabular-nums`, 행 이름 16px 굵게보다 한 단계 위). 오른쪽 `outline` 버튼 '+ 채널 만들기'·'+ 카테고리 만들기'·'+ 타입 만들기'. 좁은 화면에서 버튼은 줄을 바꿔 아래로 간다.
- **행:** 이름(16px 굵게, 줄바꿈해 다 보임), 메모(회색 14px, 이름 아래, 다 보임), 채널 주소(청록 14px 링크, 한 줄 말줄임 + 바깥 링크 아이콘, `title`에 전체 주소). 오른쪽 44px 아이콘 버튼 연필·휴지통(툴팁 '고치기'·'지우기').
- **묶음 예시(critique 반영):** 묶음 머리 바로 아래 회색 14px 한 줄로 예시를 늘 보인다. "예: 경제 한 입, 주말 레터"(카테고리 "예: 쇼핑, 지식, 뉴스, 사연, 교육", 타입 "예: 차분함, 활기참, 신뢰감, 캐릭터형"). 항목이 생겨도 카테고리·타입의 뜻이 화면에 남는다.
- **빈 상태(B1):** 목록과 같은 흰 그릇(같은 반경·테두리) 안에 회색 한 줄 "아직 채널이 없어요"(보통 굵기). 예시는 위 묶음 예시가 맡는다. 권유 문구("첫 채널을 만들어 보세요")는 쓰지 않는다. 다음 행동은 바로 위 '만들기' 버튼이다. 그릇을 목록과 같게 두어 첫 항목을 만들 때 자리가 튀지 않는다.
- **입력 창:** 767px 이하 아래에서 올라오는 시트, 768px 이상 가운데 창(폭 `max-w-md`). 모양은 기존 확인 창(AlertDialog)과 같다: 반경 16px, 얇은 테두리, 흐려지며 나타남(확대 없음), 제목 20px 굵게.
  - 제목 '{그룹} 만들기' / '{그룹} 고치기'.
  - 칸 순서: 이름 → (채널만) 채널 주소 → 메모. 라벨 14px 굵게. 칸 높이 44px 이상, 767px 이하 글자 16px.
  - **라벨(B5):** 'URL' 대신 **'채널 주소'**(GLOSSARY "채널 주소(URL)"). 칸 안 예시 `https://youtube.com/@…`. 선택 칸 라벨 뒤 회색 "(선택)".
  - 고치기 창의 채널 주소 칸은 목록과 같게 퍼센트 인코딩을 푼 주소로 채운다(`@%EA%B2%BD…` → `@경제한입`). 그대로 저장하면 푼 주소가 저장된다(링크 동작은 같다).
  - 메모는 2~3줄 칸, 아래 오른쪽 'N / 200자'(190자부터 주황).
  - **버튼(B3):** 만들기 창은 '만들기', 고치기 창은 '저장하기'. 왼쪽 '취소'(outline). 휴대폰 시트에서 두 버튼은 시트 끝에 가로 반반.
  - **시트(B5):** 최대 높이는 화면 높이, 넘치면 시트 안에서 스크롤. 휴대폰 키보드가 올라와도 저장 버튼까지 스크롤로 닿는다. 앱이 `viewport-fit=cover`를 쓰지 않아 아래 안전 영역은 브라우저가 비운다(추가 여백 없음).
- **삭제 확인 창:** 기존 AlertDialog. 제목 "‘{이름}’ {그룹}을 지울까요?", 설명 "메모와 채널 주소도 함께 지워지고 되돌릴 수 없어요. 프리셋과 대본의 채널 연결, 기본 프리셋 지정도 풀려요"(분류는 "메모도 함께 지워지고 되돌릴 수 없어요. 대본에 붙인 연결도 풀려요"). 연결된 성우가 있으면 뒤에 ". 연결된 성우 N명은 보관함에 그대로 남고, 이 {그룹} 연결만 풀려요."가 붙는다. 버튼 '취소'·'지우기'(destructive).

## 6. 상태와 표현
| 상태 | 표현 |
|---|---|
| 첫 로딩 | 묶음마다 목록 자리 회색 자리 표시 하나(머리 개수는 숨김) |
| 빈 | 5절 빈 상태 |
| 목록 오류 | 묶음 자리에 회색 한 줄 "채널 목록을 불러오지 못했어요" + '다시 불러오기'. 성공하면 포커스를 묶음 머리로 |
| 소유자 없음 | 세 묶음 대신 `LoopbackNotice` 하나 "이 주소에서는 채널·분류를 쓸 수 없어요" |
| 칸 오류 | 칸 아래 주황 글자, 화면 낭독기가 읽음. 첫 문제 칸으로 포커스 |
| 저장·삭제 중 | 칸 읽기 전용, 버튼 눌리지 않음 + 버튼 안 스피너, 창 닫히지 않음 |
| 성공 | 창 닫힘 + 알림 "‘{이름}’ 채널을 만들었어요."(고쳤어요·지웠어요) |
| 같은 이름 | 창 유지, 이름 칸 아래 "같은 이름의 채널이 이미 있어요." |
| 다른 탭에서 지움 | 창 닫힘 + 알림 "이미 지워졌거나 찾을 수 없어요." + 목록 다시 받기 |
| 저장·삭제 실패 | 창 유지·입력 보존, "저장하지 못했어요. 잠시 뒤 다시 해 주세요."(삭제는 "지우지 못했어요. …") |

**문구 규칙(B6):**
- 다시 하기 문구는 "잠시 뒤 다시 해 주세요."로 통일한다(스펙 5절. 이 화면 안).
- 마침표: 문장으로 된 알림·칸 오류·확인 창 설명은 마침표로 끝낸다. 한 줄 상태(빈 상태 첫 줄, 목록 오류 한 줄, `LoopbackNotice` 제목)는 마침표 없이 쓴다(T5 결과 목록과 같다).
- 그룹 이름 뒤 조사는 받침에 맞춘다: 채널이/채널을, 카테고리가/카테고리를, 타입이/타입을.

## 7. 값의 범위와 형식
- 이름 1~40자, 메모 0~200자, 채널 주소 0~500자(`http`·`https`만). 정리 규칙은 스펙 2절.
- 실제 범위: 채널 1~5개, 카테고리 5~15개, 타입 5~10개를 예상한다. 50개를 넘는 목록은 생각하지 않는다(가상화 없음).
- 이름순은 한국어 정렬(숫자는 크기순: "2화" < "10화"), 영문 대소문자 구분 없음.
- 채널 주소는 `https://`와 `www.`를 떼고 보이며, 한글 핸들의 퍼센트 인코딩은 풀어 보인다.

## 8. 상호작용과 접근성
- 첫 포커스: 입력 창은 이름 칸, 삭제 확인은 '취소'.
- Enter는 어느 칸에서든 저장이다. 한글 조합을 끝내는 Enter는 저장하지 않는다. 메모의 줄바꿈은 저장 때 공백이 된다.
- Esc·취소는 저장 없이 닫는다. 바깥 누르기는 값을 바꾸지 않았을 때만 닫는다.
- 닫힌 뒤 포커스: 연 버튼으로. 지운 뒤에는 다음 행 → 이전 행 → 그 묶음 '만들기'.
- 행 아이콘 버튼 접근 이름 '{이름} 고치기'·'{이름} 지우기'. 채널 주소 링크 접근 이름은 보이는 주소 + "(새 탭)".
- 인터랙티브 요소 44px 이상, `focus-visible` 고리. 모션은 창의 흐려짐과 스피너뿐이고 `prefers-reduced-motion`이면 멈춘다.
- 휴대폰 앱 틀: 위 막대 4칸 그대로, '채널·분류'는 더보기 안 맨 위 '열린 화면' 줄. 이 화면에 있으면 더보기 버튼이 활성 표현, 접근 이름 "더보기, 현재 채널·분류". 더보기 안 링크를 누르면 포커스는 더보기 버튼으로.

## 9. 시각 자산
- 서체: Pretendard(400·700)만. 개수는 `tabular-nums`.
- 이미지: 없다.
- 아이콘: lucide 한 벌. 만들기 `Plus`, 고치기 `Pencil`, 지우기 `Trash2`, 바깥 링크 `ExternalLink`, 메뉴는 기존 '채널·분류' 아이콘 그대로.
- 모션: 창 흐려짐(확대 없음), 저장 중 스피너.

## 10. 제약
- 토큰과 Tailwind 기본 눈금만. 원시 색 값·임의 값 금지. 굵기 400·700.
- 프리미티브: 기존 `Button`·`Input`·`Textarea`·`Label`·`Skeleton`·`Spinner`·`Tooltip`·`AlertDialog`와 새 `Dialog`(shadcn add 뒤 AlertDialog 모양·휴대폰 시트로 맞춤).
- 이 브리프에 없는 문구·색을 구현하는 쪽이 새로 만들지 않는다.
