# 음성 작업실 브리프 (T9)

- 상태: **확정(2026-10-20, 사용자 확인).** 대조표 18행 `impeccable shape`의 결과다. 13절의 결정은 모두 추천안(A)으로 정했다(DN-1 바닥 고정, DN-7 주 버튼에 합침, DN-6 두지 않음은 따로 묻고, 나머지는 "추천안대로, 브리프 확정").
- 정본: 화면 동작은 [T9 스펙](../plans/tasks/T09-studio-typecast.md) 4·5·8·10절이 정한다(구속력 있음). 이 브리프는 [T9 계획](../plans/tasks/T09-studio-typecast-plan.md) '브리프로 넘길 결정'과 디자인 계획 리뷰(gstack `plan-design-review`, 요약은 계획 '계획 리뷰' 절)의 4절 체크리스트 12항, 5절 DN-1~10을 닫는다. `STUDIO_TEXT`·`EMOTION_NOTE` 초안(`apps/web/src/lib/studio-view.ts`, Task 5)은 8절이 정본 문구로 고정한다. 브리프와 계획 코드가 다르면 브리프를 따른다. 고칠 자리는 11절이다.
- 사이트맵: [사이트맵](site-map.md)의 `/studio` 행. 새 URL은 없다. 더해지는 것은 오류 줄의 '이전 결과 보기'(같은 화면 안 이동) 하나다(Task 11).
- 모드: Operate. 시각 기준: `DESIGN.md`, [앱 틀](app-shell.md), [성우 캐스팅](casting.md) 12절(유료 표식, 확인 창, 결과 줄), [프리셋](presets.md) 5·8절(메뉴, 불러오기 창, 문구 규칙), [채널·분류](classes.md)(입력 칸, 목록 그릇), 시안 `docs/prototypes/tts-studio/index.html`(문단 카드, 하단 막대). 새 시각 세계·색·프리미티브·의존성은 없다.
- 변경 기록: 페이지 설명을 [리디자인](redesign.md) 3절의 고정 문구 "대본과 성우를 골라 한국어 음성을 만들 곳이에요."에서 "대본과 담아 둔 Typecast 성우로 한국어 음성을 만들고 내려받아요."로 바꾼다. 흐름 지도가 편집기로 바뀌어 '만들 곳'이 아니게 됐다.

## 1. 누가, 언제
본인 한 명이 성우 캐스팅에서 담아 둔 Typecast 성우로 실제 납품용 음성을 만든다. 오는 때는 셋이다.
- 채널 작업을 시작할 때: 채널을 고르고, 그 채널의 기본 프리셋을 불러온 뒤 대본을 붙여 넣는다.
- 같은 대본을 다른 감정·속도로 다시 만들 때: 설정만 바꾸고 다시 만든다.
- 만든 것을 다시 들을 때: 이전 결과에서 재생하거나 내려받는다. 크레딧이 들지 않는다.

크레딧이 드는 화면이다. 사용자는 "이걸 누르면 돈이 나가나", "이 소리가 지금 대본인가", "한 번만 나갔나"를 늘 확인하려 한다.

## 2. 결과와 증거
- 성공: 대본 → 확인 창 → 플레이어에 결과가 올라오고, 탐색·볼륨이 되고, 파일 이름 규칙대로 내려받아진다. 다시 듣기, 내려받기, 같은 조합 열기는 공급자 호출이 0회다.
- 증거: 스펙 8절 수용 기준 1~16과 10절 S1~S20b. 이 브리프가 더하는 QA는 12절이다.
- 이 화면만의 사실: 생성은 최대 180초 걸린다. 처리 여부를 모를 수 있고, 늦게 온 결과가 같은 줄을 완료로 바꾼다. 화면은 이것을 숨기지 않고 크레딧이 쓰였을 수 있다고 말한다.

## 3. 방향
- **초점은 하나다.** 채운 청록 버튼은 한 번에 하나만 눌 수 있다. 첫 동작을 넘겨주는 순서는 '성우 고르기' → 대본 칸 → '음성 만들기' → 플레이어다.
- **막대가 화면의 바닥이다.** 하단 막대는 늘 보이고(고정), 키보드는 카드 → 막대 → 이전 결과 순으로 지난다(DN-1).
- **설정은 접혀 있다.** 카드 머리줄은 성우, (기본값이 아닐 때만) 감정, '설정' 셋이다. 가장 자주 바꾸는 감정은 머리줄의 표식에서 바로 간다(DN-2).
- **돈이 드는 곳에만 `Coins`.** 주 버튼('음성 만들기')과 유료 확인 창뿐이다.

| 상태 | 초점(눌 수 있는 채운 청록) | 나머지 |
|---|---|---|
| 처음(성우 없음) | 카드의 '성우 고르기' | 주 버튼 잠김(50%), 이유 "성우를 골라 주세요" |
| 성우 있음, 대본 없음 | 대본 칸(채운 버튼 없음) | 성우 버튼 outline, 주 버튼 잠김, 이유 "대본을 먼저 써 주세요" |
| 만들 수 있음 | 막대의 '음성 만들기 · 약 N크레딧' | 모두 outline·ghost |
| 같은 조합의 결과가 있음 | '저장된 결과 열기'(표식 없음) | 도움 줄 "… · 크레딧 0" |
| 결과가 올라 있음 | 막대 왼쪽 플레이어와 캡션 | 주 버튼은 outline '저장된 결과 열기'와 도움 줄 `shownSame`(24행). 대본·설정을 바꾸면 주 버튼이 다시 '음성 만들기' |

**버릴 것**(리디자인 4절): 7 모든 조작이 같은 무게의 테두리 알약이고 기본값까지 버튼으로 보이는 것, 8 유료 생성과 무료 재생이 같은 ▷인 것, 10 세 단·상단 버튼 넷·하단 막대가 다투는 구성.

## 4. 범위와 만들지 않는 것
포함: 머리(채널 고르기, '프리셋' 메뉴), 불러온 프리셋 줄, 문단 카드 1장(성우 고르기 창, 감정 표식, 설정 칸과 감정 팔레트, 대본 칸), 하단 막대, 유료 확인 창, 이전 결과와 지우기 확인. 만들지 않는 것은 스펙 6절이다. 화면에서 특히 두지 않는 것:
- 같은 조합의 '새로 만들기'(DN-6), 생성 취소, 화면을 떠날 때 묻기
- 성우 고르기 창의 검색·필터(DN-9), 이전 결과의 '더 보기'·검색·묶음
- 결과 자동 재생(새로 만든 결과, 저장된 결과 열기), 가짜 진행률
- 문단 추가·나누기(P1), 대본 저장(T12), 숫자 검수(T11), 다른 공급자(T10)

## 5. 배치

### 5.1 열과 너비
- 편집 열: 머리 아래 `px-4 md:px-11`, 폭 `max-w-4xl`(896px), 왼쪽 정렬(DN-11). 대본 한 줄이 약 60자를 넘지 않는다.
- 순서는 DOM·화면·Tab이 같다: 머리 → 불러온 프리셋 줄 → 문단 카드 → 하단 막대 → 이전 결과. 막대는 화면 바닥에 고정되지만 DOM은 카드 바로 뒤다.
- 열 바닥 여백은 막대 높이 + 24px다(마지막 이전 결과 줄이 막대에 가리지 않는다).

| 너비 | 열 | 하단 막대 | 카드 머리줄 | 이전 결과 줄 |
|---|---|---|---|---|
| 1440·1280 | 사이드바 256px 옆 896px | 떠 있는 카드, 한 줄: 결과 칸 \| 동작 칸 | 한 줄 | 동작 아이콘이 오른쪽 |
| 1024 | 레일 64px 옆 872px | 1440과 같다 | 한 줄 | 오른쪽 |
| 768 | 레일 옆 616px | 떠 있는 카드: 결과 줄 / 그 아래 주 버튼(오른쪽)과 한 줄 칸(버튼 아래) | 넘치면 '설정'이 다음 줄 | 오른쪽 |
| 390·320 | 위 막대 아래 358·288px | 바닥에 붙은 판, 압축(5.6) | 성우 버튼이 줄을 채우면 감정·'설정'이 다음 줄 | 아이콘이 글자 아래 오른쪽 |

가로 넘침은 어느 너비에도 없다(긴 성우 이름은 버튼 안 말줄임, 2,000자 대본은 칸 안 줄바꿈).

### 5.2 머리
- `PageHeader`: 제목 '음성 작업실', 설명(8절). 동작 묶음은 모든 너비에서 설명 아래에 둔다(`mt-4 flex flex-wrap items-center gap-2`). 제목 줄 오른쪽에 두지 않는다. 편집 열(896px)과 왼쪽 끝이 맞고 320px에서도 감기기만 한다.
- 채널 고르기(`RadioMenu`, outline `lg`): "채널 · 채널 없음" / "채널 · {이름}"(값 굵게, 160px 말줄임). 프리셋 저장 창의 채널 칸과 같은 말이다(presets.md 5절 D6). 메뉴는 '채널 없음'이 맨 위, 나머지는 이름순. 채널이 없으면 메뉴 끝에 '채널·분류에서 만들기' → `/classes`. 받는 중이면 잠기고, 받지 못하면 메뉴 끝에 경고색 "채널 목록을 받지 못했어요"(T8 문구).
  - 고르면 그 채널의 Typecast 기본 프리셋이 있을 때 불러오기 창(T8 `LoadDialog`, 작업실 비교 `studioLoadView`)이 뜬다. 없거나 다른 공급자 것이면 채널만 바뀌고 알림도 없다.
- '프리셋'(T8 `PresetMenu`, `lg` + `ChevronDown`): Typecast 프리셋만. 트리거는 옆 채널 고르기와 같은 무채색 조건 버튼이다(`trigger="condition"`, 캐스팅은 outline 그대로, 24행 critique P2-3). 성우를 고르기 전에는 '지금 설정으로 새 프리셋 저장'이 꺼지고 둘째 줄에 회색 14px "성우를 먼저 골라 주세요"를 둔다(T8 두 줄 항목 문법, DN-8). 덮어쓰기는 숨는다. 불러오면 성우와 설정이 함께 바뀌고 알림은 "‘{이름}’ 프리셋을 불러왔어요."다(DN-5).
- 불러온 프리셋 줄(`PresetLine`): 열 맨 위, 카드 위의 회색 14px 한 줄. T8과 같다.

### 5.3 문단 카드
- 그릇: `section`, `rounded-2xl bg-card ring-1 ring-border ring-inset p-4 md:p-5`, 이름 '문단 1'.
- 머리줄(`flex flex-wrap items-center gap-2`):
  1. 번호 `1`: 회색 14px 700 `tabular-nums`(`aria-hidden`). 화면 낭독기는 숨은 제목 '문단 1'을 읽는다. 스펙의 번호는 남기되 위계를 성우 버튼에 준다(리뷰 D14).
  2. 성우 버튼(`lg`, 44px): 성우가 없으면 채운 청록 '성우 고르기'. 있으면 무채색 테두리(`border-border`, hover `muted`) "{이름}"(진한 굵은 글자, 이름만 말줄임) + 회색 보통 " · Typecast"(24행 critique P2-3). 고른 성우가 이용 불가면 버튼 뒤에 회색 배지 '현재 이용 불가'.
  3. 감정 표식(기본값과 다를 때만, DN-2): `ghost lg` 버튼, 14px 회색 "감정 · " + 진한 굵은 값(예: "감정 · 기쁨"). 누르면 설정 칸을 펴고 팔레트의 눌린 알약으로 포커스를 옮긴다. v30 '자동', v21 '기본'이면 없다.
  4. '설정'(`ghost lg` + `ChevronDown`, `ml-auto`): 펴고 접는다. `aria-expanded`·`aria-controls`. 처음은 접힘이고 펼침은 저장하지 않는다. 화살표는 전환 없이 뒤집힌다.
- 알림 줄(머리줄 아래, 있을 때만, 14px):
  - 프리셋의 성우를 쓸 수 없음: `role="status"`, 경고색 + 16px `TriangleAlert` + 문구(8절).
  - 담은 성우 목록을 받지 못함: 경고색 문구 + `ReloadButton` '다시 불러오기'(창을 열어야만 오류를 아는 일이 없게, 리뷰 D7).
- 설정 칸(`border-t pt-3`, 안쪽 한 열 `md:max-w-md`): 모델 → 감정 팔레트 → 강도('자동'이 아닐 때) → 언어 → 속도 → 음높이 → 음량 → '처음 값으로'(ghost 회색, 왼쪽 정렬, 처음 값이고 불러온 프리셋이 없으면 `aria-disabled` 50%). 성우를 고르기 전에는 회색 한 줄(8절)만.
- 대본 칸: 라벨 '대본'(화면 밖). T6 입력 칸 문법(`fieldClass`: 반경 12px, 767px 이하 16px·768px 이상 14px 글자, 넘치면 `warning` 경계) + 최소 높이 160px(`min-h-40`). 768px 이상은 448px(`md:max-h-112`)까지 늘고 그 뒤 칸 안에서 스크롤한다. 767px 이하는 상한 없이 내용대로 늘어난다(DN-4). 글자 수는 칸 아래 오른쪽 14px `tabular-nums` "1,234 / 2,000자"이고 넘으면 경고색과 `aria-invalid`. 입력은 막지 않는다(붙여 넣은 글이 잘리지 않는다). 만드는 중에도 고칠 수 있다. 요청은 이미 정해졌고, 결과 캡션이 그때의 대본을 말한다.

### 5.4 감정 팔레트
- 이름표 '감정'(설정 칸 다른 이름표와 같은 14px). 알약 묶음은 `ToggleGroup` 하나 고르기다(다시 눌러 비울 수 없음). 출처 세그먼트, 캐스팅 감정 모드와 같은 집 컴포넌트다. 설치본 Base UI 1.8.0 `ToggleGroup`은 가로 CompositeRoot라 ←→로 알약 사이를 옮기고 Tab 정지는 하나다(설치본 코드 확인, 런타임은 S18). 그룹 이름은 '감정'이다.
- 알약(`Toggle`): 최소 높이 44px, `rounded-full px-4`, 14px, 사이 `gap-2`, 넘치면 감긴다(320px에서 최대 3줄). 안 고른 알약은 카드색 바탕, `ring-1 ring-border ring-inset`, 보통 굵기 진한 글자, hover `muted`. 고른 알약은 `bg-primary-subtle text-primary ring-primary font-bold`이고 앞에 16px `Check`를 붙인다(조건 버튼의 '고른 조건' 모양, 색만으로 구분하지 않는다).
- 순서: '자동'(v30만) → 기본 → 기쁨 → 슬픔 → 화남 → 속삭임 → 높은 톤 → 낮은 톤 가운데 그 성우·모델이 받는 것(`emotionBadges`).
- 설명: 알약마다 툴팁(가리키기와 키보드 포커스)과 화면 밖 설명(`aria-describedby`)에 `EMOTION_NOTE`. 팔레트 아래 회색 14px 한 줄은 지금 눌린 알약의 설명이다(터치 화면용). 툴팁이 방향키 이동을 깨면 툴팁만 빼고 설명 줄과 화면 밖 설명은 남긴다.
- 알약이 하나뿐이면 팔레트 대신 회색 "이 성우는 감정을 바꿀 수 없어요".
- 값이 맞춰질 때(모델을 v21로 바꿔 '자동'이 빠짐, 새 성우가 그 감정을 받지 않음): 설명 줄 아래 회색 한 줄 `emotionShift` "감정 속삭임 → 기본 (이 성우·모델에서 쓰는 값)". T8 성우 맞춤 줄과 같은 화살표 문법이다. 설정 칸이 접혀 있어도 알리도록 카드 머리줄에 같은 글자의 화면 밖 `role="status"`를 둔다. 저장 값은 그대로라 v30으로 돌아오면 '자동'이 다시 눌린다.

### 5.5 성우 고르기 창
- `Dialog`(공용): 768px 이상 가운데 `md:max-w-lg`(512px), 767px 이하 아래 시트. 머리는 제목 '성우 고르기'(20px 700), 설명(8절), 오른쪽 위 44px ghost 아이콘 버튼 '닫기'(`X`, 툴팁 '닫기'). 제목이 버튼 밑으로 가지 않게 머리 오른쪽을 비운다.
- 목록: 줄 사이 가름선. 768px 이상은 `md:max-h-96` 뒤 창 안에서 스크롤하고, 767px 이하는 상한 없이 시트가 스크롤한다(이중 스크롤 없음, 리뷰 D11).
- 줄: 왼쪽 공용 샘플 버튼(44px, 무료 `Play`, 한 번에 하나) → 고르기 버튼(줄 나머지, 최소 44px, 왼쪽 정렬, hover `muted`).
  - 1줄: 이름 16px 700(말줄임) + 고른 성우면 오른쪽 16px `Check` + 이용 불가면 회색 배지 '현재 이용 불가'.
  - 2줄: 회색 14px 조건 요약(`metaLine`, 말줄임).
  - 3줄(사용 이력이 있을 때): 회색 14px `tabular-nums` "최근 사용 3일 전 · 12회".
- 고른 성우: `bg-primary-subtle`, `aria-current="true"`, `Check`.
- 이용 불가: 고르기 버튼은 `aria-disabled="true"`이고 포커스를 받으며 눌러도 아무 일이 없다. 배지를 `aria-describedby`로 잇는다. 이름·조건·이력 글자만 50%로 흐리고(꺼진 조작의 글자) 배지는 그대로다. hover 바탕도 없다. 보관함과 같은 회색 배지라 '흐리게, 이유 한 줄'(스펙)을 배지가 맡는다.
- 상태: 받는 중은 줄 높이 뼈대 셋(`aria-busy`). 실패는 경고색 문구 + '다시 불러오기'. 빈 상태는 본문 "담은 Typecast 성우가 없어요"와 outline 링크 버튼 '성우 캐스팅에서 담기' + `ArrowRight` → `/casting`(`cn(buttonVariants(...))`, DESIGN T8).
- 고르면 창이 닫힌다. 창이 닫히면(고름, Esc, '닫기', 바깥 누르기) 창에서 튼 기본 샘플을 멈춘다(보이지 않는 소리가 남지 않게).

### 5.6 하단 막대
- `section aria-label="음성 만들기와 결과"`. DOM은 카드 바로 뒤다(DN-1).
- **자리:** 바닥 고정 띠 `fixed inset-x-0 bottom-0 z-5`, 768px 이상 `md:left-16 xl:left-64`(앱 틀 레일·사이드바 폭). 띠 안쪽 `px-4 md:px-11`, 그 안 막대 `max-w-4xl`(열과 왼쪽 끝이 같다). `z-5`는 앱 메뉴(`z-10`, 휴대폰 더보기 펼침) 아래, 본문 위다.
  - 768px 이상: 띠는 페이지 바탕색(`bg-background`) `pt-3 pb-4`이고 막대는 그 안에 뜬 카드(`rounded-2xl bg-card ring-1 ring-border ring-inset p-4`, 그림자 없음)다. 본문은 띠 위 끝에서 깨끗이 끊긴다.
  - 767px 이하: 띠가 곧 막대다. `bg-card rounded-t-2xl ring-1 ring-border`, 안쪽 `px-4 pt-3`, 바닥 `pb-4`(16px). 앱 viewport에 `viewport-fit=cover`가 없어 `env(safe-area-inset-bottom)`는 늘 0이라 쓰지 않는다(24행 audit F2, 앱 viewport는 바꾸지 않는다).
- **높이 변수:** 띠가 자기 높이를 `ResizeObserver`로 재서 `<html>`의 `--studio-bar-height`에 둔다(떠날 때 지운다). 쓰는 곳은 셋이다. 열 바닥 여백(+24px), `scroll-padding-bottom`(+16px, 대본 칸 캐럿과 Tab으로 간 요소가 막대 뒤에 숨지 않게), 알림(토스트) 아래 간격. 임의 값 대신 `index.css`의 이름 붙은 utility로 둔다(`voice-panel-sticky`와 같은 방식).
- **결과 칸:** 결과가 있으면 캡션(회색 14px 한 줄 말줄임 "{성우} · {대본 첫 줄 앞 20자}…", 감정이 처음 값이 아니면 "{성우} · 감정 기쁨 · …", 24행 critique P1-a) 아래에 `<audio controls preload="metadata">`(브라우저 기본 조작, 가득, 1024px 이상 최대 448px)와 '내려받기'. 플레이어의 접근 이름은 캡션이다(`aria-labelledby`). 결과가 없으면 768px 이상에서 회색 "음성을 만들면 여기서 들을 수 있어요" 한 줄(767px 이하는 칸째 없다). 1024px 이상은 결과 칸 최소 높이를 `lg:min-h-20`으로 둬 결과 유무로 막대 높이가 바뀌지 않는다.
- **'내려받기':** 768px 이상 outline `lg` `Download` + 글자, 767px 이하 44px outline 아이콘 버튼(접근 이름 '내려받기'). 받는 중이면 아이콘이 스피너, `aria-busy`, 잠김.
- **동작 칸:** 주 버튼, 그 아래 한 줄 칸. 한 줄 칸은 모든 너비에서 주 버튼 아래다(DOM과 화면이 같다).
  - 1024px 이상: 결과 칸(왼쪽, `flex-1`) | 동작 칸(오른쪽 정렬).
  - 768~1023px: 결과 줄, 그 아래 주 버튼(오른쪽)과 한 줄 칸(버튼 아래, 오른쪽 정렬). 1024px 이상의 동작 칸을 결과 줄 아래로 내린 모양이다.
  - 767px 이하(DN-3): 결과 줄(있을 때만: 캡션, 그 아래 audio + 아이콘 '내려받기') → 주 버튼(가득) → 한 줄 칸. 대본 칸에 포커스가 있는 동안(소프트 키보드) 결과 줄을 숨긴다.
- **주 버튼**(`Button` 기본 `lg`, `focusableWhenDisabled`, 설명은 지금 보이는 한 줄 칸):

| 상태 | 글자 | 앞 아이콘 | 잠김 |
|---|---|---|---|
| 만들 수 있음 | 음성 만들기 · 약 1,234크레딧 | `Coins`(글자색) | 아니요 |
| 같은 조합의 결과 있음 | 저장된 결과 열기 | 없음 | 아니요 |
| 그 결과가 이미 플레이어에 있음 | 저장된 결과 열기(outline, 24행 critique P2-3) | 없음 | 아니요 |
| 막힘 | 음성 만들기 | `Coins` | `aria-disabled` 50% |
| 복원 전 | 음성 만들기 | `Coins` | `aria-disabled` 50%, 한 줄 칸 비움 |
| 찾는 중(0.3초 안팎) | 그대로 | 스피너 | `aria-busy` |
| 만드는 중 | 만드는 중 · 12초 | 스피너 | `aria-disabled`(흐리지 않음) |
| 결과 받는 중 | 결과를 받는 중 | 스피너 | `aria-disabled` |

  - 접근 이름은 보이는 글자 그대로다. 금액이 없는 '음성 만들기'만 끝에 ", 크레딧 사용"을 붙인다(캐스팅 12절 규칙, 금액이 있으면 이미 말한다).
  - 지난 초는 1초마다 글자만 바뀌고 읽지 않는다. 시작할 때 화면 밖 `role="status"` "음성을 만드는 중이에요"가 한 번 읽힌다.
- **한 줄 칸**(14px, 한 번에 하나, 이 순서로 이긴다): 오류 → 막는 이유 → 20초 안내 → 저장된 결과 도움 줄(그 결과가 플레이어에 있으면 `shownSame`).
  - 오류 줄은 실패한 요청의 조합(`comboSignature`)과 지금 조합이 같고 그 조합의 결과가 아직 완료되지 않았을 때만 보인다. 대본·성우·설정을 바꾸거나 막는 이유가 생기거나 늦은 결과가 완료로 바뀌면 내린다. 대기 시각은 그 실패의 이유라 오류 줄로 남는다(`liveProblem`, 24행 critique P1-b).
  - 오류: `role="alert"`, 경고색, 앞 16px `TriangleAlert`. 키·인증·권한이면 뒤에 44px 링크 버튼 '연결 상태 보기' → `/connections`. 처리 여부 미확인이면 링크 버튼 '이전 결과 보기'(이전 결과 제목으로 스크롤하고 포커스).
  - 막는 이유·20초 안내·도움 줄: 회색.
- **소리:** 한 번에 하나다. 플레이어를 재생하면 기본 샘플이 멈추고, 기본 샘플을 틀면 플레이어가 멈춘다. 새로 만든 결과와 '저장된 결과 열기'는 올리기만 하고, 이전 결과 '재생'은 올리고 재생한다(계획 '스펙과 다른 점' 13).

### 5.7 유료 확인 창
T5 `TrialConfirm`(`kind="studio"`)을 그대로 쓴다. 제목 "크레딧을 써서 음성을 만들까요?", 정의 목록(대본 "{앞 100자}… (총 N자)", 성우, 설정 요약, 예상 사용량 `Coins` 경고색, 남은 크레딧), 기본 샘플 상자, '취소'(outline)·`Coins` '크레딧 쓰고 만들기'(채운 청록). 첫 포커스 '취소', 바깥 누르기로 닫히지 않는다.
- 더함: 이전 결과에 같은 대본·성우·설정의 미확인 줄이 있으면 버튼 위에 경고 줄(경고색 + `TriangleAlert`) "같은 대본·성우·설정의 앞 요청은 처리 여부를 아직 몰라요. 다시 만들면 크레딧이 한 번 더 쓰일 수 있어요". 미확인 뒤 다시 누르는 사람이 중복 과금을 알고 누르게 한다.
- 24행에서 바뀜: 작업실(`kind="studio"`)은 기본 샘플 상자를 두지 않는다(성우 고르기 창에서 듣는다, critique P2-5). 경고 줄은 창 설명(`AlertDialogDescription`) 끝에 두어 창을 열 때 읽히고, 유료 버튼의 설명으로도 잇는다(audit F1). 캐스팅은 그대로다.

### 5.8 이전 결과
- 구역: `section`, 제목 h2 '이전 결과'(20px 700, 스크립트 포커스 자리 `tabIndex=-1`). 받는 중이거나 0개면 구역 전체를 그리지 않는다(DN-10). 첫 방문에 카드 아래 빈 구역과 막대 안내가 같은 말을 두 번 하지 않는다. 받지 못하면 제목 + 경고색 "이전 결과를 불러오지 못했어요" + '다시 불러오기'.
- 그릇: `boxClass`(반경 16px, 카드색, 안쪽 경계) + 가름선.
- 줄(안쪽 `px-4 py-3`), 글자 칸 위에서 아래로:
  1. 대본 첫 줄 16px 700(말줄임) + 배지: 미확인은 `warning` '처리 여부 미확인', 플레이어에 올라 있으면 `secondary` '플레이어에 있음'.
  2. 회색 14px `tabular-nums` "{3분 전} · {성우} · 약 120크레딧". 미확인이면 끝에 " · 사용 여부 미확인". 성우와 크레딧 사이에 처음 값이 아닌 설정을 확인 창 요약과 같은 말로 넣는다("3분 전 · 포세이돈 · 감정 기쁨 · 속도 1.20배 · 약 25크레딧". 처음 값인 모델 ssfm-v30과 감정 표식이 없는 감정은 뺀다, `settingsNote`, 24행 critique P1-a).
  3. (미확인만) 회색 14px "늦게 도착하면 여기서 완료로 바뀌어요". 만든 지 6분(다시 받는 창)이 지나면 `unknownExpired`(`unknownNoteOf`, 24행 critique P1-b).
- 플레이어에 올라 있는 줄: `bg-primary-subtle`, `aria-current="true"`, 배지(색만으로 말하지 않는다).
- 동작: `RowAction` 셋(44px ghost 회색, 툴팁) 재생 `Play` → 내려받기 `Download` → 지우기 `Trash2`. 미확인 줄은 지우기만. 640px 이상은 줄 오른쪽(첫 줄 높이에 맞춤), 미만은 글자 칸 아래 오른쪽 정렬(presets.md 6절과 같다). 접근 이름 "{성우} '{대본 앞 20자}' 재생"·"… 내려받기"·"… 지우기".
- 받는 중: 누른 버튼은 그대로 두고 아이콘만 스피너로 바꾼다. `aria-busy`, 접근 이름 "… 받는 중". 같은 줄의 다른 받기 버튼은 `aria-disabled`. 다른 줄은 누를 수 있다(앞 요청은 버린다).
- 20개면 목록 아래 회색 14px "최근 20개까지 보여요"(리뷰 D13).
- 미확인 줄이 있으면 15초마다 다시 받는다(계획). 완료로 바뀌면 배지와 안내가 사라지고 재생·내려받기가 생긴다. 지우기 버튼은 그대로라 포커스를 잃지 않는다.
- 지우기 확인(`ConfirmDialog`): 제목 "이 결과를 지울까요?", 설명(8절), '취소'·'지우기'(`destructive`). 진행 중에는 취소·Esc·재진입을 막는다. 실패하면 창 안 `role="alert"` "지우지 못했어요. 잠시 뒤 다시 해 주세요.", 성공 알림 "결과를 지웠어요.". 플레이어에 올라 있던 결과면 막대를 비운다.

## 7. 키보드와 포커스

**Tab 순서**(DOM과 같다)
1. 공통 틀: 본문으로 건너뛰기 → 앱 메뉴.
2. 머리: 채널 → '프리셋'.
3. 카드: 성우 버튼 → 감정 표식(있을 때) → '설정' → 알림 줄 '다시 불러오기'(있을 때) → (펼쳤을 때) 모델 → 감정 팔레트(정지 하나, ←→ 이동) → 강도 → 언어 → 속도 → 음높이 → 음량 → '처음 값으로' → 대본 칸.
4. 막대: 플레이어(브라우저 조작) → '내려받기' → 주 버튼 → 한 줄 칸 링크('연결 상태 보기'·'이전 결과 보기', 있을 때).
5. 이전 결과: 줄마다 재생 → 내려받기 → 지우기.

**S18 기대값**(대본 칸에서 주 버튼까지 Tab 횟수): 결과가 없으면 1번. 결과가 올라 있으면 2번 + 플레이어의 Tab 정지 수(브라우저마다 달라 Chrome에서 실측해 증거에 적는다). 이전 결과 0개와 20개에서 같아야 한다(막대가 이전 결과보다 앞이다).

## 9. 접근성, 유료 표식, 시각 자산
- **눌림 영역:** 버튼·알약·줄 동작·메뉴 항목·링크 버튼은 모두 44px 이상이다. `focus-visible` 2px `ring` 윤곽. 입력은 767px 이하 16px(`text-base md:text-sm`).
- **꺼진 것도 닿는다:** 주 버튼, 이용 불가 성우, '처음 값으로', 받는 중 버튼은 `aria-disabled` + 포커스 가능 + 이유를 `aria-describedby`로 잇는다. 프리셋 메뉴의 꺼진 항목은 둘째 줄이 이유다(설치본 Base UI 메뉴 항목이 `disabled`에서 포커스를 빼면 메뉴 설명으로 잇는다).
- **알림:** 만드는 중 화면 밖 `role="status"` 한 번, 오류 줄 `role="alert"`, 프리셋 성우 줄과 감정 맞춤 줄 `role="status"`, 성공·찾을 수 없음·조각 실패는 토스트. 토스트는 막대 위에 뜬다(공용 `Toaster` 아래 간격 + `--studio-bar-height`).
- **유료 표식(`Coins`):** 주 버튼('음성 만들기', 버튼 안 글자색)과 확인 창(본문 경고색, 버튼 글자색)뿐이다. 표식 없음: '저장된 결과 열기', 이전 결과 재생·내려받기, 프리셋·채널, 성우 창과 확인 창의 기본 샘플(`Play`). 이전 결과 줄의 크레딧은 정보 글자다.
