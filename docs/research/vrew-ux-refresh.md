# Vrew UX 보완 조사 — 문단 제작 계획에 적용할 범위

## 조사 유형과 직접 답변

- 유형: 공식 제품 사용법·버전 이력 조사와 UX 참고 제안.
- 조사일: **2026-09-26, Asia/Seoul**.
- 결론: Vrew에서 참고할 핵심은 **전체 대본을 읽다가 필요한 구간을 선택해 설정을 고치는 흐름**이다. 우리 작업실에는 문단 제작 계획·성우 선택·발음용 대본 검수로 적용하고, 자막 시간축·영상 씬·미디어 편집은 후속으로 분리한다.
- 대상 기술의 선택은 변경하지 않는다. 공급자는 Typecast·ElevenLabs이며 Vrew는 UX 참고 대상이다. 아래 제안은 구현 완료나 API 지원을 뜻하지 않는다.
- 기존 [서비스 비교 조사](./tts-service-comparison.md)를 보완한다. 프로젝트 용어는 [CONTEXT.md](../../CONTEXT.md)를 따른다.

## 확인 범위와 증거 수준

공식 홈페이지 `vrew.ai`, 홈페이지가 연결한 공식 사용가이드 `vrew.imweb.me`, 공식 공지 `docs.channel.io/vrew-kr`만 근거로 사용했다. 홈페이지에서 공식 공지로 이동하는 링크를 확인했다. 로그인·설치·다운로드·음성 생성·청취는 실행하지 않았다. 스크린샷을 직접 조작한 결과도 아니다. [공식 홈페이지](https://vrew.ai/ko/)

제품 페이지·Channel 문서는 본문을 열어 확인했다. Imweb FAQ 목록 직접 열기는 HTTP 403으로 실패했으며, 개별 가이드·공지의 **검색 도구가 제공한 공식 본문과 운영자 답변**을 제한적으로 확인했다. 이용자 댓글의 주장·개인 블로그·튜토리얼 영상 자체는 사실 근거에 포함하지 않았다. 메뉴명은 안내 당시 기준이고 최신 앱에서의 위치·단축키 동작은 미검증이다.

## 최신 음성 기능에서 추가로 확인한 점

**4.6.0 공지(2026-09-14)**는 자막이 여러 구간으로 나뉘어도 음성은 이어질 수 있으며 문맥에 맞는 감정·호흡·강조를 개선했다고 설명한다. 새 감정 지원 목소리의 스타일과 감정 강도 조절, 원하는 분위기를 설명문으로 입력하는 목소리 검색도 소개한다. 모든 목소리가 같은 감정 옵션을 지원한다는 뜻은 아니다. [4.6.0 공식 공지](https://docs.channel.io/vrew-kr/ko/articles/-%EB%B8%8C%EB%A3%A8-460-%EC%97%85%EB%8D%B0%EC%9D%B4%ED%8A%B8-%EC%82%AC%ED%95%AD%EC%9D%84-%EC%95%88%EB%82%B4%EB%93%9C%EB%A6%BD%EB%8B%88%EB%8B%A4--901ef11f)

**설계 해석:** 문단·합성 요청·자막 구간을 반드시 1:1로 맞출 필요는 없다. 문단은 사용자가 연출을 검토하는 단위로 두고, 합성 분할은 공급자의 문맥·길이 제한을 확인한 뒤 결정해야 한다. Vrew의 연결 발화를 우리 공급자 API의 보장으로 옮기지 않는다.

즐겨찾기의 AI 목소리에 별명을 붙이는 기능도 공식적으로 소개됐다. 우리 서비스에서는 공급자 성우 이름을 보존하면서 개인 용도·메모로 빠르게 찾는 방식의 참고가 된다. [2.12.0 공지](https://vrew.imweb.me/notice/?bmode=view&idx=159484441), 2025-03-26

## 개인 TTS 작업실 적용 제안

아래는 공식 문서를 바탕으로 한 **우리 UX 제안**이다. 세부 우선순위는 코디네이터가 최신 요구사항에 통합한다.

| 범위 | 제안 | 필요한 사용자 표시 |
|---|---|---|
| 현재 문단 제작 계획 | 전체 대본을 읽을 수 있는 화면을 기본으로 두고 선택 문단에만 성우·감정 세부 설정을 표시한다. | 문단 번호, 화자, 성우 이름·공급자, 감정 요약. 선택 상태를 색 외 체크·텍스트로 표시 |
| 선택 범위 | 여러 문단을 선택해 성우·지원 감정 설정을 일괄 적용한다. 적용 전에 범위를 명시한다. | `선택한 3개 문단에 적용`, 전체 기본값과 문단 예외의 구분. 적용은 생성과 별도 행동 |
| 대본 불러오기 | 붙여넣기나 저장 대본을 먼저 사용한다. 문단화가 필요하면 결과를 확인하고 합치기·나누기를 할 수 있게 한다. | 기존 대본 교체/추가, 문단 수, 빈 문단·화자 미배정. 임의 분할과 자동 생성의 결합 금지 |
| 화자와 성우 | 화자는 `내레이션`, `진행자`처럼 대본 역할로 남기고 성우는 별도 배정한다. | 역할만 바꾸는지, 해당 역할의 여러 문단 성우를 함께 바꾸는지 표시 |
| 발음 검수 | 원문을 보존하고 발음용 대본에서 교정 제안 적용/유지/직접 수정을 제공한다. | 현재 생성에 쓰일 문구와 승인 상태. 원문의 숫자·고유명사가 몰래 바뀌지 않도록 차이 표시 |
| 감정 설정 | 공급자·모델·성우의 지원 방식에 맞는 설정만 표시한다. | 자동·직접 감정·지시문을 구분하고, 미지원 설정은 다른 모델의 기능으로 대체하지 않음 |
| 수정 후 결과 확인 | 문단 계획 변경은 편집 상태만 갱신한다. 사용자가 명시적으로 생성한 뒤 결과를 듣는다. | `이전 설정으로 생성됨`, 기존 결과 재생, 새로 생성의 구분. 일부 실패 시 성공 문단을 식별 |
| 결과 재사용 | 대본·성우·설정 스냅샷과 생성 결과를 연결하고 다운로드를 가까이 둔다. | 결과 생성 시점과 현재 편집의 차이. ‘듣기’가 새 API 요청을 숨겨 실행하지 않음 |

최소 화면 흐름 예시:

```text
대본 입력/불러오기
  → 문단 제작 계획 확인(화자 · 성우 · 감정)
  → 선택 문단 수정 / 여러 문단에 적용
  → 발음용 대본 검수
  → 생성 대상·설정 확인 후 명시적 생성
  → 생성 결과 듣기·다운로드 / 바뀐 문단 다시 검토
```

이는 텍스트 중심 제작 동선을 설명하는 예시이며 고정 UI 배치나 새로운 저장 구조를 확정하는 문서는 아니다.

## 후속 자막·영상 기능으로 분리할 것

- **자막:** 생성 오디오의 시간 정보 확보, 자막 분할·합치기, 원문 기반 표기, SRT 내보내기. 발음용 대본을 곧바로 자막 원문으로 내보내지 않으며, 시간 정렬 근거 없이 임의 타임코드를 붙이지 않는다.
- **오디오 후처리:** 문단 사이 정확한 무음 삽입·줄이기, 음량 조절, 최종 파일 결합. 미디어 처리 방식과 원본 결과 보존을 정한 뒤 진행한다.
- **영상:** 클립·씬, 영상 프리뷰, 프레임 정지, 이미지·BGM·전환·자막 스타일·PDF 영상화. 현재 문단 작업실의 기본 화면에 영상 타임라인을 추가하지 않는다.
- **자동 탐지:** 업로드 음성의 화자 분리·전사·원고 정렬. 대본에 화자를 수동 지정하는 기능과 별도 요구로 다룬다.

## 버전·API·불확실성

1. 조회 당시 공식 홈페이지의 다운로드 버전 표시는 **4.6.2**였다. 최신 기능 근거는 **4.6.0, 2026-09-14 공지**다. 해당 문서가 모든 OS·플랜·계정의 동일한 UI를 보장하지는 않는다. [홈페이지](https://vrew.ai/ko/), [4.6.0 공지](https://docs.channel.io/vrew-kr/ko/articles/-%EB%B8%8C%EB%A3%A8-460-%EC%97%85%EB%8D%B0%EC%9D%B4%ED%8A%B8-%EC%82%AC%ED%95%AD%EC%9D%84-%EC%95%88%EB%82%B4%EB%93%9C%EB%A6%BD%EB%8B%88%EB%8B%A4--901ef11f)
2. Channel의 3.0.0 문서는 날짜가 `2026-05-12`지만 본문에는 `25년의 여름`이라고 쓰여 있다. **문서 표시 날짜를 실제 기능 출시일로 단정하지 않는다.** 버전 번호와 본문 기능만 근거로 쓴다. 3.5.0도 같은 표시 날짜이므로 최초 출시일을 따로 확정하지 않았다. [3.0.0 공지](https://docs.channel.io/vrew-kr/ko/articles/-%EB%B8%8C%EB%A3%A8-300-%EC%97%85%EB%8D%B0%EC%9D%B4%ED%8A%B8-%EC%82%AC%ED%95%AD%EC%9D%84-%EC%95%88%EB%82%B4%EB%93%9C%EB%A6%BD%EB%8B%88%EB%8B%A4--cc44edab)
3. Vrew 공개 TTS·클론 API의 인증·엔드포인트·요청 스키마를 이번 공식 공개 자료에서 찾지 못했다. **공개 API가 없다고 단정하지 않는다.** 개인정보 처리방침에 나오는 외부 업체 API 사용은 Vrew가 고객에게 API를 제공한다는 근거가 아니다. [공식 개인정보 처리방침](https://vrew.ai/ko/privacy-policy/)
4. 성우 수·가격·사용량·생성 속도·음질은 이번 UX 제안의 기준으로 사용하지 않는다. 기존 블로그와 최신 공지의 표현 차이를 현재 계약으로 합치지 않는다.
5. 과거 가이드에서 음성 내용과 자막의 수정 관계를 설명하는 방식이 다르므로 ‘텍스트를 고치면 모든 음성·자막이 자동 동기화된다’고 일반화하지 않는다. 현재 선택 대상과 영향을 UI에서 명시하는 설계가 필요하다.

## 재사용 가능한 결론

**대본 전체의 흐름을 유지하면서 선택한 문단의 화자·성우·감정을 고치고, 명시적으로 생성한 결과를 확인하는 작업실**로 좁힌다. 문단 분할과 자막 분할은 구분한다. 현재 공급자의 실제 API 계약을 확인해야 할 항목은 감정·발음 제어·정확한 쉼·연결 합성이며, Vrew 제품 UI만으로 지원을 추정하지 않는다.
