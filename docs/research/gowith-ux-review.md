## 흐름 분석과 채택

| 작업 | 장점 | 초기 개인 작업실 설계 |
|---|---|---|
| 제작 진입 | 랜딩에서 제작 행동이 명확함 | 초기에는 마케팅 랜딩 없이 소유자 로그인 후 바로 작업실 |
| 성우 찾기 | 청취와 선택을 별도 행동으로 구분 | 목록의 재생/선택/즐겨찾기 버튼을 독립 배치. 가상 샘플과 실제 샘플 구분 |
| 대본 작성 | 문단마다 성우·연출 지정이 가능하다는 구조 | P0는 대본 한 개/성우 한 명. 다중 문단·화자 제어는 P1로 미뤄 편집면을 확보 |
| 감정·세부 설정 | 문단 가까이 설정을 배치 | 선택한 공급자·모델에서 지원되는 옵션만 접이식 설정에 표시 |
| 발음 교정 | 비용 요약에서 숫자/단위 변환 후 글자 수 변화 안내 | 원문과 발음용 대본의 차이, 항목별 검수, 실제 전송 글자 수를 생성 전에 노출 |
| 내 목소리 | 공급자 선택, 파일/마이크 대체, 이름·동의를 한곳에 배치 | 입력→확인→처리/검증→사용으로 단계 분리. 짧은 녹음만으로 품질/완료 시간을 보장하지 않음 |
| 결과 재생 | 공통 하단 플레이어로 작업 위치를 유지 | 결과를 현재 입력과 묶고 대본 변경 후 ‘이전 대본으로 만든 결과’ 표시. 다운로드가 재생성을 호출하지 않음 |
| 안내 | 단계별 둘러보기가 제공됨 | 전체 화면을 계속 덮는 안내 대신 빈 상태와 가까운 짧은 도움말. 첫 대본 예제로 시작 |
| 확장 기능 | 자동 감정·매칭·자막·무음 등 작업 범위가 넓음 | 모두 후속 TODO에 두고 초기 내비게이션에는 표시하지 않음 |

## 그대로 옮기지 않을 것

- ‘600종’, ‘10초’, ‘100% 싱크’, ‘무료 무제한’, 제공사별 환산 단가와 고객 후기 수치는 이 앱의 사실이 아니다.
- UI 이미지 속 녹음 파일 형식은 사이트가 자체 변환을 제공할 가능성이 있다. Typecast API의 직접 업로드 형식과 동일하다고 해석하지 않는다.
- 추천 순위와 퍼센트는 계산 근거가 없으면 제공하지 않는다.
- 회원가입·크레딧 충전·요금제·홍보 영역은 현재 개인용 범위에서 제외한다.

## 설계 결론

‘한 화면에서 대본을 완성한다’와 ‘목소리 청취/선택 분리’는 채택한다. 풍부한 연출·비디오 기능은 단계적으로 확장한다. 공개 가이드의 이미지와 설명이 일치하지 않는 항목은 미검증으로 남기고, 영상 근거·공식 API 문서와 분리해 추적한다.
