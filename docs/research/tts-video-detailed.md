# 지정 TTS 영상 구간 상세 분석

조사일: 2026-09-26. 대상은 [2026-08-03 개발남노씨 오토워커2기(앵콜), 1:56:02~1:59:45](https://www.youtube.com/watch?v=Z4hi1VpZVsU&t=6962s)이다. 영상 안에서 시연하는 제품명은 **튜브워커**로 보인다. 이 구간을 gowith153 서비스의 직접 시연이라고 단정하지 않는다.

## 1. 이번에 실제 수행한 확인

- 기존 설치된 yt-dlp 2026.08.19와 FFmpeg로 **해당 223초 구간만 다운로드**했다. 전체 약 4시간 50분 영상은 저장하지 않았다.
- FFprobe 확인: **223.000초, 1920×1080, H.264 영상 + AAC 48kHz 음성, 13,223,146바이트**. 영상 파일은 `/tmp/tts-pilot-research/tts-section.mp4`에 있다.
- 16kHz mono WAV를 추출하고, 기존 로컬 whisper.cpp 1.9.4 / large-v3 모델로 한국어 전사를 두 번 실행했다. 두 번째는 문맥 누적으로 생기는 반복을 줄이기 위해 `-mc 0`을 사용했다. 외부 음성 API를 사용하지 않았다.
- **10초 간격과 마지막 시점 24개 프레임**, 조작 전후를 좁힌 **추가 24개 프레임**을 직접 이미지로 검토했다. 접촉 시트 8장과 주요 장면 확대 이미지를 아래 증거 폴더에 보관했다.
- YouTube 메타데이터에는 수동 자막과 자동 자막이 모두 없었다. 따라서 아래 발언 요약은 **원본 오디오의 로컬 자동 전사 기반**이다. 사람이 전 구간을 청취·교정한 전사나 공식 자막이라고 주장하지 않는다.
- 새 소프트웨어·모델 설치, 로그인, 유료 API 호출, 커밋·Git 추가를 하지 않았다. 동영상·오디오·전체 전사는 `/tmp`에만 있고 저장소에는 요약과 정지 화면만 있다.

증거: [출처 정보](../../tasks/evidence/tts-ui-prototype/video/source.json), [파일·전사·샘플링 검증](../../tasks/evidence/tts-ui-prototype/video/verification.json).

### 증거 읽는 기준

- **화면 확실**: 직접 본 프레임의 글자·선택 상태·입력창·결과 상태.
- **음성 보통**: 두 차례 자동 전사의 의미가 대체로 일치한 발언 요약. 발음 자체·고유명사는 오류 가능성이 있다.
- **추정/미확인**: 버튼의 실제 서버 동작, API 공급자 내부 구현, 가격, 저장 지속성 등 영상만으로 확인할 수 없는 내용.
- 시점은 원본 영상 기준이다. 로컬 영상 0초가 원본 1:56:02에 해당한다. 프레임으로 좁힌 전환 시간에는 샘플 간 2~10초 오차가 있을 수 있다.

## 3. 장면별 UX 분석과 이 제품에 주는 시사점

### A. 성우 탐색: 비교·선택·즐겨찾기는 다른 동작

실제 화면은 성우 카드의 이름, 별표, 미리듣기, 선택 테두리를 나눈다. 카드 6개와 페이지 이동을 함께 보여준다. 샘플을 비교한 뒤 KKC가 선택되는 과정을 확인했다. 별표는 존재하지만 이 구간에서 즐겨찾기를 추가·삭제하는 조작이나 저장 지속성을 검증하지는 못했다.

**제품 제안:** 재생 버튼과 선택 버튼의 역할을 구분하고, 새 샘플을 틀면 기존 샘플을 멈춘다. 즐겨찾기는 재생·선택과 독립적으로 동작하게 한다. 카테고리·타입·채널·프리셋은 사용자 요청에 따른 우리 제품 기능이며 영상에서 검증된 기능이라고 쓰지 않는다.

### B. 숫자 교정: 원문 문맥과 수정 범위가 핵심

모달은 숫자가 들어간 문장을 번호와 함께 보여주고 원문을 푸른색, 변환 발음을 붉은색 계열로 구분한다. 예를 들어 연도, 월·일, 금액에 변환 표시가 있다. 모달 안내는 AI 변환 결과 확인과 클릭 수정을 설명한다. **이 문구만으로 실제 구현이 LLM인지, 규칙 엔진인지 판단할 수 없다.**

추가 프레임에서 중요한 동작이 확인됐다. 1:57:06에 29일 항목을 누르자 해당 문장 아래에 원문 범위와 한글 입력창이 펼쳐졌다. 좌우 범위를 늘리거나 줄이는 조작부도 보인다. 단순한 전체 문자열 치환 UI보다, 문맥 속 특정 구간의 읽기를 지정하려는 구조다.

**제품 제안:** 원문을 보존하고 변환 결과를 별도 관리한다. 초기에는 개별 변환 후보의 채택·제외·수정을 지원한다. 범위 조정은 숫자 뒤의 단위·조사까지 수정할 필요를 검토하되, 실제로 사용자가 요구한 최소 기능과 일정에 맞춰 범위를 결정한다. 색 외에도 화살표·라벨·접근 가능한 이름으로 변경을 구분한다.

### C. 검수 상태: 닫아도 합성하지 않고 다시 돌아올 수 있음

1:57:10~1:57:14 사이에는 검수창을 닫은 뒤 검수 대기 상태가 보이고 다시 연다. 실제 합성으로 넘어간 장면은 1:58:14~1:58:16 사이다. 이 구분은 검수 완료와 창 닫기를 같은 동작으로 취급하지 않아야 한다는 근거가 된다.

**제품 제안:** 대본 수정 중, 교정 결과 준비, 검수 대기, 생성 중, 완료, 실패 상태를 나눈다. 닫기·취소는 합성 요청을 보내지 않아야 한다. 교정 결과가 오래된 원문을 참조하면 다시 확인하도록 표시한다. 영상에서는 새 발음으로 저장 완료·새로고침 후 복원까지 확인하지 못했다.

### D. 생성 대기: 상태 이름과 실제 진행률을 구분

준비 중→발음 변환→검수→음성 생성→마무리→완료의 단계가 관찰된다. 음성 생성 화면은 여러 샘플에서 약 50%에 머물다가 완료 직전 크게 진행한다. 검수 승인 후 생성 시작은 1:58:14~1:58:16, 완료는 1:59:24~1:59:26 사이이므로 **이번 단일 시연의 합성·후처리 대기는 약 68~72초 범위**로 관찰된다. 이는 공급자 API 지연 시간 벤치마크가 아니다.

**제품 제안:** 실제로 측정할 수 없는 진행률을 임의로 정확한 퍼센트처럼 표시하지 않는다. 처리 단계·경과 시간·재시도 가능한 오류를 보여준다. 생성 중의 설정 수정 허용 여부, 이탈 후 상태 복원, 중복 요청 방지는 별도 명세로 정의한다.

### E. 결과 확인: 음성과 텍스트가 같은 화면에 있음

완료 후 길이 2:28의 오디오 플레이어가 보이고 실제 재생한다. 현재 자막 문장과 전체 자막 목록을 전환하며 목록에서 현재 줄이 강조된다. 싱크 재시도와 무료 잔여 횟수 안내는 화면에 있지만, 이를 실행하거나 성공을 확인하지는 않았다. 음성재생성과 다음 버튼도 보인다.

**제품 제안:** P0에서는 재생·일시정지·탐색·다운로드와 생성에 사용한 최종 대본을 함께 제공한다. 동기화 자막·현재 줄 추적·싱크 재시도·무음 압축은 이 영상에서 발견한 확장 후보로 따로 관리한다. 영상의 무료 재시도 정책을 우리 제품의 과금 정책으로 복사하지 않는다.

### F. 전체 구성: 이 영상은 단계형 단일 작업 화면

시연은 대본과 음성을 단계로 나누고 한 화면의 중심 영역에서 성우·자막·무음·상태를 세로로 쌓는다. 상단 단계에는 후속 스토리보드·이미지·영상·완성으로 보이는 항목도 있지만 지정 구간에서는 그 단계를 실제 실행하지 않는다. 녹화에 보이는 채팅·발표자·Zoom 워터마크는 서비스의 UI가 아니다.

**제품 제안:** 사용자가 고른 성우·교정 대본·생성 상태를 한눈에 확인할 수 있게 작업 흐름을 구성한다. 고정 3단 레이아웃이 영상에서 검증됐다고 쓰지 않는다. 화면 배치는 DESIGN.md와 이 프로젝트의 실제 사용자 작업에 맞춰 별도로 결정한다.

## 4. 이번 영상으로 확정할 수 없는 것

- Typecast 공급자 전환, 양사 API 동시 지원 여부와 정확한 API 구현.
- 개인 클론 생성·본인 확인·삭제; 커스텀 음성 버튼은 보이지만 클릭 시연 없음.
- 개인 카테고리·타입·채널·프리셋 관리, 저장 대본, 프로젝트 영구 저장.
- 성우 샘플이 미리 준비된 파일인지 요청마다 생성되는지, 샘플 과금 여부.
- 발음 변경의 모든 예외 처리, 실제 숫자 읽기 정확도, 변경문 저장/복원 성공.
- 무음 압축의 알고리즘·시간 단축량·음질 차이. 옵션은 보이지만 효과 비교는 없음.
- 싱크 재시도의 성공, 재생성과 다운로드 실제 완료, 모든 자막의 정합성.
- 모바일 반응형 화면. 모바일 버전을 보여주겠다는 발언만 있고 해당 구간에는 모바일 시연이 없음.
- 시연의 대본 글자 수 상한·자막 기본값·무료 재시도 횟수가 우리 앱에도 적절한지 여부.

## 5. 재현 경로와 처리 한계

사용한 주요 명령 형태:

```sh
yt-dlp --js-runtimes node --no-playlist \
  --download-sections '*01:56:02-01:59:45' --force-keyframes-at-cuts \
  -f 'bestvideo[height<=1080]+bestaudio/best[height<=1080]' \
  --merge-output-format mp4 -o '/tmp/tts-pilot-research/tts-section.%(ext)s' \
  'https://www.youtube.com/watch?v=Z4hi1VpZVsU'
ffmpeg -i /tmp/tts-pilot-research/tts-section.mp4 -vn -ac 1 -ar 16000 \
  /tmp/tts-pilot-research/tts-section.wav
whisper-cli -m /Users/freelife/.cache/hyperframes/whisper/models/ggml-large-v3.bin \
  -f /tmp/tts-pilot-research/tts-section.wav -l ko -t 8 -mc 0 -osrt -oj \
  -of /tmp/tts-pilot-research/transcript-no-context
```

실제 yt-dlp는 PATH 기본 명령이 아니라 기존 캐시의 `/Users/freelife/.cache/uv/archive-v0/5K0KrJugkoL2xV7wZgToX/bin/yt-dlp`를 사용했다. 로컬 `/tmp` 파일은 운영체제 정리 시 사라질 수 있다. 공급자 서명 미디어 URL이 들어갈 수 있는 원본 메타데이터·다운로드 로그는 저장소로 복사하지 않았다.

자동 장면 탐지는 JPEG 출력 오류 후 PNG로 재시도했지만 문턱값 0.06에서 장면을 검출하지 못했다. 그래서 자동 탐지 결과에 의존하지 않고 명시적 시점의 48개 프레임을 사용했다. 다운로드 로그에는 H.264 SEI 경고가 있었지만 파일 생성·FFprobe·정시 프레임 추출·음성 전사가 완료됐다.

첫 전사에는 같은 문장의 중복과 길이 0인 구간이 있었다. 두 번째 전사에서 반복이 줄어든 것을 확인했고, 최종 표는 두 결과와 화면이 뒷받침하는 의미만 요약했다. 12월·31일·37살 등 발음 대비는 ASR이 다시 숫자로 표기하므로 정확한 소릿값을 확정하지 않았다. 마지막 결과 재생에서는 진행자와 합성 음성이 겹쳐 전사 오류가 더 생길 수 있다. 이 문서는 **실제 다운로드·프레임 검토·기계 전사에 근거한 UX 분석**이며, 사람이 모든 음절을 청취해 검증한 음질 평가가 아니다.
