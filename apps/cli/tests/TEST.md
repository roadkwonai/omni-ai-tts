# CLI 검증 계획과 결과

실제 공급자는 호출하지 않는다. 설치된 것과 같은 `dist/cli.js`를 저장소 밖 폴더에서 별도 프로세스로 실행하고, 종료 코드뿐 아니라 stdout·stderr·출력 파일의 바이트를 확인한다. 설정은 늘 임시 `OMNI_TTS_CONFIG_DIR`이다.

## T17 계획 (core.test.ts, cli.test.ts)

- origin 검증과 세션 파일 권한, 갱신과 로그아웃 경합을 단위 테스트한다.
- 설치된 CLI를 별도 프로세스로 실행해 도움말, JSON 출력, 오류 코드와 인증 없는 요청을 확인한다.
- 로컬 HTTP 서버에서 Better Auth 및 oRPC 경계를 확인하고 데모의 인증 404를 검증한다.

### studio.test.ts: 가짜 라우터 + 실제 oRPC 처리기 (약 45개)

작업실 서버를 흉내 낸 상태(저장 결과, 요청 상태, 합성 수)를 두고 CLI를 서브프로세스로 실행한다.

1. 정상: 성우와 프리셋으로 만들기, 3MiB를 넘는 파일, 결과 ID로만 내려받기, JSON 한 건, 사람용 출력, 프리셋 목록.
2. 과금 막기: 비대화에서 `--yes` 없음과 `--input -`, 확인 거절, 저장 결과 재사용, `--dry-run`, 같은 입력의 동시 실행, 확인 프롬프트에 함께 선 두 프로세스, 선점 뒤 재조회(완료·미확인·실패).
3. 복구: 응답 유실, 기록 우선, `resume`의 완료·실패·진행 중·미확인·없음, 다른 결과를 완료로 보지 않음, `--new`의 새 UUID와 되돌리기, 남의 기록 보존, 사유별 분류 표, `Ctrl+C`의 2·6·7.
4. 파일: 있는 파일·심볼릭 링크·없는 폴더·확장자, 조각 길이·MIME·중간 실패, 경로 경합, `--overwrite`.
5. 오류·경계: 빈 글·상한·잘못된 UTF-8·BOM, 옵션 충돌, 없는 성우·이용 불가, 세션 없음·비소유자·빈 user id, 프리셋 보정, 태그 원문, 무료 모델, 기록 파일의 권한과 내용.

### core.test.ts에 더하는 단위 테스트 (약 6개)

`requests.ts`(지문, 선점, 내 것만 지우기·되돌리기), Fish 무료 종료 전후의 요청과 안내, 사용량 문구.

### e2e.test.ts: 실제 라우터 + 모의 공급자 + PostgreSQL (약 6개)

`CLI_TEST_DATABASE_URL`(이름이 `_test`로 끝나야 한다)이 있을 때만 돈다. 건너뛴 것은 통과가 아니다.

- 작업 흐름 "처음 만들기": 라우터로 성우를 담고 프리셋을 만든 뒤 → `presets list` → `generate`(성우, 프리셋) → 파일 바이트 = 저장 결과 → 별도 실행 `download`.
- 작업 흐름 "두 번 과금 막기": 같은 입력 동시 실행과 재실행에서 `synthesize` 1회.
- 작업 흐름 "응답 유실": 서버는 만들었지만 응답이 끊김 → `resume`·`generate`가 같은 UUID로 받고 `synthesize`는 더 늘지 않는다.
- 3MiB를 넘는 오디오(조각 순서·전체 바이트), WAV(Gemini), 비소유자.

## T18 실행 결과 (2026-11-24, macOS, Node 26.13.0)

`CLI_TEST_DATABASE_URL=…/tts_t18_cli_test pnpm --filter @tts-pilot-app/cli test` — 파일 4개, 테스트 124개 통과, 건너뜀 0, 42.4초.

| 파일 | 수 | 본 것 |
|---|---|---|
| `core.test.ts` | 11 | T17 여섯, 지문, 선점·지우기·되돌리기, 제어·방향 제어 문자, 사용량 문구 |
| `cli.test.ts` | 3 | T17 그대로 |
| `studio.test.ts` | 102 | 위 1~5. 정상 6, 과금 막기, 복구(사유 분류 22, 앞단 HTTP 6, 결과 아닌 200 응답 3, 모르는 사유 2), 파일(권한, 모르는 형식 3), 오류와 경계(배열 아닌 조회 3) |
| `e2e.test.ts` | 8 | 실제 라우터와 PostgreSQL. 만들기·내려받기·프리셋, 3MiB 초과, WAV, 동시 실행, 함께 선 확인 프롬프트, 응답 유실, 공급자 실패와 미확인, 비소유자·남의 결과 |

- 구현 전 `studio.test.ts`는 90개 중 86개가 실패했다(명령 없음). 뒤에 더한 "결과 아닌 200 응답"은 2개가 실패하는 것을 보고 고쳤다(기록을 지우던 결함).
- 테스트가 실제로 잡는지 `dist`를 바꿔 확인했다: 선점 뒤 재조회를 없애면 6개, 선점이 앞 기록을 무시하면 1개, 내 것인지 보지 않고 지우거나 되돌리면(각각) 1개가 실패한다.
- 리뷰 반영으로 더하거나 고친 검사는 구현 전에 13개가 실패하는 것을 봤다.
- 저장소 밖 폴더에서 심볼릭 링크로 실행해도 `@tts-pilot-app/api`의 TypeScript 모듈을 그대로 읽는다(빌드 설정 변경 없음).

보지 않은 것: 실제 공급자와 배포 주소, Linux, 하드 링크가 없는 파일 시스템, 강제 종료(SIGKILL·SIGTERM) 때 남는 임시 파일. 확인 프롬프트 테스트는 macOS `/usr/bin/script`를 쓴다.

## T17 실행 결과

- `pnpm --filter @tts-pilot-app/cli test` — 주소, 느슨한 세션 디렉터리 권한 거절, 강제 종료 후 잠금 재획득, 데모 거절, 늦은 갱신과 로그아웃 경합을 확인했다. 별도 CLI 프로세스에서 도움말·입력 오류·사람용 목록·JSON·공급자 필터도 확인했다.
- 기존 Better Auth 설정과 oRPC 라우터를 연결한 로컬 HTTP 서버 및 마이그레이션을 적용한 임시 PostgreSQL 16에서 검증했다. 별도 프로젝트에 `pnpm link`로 설치한 명령으로 합성 테스트 계정에 로그인한 뒤 상태, 동명이인 성우 두 명, 즐겨찾기·채널 필터, 로그아웃 후 조회 거절을 확인했다. 비소유자는 보호 조회에서 거절됐다.
- 빠른 터미널 입력에서 암호가 반향되던 문제를 재현하고 수정했다. 빠른 입력을 다시 실행했을 때 합성 암호가 터미널 출력에 나타나지 않았다. 임시 DB는 확인 뒤 종료했다.
