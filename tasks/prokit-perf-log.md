# pro-kit 성능 개선 모니터링 기록

pro-kit v0.3.10(템플릿 f406eb60 "화면 라운드 병목 개선과 UI SDK 선택 묶음", 이 저장소 반영 27791e7)의 개선이 실제 라운드에서 효과를 내는지 B 라운드마다 잰다.

이 버전의 개선점은 다섯 가지다.
- 검증 증거 묶음(`dev-cycle packet capture`): 한 번 찍어 봉인하고 리뷰·감사·재확인이 다시 읽는다.
- 함께 시작할 수 있는 행 안내
- 하위 에이전트 감독(`dev-cycle supervise`, 15분 예산)
- 같은 평가자·수행자를 이어 쓰기(SendMessage)
- 구현 전 바닥선(build-floor)

비교 기준은 v0.3.9로 한 MG-09·MG-10 라운드다(같은 알림·모달 영역, 같은 B 대조표).

## 재는 값
- 하위 에이전트마다 걸린 시간(초)과 도구 호출 수. 에이전트 완료 보고의 `duration_ms`·`tool_uses`에서 옮긴다.
- 묶음을 다시 읽은 평가자 수(다시 찍지 않은 횟수)
- 환경 문제로 막힌 시간. pro-kit과 무관해서 따로 적는다.

### 절차 보완 요청

1. **백로그 표의 적용 범위를 표를 열 때 보여준다.** 기존 실행 효율 지침은 백로그 제목이면 디자인 비평 A/B를 생략하지만 공통 B/C 표에 디자인 리뷰 행이 남고, 이번 Main은 불필요하게 두 역할을 호출했다. A 118.462초·7회, B 두 차수 187.467초·14회. 세 화면 공통 21회·기록된 입력+출력 1,873,354개(그중 캐시 입력 1,688,320개). 호출하지 않았다면 예상되는 새 라운드 시간은 측정하지 않았다. 이미 존재하는 면제의 표시를 표 생성·첫 지시에 연결하고 **접근성 감사·코드 리뷰·실제 기능 회귀는 유지**한다.
2. **구현 전 증거와 최종 인수 자료를 자동으로 전달한다.** D의 독립 코드 검토는 처음에 코드 지적이 없었으나 제공한 구현 보고서에 native 패킷이 연결되지 않아 보충이 필요했다. 근거 파일·실제 host 수락·canonical/generated hash·범위 대조를 함께 넘겨 수용됐다. B/D의 두뇌 스킬 경로를 첫 지시에서 빠뜨려 사후 대조도 발생했다. 실제 누락이었던 시점을 보존하고 제출 직전에 자동으로 검사를 반복하지 않는다. 초기에 먼저 필요한 선택 스킬·검사·최종 패킷 목록을 한 번만 계산하는 방안을 요청한다.
3. **상향된 C에서는 필요한 소비자 근거에 집중한다.** T10-09는 late consumer에서 음수가 불가능한지 증명할 수 없어 정상적으로 화면 검증에 상향됐다. 음수는 유닛, 실제 200문단·붙여넣기 상태는 브라우저로 검증했다. 무료 전체 화면 캡처가 변경 경계 상태를 자동으로 포함하지는 않았다. 첫 B 위임에 그 상태와 준비 방법을 넣고, 패킷 봉인 후 이 상태를 확인할 추가 왕복이 필요할지 미리 표시한다. 상한을 증명하지 못한 C의 화면 검증을 생략하지 않는다.
4. **패키지 타입 검사가 통합 빌드 실패를 예측할 수 있는 지점을 좁힌다.** T9-04는 실제 DB 회귀·대상 린트가 통과했지만 SQL 스파이 테스트의 TS2339 때문에 최초 전역 타입 12.119초·빌드 3.743초가 같은 이유로 실패했다. 구현자 보완 1회 뒤 통과. 모든 작은 변경에 전역 타입/빌드를 두 번 붙이지 말고, 오버로드·mock typing 변경에 대한 패키지 타입 또는 직렬 fail-fast를 검토한다. 오프라인 설치 전에는 pnpm wrapper가 먼저 자동 설치한 실사례(5.6초·0 다운로드)가 있으므로 자원 보호 진입은 node runner 경로로 한다.
5. **권한·fixture·스크린샷의 전제를 분리한다.** VC-10 공용 데모에서 새로 고침 버튼 자체가 없어 첫 재현 차수가 끝났다. 실제 코드의 demo 분기를 미리 확인하고 공급자 키 없는 로컬 소유자 + 고유 테스트 DB + 정상 초기 목록 fixture를 준비한 뒤 mutation만 실패시키면 된다. 실패 사실만 알리는 초기 문구는 UI 리뷰에서 행동 안내 보완 1회를 받았다. 문구가 바뀐 최종 지문에서 재확인했다. 공용 데모에서 버튼을 노출하는 방식으로 제품 동작을 변경하지 않는다.
