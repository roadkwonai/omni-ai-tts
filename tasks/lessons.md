# 교훈

사용자가 바로잡은 패턴과 다시 하지 않을 규칙을 적는다.

## 2026-09-29 참고 서비스 반영이 화면에서 체감되지 않음

- **상황:** gowith 조사를 HTML에 반영했다고 보고했지만, 사용자는 "별로 반영된 게 없다"고 했다. 68개 기능 가운데 28개가 모드 전환, 대화상자, 스크롤 아래에 숨어 있었다. 첫 화면에는 문단 카드가 0장이었다.
- **원인:** 기능 목록(무엇이 있나)만 옮기고 배치 원리(무엇이 늘 보이나)를 옮기지 않았다. 반영 여부를 "코드에 있다"로 판정했다.
- **규칙:**
  - 참고 서비스를 반영할 때는 그 서비스의 첫 화면 구성, 상시 노출 요소, 밀도를 먼저 적고 우리 첫 화면과 나란히 비교한다.
  - 반영 완료를 보고하기 전에 발견성 감사를 한다. 기능마다 새 방문자 기본 로드 상태에서 1440과 390 첫 화면에 보이는지, 몇 번 눌러야 닿는지 표로 만든다. "숨김"이 많으면 완료가 아니다.
  - 핵심 작업면(이번에는 문단 카드)을 조건부 모드 뒤에 두지 않는다.

## 2026-09-29 "API에 없다"고 뺀 항목이 응답 필드에는 있었음

- **상황:** 공급자별 필터와 성우 캐스팅 브리프에서 인기·카테고리 묶음·신규·체험을 "API에 없음"으로 범위 밖에 두었다. 사용자는 Typecast 화면을 보여 주며 이 항목들을 다시 요청했다. 확인해 보니 ElevenLabs는 `sort=trending`, 응답의 `date_unix`와 `free_users_allowed`가 있었다. Fish Audio는 `sort_by=score`와 응답의 `created_at`이 있었다. 없는 것은 Typecast뿐이었다.
- **원인:** 조회 조건(query)만 보고 응답 필드와 정렬은 보지 않았다. 한 공급자에 없는 것을 세 공급자 모두에 없는 것처럼 적었다.
- **규칙:**
  - 참고 화면의 항목을 "API에 없음"으로 빼기 전에 공급자마다 조회 조건, 정렬, 응답 필드 세 곳을 확인한다. 결과는 항목 × 공급자 표로 적는다.
  - 일부 공급자만 주는 항목은 빼지 않는다. 주는 공급자에서만 보이고, 없는 공급자에서는 없다고 알린다.

## 2026-09-29 확인 요청한 화면이 사용자 브라우저에서 옛 모습으로 보임

- **상황:** 성우 캐스팅 수정을 확인해 달라며 `http://127.0.0.1:4317/index.html#casting`을 주었다. 사용자는 "추가된 부분이 안보인다"고 했다. 서버 로그를 보니 수정 뒤 요청이 한 건도 없었다.
- **원인:** 사용자는 이미 열려 있던 탭에서 주소의 `#`만 바꿨다. 그래서 새로 고침이 일어나지 않았다. 프로토타입이 `hashchange`를 처리하지 않아 화면도 그대로였다.
- **규칙:**
  - 화면 확인을 요청할 때는 강력 새로 고침(Cmd+Shift+R)을 함께 안내한다.
  - 해시로 화면을 고르는 프로토타입은 첫 로드와 `hashchange`를 둘 다 처리한다.
  - "안 보인다"는 답을 받으면 먼저 서버 로그에서 요청이 왔는지 본다.

## 2026-09-29 로드맵 첫 TASK를 로그인으로 잡음

- **상황:** 구현 로드맵의 T1을 "소유자 전용 로그인"으로 잡고 스펙까지 썼다. 사용자는 로그인은 아직 중요하지 않다며 순서를 바꿨다. 공급자 연결, 성우 조회와 미리듣기, 채널·분류, 성우 보관함 같은 기본 기능과 공통 구조를 먼저 하고, 로그인과 복잡한 기능은 뒤로 미루라고 했다.
- **원인:** 배포 뒤에 필요한 보호(공유 공급자 키를 본인만 쓰게 하기)를 로컬에서만 쓰는 기간에도 그대로 요구했다. 그 기간에는 production 차단, `127.0.0.1` 바인딩, CSRF 방어처럼 가벼운 보호로 같은 위험을 막을 수 있다. 그런데 이 대안을 선택지로 드리지 않았다.
- **규칙:**
  - 보안 요구가 작업 순서를 정할 때는 그 보호가 언제부터 필요한지 나눠 본다. 로컬에서만 쓰는 기간과 배포한 뒤를 따로 본다. 가벼운 대안이 있으면 선택지로 드린다.
  - 개인 도구의 로드맵은 기본안을 이렇게 잡는다. 사용자가 바로 써 볼 핵심 기능과 공통 구조를 앞에 둔다. 인증, 배포, 복잡한 기능은 뒤에 둔다.

## 2026-09-29 브라우저 오류를 "환경 탓"으로 빼고 사용자에게 넘김

- **상황:** T1 라운드의 런타임 확인(20행)과 통합 확인(26행)에서 수화 경고 1건을 봤다. `<body>`의 `ap-style`을 자동화 브라우저가 넣었다고 보고 "콘솔 오류 0(…은 제외)"로 적었다. 사용자는 같은 경고를 자기 브라우저의 개발 오버레이에서 봤다. `[confirm]`을 요청할 때 개발 서버도 띄워 두지 않았다. 사용자가 "서버 띄웠어?"라고 물어야 했다.
- **원인:** 오류 예산 규칙이 없었다. 원인을 추정만 하고 제외했다. 깨끗한 브라우저로 원인을 가르지 않았다. 사용자 브라우저에서도 보이는지 보지 않았다. 보고에도 넣지 않았다. QA는 "보고만" 하는 행이었다. 발견을 고치고 다시 확인하는 행이 없었다. 미룬 P3 지적은 닫힌 대조표에만 남았다.
- **규칙:**
  - 콘솔 오류·경고, 개발 오버레이 Issues, `/_next/mcp get_errors`, 개발 서버 로그는 모두 0이어야 한다. 환경 탓으로 보이는 항목도 두 가지를 확인한다. 깨끗한 브라우저(agent-browser)에서 재현되지 않는지, 사용자 브라우저(ego-browser)에서 보이는지다. 사용자 브라우저에 보이면 고친다. 고칠 수 없으면 `[confirm]` 보고에 알려진 문제로 적는다. "0(…은 제외)"로 적지 않는다.
  - `[confirm]`을 요청할 때는 개발 서버를 띄운 채로 둔다. 주소, 테스트 순서, 알려진 문제를 함께 준다.
  - 미룬 지적은 닫기 전에 백로그나 다음 TASK 메모로 옮긴다.

## 2026-10-04 조사 에이전트가 사용자 확인용 개발 서버를 껐음

- **상황:** 캐싱 조사를 맡긴 에이전트가 실험 서버를 정리하며 `pkill -f "next-server"`를 실행했다. 사용자가 `[confirm]`에 쓰던 3001 개발 서버까지 꺼졌다(exit 143). 에이전트는 저장소 복제본(1.1GB)과 실험 서버(3066)도 남겼다.
- **원인:** 조사 지시에 "서버를 띄우거나 끄지 말 것, 프로세스를 이름 패턴으로 죽이지 말 것"을 적지 않았다. 문서 조사라도 실측하려고 서버를 띄울 수 있었다.
- **규칙:**
  - 서브에이전트 지시에는 늘 적는다: 3001 개발 서버를 끄거나 다시 켜지 않는다. `pkill`·`killall`처럼 이름 패턴으로 프로세스를 죽이지 않는다. 직접 띄운 프로세스만 PID로 끈다. 실험은 scratchpad 안에서, 다른 포트로만 하고 끝나면 정리한다.
  - 저장소 복제본을 만들면 `.env`가 따라가지 않았는지 확인하고 끝나면 지운다.

## 2026-10-04 Fish Audio 잔액이 공급자 웹 화면과 달라 보임
- **상황:** 사용자가 fish.audio 웹의 '남은 크레딧 10,000 / 8,000'과 연결 상태의 'API 크레딧 잔액 0'을 비교하며 왜 0이냐고 물었다. 두 값은 서로 다른 잔액이었다(웹 구독 패키지 `/wallet/self/package`와 API 충전 잔액 `/wallet/self/api-credit`).
- **원인:** T2 설계에서 잔액 조회를 하나만 골랐다. 그 값이 사용자가 공급자 웹에서 보는 값과 어떻게 대응하는지 적지 않았다. 단위도 없어 '0원'으로 읽혔다.
- **규칙:**
  - 공급자 사용량을 보여 주기 전에, 사용자가 공급자 웹 대시보드에서 보는 값과 같은지 확인한다.
  - 다르면 이름에 어느 잔액인지 적는다(API 충전 잔액, 웹 플랜 크레딧). 그리고 둘을 함께 보이거나 차이를 안내한다.
  - 단위가 문서에 없으면 단위를 추정해 붙이지 않는다. 무엇의 잔액인지를 이름으로 알린다.
  - 과금 규칙(어느 잔액이 어디에 쓰이는지)은 공식 문구가 있을 때만 화면에서 단정한다.

## 2026-10-05 · Ego CDP 주입이 다음 실행에 남지 않음
- about:blank에서 주입을 증명한 뒤 다른 `ego-browser nodejs` 실행에서 앱으로 이동하면 mock이 없어졌다. 읽기 RPC 9회가 서버 캐시에 닿았고 생성은 0회였다.
- `Page.addScriptToEvaluateOnNewDocument`와 Network 차단은 Node 실행 사이에 남는다고 가정하지 않는다. 주입·차단·about:blank 증명·앱 이동을 한 실행에 묶고 앱에서 hits를 확인한다. reload/새 이동마다 같은 실행에서 다시 주입하며, 매 상호작용 실행에 네트워크 차단을 재적용한다.

- T5 진행 안내에 한자가 섞인 단어가 반복됐다. 한국어 문장으로 안내하고 보내기 직전에 한자·가나가 섞이지 않았는지 확인한다. 도구 출력의 영어 코드명과 사용자 안내 문장을 구분한다.

## 2026-10-07 · oRPC `key()`로 `setQueryData`를 써서 캐시가 엉뚱한 칸에 들어감 (T7)
- **무슨 일:** 보관함 훅이 `orpc.savedVoiceList.key()`(`[["savedVoiceList"],{}]`, 접두 키)로 `setQueryData`·`getQueryData`를 불렀다. 실제 캐시 키는 `queryOptions(...).queryKey`(`[["savedVoiceList"],{"type":"query"}]`)라 처음 담기·낙관적 갱신·연결 계산·빼기·확인 결과가 화면에 반영되지 않았다. 계획 코드에서 온 실수이고, 실행 없이 읽는 태스크 리뷰 5회가 모두 놓쳤다. 런타임 확인에서 별이 저장 뒤에도 꺼진 채인 것으로 잡았다.
- **규칙:**
  - `invalidateQueries`·`cancelQueries`에는 `.key()`(접두 일치), `setQueryData`·`getQueryData`에는 그 쿼리의 `queryOptions(...).queryKey`(정확 일치)를 쓴다. 한 파일에 키 상수를 하나 두고 그 값은 `queryKey`로 만든다.
  - 캐시를 직접 고치는 화면은 리뷰 통과와 별개로 런타임에서 "누른 직후 화면이 바뀌는지"를 새로 고침 없이 확인한다.

## 2026-10-07 T7.5: 입력 지연은 QA가 잡지 못했다
- 패턴: 탭을 keepMounted로 남긴 화면에서 행 수백 개가 읽는 컨텍스트에 입력 값을 두면 글자마다 모든 행이 동기로 다시 그려진다. 스크린샷 QA로는 보이지 않는다.
- 규칙: 자주 바뀌는 입력 값(문장, 검색어)은 그 값만 읽는 작은 컨텍스트나 하위 컴포넌트에 두고, 많은 행이 읽는 값은 useDeferredValue로 넘긴다. React Compiler가 Provider를 메모이즈한다고 가정하지 않는다(번들의 `_c(`로 확인). 행이 많은 화면의 QA에는 Event Timing으로 글자당 입력 지연을 잰다.
